# Social-Nav 中文文档

让具备机器人和编程基础、但未参与本次开发的协作者读懂系统，并找到完成任务所需的信息。遵循项目 AGENTS.md 的文档表达和维护规则；用户指定的读者、范围和文体优先。

## 按当前任务取材

从项目 README 找到负责该主题的文档，只读当前任务需要的段落及关联配置、代码。沿用已有文档归属，不另建重复的总览、状态表或操作手册。

审阅任务交付具体问题和建议；已授权的文档修改直接完成，不重复确认。润色授权只覆盖表达和组织，不能借机改变算法、接口、默认参数或研究结论。修正事实冲突时先核对依据；暂时无法确认的内容列入审校说明，不自行选一个说法写成事实。

改写较长段落或需要判断文风时，按问题选读[项目示例](references/examples.md)。这些例子展示表达方法，不是当前实现状态的来源；普通局部更新无需逐例阅读。

需要外部范文时，按用途查阅[参考阅读](references/reading.md)：Vue 用于中文概念解释，Python 用于操作说明，ROS 设计文档用于状态与失败处理，Google 指南用于措辞审校，Diátaxis 用于内容归属。通常使用其中的摘要即可，需要完整上下文时再打开对应原文，无需每次联网或通读。

## 根据读者的问题组织内容

下表用于判断哪些信息值得展开，不要求每篇文档具备全部栏目。

| 文档用途 | 优先回答 | 适合放到专题或引用处的细节 |
|---|---|---|
| 总览与系统方案 | 系统解决什么问题，各模块如何配合，目前能做到哪一步 | 文件清单、字段名、后端参数和历史排错过程 |
| 操作指南与速查 | 什么情况下用、需要什么输入、在哪里执行、怎样确认完成、失败后查哪里 | 算法推导、全部可选分支和实现历史 |
| 技术实现 | 输入如何变成输出，为什么这样做，什么情况会失效 | 操作命令和反复出现的全局限制 |
| 接口约定 | 谁提供、谁使用，字段的单位、坐标、时间、身份和无效值如何解释 | 实现流水和与该接口无关的研究计划 |
| 研究与评测 | 要验证什么，使用什么数据和对照，结果支持哪些结论 | 安装步骤和每次运行的检查日志 |

先交代主要流程，再解释影响理解的分支和例外。表格适合比较字段、模式和事件行为；顺序操作用列表，因果解释用连贯段落。内容简单时直接写清楚，不凑标题、图表或固定数量的要点。

总览中遇到“绑定”时，说明哪两项数据必须对应；遇到“失效”时，说明失效后哪个模块采取什么动作。接口文档保留准确的标识和必要术语，不为了通俗而另造名称。“闭环”“生命周期”等不是禁词，解释它们在当前段落中的具体含义即可。

## 修改时保留事实

先辨明原文的主体、动作、条件、结果及验证范围，再拆分或调序。必要时可增加解释性文字，但新增细节须有依据。保留独立信息；删掉重复句不能顺带删掉其中独有的例外。

本项目尤其需要检查以下含义是否在改写中变化：

- 源观察时间与接收、处理时间；位姿、地图和人物身份的对应关系。
- 未知、缺失、失效与零值；历史先验与当前观测。
- 请求已接收、几何可达、仿真完成与真实到达或停车。
- 设计、实现、离线检查、回放结果与实机验收；性能数据的输入、配置、硬件和统计范围。

代码块、命令、路径、字段名、数值及链接目标默认原样保留。任务确需更新这些内容时按实际依据修改；改标题或移动内容时核对引用与锚点。当前方案变化后整理受影响段落，必要历史按既有归档规则处理，不累积“现在改为……”式补丁。

## 交付前检查

通读改动后的完整段落，确认读者能说出主要流程，或找到操作前提和完成判据。与原文对照，检查是否新增、遗漏或强化事实，以及否定和限制是否仍落在正确对象上。原本清楚的段落保留即可。

检查受影响的链接、锚点和命令示例；文档改写不自动触发模型调用、训练、部署或整套回归。长句、术语数量和否定句只能提示人工检查，不能作为可读性评分或机械改写依据。

交付说明实际改动、已做检查及尚未核实的问题，不附例行自评分或逐词审校流水。只报告真实完成的验证，规则和格式检查通过不代表写作效果已经得到用户认可。
