# PIN-SLAM 来源与适配

来源为 [PRBonn/PIN_SLAM](https://github.com/PRBonn/PIN_SLAM)，固定提交
`e2b7fbf328e5fac1d638e217d70a69cbe9f30a52`（2025-09-26），MIT。
`upstream/` 保留原许可证、原始依赖说明，以及几何解码器、神经点、配准、映射、
回环、位姿图及其必要支持模块；不包含原入口、GUI、示例、数据或 Git 历史。
上游文件保留作者声明；原依赖文件仅记录来源，实际适配依赖见本目录 `requirements.txt`。
适配依赖使用同系列GTSAM `4.2.2`；上游原始依赖记录保留，检测环境的Python／Torch独立维护。

当前上游差异：`utils/tools.py::deskewing` 使用已归一化的整扫描时间，
不在空间过滤后重新定义扫描区间；参考时刻改为扫描结束，与输入消息头一致。
`utils/tracker.py`增加配准拒绝原因/迭代指标，移除仅供已注释输出使用的逐次 CUDA 同步计时；
原配准计算、接受阈值和迭代上限保持。其余算法核心沿用固定提交。项目适配放在本目录的 `core.py`、`inputs.py`、
`map_io.py`、`map_refinement.py` 与 `ros_node.py`，避免原入口的 GPU 覆盖、远程日志和重复输出。

完整地图使用张量和基本类型，保留回环后点局部坐标查询状态，受限读取后重建哈希；
早期项目地图根据原有回环修订记录兼容恢复该状态，不改写输入。原上游包含类对象的 pickle
不作为输入。首版仅几何与 LiDAR，固定地图定位关闭地图训练和回环优化，
需要已知六维起点。实际操作与边界见项目的[建图与定位技术说明](../../../../docs/perception/技术实现-建图与定位.md#pin-slam实验后端)。

项目配置选择上游已有的逐邻点解码后聚合模式，使配准使用真实邻域 SDF 分歧，
不把单次特征聚合的预测当作零分歧。固定地图恢复以保存的模型/查询参数为准，
仅允许显式覆盖设备、两级输入采样、推理批量、配准迭代预算和短时运动预测窗口。
拒绝帧后保留有时限的运动初值及去畸变，预测不作为有效位姿发布；接受阈值保持上游设置。

`map_refinement.py`为项目增加的建图结束阶段：在恢复定位所用的全局哈希及查询方式下，
使用已观测的地图表面、几何法向及原场符号方向构造有限近表面 SDF 样本，
以原 SDF BCE 损失优化全局几何特征。解码器、点位置/方向和原置信/时间记录固定，
不使用定位数据、外部位姿或未知区域的空闲标签。保存前刷新局部特征缓存，避免覆盖精修结果。
迭代、批量与采样范围由项目 YAML 维护，实际精修来源及统计保存在地图 manifest；
该阶段仅在建图保存时执行，固定地图定位不训练或改写输入。
