本页集中维护操作命令。先按[准备](#准备)选择解释器，再从下表进入所需任务；各示例独立选用，不需要从头执行。日常流程直接展开，首次安装、ROS诊断和专项实验收在折叠块中。

## 准备

在模型环境中运行联合推理、检测预计算和训练。系统ROS解释器负责读取bag、原生定位和ROS工具，直接运行时会通过子进程调用它。先按本机记录替换下列三项：

```bash
PEOPLE_PYTHON=/path/to/project/env/bin/python
ROS_PYTHON=/path/to/ros/python3
GPU_ID=0
export CUDA_VISIBLE_DEVICES="$GPU_ID"
```

`GPU_ID`选择物理卡。RGB工具中的`--device 0`和跟踪中的`cuda:0`表示可见设备中的第一张卡。专用任务在各节声明自己的输入和输出；同一任务的连续步骤在同一终端执行。

```bash
CUDA_COMPILER=/path/to/cuda/bin/nvcc

```

ROS诊断另按[对应构建步骤](#ros诊断准备)准备，不需要为直接运行时构建全部catkin包。

## 日常运行与回看

常规推理使用`python -B -m runtime`；`perception/scripts/run.sh`调用同一入口。读取bag不需要ROS master，在线输入连接已有传感器。每条运行命令都包含定位、三维检测跟踪和局部环境更新，`--mode`只选择建图定位模式。默认使用GPU定位近邻、去畸变、三维检测、环境更新和DWA，IMU传播、原拟合与小矩阵仍在CPU上执行。

当前速度输出均为不可执行的影子建议，真实底盘尚未接通。默认不加载YOLO或请求VLM；未提供目标时，记录感知结果与停车建议。

常规导航在计算繁忙时只保留最新待处理扫描和地图观察，不累积旧帧。`summary.json`中的`counts.source_scans`是源扫描数，`counts.scans`是实际进入检测的扫描数，`counts.maps`是发布的地图数；`scan_scheduling`和`map_scheduling`记录替换与失效丢弃。定位仍完整进入独立安全通道，所有年龄沿用测量时间。扫描归档、场景保存、决策输入记录或Agent观察使用顺序处理，负载与常规模式不同。当前地图始终生成原始距离场，详见[环境地图专题](perception/技术实现-环境地图与场景表示.md#栅格与坐标)。

当前地图采用整数高度计数、0.45局部自由门限及0.2秒人物期限。`navigation_support`在地图线程内生成GPU二维派生图，不启动CPU融合进程。`environment_device`包含基础地图与二维支持，`safety_capsule_materialize`记录必要图层取回和场景准备；没有导航图回传上传。原生地图保留默认流及显式跨流依赖，测速输入与复现命令见[推理速度](感知导航推理速度.md)。

### 从bag运行感知导航

**有图或混合定位。** 三维定位地图、人工起点和bag须对应。`LOCALIZATION_MAP`用于扫描配准，`STATIC_MAP`是供环境与导航查询的静态环境包，两者不能互换。缺少这些输入时先做[地图准备](#地图准备)。

```bash
BAG=/path/to/recording.bag
LOCALIZATION_MAP=/path/to/complete_3d_localization_map
POSE="${BAG%.bag}.initial_pose.json"
COVERAGE=/path/to/localization_coverage.yaml
STATIC_MAP=/path/to/static_environment_map
OUT=outputs/perception/session_new

"$PEOPLE_PYTHON" -B -m runtime --bag "$BAG" --mode localization \
  --map "$LOCALIZATION_MAP" --pose-file "$POSE" --coverage "$COVERAGE" \
  --static-map "$STATIC_MAP" --output "$OUT/localization" --gpu "$GPU_ID"
```

不使用手绘可信区域或静态环境先验时，分别省略`--coverage`或`--static-map`。有图关联撤销后，混合模式继续维护连续局部位置与局部环境地图。无图段不会自动探索，仍需明确的局部目标。

**无图定位与局部目标。** 目标为连续`odom`坐标系中的`base_link`位置，单位为米。

```bash
BAG=/path/to/recording.bag
OUT=outputs/perception/session_new

"$PEOPLE_PYTHON" -B -m runtime --bag "$BAG" --mode odometry \
  --goal 3 1 --goal-frame odom --output "$OUT/odometry" --gpu "$GPU_ID"
```

首次Ctrl+C请求停车并等待排空和保存。结束后查看`summary.json`中的成功或失败状态、帧数和阶段计时；地图与参数以同次`run.json`为准。失败时先读该运行的日志，参考搜索缓慢时看`reference.jsonl`中的`planning_timing_ms`和`search_attempts`。计量含义见[推理速度](感知导航推理速度.md)。

### 按录制路线生成分段目标

只有提供目标时才执行有效规划。`--coverage`负责撤销或恢复定位的地图关联，不会自行生成室外导航目标。已有带来源的演示路线时，可以显式启用bag影子回放：

```bash
ROUTE=/path/to/recorded_route.json

"$PEOPLE_PYTHON" -B -m runtime --bag "$BAG" --mode localization \
  --map "$LOCALIZATION_MAP" --pose-file "$POSE" --coverage "$COVERAGE" \
  --static-map "$STATIC_MAP" --route "$ROUTE" --route-floor floor1 \
  --start 0 --duration 367 --display --record-views \
  --output "$OUT/route_floor1" --gpu "$GPU_ID"
```

上例窗口对应10月29日一楼及室外段。其路线参考位于`outputs/navigation/wheelchair_20261029/route_readiness/route.json`，各楼层地图和起点由[本机记录](../ENVIRONMENT.local.md#10月29日分段路线与独立显示)索引。二楼另开运行，改用二楼地图、环境包、起点与可信区域，并设置`--route-floor floor2 --start 402`。起点文件的偏移必须一致。

调度读取原bag的测量时间选择路线段，再根据当前位姿生成前视目标。室外使用离图前有效关联建立的局部锚点，返图后重新检查地图关联。`route.jsonl`记录选段、目标及暂停原因，`reference.jsonl`记录实际规划结果。原驾驶轨迹不会被作为本轮执行反馈。

该功能只用于同一原包的显式开发回放，不接受live，也不能与`--goal`或`--commands`同时使用。手动目标、取消或接管会停用路线调度。电梯段等待外部确认，两层分开运行，不根据录制时间宣告到层。机制见[路线回放](navigation/技术实现-任务与路线.md#录制行程的分段目标回放)。

### 使用在线传感器

先完成[真实设备启动](#采集与bag处理)，保证外部master、点云与IMU运行。下面示例运行60秒无图定位：

```bash
OUT=outputs/perception/session_new

"$PEOPLE_PYTHON" -B -m runtime --live --mode odometry --duration 60 \
  --output "$OUT/live" --gpu "$GPU_ID"
```

有图在线任务改用`--mode localization`，并提供`--map`和明确的当前`--pose`；`--pose ROLL PITCH YAW X Y Z`的角度单位为弧度，位置单位为米。live不接受bag偏移、速率或起点文件。

真实设备使用正常ROS时钟。通过bag模拟在线传感器时，使用[外部回放命令](#外部bag回放)设置`/use_sim_time`并提供`/clock`，不要同时让同一master上的其他任务重复播放该bag。

### 复用旧运行重新推理

该入口复用旧几何、标定和原数据，重新计算定位与感知，不读取旧计算轨迹；执行后端采用当前默认。

```bash
RESULT=outputs/perception/previous_run
OUT=outputs/perception/session_new

"$PEOPLE_PYTHON" -B -m runtime --source-run "$RESULT" \
  --output "$OUT/recomputed" --gpu "$GPU_ID"
```

### 显示与提交目标

需要实时显示时，在所选运行命令中加`--display`。先启动或连接外部master，再在显示终端打开RViz；runtime只发布显示话题，不自行打开窗口。

```bash
source perception/scripts/ros1_env.sh
rviz -d perception/visualization/configs/runtime.rviz
```

默认RViz配置在连续`odom`坐标中显示三维点云和随地形起伏的导航图层。车体足迹和曲线采用对应位置的有效地面高度，不随一个固定的Z平面漂浮。只需定位和三维结果时，不必启用图像相关选项。

| RViz图层 | 显示内容 |
|---|---|
| `Navigation occupancy (terrain height)` | 导航实际使用的占据状态。浅灰为空闲，红色为占据，黄褐色为未知；静态自由支持及补充端点占据包含在内。缺少局部高度的静态支持格使用对应静态地面绘制，其余无有效高度的格子不绘制。 |
| `Terrain paths, vehicle and planning status` | 橙色车体地面投影历史、白色空间参考、青色DWA预测，以及车体轮廓、朝向和紫色意图目标。曲线不表示已经执行或获得执行许可。 |
| `Raw LiDAR path (3D diagnostic)`，默认关闭 | 雷达原点的原始三维历史，供定位诊断使用。 |
| `Navigation occupancy (XY diagnostic)`，默认关闭 | Z＝0的完整导航占据图，包括缺少可绘制地面高度的格子。 |
| `Raw local occupancy (XY diagnostic)`，默认关闭 | 补充静态自由支持前的基础局部占据图，用于对照。 |

默认地图和导航图层的话题为`/social_nav_runtime_view/ground_map`与`navigation`，扫描、人物和图像使用同前缀的`scan/people/rgb`。地图直接选用同一快照中的`navigation_occupancy`，没有静态支持派生层时使用`occupancy`；显示端不重新判定空闲。二维导航与基础图分别为`occupancy`和`raw_occupancy`。图层中的`REF/DWA`文字说明等待或拒绝原因，`GROUND`区分局部地面、静态支持高度和近车拟合，并给出曲线中有高度的采样点数量。规划可用但高度未知时，曲线会留出断口；未知高度不会补成Z＝0，也不会用线段跨接。历史点保留当时的高度，后续进入低处不会抬高或压低整条历史。

规划曲线过期、目标取消或定位失效时会清除；输入停止后也会检查到期，运行结束清除参考、预测和目标，历史仍可查看。DWA预测曲线的显示时效沿用[安全配置](../navigation/safety/config.yaml)的`max_input_age_s`，从原始反馈测量时间计算，不因重复显示刷新。真实的未知区域、运动约束或后台等待仍可能使规划不可用。辅助`path/reference/trajectory/lidar_path/occupancy`话题的内容与缺失处理见[显示接口](接口约定.md#可选显示与录制路线)。

镜头操作在三维点云区域进行。选择工具栏的`Move Camera`，或在该区域按`M`：左键拖动旋转，中键或`Shift＋左键`拖动平移，滚轮或右键拖动缩放。`Views`面板保持`Orbit`，也可直接调整`Yaw`、`Pitch`、`Distance`和`Focal Point`。RGB图像窗口不接受三维镜头操作。

显示频率由[运行时配置](../configs/runtime.yaml)的`display`独立维护：`scan_hz`、`people_hz`、`map_hz`、`rgb_hz`分别控制点云、人物、占据图和RGB，`navigation_hz`控制历史、参考、预测和状态。数值为墙钟Hz上限，设为0关闭该类别；消息仍使用原观察时间。

`height_mode: ground`为默认高度模式。`path_z_m: 0.03`表示曲线高于有效地面3cm。传感器盲区若缺少地面格子，可以在`ground_plane_radius_m: 1.5`限定的雷达周围范围内使用当前有效地面拟合，状态显示`fitted near vehicle`；设为0关闭这项显示补充。它不填充地图，也不参与导航放行。缺少有效高度时省略对应标记；需要检查固定平面投影时，可显式设置`height_mode: plane`，此时`path_z_m`表示绝对Z坐标。二维诊断时在RViz关闭`Navigation occupancy (terrain height)`，并启用`Navigation occupancy (XY diagnostic)`；该二维图使用RViz标准配色，白色为空闲、黑色为占据、灰色为未知。

参考路径表示到当前目标的空间路线。录制路线回放默认在约3m前方更新目标；DWA默认预测未来1.5s，轨迹长度随速度变化。历史和预测分别来自测量与运动预测，异步延迟可能使两者端点有小幅间隔。绘制规则与来源见[显示接口](接口约定.md#可选显示与录制路线)。

### 结果回看

查看器只读已有定位与`people.jsonl`，不重新推理。`RESULT`也可以指向完整三维地图目录。

```bash
RESULT=outputs/perception/previous_run

bash perception/scripts/view.sh --result "$RESULT"
```

按同刻原始扫描播放：

```bash
bash perception/scripts/view.sh --result "$RESULT" --play --points --rate 0.5
```

查看传感器坐标下的原生检测，包括缺定位时刻：

```bash
bash perception/scripts/view.sh --result "$RESULT" --play --points --frame lidar
```

可加`--start 5`跳到指定秒数，或加`--frame odom`查看连续局部轨迹。数据迁移后，用`--bag`和`--localization-map`指向同一原资产。

录制路线影子运行还可以生成逐控制周期的HTML审查页。运行目录须保留`control/reference/safety/route/localization.jsonl`及`run.json/summary.json`；页面区分参考可用、DWA候选生成和独立安全状态，并用同周期参考原因解释DWA等待。下面的命令只读日志，`--with-rgb`从同一bag提取过去的相机图像，不重新计算定位、检测或规划：

```bash
source perception/scripts/ros1_env.sh
"$PEOPLE_PYTHON" -B -m navigation.planning.timeline \
  --run "$RESULT" --output outputs/navigation/planning_timeline/session_new \
  --static-map "$STATIC_MAP" --with-rgb
```

输出目录必须尚不存在。无需地图背景时省略`--static-map`，无需图像时省略`--with-rgb`。直接在浏览器打开`review.html`，可拖动时间轴、逐周期查看、按原因筛选并导出审查意见。静态地图只作位置背景；旧日志没有保存的局部地图或规划曲线不会补画，也不把缺记录当作成功或失败。当前示例由[关键结果](感知导航总览.md#关键结果)索引。

需要审查实际导航图与规划曲线时，在新的runtime影子运行中加`--record-planning`。它保持正常异步地图调度，在`planning/`保存控制周期对应信息、实际参考和DWA结果，并以约2Hz保存场景及查询输入。队列有容量上限，结果须检查`summary.json`中的`planning_record.complete/dropped/error`。它不自动启用RGB或ROS显示，诊断复制与写入仍有开销，适合先做短片段。

上述HTML生成命令会自动读取这组记录，核对控制、场景和轨迹摘要后显示实际图层及曲线；没有对应场景快照时仍明确显示静态背景。紫色虚线表示保留但当前未就绪的参考，不是可执行路线。当前对照与下一步定位方法见[失败溯源专题](感知导航规划连续性与失败溯源.md)。

只需检查生产、交接和消费延迟时，可单独加`--trace-timing`。它默认关闭，每个进程在内存中最多保留20000条标量计时事件，正常退出后写入`timing.jsonl`与`timing_input.jsonl`，不会开启图层归档或改变地图调度。核对同名`*.summary.json`中的`complete`和`dropped`，截断记录不能作为完整时序。异常终止可能没有写盘，不能据此认定阶段没有执行。时间字段区分主机单调时钟与原始测量时间，不能直接混减；检查实例见[关联时效报告](../outputs/navigation/association_timing/report.md)。

### 可选图像与决策输入

需要图像时，在所选runtime命令中增加对应选项。三项分别服务不同消费者：

| 选项 | 用途与输出 |
|---|---|
| `--record-views` | 约1Hz保存带RGB的完整场景。未启用时，`final_scene/`只保存最终几何和人物。 |
| `--agent-observations` | 约1Hz在后台准备Agent观察，不加载YOLO或请求模型，连接方式见[影子测试](decision/长程导航任务与评测计划.md#真实观察与runtime影子测试)。 |
| `--record-decision-inputs` | 对选中的三帧窗口运行YOLO与关联，保存`decision_inputs/`中的RGB、BEV、原身份、图像来源和PID映射，不调用VLM。 |

只有显示、场景归档、Agent观察或VLM准备被显式请求时才读取RGB。`--record-decision-inputs`不要求`--record-views`，但不能与`--no-image`合用。`--no-image`仅保留兼容，主流程本来就不加载YOLO。

历史不足、RGB过期或消费者忙时跳过窗口，不积压旧输入。准备失败记录在`run.json`的`decision_inputs.error/complete`中，不阻断主流程。图像支路共用GPU，可能竞争资源。旧安装数据须用`--camera-calibration MATCHING.yaml`指定匹配外参，协议见[VLM手册](decision/VLM部署与调用.md#直接运行时的三帧输入与响应接纳)。

## 标注与训练

本节是行人检测标注。决策T1、T2标注使用另一套工程，见[决策标注手册](decision/决策任务标注.md)。检测预计算需要模型环境和GPU，打开标注窗口只使用缓存和手工输入，不在线推理。

### bag 行人中心标注

先预计算，再本机或远程复核，最后从Linux工程导出。多帧预计算先准备可靠离线定位；同一原始采集组可加入多个子包。工程保存模型来源与人工结果，换模型须新建工程。

**预计算。** 按需重复`--bag`添加子包，设备按本机资源选择。

```bash
BAG=/path/to/subsequence.bag
ANNOTATION=data/annotations/rosbag_people/task_scene
POSE_RESULTS=/path/to/recorded_results
ANNOTATION_GPU=0

bash perception/scripts/annotate_people.sh predict --bag "$BAG" --project "$ANNOTATION" \
  --detector-python "$PEOPLE_PYTHON" --gpu "$ANNOTATION_GPU" \
  --pose-results "$POSE_RESULTS" \
  --root-group ORIGINAL_RECORDING --location-group LOCATION --split train
```

`POSE_RESULTS`按子包优先有图定位，其次无图定位。参数含义和来源分组见[训练专题](perception/技术实现-检测训练.md#rosbag人工中心复核与增量训练)。

**Linux本机标注。** 窗口中选择要处理的子bag。

```bash
ANNOTATION=data/annotations/rosbag_people/task_scene

bash perception/scripts/annotate_people.sh open --project "$ANNOTATION"
```

可加`--sequence 子包文件名`指定初始序列，也接受完整路径或来源ID。`--sample-interval 1`显式设置一秒步长；省略时恢复各包设置，首次默认一秒。

`4`或“标记无人／空标注”将该帧保存为已标无人，拒绝范围内全部候选并清空中心，`Ctrl+Z`可撤销。绿色为已标有人，紫色为已标无人。其余状态、快捷键及核验语义见[标注操作](perception/技术实现-检测训练.md#标注操作)。

<details>
<summary>导出范围、位姿与图像配对选项</summary>

### 任务场景检测微调

先选择两张空闲卡，使用已准备的检测环境。当前新增采集默认全用于训练，历史验证仅用于遗忘与回归诊断，不是独立任务验收。完整三阶段训练和当前采样策略见[训练专题](perception/技术实现-检测训练.md#任务场景增量适配)。

下面每个子shell会进入仓库内SimpleDet3d副本，结束后当前终端仍在仓库根目录。先设置同一实验使用的变量：

```bash
RUN_TAG=task_scene_${MAX_SWEEPS}frame_new
```

```bash
    --annotations data/wheelchair_det_extra/task_scene/annotations.json --location-group TASK_ROUTE \
    --out "$TRAIN_CFG"
)
```

**预览配置与权重选择。** 不读取训练样本、不创建输出，也不启动CUDA。

```bash
(
  cd "$TRAIN_ROOT"
  TRAIN_CFG="$TRAIN_CFG" MAX_SWEEPS="$MAX_SWEEPS" RUN_TAG="$RUN_TAG" DRY_RUN=1 \
    ./train_wheelchair_task_scene.sh
)
```

```bash

    ./train_wheelchair_task_scene.sh
)
```

新实验自动加载同帧数Stage 3最佳权重，已有实验目录优先恢复断点。更改标签、策略或时序时使用新实验名；完整恢复需保持同一输入和策略。

**与基线比较。**

```bash
(

)
```

### 一次完成推理与决策标注准备

<details>
<summary>展开旧ROS联合准备；普通runtime结果导入见日常流程</summary>

本节是 ROS 联合准备方式，只用于 bag。模型环境必须同时具备三维检测与 YOLO 依赖和引擎，目标运行目录及标注工程目录均须不存在。给联合命令添加 `--decision-project` 即可在回放结束后建立标注索引。

```bash
source perception/scripts/ros1_env.sh

LOCALIZATION_MAP=/path/to/complete_3d_localization_map
POSE="${BAG%.bag}.initial_pose.json"
OUT=outputs/perception/ros_decision_new
DECISION_PROJECT=data/annotations/vlm_decision/SESSION
bash "perception/scripts/run_ros_diagnostic.sh" --mode localization --bag "$BAG" --localization-map "$LOCALIZATION_MAP" --pose-file "$POSE" \
  --people-python "$PEOPLE_PYTHON" --out "$OUT/bag_localization" \
  --decision-project "$DECISION_PROJECT" --decision-root-group ORIGINAL_RECORDING
# 无图时使用 --mode odometry 并去掉 --localization-map／--pose-file。
# 旧安装的bag须用 --camera-calibration /path/to/matching_camera_lidar.yaml 指定对应外参。
```

同一次回放并行运行定位、三维检测跟踪与 YOLO 关联，分别保存定位记录、`people.jsonl` 和 `rgb_associations.jsonl`。结束后将二维结果导入工程的 `rgb_association/` 并登记默认来源，不再运行 YOLO。

人工标签留在 `DECISION_PROJECT`，不复制 bag、全量图像或点云。命令成功后按[决策标注手册](decision/决策任务标注.md)打开或服务该工程。

只有整条命令成功，才表示标注准备完成。`run.json` 保存联合状态、二维摘要、模型和标定，工程建立来源后不改写。未处理观察仍是 `not_processed`，不会自动补跑或换图。若仅导入失败，保留感知结果，按[恢复说明](decision/决策任务标注.md#rgb框来源)处理。

### RGB人物检测与三维关联

<details>
<summary>展开TensorRT引擎准备、离线缓存和ROS图像节点</summary>

新bag或live先按[日常流程](#可选图像与决策输入)显式启用所需图像支路。已有二维记录的标注工程直接导入，无需再次离线推理。以下工具用于引擎准备、旧来源补充二维或专项比较，输入为已登记原bag及三维结果的决策观察工程。

Linux二维与三维检测共用项目环境；Windows不装YOLO。缺依赖时按[图像依赖](../perception/detection_tracking/inference/requirements-image.txt)补齐，Torch／TorchVision从官方匹配源安装，普通包优先中国镜像、TensorRT二进制用NVIDIA源，不为本功能升级既有Torch。权重来源及关联规则见[推理专题](perception/技术实现-检测与跟踪推理.md#rgb人物框与三维身份)。

```bash
DECISION_PROJECT=data/annotations/vlm_decision/SESSION
RGB_ASSOCIATIONS=outputs/perception/SESSION/rgb_association
```

```bash
# 仅缺TensorRT引擎时显式构建；目标GPU须与运行环境匹配，不覆盖现有引擎。
# 此命令可能耗时数分钟；浏览和服务启动不会自动构建。
"$PEOPLE_PYTHON" -B "perception/scripts/prepare_rgb_association.py" --export-engine --device 0
```

```bash
# 约10Hz既有三维观察逐帧准备；不重算SLAM或三维检测。
"$PEOPLE_PYTHON" -B "perception/scripts/prepare_rgb_association.py" \
  --project "$DECISION_PROJECT" --output "$RGB_ASSOCIATIONS" --device 0
# 小样本可加 --source 子bag文件名 --segments 20:25 65:70 --limit 150。
# 相同来源／配置可用原命令断点继续；改配置换新目录。
# 显式PyTorch备用：增加 --backend pytorch，输出须换新目录。
```

```bash
# 仅对含逐图二维检测的完整离线缓存：更改关联规则可复用检测，不读图、不加载GPU模型。
# 联合运行记录导入生成的缓存不适用此选项。
"$PEOPLE_PYTHON" -B "perception/scripts/prepare_rgb_association.py" \
  --project "$DECISION_PROJECT" --output outputs/perception/SESSION/rgb_association_refined \
  --detections-from "$RGB_ASSOCIATIONS"
```

上述`device 0`是`CUDA_VISIBLE_DEVICES`内的第一张卡；公共图像配置默认TensorRT FP16。独立工具只生成缓存，完成后一次登记；完整兼容缓存只核对来源和覆盖，不运行YOLO：

```bash
"$PEOPLE_PYTHON" -B -m decision.vlm.annotation prepare-rgb \
  --project "$DECISION_PROJECT" --output "$RGB_ASSOCIATIONS"
```

统一入口和标注`prepare-rgb`会登记工程默认来源，本机／远程标注及导出都从工程读取；切帧不推理，不复制全量图像或点云。来源切换与重审见[标注手册](decision/决策任务标注.md#rgb框来源)。

以下独立节点仅用于专项联调。旧ROS入口`run_ros_diagnostic.sh`显式加`--image-association`或请求`--decision-project`时才管理该节点，不要重复启动；默认直接运行时不启动此ROS支路。使用同一master／时钟，保留CameraInfo；原检测节点的`/perception/people/rgb`必须可达：

```bash
source perception/scripts/ros1_env.sh
roslaunch social_nav_people rgb_association.launch \
  project_root:="$PWD" python_executable:="$PEOPLE_PYTHON" device:=0
# 原始相机话题不同可加 camera_info_topic:=/实际/camera_info。
rostopic echo -n 1 /perception/people/rgb_associations/status
rostopic echo -n 1 /perception/people/rgb_associations
```

新增消息后仅需构建`interfaces`。节点发布关联消息、保存用记录及`/perception/people/rgb_associations/image`叠框图，旧ROS入口显式启用图像支路时RViz订阅该图；原`/perception/people/rgb`不改写。关联失败和丢帧独立报告，三维检测继续运行；正式在线VLM适配仍待接通。
