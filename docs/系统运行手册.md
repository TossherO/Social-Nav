# 系统运行手册

以下命令从仓库根目录执行。按[本机记录](../ENVIRONMENT.local.md)选择解释器、GPU、数据和地图；输出使用新目录。现场待核对事项见[系统实机问题](系统实机问题.md)。

## 准备

```bash
conda activate social-nav
export SOCIAL_NAV_PYTHON=/path/to/project/env/bin/python
export ROS_PYTHON=/path/to/ros/python3
export GPU_ID=0
source perception/scripts/ros1_env.sh
```

首次部署或原生源码变化时，按目标机 CUDA 与编译器重建：

```bash
SOCIAL_NAV_CUDA_ARCH=86 CUDACXX=/path/to/nvcc SOCIAL_NAV_CXX=/path/to/g++ \
  BUILD_JOBS=2 bash perception/scripts/build_runtime.sh
bash perception/scripts/build_ros1.sh visualization
```

`SOCIAL_NAV_CUDA_ARCH` 和编译器按本机修改。检测、建图和服务依赖见[开发指南](开发指南.md)。

## 日常运行与回看

### 从bag运行感知导航

有图定位使用相互对应的三维定位图、起点、可信区域和静态环境图：

```bash
bash scripts/run.sh --bag /path/to/input.bag --mode localization \
  --map /path/to/localization_map --pose-file /path/to/initial_pose.json \
  --coverage /path/to/coverage.yaml --static-map /path/to/static_map \
  --output outputs/perception/new_run --gpu "$GPU_ID"
```

省略 `--coverage` 时按所选地图自动生成全图关联范围；不使用静态先验时省略 `--static-map`。无图局部定位使用 `--mode odometry`。离线有图定位在匹配积压时等待后端，实际处理时间可能超过录制时长。`summary.json` 和 `run.json` 分别记录运行结果与输入配置。停止时首次 `Ctrl+C` 请求排空并保存。

### 使用在线传感器

先启动真实设备，再运行观察：

```bash
bash perception/capture/start_sensors.sh
bash scripts/run.sh --live --mode odometry --duration 60 \
  --output outputs/perception/new_live --gpu "$GPU_ID"
```

bag 模拟 live 时必须提供 `/clock`；真实设备使用真实 ROS 时间，不叠加另一份回放。

### 选择传感器时钟会话

默认使用传感器原始时间，不在启动时自动估计时差。显式补偿及安装标定应与本次设备和数据一致，见[建图与定位](perception/技术实现-建图与定位.md)。

### 按录制路线生成分段目标

回放路线仅用于对应 bag 的影子测试；按[任务与路线](navigation/技术实现-任务与路线.md#录制行程的分段目标回放)选择路线及地图，不代表轮椅执行。

### 结果回看

检查 `summary.json`、`reference.jsonl`、控制与安全日志；可视化命令及数据来源见[接口约定](接口约定.md)和[推理速度记录](推理速度记录.md)。

```bash
bash scripts/interactive.sh preflight
```

## RViz交互测试

### bag 暂停与选点

```bash
roscore
# 另一终端
bash scripts/interactive.sh --bag /path/to/localization.bag --pause-at 8 \
  --gpu "$GPU_ID" --output outputs/navigation/new_bag_session
```

人工使用 `Ground Pose Estimate` 选择雷达起点，使用 `Ground Nav Goal` 选择车体目标及朝向；已保存起点只能用于相匹配的 bag、地图和偏移。终端 `p` 暂停、`r` 继续、`s` 取消、`q` 退出；当前不能倒退，需重启选择较早位置。冻结曲线只是预览，不向底盘发送指令。

### 现场观察与执行

```bash
bash perception/capture/start_sensors.sh
bash scripts/interactive.sh observe
```

停止观察会话后，如已有现场授权与准备，可改用执行预设：

```bash
bash scripts/interactive.sh execute --execute
```

观察模式不连接底盘。选择起点后，可在 RViz 的 `Social-Nav session` 面板按按钮或使用 W/S 前后、A/D 左右平移，Q/E 旋转；平移按起点朝向计算，每次 0.05 米，旋转每次 5°。检查点云与地图对齐后，点击顶部工具栏的 `Confirm Initial Pose` 确认起点。该微调仅适用于实机初始化前的预览，bag 选点仍立即初始化。

启动检查会验证面板插件声明和本机库的接口标识。若提示插件缺失、过旧或无法加载，运行 `bash perception/scripts/build_ros1.sh visualization` 重新构建，再重新启动观察或执行会话。

执行预设读取本车档案，使用面板“轮椅使能”进行人工使能。“取消 / 退出使能”和“退出会话”沿用原会话命令；手柄接管、急停、命令超时和独立安全仍生效。终端 `c`、`a`、`s`、`q` 仍可用。目标接收、规划曲线与定位估计不等于车辆实际到达或停车。

### 显示与提交目标

参考路径显示完整 XY 路线，优先使用局部及静态地图的地面高度；缺失处用插值或回退高度显示，并在状态中标注近似值。这些高度仅用于显示，不代表实测地面或可通行。DWA 轨迹无高度时仍可能断开。目标位置是箭头起点而非箭头尖端。没有有效地图关联时，不发布虚构的地图位姿。

### 底盘受控检查

按 `bash scripts/interactive.sh execute --help` 和[本车档案](../configs/wheelchair_vehicle.yaml)使用。改变协议或排查底盘时保留串口独占、人工接管、急停和看门狗；历史对照见[现场归档](archive/感知导航现场历史.md)。

### 固件断发停车检查

固件断发停车尚未完成现场确认，按[系统实机问题](系统实机问题.md)记录实际现象；不得把软件超时或影子停车当作固件验收。

## Agent 长程任务

人工驾驶调试时，先启动传感器，再运行不连接底盘的观察会话并在 RViz 确认初始位姿：

```bash
bash scripts/interactive.sh observe --agent-observations
```

启用 `--agent-observations` 时，观察入口使用 [Agent 人工测试配置](../navigation/commissioning/interactive_agent.yaml)中的定位图和静态图；该入口不连接底盘。地图缺少单独关联区域时自动采用全图关联范围。观察程序启动后，在 RViz 确认实时扫描与地图基本对齐。

在另一个已配置模型环境的终端启动 Agent 窗口，选择观察终端打印的本次会话目录及与当前地图匹配的语义标注：

```bash
source outputs/runtime/environment/activate.sh
python -B -m decision.agent.manual_ui
```

在窗口输入任务并点击“开始新任务”。对话区的“当前请求”按最近一次实际模型请求的顺序显示消息，并列出消息数量和图片数量；模型刚产生的回复可能尚未进入该请求。“历史记录”按消息首次出现的时间显示请求、模型输出和工具结果，消息状态说明其是否出现在最近请求中，或仍等待进入下一次请求。双击消息或图片只查看该消息的内容与图片；“查看整轮请求”查看最近请求的全部内容，历史中的请求行也可双击查看整轮。图像是请求当时的观察，不代表当前画面。“查看工具”列出工具描述和参数，并标记最近一次请求提供的工具。

任务启动或打开历史会话后，会话设置自动收起；需要更换观察目录或标注时可再次展开。拖动对话区与运行事件区之间的分隔条，可调整两者的高度。

界面隐藏或缩略用于校验的长标识；原始会话记录保留完整内容。模型使用短引用指代地图或观察，程序会在调用工具前核对并还原这些引用。

人工驾驶状态区固定高度，内容较长时可滚动查看。目标示意图可双击或通过“放大查看目标示意图”打开；在消息详情中，选择图片后可双击图片或点击“放大查看选中图片”。独立图片窗口支持滚轮缩放、左键拖动，以及适应窗口和原始大小显示。

“子任务与要求”列出已登记的任务，选择一项可在下方查看完整要求，包括目标、用户指定条件和 Agent 自行选择的绕行方向。独立的运行事件区显示到达证据等待、参考路径状态和上下文裁剪等事件，可双击查看详情；这些事件不自动作为模型对话。历史会话通过“打开历史会话”只读查看，不会自动恢复执行。窗口创建新的输出目录并管理人工 Agent 进程，关闭窗口会结束该任务进程。窗口的路线进度来自定位估计；发送按钮操作后等待 Agent 接收或拒绝，操作超时不会自动重试。

服务器可直接打开交接包中的离线演示会话：

```bash
python -B -m decision.agent.manual_ui --session outputs/decision/agent/context_timeline_review/session.sqlite
```

演示包括二楼标注地图、RGB、全局轨迹图与局部地图，均来自当时发送给模型的历史冻结观察，不是当前实时画面，也不代表实机任务验收。

也可以不使用窗口，直接在终端中运行人工 Agent。使用本次观察会话输出目录中的 `run/commands.sock` 和匹配的语义标注；输出目录必须是新目录：

```bash
source outputs/runtime/environment/activate.sh
python -B -m decision.agent manual --runtime-socket /path/to/observation/run/commands.sock \
  --catalog /path/to/catalog.json --instruction '绕圆形区域顺时针一圈' \
  --interactive --duration 1200 --output outputs/decision/agent/new_manual_session
```

Agent 的目标和路线是人工驾驶建议，不会发送底盘指令。人工模式会在无底盘输出的观察会话中请求当前目标的参考路径预览；多点任务预览当前待经过的点。窗口和终端显示预览是否生成及失败原因，RViz 中白色参考线为规划器结果；目标标记和途经点之间的蓝色直线表示经过顺序，不是规划结果。绕区域任务从首个途经点开始后，如有效参考路径穿过该区域，程序撤销当前建议并提示操作者手动停稳，再由 Agent 决定如何调整；预览缺失或无法检查时不表示路径通过。两种显示都不能保证现场安全通行，规划失败时请结合现场情况决定如何继续。参考线缺失的地面高度会用显示近似值补全。

Agent 标记高度优先使用地图地面高度；无对应高度时使用地图地面高度中位数，仅用于显示，并提示近似高度的点。地图完全缺少地面高度时，该点不显示。操作原车手柄完成目标，停稳后在窗口点击“确认到达”，或在 Agent 终端输入 `arrived`。多点路线从第一个途经点开始记录，中间点可连续经过；最终由连续定位轨迹检查绕行或依次经过的要求。目标 PNG、事件和任务证据保存在该会话目录。`pause`、`resume`、`cancel`、`answer 补充说明` 和 `replace 新指令` 用于管理 Agent 任务；取消任务或关闭窗口不会控制原车手柄或停车。

上述人工路线和观察阶段已通过合成数据检查，尚需实机验证。模型调用会向所配置的服务发送任务和当前需要的地图、RGB 等输入，应在现场测试前确认数据发送范围。跟随候选额外需要 `--agent-follow-candidates`，当前人工适配器不支持跟随。

实机自动执行使用不同入口，需明确打开 Agent 通道：

```bash
bash scripts/interactive.sh execute --execute \
  --agent-observations --agent-follow-candidates --agent-execution
# 另一终端，使用本次会话输出的 socket 和匹配当前地图的语义目录
python -B -m decision.agent execute --runtime-socket /path/to/run/commands.sock \
  --catalog /path/to/catalog.json --instruction '先到门口，再跟随红衣人物到电梯旁' \
  --interactive --output outputs/decision/agent/new_session
```

确认地图定位并人工使能后才可运动；跟随目标应等运行状态为 `running` 后再开始行走。Agent 的 `cancel` 取消任务，交互终端 `s` 撤销目标和使能。完成仍依赖目标、来源、停稳与语义条件；T1、T3 尚未接入实机任务链。

只读状态与地图目录：

```bash
python -B -m decision.agent --help
python -B -m decision.agent status --session /path/to/session.sqlite
python -B -m decision.agent catalog --catalog /path/to/catalog.json
python -B -m decision.agent.map_annotation --static-map /path/to/static_map \
  --floor-id floor2 --vehicle-profile configs/wheelchair_vehicle.yaml --out /path/to/new_catalog.json
```

## 可选图像与决策输入

`--agent-observations` 提供同源场景及 RGB；`--agent-follow-candidates` 另启用人物框及三维关联。`--record-decision-inputs` 准备局部 VLM 三帧输入，不自动调用模型。服务和 T1／T2／T3 操作见[VLM 局部决策](decision/技术实现-VLM局部决策.md)。这些可选支路会占用资源，但不能成为主感知导航链的前置条件。

## 地图准备

```bash
bash perception/scripts/build_map.sh --bag /path/to/mapping.bag \
  --out outputs/perception/new_mapping --gpu "$GPU_ID"
bash perception/scripts/pick_start.sh --bag /path/to/localization.bag \
  --localization-map outputs/perception/new_mapping/map --out /path/to/initial_pose.json
bash perception/scripts/pick_coverage.sh --localization-map outputs/perception/new_mapping/map \
  --out /path/to/coverage.yaml
"$ROS_PYTHON" -B -m perception.environment export --run outputs/perception/new_mapping \
  --out outputs/perception/new_static_map --export-pgm
```

静态导出使用具备 ROS 环境的系统 Python；定位图和静态图不可互换。建图完成不证明几何正确，应检查轨迹、墙面及高度一致性。地图分辨率与生成机制见[环境地图](perception/技术实现-环境地图与场景表示.md)。

若同一环境有多次保留了封存扫描的建图运行，可将它们融合到同一张最终定位地图：

```bash
bash perception/scripts/build_static_multi.sh \
  --map /path/to/final_localization_map \
  --evidence-run /path/to/first_mapping_run \
  --evidence-run /path/to/second_mapping_run \
  --out outputs/perception/multi_survey_static --gpu 0
```

每个 `--evidence-run` 对应一次完整建图运行，可以继续添加。脚本按传感器观测时间排序，依次要求为各 bag 在最终地图上选择初始位姿，再沿用各次建图记录中的传感器外参及时间参数重新定位。随后自动融合扫描并保存至输出目录的 `static_map/`。原始 bag、运行记录和扫描封存均须可用，时间段重叠或来源不一致时停止。

如果最终地图由这些历史地图逐次更新而来，可加 `--auto-initial-poses`。脚本会检查更新链和保留的旧关键帧位姿，复用各次人工选点或原始建图初值作为配准初猜；它们不代表配准已经成功。自动或人工初值都须经过有图定位和质量检查。若已有各 bag 在最终地图上的定位运行，也可用 `python -B -m perception.environment export` 重复传入成对的 `--evidence-run` 和 `--reference-run`，按对应顺序指定。

融合按采集时间由旧到新处理。一次采集形成有效占据或满足支持条件的空闲时覆盖更早的结论，未观测或无法分类的格子保留旧结果；这依赖各次传感器时间可比较，不保证检测出所有动态变化。检查各次配准和生成地图后再决定是否启用；历史人工修改和 Agent 标注不会自动迁移。

### 用局部 bag 生成三维地图更新候选

先让新 bag 从旧地图覆盖区域开始采集，并保留该 bag 的完整雷达和 IMU。在有桌面的终端运行：

```bash
bash perception/scripts/update_map.sh --bag /path/to/local.bag
```

脚本默认读取 `navigation/commissioning/interactive.yaml` 中的定位地图和关联区域，启动前校验它们是否匹配。弹出选点窗口后，根据地图、雷达首帧和可用的 RGB 对照选择 bag 首帧的雷达位置及朝向，核对预览并保存。关闭窗口而不保存会停止处理。保存后脚本自动完成整个 bag 的局部建图、旧图定位和候选生成，不连接底盘。

可用 `--map /path/to/old_map` 指定其他地图，未同时指定 `--coverage` 时自动按该地图的点云范围构建关联区域；需要限制范围时用 `--coverage /path/to/coverage.yaml` 指定对应地图的区域。用 `--gpu 0` 指定 GPU。默认在 `outputs/perception/` 创建带时间的目录，也可用 `--out` 指定该目录下或 `/tmp/` 下尚不存在的目录。步骤失败会停止并保留已生成的中间结果；修正问题后使用新输出目录重试。

运行目录的 `initial_pose.json`、`local_mapping/` 和 `local_reference/` 分别保存人工初值及两次处理结果。`candidate/map/` 是新的 ROLL 地图候选；`candidate/report.json` 记录来源、证据和限制，`candidate/changes.npz` 保存旧图删除候选点和保留的新采集特征点，后者可能与旧结构重合。`candidate/comparison.png` 和 `candidate/comparison_detail.png` 分别提供全图及变化区域的俯视对照。候选不会自动启用或覆盖源地图。应检查配准、变化点及独立定位表现，再决定是否使用。

定位使用与旧图对应的关联区域，并启用地图关联质量门控；自动区域包含未知空间，区域内仍需检查定位轨迹和匹配结果。当前实现按时间间隔累计射线证据，尚不能证明每个删除点都有不同视角支持；附近稳定回波可以阻止删除，但动态物体和错误配准仍可能影响结果。它只在旧图边界附近处理，不支持地图扩展或跨次时间戳重叠。静态环境地图、历史人工修改和 Agent 标注不会自动迁移；使用新地图导航前须单独处理并核对这些资产。

### 人工修正地图

```bash
bash scripts/edit_map.sh --static-map /path/to/static_map --out /path/to/new_static_map
bash scripts/edit_map.sh --localization-map /path/to/localization_map --out /path/to/new_localization_map
```

### Windows客户端

在解压后的客户端目录安装 `perception/detection_tracking/annotation/requirements-client.txt`，将地址和工程 ID 换为当前 Linux 服务：

```powershell
conda create -n social-nav-annotator python=3.11 pip
conda activate social-nav-annotator
python -m pip install -r perception/detection_tracking/annotation/requirements-client.txt
python -B -m perception.detection_tracking.annotation open --server http://LINUX_TAILSCALE_IP:8765 --project-id wheelchair
```

已有环境时跳过创建命令，避免覆盖。只读浏览加 `--read-only`。未同步草稿保留在客户端缓存，需等待服务器确认保存。

### 保存结果重跟踪

重跟踪复用已有检测和定位，不加载检测模型。新结果包含新的轨迹身份，旧二维关联和决策标签不能直接沿用：

```bash
python -B -m perception.detection_tracking.inference.retrack --source outputs/perception/previous_run/people.jsonl --association-backend cpu --out outputs/perception/retracking_new
```
