以下命令从仓库根目录执行。按本机的 `ENVIRONMENT.local.md` 选择解释器、GPU、数据和地图，输出使用新目录。首次拉取参见[车载机接入](开发指南.md#车载机接入)，现场待核对事项见[系统实机问题](系统实机问题.md)。

## 准备

先激活本机的模型运行环境，并用 `SOCIAL_NAV_PYTHON` 指定其中的解释器。系统 ROS 解释器由 `configs/runtime.yaml` 的 `input_python` 选择，ROS 环境脚本加载 Noetic。

```bash
export SOCIAL_NAV_PYTHON=/path/to/project/env/bin/python
export GPU_ID=0
source perception/scripts/ros1_env.sh
```

首次部署缺少车载构建产物时，先准备系统依赖和 ROS 工作区，再按目标机 CUDA 与编译器构建直接运行时。ROS 全量构建需要另外提供 `data/cache/perception/` 中的固定依赖缓存，准备脚本会从缓存解包。已有环境按缺失产物和源码变化选择相应构建。[ROS 构建依赖](perception/技术实现-建图与定位.md#运行环境与构建)

```bash
bash perception/scripts/build_ros1.sh all
SOCIAL_NAV_CUDA_ARCH=86 CUDACXX=/path/to/nvcc SOCIAL_NAV_CXX=/path/to/g++ \
  BUILD_JOBS=2 bash perception/scripts/build_runtime.sh
source perception/scripts/ros1_env.sh
```

命令中的 CUDA 架构和编译器路径按本机修改。交互预设用 `taskset` 设置 CPU 亲和性。若车载机的可用 CPU 不同，按该机的允许范围设置 `SOCIAL_NAV_COMMISSIONING_CPU_LIST`。[开发指南](开发指南.md#选择运行环境) · [车载性能预设](../navigation/commissioning/performance.env)

按实际启动的预设准备本车地图。每份预设中的 `map` 指向 ROLL 三维定位图，`static_map` 指向环境和规划使用的静态地图，`initial_pose_hint` 提供选点时的高度与姿态提示。显式配置 `coverage` 时使用与该定位图相符的关联区域。Agent 还读取对应静态地图的 `catalog`。这些现场资产位于 Git 忽略的目录，应保留本车已有的配套文件，或把匹配的资产放在相应预设指定的位置。

| 用途 | 预设 |
|---|---|
| 部署自检与直接执行 | [interactive.yaml](../navigation/commissioning/interactive.yaml) |
| 普通无底盘观察 | [interactive_observation.yaml](../navigation/commissioning/interactive_observation.yaml) |
| 二楼 Agent 人工驾驶观察和单楼层回放 | [interactive_agent.yaml](../navigation/commissioning/interactive_agent.yaml) |
| 一楼 Agent 人工驾驶观察和单楼层回放 | [interactive_agent_floor1.yaml](../navigation/commissioning/interactive_agent_floor1.yaml) |

交互导航和非仿真 Agent 命令行默认读取二楼资产。使用一楼时，Agent 观察入口传入 `--agent-observations --floor floor1`，Agent 回放入口传入 `--floor floor1`。直接调用 `decision.agent` 时用 `--catalog` 指定一楼预设里的语义目录。重放按旧地图登记的任务或观察时，应显式选择当次的地图和标注。

基础感知导航还需要对应的三维检测权重及兼容的 CUDA 扩展。T2 需要额外的二维人物检测权重、可用相机标定和所选跟随后端。Agent 使用托管 API，凭证在车载机单独准备。[检测与跟踪推理](perception/技术实现-检测与跟踪推理.md) · [Agent 服务配置](decision/技术实现-Agent长程导航.md#服务配置与思考模式) · [T2 后端与权重](#启用持续跟随)

## 日常运行与回看

### 从bag运行感知导航

有图定位使用相互对应的三维定位图、起点、可信区域和静态环境图：

```bash
bash scripts/run.sh --bag /path/to/input.bag --mode localization \
  --map /path/to/localization_map --pose-file /path/to/initial_pose.json \
  --coverage /path/to/coverage.yaml --static-map /path/to/static_map \
  --output outputs/perception/new_run --gpu "$GPU_ID"
```

省略 `--coverage` 时按所选地图自动生成全图关联范围；不使用静态先验时省略 `--static-map`。无图局部定位使用 `--mode odometry`。离线有图定位在匹配积压时等待后端，实际处理时间可能超过录制时长。`summary.json` 和 `run.json` 分别记录运行结果与输入配置。停止时首次 `Ctrl+C` 请求排空并保存。

### 使用在线传感器

先启动真实设备，再运行观察：

```bash
bash perception/capture/start_sensors.sh
bash scripts/run.sh --live --mode odometry --duration 60 \
  --output outputs/perception/new_live --gpu "$GPU_ID"
```

bag 模拟 live 时必须提供 `/clock`；真实设备使用真实 ROS 时间，不叠加另一份回放。

### 选择传感器时钟会话

默认使用传感器原始时间，不在启动时自动估计时差。显式补偿及安装标定应与本次设备和数据一致，见[建图与定位](perception/技术实现-建图与定位.md)。

### 按录制路线生成分段目标

回放路线仅用于对应 bag 的影子测试；按[任务与路线](navigation/技术实现-任务与路线.md#录制行程的分段目标回放)选择路线及地图，不代表轮椅执行。

### 结果回看

检查 `summary.json`、`reference.jsonl`、控制与安全日志；可视化命令及数据来源见[接口约定](接口约定.md)和[推理速度记录](推理速度记录.md)。

分析时延时，将 `RUN_DIR` 设为本次会话中含 `timing.jsonl` 的目录，在仓库根目录执行 `python -m runtime.timing_report "$RUN_DIR"`。报告区分地图发布频率、从源扫描到控制或独立安全首次使用地图的时间，以及目标进入规划循环到同一任务、请求和修订首次取得参考路径的时间。安全统计只计实际几何检查，检查中换用的新图单独计入。

持续跟随可能在参考路径生成前更新目标，须同时查看 `observed_goal_revisions` 和 `goal_to_first_available_reference_ms.n`。旧日志缺事件时样本为零，事件丢失时首次使用取首次记录的使用。[二楼导航优化回放](推理速度记录.md#二楼导航优化回放)

## 实机部署自检

```bash
bash scripts/interactive.sh preflight
bash scripts/interactive.sh execute --check
```

本车观察、执行和档案检查都从所选交互预设读取 `motion_config` 和 `motion_profile`。第一条输出各项检查的状态和失败细节，涵盖执行预设的地图配套、三维检测资源、CUDA、原生库、ROS 与 RViz 插件。第二条检查执行所需的车辆档案。两条命令均不连接底盘，实际停车须现场确认。检查其他楼层的地图和软件时，先加载 ROS 环境，再用选定的本机 Python 运行 `-B -m runtime.preflight --config 预设路径`。

更新环境建图代码后，若 `library_abi` 报告缺少符号，按本页的构建步骤重建目标机的直接运行库。若 `project_ros_messages` 列出缺失或不匹配的字段，运行 `bash perception/scripts/build_ros1.sh environment` 重新生成消息，再加载 ROS 环境。独立 ROS 建图节点使用 CUDA 时，还需按目标 GPU 的计算能力设置 `ENVIRONMENT_CUDA_ARCH`，运行 `bash perception/scripts/build_environment_cuda.sh` 更新 ROS 工作区里的 CUDA 库。地图发布端和规划订阅端使用同一份消息定义后，再运行预检。

## RViz交互测试

### bag 选点与沿录制路线规划

```bash
roscore
# 另一终端
bash scripts/interactive.sh --bag /path/to/localization.bag --pause-at 8 \
  --gpu "$GPU_ID" --output outputs/navigation/new_bag_session
```

先用 `Ground Pose Estimate` 选择雷达起点，或通过 `--pose-file` 加载与 bag、地图和回放偏移相符的起点。通用 bag 回放的地图配准重力偏差上限默认为 8°，需要覆盖时可传入 `--roll-gravity-deg`。地图关联建立后，可以用两种方式检查规划。

- **手动给目标**。用 `Ground Nav Goal` 指定车体目标及朝向，或用 `Publish Point` 只指定位置。暂停后也能在同一帧试不同目标。
- **沿录制路线规划**。在 `Social-Nav session` 面板点击“启动影子导航”。程序用这段 bag 的录制行程选取前方目标，参考路径和 DWA 局部轨迹由规划器根据当前观测计算。画面中的轮椅仍沿原始 bag 运动。可点击“停止影子导航”，也可手动选点接管。

首次使用时，可先暂停回放，再启动影子导航。若没有匹配的路线缓存，程序会在后台用所选地图和起点重算这段 bag 的雷达定位。路线准备好后可在冻结帧查看规划，再继续播放。面板分别显示参考路径和 DWA 的结果，悬停可查看原始拒绝原因。已有同一 bag、同一定位图的成功定位记录时，启动命令可加 `--shadow-route-run /path/to/run`，该目录应含 `run.json` 和 `localization.jsonl`。只有记录覆盖且地图定位连续有效的行程才会给出前方目标。路线来源与给点方法见[任务与路线](navigation/技术实现-任务与路线.md#交互回放沿录制行程给点)。

面板可以暂停、继续回放、取消目标和退出会话。终端也可输入 `p`、`r`、`s`、`q` 后回车执行对应操作。回放只能向前播放，要回到较早时刻需重新启动并选择起点偏移。bag 会话只用于检查规划结果，不向底盘发送命令。

在回放中看到异常时，先打开「导航地图」或「局部地图」，再点「暂停回放」。等待冻结地图发布后，「标记异常区域」才会启用。选择 RViz 工具栏的 `Publish Point`，依次点击矩形的两个对角点。两次选点和证据导出都使用这次暂停固定的地图快照。保存成功后，RViz 用黄框标出区域，启动终端打印审核目录。终端输入 `review` 也可进入圈选模式。继续回放后恢复给点操作。

每条记录保存在本次会话的 `run/anomaly_reviews/` 中。`review.json` 保存地图坐标、回放暂停时间和地图实际采集时间，`scene/` 保存该帧地图及人物证据。需要追查此前多帧的变化时，可同时查看本次会话的 `run/planning/scenes/`。

### 现场观察与执行

```bash
bash perception/capture/start_sensors.sh
bash scripts/interactive.sh observe
```

观察模式不连接底盘。选择起点后，可在 RViz 的 `Social-Nav session` 面板按按钮或使用 W/S 前后、A/D 左右平移，Q/E 旋转；平移按起点朝向计算，每次 0.05 米，旋转每次 5°。检查点云与地图对齐后，点击顶部工具栏的 `Confirm Initial Pose` 确认起点。该微调仅适用于实机初始化前的预览，bag 选点仍立即初始化。

执行前先在观察会话中确认实时扫描与本车地图对齐，用当前目标查看参考路径，并核对会话记录中的地图关联状态。若定位或预览未建立，先根据本次会话的 `runtime.log` 和 `run/reference.jsonl` 查原因。

启动检查会验证面板插件声明和本机库的接口标识。若提示插件缺失、过旧或无法加载，运行 `bash perception/scripts/build_ros1.sh visualization` 重新构建，再重新启动观察或执行会话。

停止观察会话后，如已有现场授权与准备，可改用执行预设。

```bash
bash scripts/interactive.sh execute --execute
```

执行预设读取本车档案，使用面板“轮椅使能”进行人工使能。“取消 / 退出使能”和“退出会话”沿用原会话命令；手柄接管、急停、命令超时和独立安全仍生效。终端 `c`、`a`、`s`、`q` 仍可用。目标接收、规划曲线与定位估计不等于车辆实际到达或停车。

### 显示与提交目标

RViz 左侧显示会话按钮和 RGB，右侧显示地图和实时扫描。扫描点按 Z 轴高度着色，可在左侧 `Displays` 中关闭 `Current scan`。规划状态可在按钮下方滚动查看，拖动 RGB 上方分隔线可调整图像大小。

在 `Social-Nav session` 面板可以切换三种视图。切换按钮下方的图例随当前显示的地图图层更新。选点、规划和暂停回放时都可以切换，当前目标与规划继续保留。

- **静态地图**只显示选定楼层的静态栅格，用于初始选点和核对地图范围。
- **局部地图**只显示感知模块生成的滚动栅格。浅紫色标记有局部证据的未知格，包括扫描后仍无法确认状态的格子，以及局部占据过期的格子。完全未观测区域留空。在使用楼层地图的会话中，需要建立地图关联后才能将局部栅格显示在当前视角。
- **导航地图**默认开启。静态底图只发布一次，局部变化按全局规划的投影规则叠加。橙红色表示新增占据，青绿色表示得到局部证据支持的新增空闲，浅紫色标记局部占据过期后仍未知的位置。没有有效的楼层关联时，面板提示正在等待并显示静态地图。回放使用所选静态地图作为显示底图，面板会注明来源，推理中的时间校验继续生效。

局部地图和导航地图都随新环境图刷新。环境图的默认生成目标是 7.5 Hz，RViz 的 `display.map_hz` 是显示发布上限。提高显示上限可以容纳相邻两帧到达时间的波动，实际能看到多少帧仍取决于环境图的产出和显示负载。

当前实机的静态图和局部图均为 0.1 m。若将 1 m 静态图与 0.1 m 局部图叠加，单个静态格的重叠计算可能超限，使 RViz 各图层停止刷新。使用这组分辨率查看数据时，请在开始回放前选择「静态地图」或「局部地图」。

要核对某次 Hybrid A* 的实际搜索输入，在 `Displays` 中开启 `Navigation search grid`，等待下一次查询。面板会显示查询编号，赭黄色格子带条件代价。点击任一地图模式可回到常规显示。搜索会附加任务相关的限制，DWA 也会另用碰撞栅格和行人预测验证候选轨迹。[路径规划](navigation/技术实现-路径规划.md)

有图导航的白色参考线沿用规划结果的地图坐标。定位更新可影响显示高度，参考线的平面位置仍以规划结果为准。缺少地面高度时，用显示近似值补齐 XY 路线。DWA 只绘制具有有效显示高度的轨迹段。车体轮廓、自车轨迹、规划曲线和行人框根据可见地面调整标记高度，以减少遮挡。车体显示间距由 `display.vehicle_clearance_m` 设置。检测框和跟踪框整体抬升，保留原尺寸。目标箭头的起点是目标位置。查看地图位姿时须有有效的地图关联。

可在 `Displays` 中手动开关图层。开关会一直保留，再次点击地图模式按钮时才恢复该模式的预设。图例和状态根据实际开启的图层更新。无订阅者时，程序跳过该图层专用的数据准备。重新打开后，地图从有效快照恢复，扫描和 RGB 在下次采样更新，关闭期间已有新行人观测时会撤销旧标记。地面轨迹只连接取得过有效高度的位置。若关闭过全部导航显示，地面轨迹可能断开，原始雷达位姿历史仍保存。无人查看期间未保存的实时搜索快照，要等下一次查询才能看到。

### 启动人工驾驶测试

先启动传感器，再用匹配现场楼层的预设启动观察。此入口不连接底盘。

```bash
bash scripts/interactive.sh observe --agent-observations --floor floor2
```

默认用 `--floor floor2` 对应的[二楼配置](../navigation/commissioning/interactive_agent.yaml)，在一楼改用 `--floor floor1` 和[一楼配置](../navigation/commissioning/interactive_agent_floor1.yaml)。预设提供定位图、静态图和高度初值，未配置关联区域时采用全图范围。在 RViz 确认初始位姿及实时扫描与地图的对齐情况。

在另一终端激活同一模型环境，设置相同的 `SOCIAL_NAV_PYTHON`。窗口需要 PyQt5 和桌面会话，任务调用需要[托管 API 的本机配置](decision/技术实现-Agent长程导航.md#服务配置与思考模式)。开始前确认允许向所配置的模型服务发送任务、地图和本次所需的相机画面。

```bash
"$SOCIAL_NAV_PYTHON" -B -m decision.agent.manual_ui --floor floor2
```

1. 在会话设置中选择观察终端打印的本次会话目录。楼层预设会填入语义标注路径。缺标注时先为当前地图创建标注。换地图后须重新核对标注，切换楼层预设后须重选该楼层的观察会话。
2. 在“模型与思考强度”选择外层 Agent，分别设定登记、执行、监控强度。默认模型为 Qwen，选择 GPT 后三项初始值均为 `low`。运行中锁定设置，可在“当前请求”核对本轮实际使用的模型、阶段和强度。启动窗口时也可加 `--model gpt-6.1-terra` 预选 GPT。
3. 输入任务并点击“开始新任务”。需要自动录包时，在点击前勾选“任务执行时自动录制传感器 bag”。启动后可展开自动收起的会话设置。

复测时，可用“选择历史任务”打开原会话的 `session.sqlite`，查看原指令、澄清和完整登记要求，再点“开始新任务”。新会话跳过模型登记，按登记内容从第一项重新执行，重新选目标和路线并检查到达。仍须核对地图、标注和起始楼层。跨楼层复测须勾选跨楼层选项，历史记录须含所有相关楼层的地图来源。点“取消复用”可恢复输入新任务。

### 查看进度与处理等待

在“子任务与要求”选中一项，可核对目标、用户条件、完成区域和等待口令。“任务监控”显示楼层、参考路径、最近一次复核与 Agent 判断，以及定位估计的距离、停稳和必要的朝向误差。点“立即复核”可提前让 Agent 判断，驾驶和到达确认仍按现场流程。若设置了条件式监控，界面还显示车辆与监控区域的关系、定位是否有效、观察和复核进度，跟随时同时显示 T2 状态。登记了完成区域时，提交完成会再次核对是否仍在该区域。连续复核会增加调用，人工窗口每次任务默认最多 512 次请求。

排查模型和工具行为时，先看运行事件中最近的触发、等待证据或规划原因，双击可展开详情。“当前请求”列出实际发送的消息和图片数量，按发送顺序展示，最新回复可能尚未纳入。“历史记录”按消息首次出现时间展示请求、模型回复、工具结果和消息是否已经发出。点“查看整轮请求”或双击历史中的请求行查看整轮，双击单条消息只打开该条内容。图片来自当时的观察，可在详情中双击或用“放大查看选中图片”。目标示意图也可双击放大。“查看工具”显示参数及最近请求提供的工具。完整校验标识可查原始会话记录。[请求和引用](decision/技术实现-Agent长程导航.md#模型调用与响应)

- **等待答复**时用“发送答复”回答澄清。若模型登记时只返回文字，程序会在预算内纠正一次。任务仍未登记时，可补充要求或用“替换任务”重下指令。
- **等待口令**时查看状态区中的原话。例如到电梯口后等待通知的任务，点“继续”才会进入乘梯阶段。
- **模型未提交执行动作**表示执行模型连续两次只返回文字，程序已请求暂停。确认暂停后可点“恢复”。其他按钮操作也须等待 Agent 确认，超时不会自动重试。

### 自动录制传感器 bag

勾选录包后，程序在任务登记结束时连接观察会话使用的 ROS master，检查传感器并等待 bag 实际写入数据，再进入执行阶段。录制覆盖暂停、等待用户和人工驾驶换层。窗口使用本车默认采集目录，路径不可写时可改用[命令行人工模式](#命令行人工驾驶)，用 `--record-bag` 启用录包，以 `--bag-output-root` 指定本机输出根目录。若旧观察会话没有提供 ROS master 地址，需重启观察。bag 影子回放不支持自动录包。

`navigation_时间/` 下保存 `navigation.bag`、`capture.json`、录制日志及 SHA256。bag 包含雷达、IMU、相机图像、相机内参和静态 TF。任务、对话和运行事件保存在独立的 Agent 会话目录。

从自动录包状态栏查看阶段和文件路径。正常结束、取消、关闭窗口或 Agent 进程异常退出时，录包会停止并收尾。“正在关闭与校验”表示仍在校验话题、索引和完整 SHA256。保存成功只代表这些检查通过，逐消息质量需另行检查。等本次保存完成再录下一包，以免争用采集独占锁。

录制启动失败会阻止任务执行。按提示排查后，取消并重开任务，或在新任务中取消勾选录包。录制中途失败时，窗口会提示，人工驾驶任务可继续，录包不自动重试。

历史窗口只读显示常规阶段的模型输入图像、对话、工具调用和完成记录，无需启动传感器或调用模型，也不会恢复执行。乘梯和目标楼层定位的逐轮图像仅在运行中显示，事后可查阶段事件。重处理传感器数据时使用同一演示的 `capture/navigation.bag`，配套地图和初值见车载机演示索引 `outputs/field_demos/README.md`。

也可以将演示导出为 MP4。解压实机演示包时保留演示目录及同级的 `assets/`。在仓库根目录加载 ROS Noetic，使用能读取 ROS bag 的系统 Python 运行下例。绘图需要 Pillow 和 Noto Sans CJK 中文字体，视频编码使用 OpenCV 的 FFmpeg H.264 编码器。导出过程无需启动 ROS master 或调用模型。

```bash
source /opt/ros/noetic/setup.bash
/usr/bin/python3 -m scripts.field_video \
  outputs/field_demos/20261122_195100_blocked_door_detour \
  --output outputs/field_demo_videos/blocked_door_detour_occupancy.mp4
```

视频左侧显示局部导航图、同期扫描和实走轨迹，下方显示 Agent 事件。右上是带语义标注、实走轨迹和已接受点序的全局图，虚线表示 Agent 提交的点序。深灰为占据，蓝灰为未知，浅米色为空闲。右下是前置 RGB，归档的判断用帧会标出。换层后使用对应楼层地图。

以局部图角标判断来源。“现场导航栅格快照”来自当时保存且定位匹配的栅格，外围由静态图补充，最长保留至原始观测后 1 秒。换层、重新建立定位或场景失效时，停止使用旧快照。有定位但无快照时显示“回放估算代价”，以静态图和可用的同期激光障碍为依据。无有效定位时只显示车体坐标中的同期扫描。

11 月 22 日门口改道演示缺逐帧局部代价和原参考曲线。导出器用归档目标、位姿和静态图离线复算参考路径，并标记来源。用 `SOCIAL_NAV_PYTHON` 或 `--planning-python` 选择带规划依赖的项目 Python，读 bag 仍使用 ROS 的系统 Python。复算失败的区段保留目标和实走轨迹，原因见终端。

默认精简模式保留关键事件及判断所用画面，缩短连续静止超过 8 秒的等待，并在跳转时显示略过的秒数。使用 `--mode full` 可保留原始录像时长。需要调整剪辑时，用 `--keep 30:40` 指定保留的一段，或用 `--cut 40:50` 增加候选剪辑段。秒数从第一张 RGB 的测量时间算起，关键事件和证据画面仍受保护。

### 驾驶、到达与任务中断

人工模式只向观察会话请求参考路径预览，驾驶者使用原车手柄。RViz 的白线是规划器对当前待达点的参考路径，蓝色直线表示途经点顺序。洋红箭头表示 Agent 选定的单点或路线终点朝向，是否需要对准以任务要求和状态为准。参考线或标记可使用近似显示高度。若标记位置缺少地面高度，会按地图地面高度中位数近似并提示，地图完全无高度时不显示该点。预览和示意图均不能保证现场通行。预览失败时，在窗口或终端查看原因，结合现场判断如何继续。[观察与人工路线预览](decision/技术实现-Agent长程导航.md#观察与人工路线预览)

驶入目标 0.20 米范围并按要求对准、停稳后，系统用新鲜地图定位检查这些条件是否持续成立。停稳时间及其他阈值来自导航配置。到达证据失效后，满足条件可重新生成。窗口“人工确认（备用）”或终端 `arrived` 可辅助确认同一目标，仍须通过定位和停稳检查。对话中回复已到达只作补充说明。多点路线依次记录实际经过的点，中间点可连续驶过。终点停稳后，Agent 结合任务要求、轨迹和当前观察判断完成，目标 PNG、事件和任务证据保存到本次会话。[到达检查](decision/技术实现-Agent长程导航.md#导航与人工驾驶到达检查)

- **暂停或取消任务**可在窗口操作，或用终端 `pause`、`resume`、`cancel`、`answer 补充说明`、`replace 新指令` 管理任务。关闭窗口会结束 Agent 进程。取消任务或关闭窗口时，由驾驶者操作手柄停车。
- **跳过无法完成的子任务**时，点击“跳过当前子任务”并确认。收到参考目标取消确认后，该项记为“已跳过”，再执行后续项。无后续项时以“部分完成”结束。操作者仍负责驾驶和停车。乘梯阶段及自动执行模式不可跳过。
- **观察进程或 RViz 异常退出**时，用原车手柄停稳。参考路径和地图定位不再更新，检查观察会话的 `runtime.log` 和 Agent 会话事件。

### 人工乘梯和出梯定位

开始前勾选“跨楼层任务”，选择当前楼层的观察会话，核对两层地图和标注。ROS 相机和原始雷达话题须独立于定位进程。使用一楼标准起点时，按 `reference_observation` 准备 `reference.json`、`rgb.jpg` 和 `lidar.png`，程序会核对采集时的地图身份与图像摘要。初值来自采集参考图时的雷达地图位姿。增量图经核实保留原地图坐标后，可把确切地图 ID 加入 `same_frame_map_ids` 以复用初值。[标准起点配置](../decision/agent/configs/elevator_standard_starts.json)

1. 进入已登记的乘梯阶段后，程序关闭来源楼层的只读定位，启动独立传感器观察。此时不要求原地图关联有效或车辆停稳。启用录包时先等录包就绪。操作者用原车手柄进出电梯并操作电梯。
2. 有标准起点时，驶至该位置，调整到参考朝向并停稳。Agent 默认每 5 秒对照当前 RGB、局部雷达图与历史参考图判断是否到达。实时画面和本机参考图会发送给所配置的 Agent 模型服务。窗口可查看本阶段的请求、图片、模型判断或观察故障，阶段结束后清除临时内容。
3. Agent 判断到达后，程序取得新出梯扫描，自动用完整雷达位姿尝试一次定位。缺少新扫描时检查独立传感器流。目标楼层无标准起点时，Agent 用出梯扫描和目标地图选初值，失败或超时后可结合最新扫描与上次叠图重新选点。

一楼标准初值启动失败，或配准开始后 30 秒仍无有效地图关联时，任务留在乘梯阶段并自动打开一楼 RViz 选点窗口。保持轮椅停稳，用 `Ground Pose Estimate` 选择雷达位置和朝向。对照点云与地图调整后，点击 `Confirm Initial Pose`。预览不计时，每次确认后最多配准 30 秒。失败会重新打开选点。窗口意外关闭或启动失败时，可在 Agent 窗口看原因并点击“重开选点窗口”。目标地图关联有效后，Agent 自动获得定位证据并继续原任务。

连接超时等临时模型故障会保留阶段并显示等待提示。首次等待 5 秒，连续失败加倍至本地上限 60 秒，服务端 `Retry-After` 要求更久时按服务端执行。乘梯监控重试前还须取得新观察。正常响应后重置等待。认证错误、响应不符合协议或达到请求上限时暂停，等待人工处理。

已有二楼人工辅助乘梯、一楼恢复定位后继续到大厅的记录。不同出梯位置的配准和自主行驶仍待验证。[11 月 22 日现场演示](系统实机问题.md#11-月-22-日-agent-人工驾驶演示)

### 启用持续跟随

人工驾驶观察用 `observe --agent-observations --agent-follow-candidates`。驾驶者使用原车手柄，动态目标仅供预览。首次选人使用 YOLO 二维检测，需要[检测权重和图像依赖](perception/技术实现-检测与跟踪推理.md)，运行还需可用相机标定。

后端优先取命令行 `--t2-backend`，其次读 `configs/t2_backend.local.json`，未配置时实机使用 [DSPARK](decision/技术实现-VLM局部决策.md#远程服务启停与访问默认)。`--t2-backend hosted` 复用 Agent 托管 API。轮椅预设的远程后端默认发送质量 80 的 JPEG，可用 `--t2-jpeg-quality` 调节，或用 `--t2-image-format png` 切换为 PNG。更换后端或图像格式后重启观察。

本地 OSNet 使用 `--t2-backend reid`，通过 `--t2-reid-weights` 指定 OpenCV CPU 的 `.onnx` 或 TensorRT CUDA 的 `.engine`。选人和任务复核仍由外层 Agent 调用托管 API。[T2 模型输入与时效](decision/技术实现-T2行人跟随.md)

可以把已导出的 ONNX 复制到轮椅的 `models/follow_reid/`，并用 `sha256sum` 对照转移前的文件摘要。仅从 Git 准备时，先通过导出工具的帮助获取固定的上游源码和权重地址，再在具备 PyTorch、ONNX 和 OpenCV 的环境中导出。导出工具检查两份上游材料的摘要，并比较 PyTorch 和 OpenCV 的特征输出。

```bash
python -B -m decision.osnet.export_reid --help
python -B -m decision.osnet.export_reid /path/to/osnet.py /path/to/checkpoint.pth \
  models/follow_reid/osnet_x0_5_msmt17.onnx
```

选择 GPU 推理时，按轮椅本机环境记录激活运行时所用的 Python、TensorRT 和 CUDA 环境，并让运行时所用的 GPU 可见，再从这份 ONNX 构建 FP32 引擎。若已知原 ONNX 的 SHA256，可用 `--onnx-sha256` 在构建前核对。引擎和生成的 `.engine.json` 须留在同一目录。更换 GPU 型号或 TensorRT 版本后，从 ONNX 重新构建到新路径，避免覆盖已有引擎。

```bash
python -B -m decision.osnet.build_reid_engine \
  models/follow_reid/osnet_x0_5_msmt17.onnx models/follow_reid/osnet_x0_5_msmt17.engine
bash scripts/interactive.sh observe --agent-observations --agent-follow-candidates \
  --t2-backend reid --t2-reid-weights models/follow_reid/osnet_x0_5_msmt17.engine
```

引擎无法加载时，跟随会报告失败。检查引擎、同名 JSON 和本机 GPU 环境，或改用 `.onnx` 路径重启观察程序以启用 CPU 后端。首次跟随得到局部结果后，在 `run/reference.jsonl` 的 `follow_t2_result` 事件中查看 `reid_model`，其中记录实际后端、设备、模型路径、模型及原始 ONNX 摘要。

要设为本机默认值，在 `configs/t2_backend.local.json` 写入 `{"backend":"reid","reid_weights":"models/follow_reid/osnet_x0_5_msmt17.engine"}`。跨楼层交接沿用当前后端与权重路径。

排查 T2 时延或地图关联中断时，可在 `observe` 命令中加 `--trace-timing`。结束本次观察后，输入进程的匹配事件在 `run/timing_input.jsonl`，主进程的感知和控制事件在 `run/timing.jsonl`。两个文件各有一份 `.summary.json` 记录写入和丢弃条数。跨楼层自动启动的目标楼层进程有独立的 `command.json`，当前不会继承该开关。

人工驾驶观察用 DSPARK 或托管后端时，可加 `--t2-raw-rgb` 对照原始 RGB 和独立俯视图。首次选人仍用 YOLO。该模式缺少结束跟随所需的当前二维关联证据，只用于非执行观察。切换到 `reid` 前须去掉 `--t2-raw-rgb` 并重启。

### 启用桌边停靠

桌边停靠在 `observe` 或已授权的 `execute` 入口使用 `--agent-observations --agent-seating`，需要局部 DSPARK 服务、可用相机标定和当前扫描。圆桌按所在楼层和正式标注 ID 配置桌面半径，单位为米。标注坐标对应桌面中心。[圆桌配置](../decision/vlm/t3/configs/round_tables.json)

```bash
bash scripts/interactive.sh observe --agent-observations --agent-seating --floor floor1
```

完成定位后，在看得清小圆桌 1 和附近椅子的位置停稳，在人工驾驶窗口下达“在小圆桌1旁选一侧没有椅子的位置停靠，车头朝向桌子”。到直桌沿停靠时，须先在能看到目标桌沿的位置停稳。

从运行事件查看候选和拒绝原因，在 RViz 查看已接受目标与参考路径。若 T3 提出桌外观测点，用手柄驶到该点，朝向桌子停稳，让系统用新画面和扫描再次选点。移动椅子后可重做同一任务，核对停靠方位是否随现场变化。跨楼层与局部任务的组合仍待现场验证。[T3 阶段与完成反馈](decision/技术实现-T3桌边停靠.md#阶段与完成反馈)

### bag 回放调试 T2 跟随

脚本在独立 ROS master 中启动 Agent 窗口、RViz 和 T2 回放，不连接底盘。默认使用二楼的定位图、静态图和标注，回放限单楼层。显式指定 `--t2-backend` 时优先采用命令行，否则读取 `configs/t2_backend.local.json` 中的后端和 ReID 权重。无本机配置时，默认用 `hosted` 发送质量 70 的 JPEG。`--t2-backend dspark` 默认发送 PNG。远程请求包含 bag 的人物图像和相关观察，发送前须确认授权，可用 `--t2-image-format jpeg --t2-jpeg-quality 80` 调整编码。下例使用本地 T2，见[启用持续跟随](#启用持续跟随)。

回放使用 `SOCIAL_NAV_PYTHON` 或已准备的当前环境。车载机若已有 `outputs/runtime/environment/activate.sh`，脚本会加载该本机环境；显式指定的解释器优先。回放需要 Noetic、原生库、RViz 插件及对应楼层资产。

```bash
cd /path/to/Social-Nav
bash scripts/t2_bag_replay.sh \
  --bag /path/to/navigation.bag --t2-backend reid \
  --t2-reid-weights models/follow_reid/osnet_x0_5_msmt17.engine
```

RViz 出现后，用 `Ground Pose Estimate` 选择 **本次回放起点**的雷达位置与车头方向，选点后立即启动定位。定位就绪后，在 Agent 窗口输入带外观描述的任务，例如“跟随前方穿深蓝色上衣的人”，点击“开始新任务”。Agent 窗口查看 T2 状态，RViz 查看感知和规划。用 RViz 面板或终端 `p`、`r`、`q` 暂停、继续和退出。暂停期间没有新观测，活动任务可能因状态过期而取消。播完需重新启动才能重放。

默认 1 倍速，以便比较时间相关行为。`--rate 0.5` 可放慢播放，`--start 秒` 可从指定录制偏移开始。播放速度变化会影响结果返回时的观察年龄，实时性数据应注明播放倍率。使用一楼地图加 `--floor floor1`。ROS 端口冲突时可用 `--ros-port` 指定其他端口。

若要跳过 RViz 选点，可以用 `pick_start.sh` 查看首帧扫描与 RGB，在对应三维地图中保存初值，再通过 `--pose-file` 加载。初值文件与 bag、地图及 `--start` 偏移绑定。回放开始后仍需核对地图关联和扫描对齐。本机两份演示的路径和已准备初值见被 Git 忽略的本机环境记录。手动选点时可用 `--initial-z 米` 指定雷达高度初猜。

对于已经完成登记、第一项为跟随的任务，可以预先准备该 bag 的初值文件和历史 Agent `session.sqlite`，随后自动启动跟随：

```bash
bash scripts/t2_bag_replay.sh --bag /path/to/navigation.bag \
  --pose-file /path/to/bag_initial_pose.json \
  --reuse-session /path/to/registered_task/session.sqlite --auto-follow
```

程序核对已登记任务的楼层、地图与标注，等本次地图关联和观察就绪后，由外层 Agent 根据带编号的当前观察选人并启动跟随。可以在 RViz 手动选点提供初值。历史第一项须为跟随，地图与标注不匹配时会拒绝启动并提示。VLM 后端积累约 1 秒的有效三帧观察后请求模型，失败等人工处理。`reid` 使用最新帧，须连续两次确认身份。[T2 后端机制](decision/技术实现-T2行人跟随.md#观察与后端)

已知目标是单人演示中的行人时，可以在上述命令中加 `--auto-follow-single-person`。定位就绪后，如果当前 RGB 图像只检测到一人，而且此人与已确认的三维轨迹匹配，程序就用本帧裁剪建立参考并启动跟随。画面没有候选，或唯一候选还没有匹配轨迹时，程序等待新观察。一旦同一帧检测到多人，即使只有一人匹配轨迹，也会退出快捷启动，由外层 Agent 按原任务指令选人。

RViz 的目标点表示 T2 当前期望位置。参考线表示规划器当前采用的路径，可能通往通过车体检查的替代终点。局部轨迹在参考和当前观测足以通过 DWA 检查后才出现。VLM 选择原地转向时需要停稳证据。使用 OSNet 时，检查前往最后观测位置期间目标和修订号是否保持一致，并区分路径预览、录包中的轮椅运动和实际到达反馈。

终端打印的回放目录下，`interactive/run/reference.jsonl` 记录 T2 结果、等待中的跟随点、搜索拒绝和规划结果。`interactive/run/control.jsonl` 用于核对 DWA 是否生成局部轨迹及其拒绝原因。`interactive/run/t2_requests/` 保存 VLM 后端的实际请求、结果及人物图像，或本地后端的 `*.reid_observation.json`，其中包含观察来源、匹配评分和搜索选择。按原始数据保护这些记录，通过 `recording_summary.json` 的 `dropped` 和 `error` 检查写入是否完整。外层 Agent 的工具调用和任务状态可在 `outputs/decision/agent/replay_ui_*` 的 `session.sqlite` 查看。

回放位姿来自原始录制，生成的轨迹和速度属于影子建议。真实跟随、到达和制动由实机测试验证。

## 地图准备

### 新建楼层地图

依次生成三维定位图、为定位 bag 选择起点、按需划定可信关联区域，再导出配套静态图。

```bash
bash perception/scripts/build_map.sh --bag /path/to/mapping.bag \
  --out outputs/perception/new_mapping --gpu "$GPU_ID"
bash perception/scripts/pick_start.sh --bag /path/to/localization.bag \
  --localization-map outputs/perception/new_mapping/map --out /path/to/initial_pose.json
bash perception/scripts/pick_coverage.sh --localization-map outputs/perception/new_mapping/map \
  --out /path/to/coverage.yaml
"$ROS_PYTHON" -B -m perception.environment export --run outputs/perception/new_mapping \
  --out outputs/perception/new_static_map --export-pgm
```

默认离线流程面向地面大致水平的单层环境，启用稳健回环和地面高度校正。最终定位图在 `new_mapping/map`，原始图在 `new_mapping/raw`，中间结果在 `levelled` 和 `optimized`。片段过短、地面支持不足或留出检查失败时，程序报错并保留已完成阶段。需要原始算法或与旧图配准的局部更新时用 `--pipeline raw`。直接运行时的 `mapping` 模式不做这些离线校正。[建图流程](perception/技术实现-建图与定位.md#任务配置与输入)

用具备 ROS 环境的系统 Python 导出静态图。`export --run` 默认用同源封存扫描估计地面。扫描不全时可显式选 `--ground-method map_endpoints`，也可从定位地图直接导出。定位图用于定位，静态图用于环境和规划。启用前核对轨迹、墙面、高度、占据和未知区域。[静态图构建](perception/技术实现-环境地图与场景表示.md#构建流程)

排查高度错层时，建图加 `--trace-roll`，再用 `python -m perception.mapping_localization.height_review --map /path/to/map --out /path/to/review.json` 查看重访统计。默认流程需构建支持稳健回环的离线 ROLL 库，也可用 `--roll-library /path/to/library.so` 指定兼容库。地图通过检查后仍需实机验证。

### 校正已有原始地图

也可对已有原始建图单独生成高度校正候选。以下命令都要求输出目录不存在；派生运行通过符号链接只读引用原扫描日志，移动或打包时需要保留该来源。`level_map` 可省略 `--static-map`，直接从该运行的同源封存扫描提取地面。

```bash
"$ROS_PYTHON" -B -m perception.mapping_localization.level_map \
  --run /path/to/mapping_run --static-map /path/to/tracked_scan_static \
  --out outputs/perception/levelled_candidate
"$ROS_PYTHON" -B -m perception.mapping_localization.ground_refine \
  --run outputs/perception/levelled_candidate --out outputs/perception/ground_candidate
"$ROS_PYTHON" -B -m perception.environment export \
  --run outputs/perception/ground_candidate --ground-method tracked_scans \
  --out outputs/perception/ground_candidate_static --resolution 0.1 --export-pgm
```

整体校正后的地图不自动满足定位对重力方向的要求；地面软约束也可能扭曲真实坡道或墙面。使用前须检查对应的定位地图和静态地图，旧地图的人工修改及标注不能直接视为适用。两种修正的假设和留出检查范围见[建图与定位](perception/技术实现-建图与定位.md)。

### 融合同一楼层的多次采集

若同一环境有多次保留了封存扫描的建图运行，可将它们融合到同一张最终定位地图。

```bash
bash perception/scripts/build_static_multi.sh \
  --map /path/to/final_localization_map \
  --evidence-run /path/to/first_mapping_run \
  --evidence-run /path/to/second_mapping_run \
  --out outputs/perception/multi_survey_static --gpu 0
```

每个 `--evidence-run` 对应一次建图，须备齐原始 bag、运行记录和扫描封存，时间段重叠或来源不一致时处理会停止。按提示依次在最终地图上选初始位姿。脚本沿用各次外参和时间参数重新定位，融合结果保存到 `static_map/`。

如果最终地图由这些历史地图逐次更新而来，可加 `--auto-initial-poses`。脚本会检查更新链和保留的旧关键帧位姿，复用各次人工选点或原始建图初值作为配准初猜；它们不代表配准已经成功。自动或人工初值都须经过有图定位和质量检查。若已有各 bag 在最终地图上的定位运行，也可用 `python -B -m perception.environment export` 重复传入成对的 `--evidence-run` 和 `--reference-run`，按对应顺序指定。

要保留人工修订的静态图时，使用下方局部更新入口并提供该静态图。[补采证据与分类变化](perception/技术实现-环境地图与场景表示.md#补采地面与空闲区域的融合)

### 用局部 bag 更新定位图和静态环境图

先让新 bag 从旧地图覆盖区域开始采集，并保留该 bag 的完整雷达和 IMU。在有桌面的终端运行：

```bash
bash perception/scripts/update_map.sh --bag /path/to/local.bag \
  --map /path/to/old_roll_map --static-map /path/to/old_static_map
```

也可省略两个地图参数，用 `--config` 选择对应楼层的运行配置，例如 `navigation/commissioning/interactive_agent_floor1.yaml`。默认配置是 `navigation/commissioning/interactive.yaml`。脚本读取配置里的 `map`、`static_map` 和 `coverage`，核对静态图和关联区域是否属于所选定位图。显式传入 `--map` 时，需同时传入要继承的 `--static-map`；单独指定 `--map` 或在使用配置时加 `--3d-only`，均只生成三维定位候选。

在选点窗口中，根据旧图、首帧雷达和可用的 RGB 选择雷达位置及朝向。核对预览并保存后，脚本完成局部建图、固定旧图定位和候选生成。关闭窗口而不保存会停止处理。显式指定定位图时，默认用点云范围建立关联区域，可用 `--coverage /path/to/coverage.yaml` 替换。用 `--gpu 0` 选择 GPU。如果三维融合因体素容量不足退出，可按可用内存设置 `--max-voxels`；该选项只改变容量上限。默认输出在 `outputs/perception/` 的新目录，也可用 `--out` 指定项目 `outputs/` 或 `/tmp/` 下的新目录。失败时保留中间结果。

运行目录的 `initial_pose.json`、`local_mapping/` 和 `local_reference/` 分别保存初值、局部建图和固定旧图定位结果。`candidate/map/` 是新的 ROLL 定位图。`candidate/report.json` 记录三维变化依据，`candidate/changes.npz` 保存旧特征删除候选与新采集特征点。`candidate/comparison.png` 和 `candidate/comparison_detail.png` 可查看全图和局部变化。

提供旧静态图后，二维候选写入 `candidate/static_map/`。在 `update_report.json` 查有效射线数、接缝高差和分类变化数，再从 `changes.npz` 的 `manual_review` 与 `ground_height_conflict` 找到要现场复查的人工分类分歧和地面高差。`grid.survey_offset_yx` 标出这些数组在全图中的起点。人工分类和估算高度保留原值。

源地图和运行配置保持原样。局部更新适用于旧图覆盖范围附近，各次时间戳须可比较且互不重叠。启用候选前，检查变化位置和独立轨迹的定位表现，核对关联区域与 Agent 标注对应的地图身份。

### 人工修正地图

```bash
bash scripts/edit_map.sh --static-map /path/to/static_map --out /path/to/new_static_map
bash scripts/edit_map.sh --localization-map /path/to/localization_map --out /path/to/new_localization_map
```

滚轮缩放，右键或中键平移。静态图可修改空闲、占据和未知。默认勾选“拟合人工空闲缺失地面高度”，保存时填入估算高度，参考点不足则拒绝保存。取消勾选可保留缺失高度。也可打开已修正的图，仅补高度并另存。人工空闲属于人工分类，估算地面只用于显示。修改三维定位图后，地图身份会变化，需核对配套资产。[地图人工修正机制](perception/技术实现-环境地图与场景表示.md#端点导出与人工修正)
