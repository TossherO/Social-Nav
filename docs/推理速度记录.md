# 推理速度记录

2026 年 11 月 24 日在轮椅计算机（Intel Core i7-12700，RTX 4060 Ti 16 GB）用当前工作区复测。固定目标导航能够在原速回放中维持约 7.5 Hz 的地图发布率。打开默认 RViz 后，控制首次使用一张地图时，这张图的源扫描年龄中位数为 111 ms，P95 为 211 ms。地图平均更新率和控制拿到的观测有多新，是判断实时性时需要同时看的两个指标。

## 二楼导航优化回放

从 11 月 19 日 16:42 的二楼导航 bag 起点原速播放 24 秒，使用正式二楼定位图和人工修订静态图、同一初始位姿和地图目标 (−11.41, 5.34) m。三帧 VoxelRCNN 使用 FP32，环境图窗口为 18 m、分辨率为 0.10 m、目标更新率为 7.5 Hz，运动档位为 `trial`。固定图定位、三维检测跟踪、局部制图、参考规划、DWA 和独立安全同时运行。轮椅运动由 bag 提供。

无显示、打开默认 RViz、RViz 仅显示静态底图三组交错运行，各两次，运行进程可用 CPU 0–19。有窗两组都实际收到了实时扫描、RGB、行人和导航标记。显示层配置的地图发布上限为 5 Hz，与导航内部制图频率独立。静态底图模式只关闭局部导航底图及其边框。热段从首扫源时间第 10 秒算起，下表合并同组两轮原始样本。单位为毫秒，单元格为 P50 / P95。

| 环节 | 无显示 | RViz 默认叠加 | RViz 仅静态底图 |
|---|---:|---:|---:|
| 雷达输入就绪到前端定位返回 | 7.6 / 13.0 | 7.5 / 12.4 | 8.1 / 12.9 |
| 三维检测与跟踪完整调用 | 43.9 / 73.0 | 48.4 / 75.6 | 51.4 / 69.9 |
| 局部图与静态支持计算 | 10.5 / 15.7 | 13.6 / 21.3 | 14.1 / 19.8 |
| 含原生搜索的完整参考规划 | 292 / 750 | 407 / 793 | 257 / 929 |
| DWA 实际生成候选的控制周期 | 12.0 / 19.3 | 13.4 / 19.0 | 13.6 / 17.1 |
| 独立安全实际检查扫掠轨迹 | 8.2 / 15.8 | 9.1 / 18.7 | 9.9 / 18.9 |
| 源扫描到控制首次取图 | 110.5 / 117.4 | 111.1 / 210.6 | 111.0 / 209.5 |
| 源扫描到独立安全首次取图 | 149.4 / 173.2 | 150.9 / 171.3 | 154.9 / 174.7 |

**地图发布和使用。** 六轮各输入 241 扫，处理 235–238 扫，发布 167–168 张地图。每轮热段的 141 次定位输出均已关联到地图，并发布了 106 张新图，实际更新率为 7.477–7.530 Hz，地图故障和计时日志丢失均为零。默认 RViz 下，从雷达输入就绪到地图发给安全进程为 84.8 / 131.7 ms，地图发布间隔 P95 为 204 ms。仅显示静态底图，每轮少传 10.4–10.9 MiB 局部地图点云，显示专用 GPU 回读减少约 5.8–5.9 MiB，但本次控制首次取图 P95 仅相差 1.1 ms。屏幕实际绘制帧率未计时。

**规划和设备计时。** 默认 RViz 组热段有 282 次检测跟踪、18 次进入原生搜索的规划、179 次实际生成候选的控制周期。后台 ROLL 匹配为 10.3 / 27.2 ms，检测后的跟踪本身为 1.0 / 1.4 ms，规划工作图准备为 18.5 / 26.2 ms。主六轮中，固定目标从规划循环首次看见到取得对应参考路径为 416–711 ms，每轮出现一次。单轮全段 CUDA 事件中位数分别约为 FAST-LIO 去畸变 0.022 ms、ROLL 近邻查询 1.03 ms、DWA 候选计算 1.1 ms。设备事件只计相应内核，表中的完整阶段墙钟还包含主机工作与等待。

**启动和实机配置差别。** 六轮从运行时内部开始计时到输入就绪为 4.10–5.89 s，不含 Python 导入和静态地图加载，系统缓存也未清空。首次单帧检测为 448–741 ms。另将运行时及其子进程限制在实机启动器使用的 CPU 0–15，保留默认 RViz，补测一轮得到 7.551 Hz，控制和独立安全首次取图 P95 分别为 214.5 和 256.1 ms。这一轮不足以判断限核本身的影响。七轮沿用 bag 入口约 5° 的 ROLL 重力阈值，实机入口为 8°。

### 与早期优化的对照

同一车载机在 11 月 24 日对照过提交 `7f6fb93` 和优化后的工作区。单独重放 56 帧相同点云，检测跟踪 P50 从 23.31 降至 21.36 ms。雷达原始点和 FAST-LIO 输入准备从 1.88 降至 0.57 ms。一楼 42 次封存规划查询的工作图准备从 74.75 降至 17.21 ms。工作图只是参考规划的一步，搜索和整车可行性检查仍会占用数百毫秒。这组单独检测的输入和并发负载与上表不同。

早期真实 RViz 对照中，显示专用的 GPU 回读量从每轮 39.37 降至 19.16 MiB。仅启动 ROS 显示发布且没有订阅者时，优化后的显示专用回读为零。在 11 月 22 日另一组持续更新跟随目标的六轮回放里，端点检查与代价图准备的单轮中位数从 71–79 降至 32–40 ms，但新目标首次取得同一修订路径的单轮 P95 仍为 426–483 ms。

## T2 本地身份匹配

## 离线制图

使用系统 Python 3.8，在上述 GPU 回放结束后单独计时。OpenBLAS、OpenMP 和 OpenCV 均设为单线程，各阶段用相同输入执行三次，以下为墙钟中位数。

- 一楼正式三维图含 240,827 个端点。按 105 个位姿拟合地面并生成全层 0.10 m 端点栅格，用时 **0.84 s**，点云和位姿已提前载入内存。
- 对 11 月 22 日一楼补采的 2,510 扫按 0.2 s 间隔选取 957 扫，生成扫描支持的地面图层用时 **6.03 s**。对同一批扫描单独提取关键帧高度约束用时 **7.03 s**，其中 854 扫提供了可靠高度观测。

这些测量覆盖静态地图生成中的指定计算。未重跑从原始 bag 开始的三维建图、多次补采融合、人工修订或完整导出的总流程。

## 外层 Agent 托管 API

用相同的合成大厅、同一句“到大厅门口。”分别运行两轮正式 Agent。每轮都实际调用托管模型三次，依次登记任务（`record_task`）、提交目标（`navigate`）、确认完成（`complete_subtask`），四轮均在模拟器中完成。Qwen3.8-flash 是默认模型，也可选择 GPT-6.1-terra。下表按任务登记、执行、监控的顺序列出默认思考档位。阶段单元格为两次请求的中位数，单位为秒。

| 模型与默认档位 | 登记首片段 / 完整 | 执行首片段 / 完整 | 监控首片段 / 完整 | 从开始登记到完成工具返回，两轮墙钟 |
|---|---:|---:|---:|---:|
| Qwen3.8-flash（low / off / off） | 7.70 / 9.83 | 2.70 / 3.02 | 7.37 / 9.19 | 21.55、26.67 s |
| GPT-6.1-terra（low / low / low） | 4.12 / 4.71 | 3.70 / 4.00 | 2.79 / 3.47 | 15.20、13.82 s |

GPT 在这项任务的整体等待时间较短，Qwen 的单次执行请求反而较快。阶段耗时从车载客户端发请求开始计，包含网络、服务端排队和生成。各服务最先返回的片段可能是推理、文本或工具事件。整任务墙钟另含本地处理、模拟反馈和调度。每个后端只有两轮，不能从这里推算复杂任务成功率或现场行驶用时。

另取历史会话中同一个停稳后视觉复核节点，保留原来的消息、四张图和工具说明，两端各取得一次有效回复。Qwen 的首片段 / 完整返回为 3.72 / 6.87 s，申请完成子任务。GPT 为 4.23 / 4.37 s，选择等待新相机帧。两端报告的输入缓存命中率均超过 99%，返回的工具均未执行。首次本地计时未能读取响应，以上数值取自修复计时器后的补测。

此前对 4 个历史会话的 8 个图文节点做过 40 次配对调用。各节点等权，GPT 从关闭推理改为 low，完整返回中位数由 4.82 变为 4.97 秒，按请求配对的增量为 0.11 秒。Qwen 从 6.84 变为 16.89 秒，配对增量为 11.19 秒。模型缓存命中率及网络路径不同。对三个已知失败节点，保持旧工具说明的 medium、high、xhigh 共 27 次都未纠正错误。在电梯口视觉任务登记节点，直接说明 `floor_id` 与 `conditions` 的字段层级后，GPT low 从 0/3 变为 3/3 通过登记。提高思考强度的时延和修正工具调用的效果应分别评估。

## 统计口径与复核

固定目标回放按源扫描时间匹配日志。控制端按场景、独立安全端按源时间与地图快照去重，记录各自第一次选用地图时的年龄。独立安全随后完成几何检查。参考规划只统计实际进入原生搜索的工作进程。异步阶段彼此重叠，各行 P95 不能相加。各负载分别测速，未测真实底盘响应，也未测所有模块同时运行时的时延或实机任务成功率。T3 和远程跟随 VLM 未在本轮复测。
