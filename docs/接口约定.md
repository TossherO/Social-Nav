# 接口约定

本文规定数据跨模块传递时，坐标、单位、观察时间、身份和有效性分别怎样解释。字段定义用于让提供方与使用方核对同一件事，不代表对应功能已经完成集成。

实际内部数组与观察描述由 [interfaces/runtime.py](../interfaces/runtime.py) 维护。[contracts.py](../interfaces/contracts.py) 则是跨模块 Python 类型草案，检测跟踪已有 `to_snapshot` 转换，其余类型不能视为已接通协议。dataclass 本身不检查数值、时间、坐标变换或响应 Schema，也不是 ROS 消息、调度器或安全实现。

T1、T2 继续使用各自的 `v/dt/ts/e/o/d` 等 HTTP 字段，T3 使用专用候选协议。共享类型不会自动替换这些输入。算法和使用说明见[感知导航总览](感知导航总览.md)，本页保留接口的精确语义。

可按数据类型查阅：[运行时与数组](#感知导航直接运行时)、[定位状态](#定位状态与连续位姿)、[地图与场景](#可选环境状态与地图关联)、[导航结果](#只规划结果)、[检测消息](#检测消息与协方差)，或查看[外层 Agent](#外层agent开发接口)和 [T3 候选](#t3目标点选择)的约定。

## 单位、身份与缺失值

提供方必须说明长度、角度和时间单位，通常为米、弧度和秒，同时给出观察 ID、坐标系、时钟域、源序列及相关版本。

缺位姿、速度或协方差使用 `None`，不能填零或单位位姿。空地图不表示自由空间，未观测也不表示没有障碍。

雷达—IMU时间补偿约定为`t_imu_used = t_imu_header + offset_s`。当前默认偏移为零，不运行启动时差估计；显式固定补偿只改变输入组装使用的时间，不改写原消息。`imu_time_calibration.offset_s`记录生效值，`offset_policy`为`sensor_timestamps`或`configured_offset`，分别表示使用原时间戳或非零固定补偿；`validation_performed=false`表示本次没有重新校准。会话声明和配置摘要继续保留，不能把未知会话解释为已验证。旧记录中的`status`、`configured_time_calibration`及`publish_after_s`属于已移除的启动估计，不作为新运行的发布条件。后续封存、传输及推理均不刷新源时间。完整机制见[标定专题](perception/技术实现-建图与定位.md#雷达imu标定与同步实施策略)。

异步参考作业同时保存源时钟锚点`now`、提交时的`sent_mono`和`clock_rate`。工作进程以`now + (当前单调时间 - sent_mono) * clock_rate`取得查询源时间，不能把非1倍bag回放按墙钟直接推进。该换算不改变地图、人物或位姿的原测量时间。

`TrackIdentity` 标识源轨迹及其生命周期。模型窗口中的短 PID 只在当前输入中有效，不能作为长期人物身份。

## 外层Agent开发接口

当前 [Agent](decision/Agent技术实现.md) 使用单模型原生工具循环。请求用 `tools` 提供函数及参数定义，响应使用 `assistant.tool_calls`，每轮最多一项调用。`function.name` 是工具名，`function.arguments` 是待解析并校验的 JSON 字符串，`id` 是服务端返回的原调用身份。程序以 `role=tool/tool_call_id/content` 返回结果，不从回复正文提取动作。

助手消息和工具结果成对加入累积对话。系统提示之后、原任务之前可以放置 `static_reference_map`，包含宽高自适应、最长边不超过 2048 像素的固定全局图、全部固定标注和 `reference_map_id`。`image_size=[width,height]` 记录实际像素尺寸，`image_layout=map_aspect_and_wrapped_legend` 表示保留地图比例并为文字换行预留空间；`max_image_edge=2048` 记录最长边上限。它不带当前自车和任务起点，同一会话保持图片及尺寸不变。每轮末尾另附 `runtime_current_state`、有效当前 RGB、全局概览和局部图。普通旧图不累积，模型显式保存或重读的历史 RGB 通过对应历史消息提供，最多两张；加上固定地图与当前三图，总计最多六张。对话修订参与迟到结果检查，原任务和要求独立保存，原始请求和响应仍完整记录。助手文字不作为任务成功。

固定标注在前部 `static_reference_map.reference.annotations` 中完整定义。初始目录及当前、历史视图仅在固定标注、坐标及栅格对应时，通过 `annotation_reference.reference_map_id` 引用该定义，动态 `mission_start` 点单独保留；初始目录的地图条件、单位及访问政策不删除。视图以 `record_representation=projection_of_original_view_id` 明确表示模型输入投影，原 `view_id`、`catalog_fingerprint` 和源绑定指向未修改的完整原记录，不是精简正文的新摘要。缺少参考图或匹配失败时保留完整标注。

当前附件中的 `details_in_tool_call_id` 只引用本轮仍保留、且所需模型输入投影与当前投影完全相同的工具结果。附件继续给出原 `view_id` 或 `observation_id`、源时间和坐标约定，图像正常附带；原记录缺失时发送完整投影，固定目录依然在本轮请求中。缓存标记不更新观察时间、不复用旧响应，也不放宽返回身份检查。

`runtime_current_state.requirements_registered` 明确说明是否已登记任务。`selected_goal`、`last_tool_feedback`、全部已接受的 `clarifications` 和 `task_start` 分别提供当前选择、最近工具结果、用户补充及带正式身份和显示编号的任务起点。`robot_context` 只报告适配器实际提供的几何和运动资料；假设状态与来源同时出现，未发布限值为未知，不能套用默认参数冒充当前性能。`recent_model_tool_choices` 是历史工具动作，不能当作环境事实。

`visual_inputs` 根据实际附件给出当前 RGB 和地图的可用性、原观察身份、源时间及年龄；缺少时给出原因。RGB 元数据独立给出 `rgb.stamp_s/frame_id/shape/age_s`，不能把场景时间替换为图像采集时间。历史关键帧索引提供原地图位姿和坐标系，历史图片不因此变为当前输入。

当前优先完备地图下的室内点、区域及有序串联。`map_condition=complete/simple/none` 分别表示完备地图、简单地图和无图先验；后两项只有条件接口，不暴露完备地图标注，也不支持目标执行。

`record_task.goals` 是有序完成要求，不是自动运行的工具计划。每项包含 `goal_id/kind/target_id/description`。点使用 `place_id`，匿名点使用空 `target_id` 和用户给出的 `position=[x,y]`；区域使用 `region_id`，不预填区域中的选定位姿。可选 `required_yaw` 是用户硬朝向，`facing` 是待面向的 `landmark_id`，`semantic_conditions` 是到达后需要 RGB 判断的要求。要求登记后保持不变，只有替换任务才能重新登记。

`lookup_places(name)` 按名称、别名或正式身份检索，返回 `places/regions/landmarks`；空字符串返回完整目录，不生成新身份。`get_navigation_state` 返回当前调用、原反馈和最近完成记录的摘要，不重复发送全部尝试历史。

`query_map` 返回 `view_id`、地图条件、坐标、范围、实际位姿、标注及图像来源。位置单位为米，角度单位为弧度，地图采用目录的 `frame_id`，目标参考点为 `base_link`。当前地图图像分别标记 `trajectory_global_overview` 和 `target_or_robot_local_map`；开头的固定图标记 `static_annotated_global_map`。全局概览中的历史轨迹只来自截止观察时刻的实测有效定位，`trajectory.source_binding` 对应同会话 `trajectory_snapshot` 的实际样本。时间间断和定位生命周期变化不连线，地图关联或坐标时钟变化清空轨迹。`local_source=static_prior_only` 表示没有当前局部栅格，仅使用静态先验裁剪。图中的 P、R、L 编号通过 `display_id` 对应正式身份，不替代工具参数。

`input_source_binding` 对应地图栅格、原场景、位姿、时钟和测量时间，用于判断是否需要重绘，不与控制循环时间直接比较。显式 `bounds` 在原来源未变时保留；来源变化时按同一范围更新，导航提交成功或任务替换后清除该范围意图。

`save_keyframe(observation_id, reason)` 仅接受本轮模型已读过且仍有效的当前 RGB，保存后返回 `keyframe_id`、原 `observation`、源时间、任务修订和内容摘要。`read_keyframe(keyframe_id)` 只能读取本任务修订已保存的观察，返回值保持原时间。对应 `historical_keyframe` 消息中的图像是历史输入，`historical_only=true`，不证明当前通行或到达，不能以其身份代替 `check_goal` 所需的当前观察。图片内容或元数据摘要不符时拒绝，不重写摘要。

`navigate` 必须包含 `goal_id`、连续 `pose=[x,y,yaw]`、当前 `view_id` 及 `orientation_source=user/semantic/autonomous`。位姿由 VLM 直接选择，工具不产生候选、不补朝向、不改写被拒绝的位姿。未指定朝向时，点资产中的朝向不自动成为用户约束。`selected_goal.allowed_orientation_sources` 从当前登记要求生成：存在 `required_yaw` 时仅允许 `user`，否则允许 `semantic/autonomous`。不符时返回 `refused` 和 `orientation_source_disagrees_with_registered_requirement`，保留原响应，不提交导航。

导航句柄包含 `task_id/plan_revision/goal_revision/call_id/catalog_fingerprint`，另记录 `goal_id/task_goal_binding/view_id`，分别对应任务要求与实际空间输入。`plan_revision` 仍表示任务指令修订，不表示编译计划。工具只操作下一项未完成要求，新的选定位姿不能借用旧导航调用的完成记录。

原生工具的 `tool_call_id` 对应一次模型工具请求；导航句柄的 `call_id` 由本地产生，对应一次长期导航。两者用途不同，runtime 的 `request_id=call_id` 继续使用导航身份。

`check_goal` 使用对应执行及停稳反馈中的实际位姿检查几何。有视觉条件时还需 `observation_id/semantic_result/evidence`；结果取 `satisfied/not_satisfied/unknown`，只有前者允许完成。观察必须来自到达后，并且确实出现在返回此判断的原模型请求中。同一模型的语义判断不是独立真值。全部已登记要求完成后才允许任务成功，完整自然语言有无遗漏仍需独立评测。

模型请求记录任务修订、要求摘要、活动调用、地图 `view_id`、原观察及实际输入摘要、源时间、时钟、定位会话和地图关联。地图 PNG 与实际发送的 RGB 均可从会话记录复核，RGB 来源摘要另行保留；实际发送图可能已缩放编码。取消、用户补充、指令替换、过期或定位重置都会使不再适用的结果作废。当前 `check_goal` 的执行完成仅限 `simulation`，影子模式不能报告完成，实车反馈仍待接入。

`runtime.command` 接受只读请求 `{"kind":"agent_state","value":{"with_image":false}}`，返回当前控制请求、定位、影子状态、来源摘要和接收年龄。查询不会刷新数据源时间。

只有显式启用 `--agent-observations` 才提供约 1Hz 的 RGB 与场景。后台保存共享主机 RGB 副本并异步编码，图像仍对应原场景，不传整个 GPU 地图。

目标与取消沿用原字段，Agent 自行保存业务句柄，用 `request_id=call_id` 对应 runtime 活动目标。控制状态另外携带同源 `map_binding` 和已处理的 `cancelled_request={task_id,goal_revision}`。

确认影子取消需要同时满足两项：回执身份匹配，且活动目标为空。旧的空状态不能替代回执，取消意图清除也不等于底盘已停车。接收确认和录包接近目标同样不能作为执行反馈；真实反馈、命令幂等恢复与完整跨模块类型接入仍未完成。

任务起点是任务私有的 `base_link` 目标，保存源时间、定位生命周期和适用地图，不写回共享地点目录。模型请求还记录原观察使用的地图关联。

空间上下文变化后，证据记忆保留历史语义，但撤销其当前空间依据，旧任务不能自动继续。断连时保留未确认调用，恢复后只查询核对，不自动重发目标，也不能用历史证据恢复成功状态。

## 感知导航直接运行时

输入进程、GPU 主进程和 CPU 消费者使用 [`interfaces/runtime.py`](../interfaces/runtime.py) 的观察与数组描述，进程职责见[总览](感知导航总览.md#运行时与资源职责)。观察头保留纳秒源时间、时钟域、坐标、会话与代次，接收时间另记，不能替代源时间。

默认核心不要求 RGB、CameraInfo 或二维检测。三维人物、局部环境和导航不会等待 YOLO 匹配。显式开启显示、归档或 VLM 准备后，图像仍要与原内参和三维观察对应，不能回写三维身份或几何证据。

原生地图匹配完成后，定位上下文可针对最后一份真实前端观察重新检查关联，并通过私有Unix数据报发送完整关联记录。`stamp_s`仍是该前端观察时间，`measurement_stamp_s`仍是实际地图匹配时间，接收或重新检查不会推进两者。主进程保存最多64份记录，提交地图任务前核对`local_session_id/local_generation/local_frame/stamp_s`与原扫描关联完全相同，并核对`map_id/asset_fingerprint`；未来匹配和较旧迟到结果不能替换原记录。新结果可以是有效或失效状态，不能仅接纳成功结果。

通道发送不等待接收方，发送缓冲区满时保留原流程并统计`association_updates_dropped`；主进程的接收与使用数量写入`summary.association_delivery`。缺少对应更新时沿用扫描包原关联的源时间与有效期，不伪造新证据。后续场景须重新生成派生支持与摘要，已封存的主机或设备场景不回填。

### 数组所有权

主机数组写入 memfd 共享槽后封存，描述记录形状、类型、偏移、槽代次和内容摘要。接收端只读映射，所有读取方释放引用后，槽位才能复用。

常规导航接收端在感知繁忙时释放尚未消费的旧扫描，只保留最新待处理扫描。源定位记录和独立安全输入保持完整，`counts.source_scans`与`counts.scans`分别统计接收和实际感知数量，不能混用。地图线程另持有有界的点坐标和射线原点副本，替换待处理任务不刷新测量时间；定位失效或生命周期变化后，旧任务不得发布。归档与决策输入记录模式继续顺序处理，调度统计见`scan_scheduling/map_scheduling`。

生产者为每帧 GPU 图层准备独立存储，再交给 `DeviceGridSnapshot.seal()` 保存引用与就绪事件。`seal()` 不会替调用者克隆张量，也不能阻止张量被原地修改，因此生产者必须保持已发布图层只读。

消费者通过 `consume()` 等待就绪事件，并登记实际使用的 CUDA 流，避免存储过早回收。需要下载时，调用 `materialize(consumer=..., fields=...)` 明确消费者与字段；返回的 CPU 数组只读，禁止隐式 NumPy 转换。DWA 的私有积分与传输工作区可以在一次调用及轨迹读取完成后复用，不属于已发布地图。

原生地图使用CUDA默认流。当前异步地图线程在调用前显式让默认流等待输出缓冲所属的PyTorch流，并登记缓冲的使用流；返回后让地图线程的流等待原生流，再转换和封存图层。不得依赖隐式默认流语义或在消费者释放前覆盖输出。

直接运行时不启动CPU融合进程。`LocalEnvironmentMap.support_observation`提供同次观察的世界端点、人物点掩码、原时间与局部身份，`NavigationSupport`在楼层和关联有效时于GPU上生成导航三层，否则返回原始图并记录`navigation_support_status`。该输入只供同进程地图线程使用，不通过ROS或逐体素RPC传递。

CPU 安全胶囊、搜索快照和完整场景按各自实际内容保存摘要，不能冒用完整地图 SHA。安全胶囊保留原占据和对应人物背景。启用二维导航支持时，还传递 `navigation_occupancy/navigation_source/navigation_source_stamp` 及来源元数据，由场景摘要覆盖实际数组；派生所用地面与覆盖等测量不重复塞入胶囊，补充端点占据使用来源10及原命中时间。来源枚举、时间与复核条件由[导航派生图](perception/技术实现-环境地图与场景表示.md#静态自由支持的导航派生图)集中维护。当前接触使用核验后的导航视图，原占据命中仍具有优先级。完整复核结束并释放引用后，生产者才可覆盖该数据。

导航派生与背景图使用同一局部栅格、坐标和观察截止时间。静态来源记录资产摘要、关联身份和原支持时间，不刷新为场景时间；派生过程不改写原始`occupancy/coverage/last_observed`。当前`metadata.navigation_fusion.method=static_background_support`记录所选静态地面、适用高度范围、障碍高度来源及普通／人物期限，不再记录在线地面确认状态。`floor_reference.stamp_s`是本次选取时刻，`source_stamp_s`才是静态参考的原支持时间，不能混用。CPU安全独立重算整格投影支持并核对资产及关联年龄。设备端新增数组后发布新的封存对象，共享背景存储保持只读。消费者拒绝旧派生方法，旧场景须由原始输入重新生成；原始数组仍可按原摘要读取。人物圆属于同观察元数据，规则见[动态碰撞视图](#动态碰撞视图)，支持层字段见[环境专题](perception/技术实现-环境地图与场景表示.md#静态自由支持的导航派生图)。

局部地面冲突使用可选二维布尔层`ground_conflict`，与占据图具有相同坐标、分辨率和观察截止。标记为真时，不得用近场历史、人物背景或静态先验补充自由，当前占据继续有效。启用导航支持的安全胶囊和搜索快照保留该层，`navigation_fusion.ground_conflict_sha256`核对其原始字节；缺失、摘要不符或冲突格被派生为空闲时拒绝。旧场景没有这一证明字段时保留原语义，不补造冲突记录。ROS诊断消息增加同名可选数组，发布新层前需重新生成环境消息。

位姿、扫描、人物和提议保留各自原观察时间，异步结果、外推和重新检查都不会刷新它们。

当前来源`10`表示基础图之外的补充端点占据，来源时间是同次或仍在期限内的实际端点命中。它只能增加障碍，不解除原占据。当前不生产小孔来源`9`，旧场景仍按原证明语义校验；无法识别的来源不得放行。

参考搜索缓存只保存自有的占据、代价和完整距离场，不持有共享槽中的数组指针。`heuristic_cache_reused=true` 只表示本次复用了几何引导；结果仍属于本次请求与原观察，必须重新经过路径和时效检查。原生诊断 `disconnected_search_region` 要求距离场完整、车体参考点严格位于足迹内部，不能由超预算的部分距离场产生。

### 人工导航意图

直接运行时的 `commands.sock` 接收 `{"kind":"goal|cancel|override","value":{...}}`。目标沿用规划请求字段，位置单位为米、朝向单位为弧度，并明确 `frame_id` 和 `target_reference=base_link`；地图目标还须携带所选静态环境包的 `map_snapshot_id`。取消使用 `task_id/goal_revision`，覆盖同任务不高于该修订的目标，并拒绝这些修订的迟到重放；接管使用布尔值 `manual_override/emergency_stop`。接收确认只说明意图进入处理流程，不能当作规划通过或真实停车反馈。

[人工目标桥接](../navigation/planning/manual_goal.py) 将 RViz `PoseStamped` 转成要求停车的 `[x,y,yaw]` 目标。它只接受所选的 `map` 或 `odom` 坐标系和有效二维朝向，不隐式变换坐标；同次桥接的目标修订递增。`source_intent_stamp_s` 原样保存目标消息头的 ROS 时间，单位为秒，表示人工意图时间，不是定位或传感器测量时间。状态输出始终保留 `executable=false/task_completed=false/execution_feedback=false`。

`runtime.interactive`显示所选环境包的只读`OccupancyGrid`，帧和时间沿用静态资产。`/initialpose`选择雷达XY与朝向，`/move_base_simple/goal`选择车体目标位姿，`/clicked_point`选择不约束朝向的XY目标。显示线程在地图位姿有效时发布该次测量的`map→odom`变换；它只服务显示，不反向修改定位或地图关联。启动与取消见[交互测试](感知导航运行手册.md#rviz交互测试)。

交互入口的`--pose-file`复用原起点文件核验，必须对应当前bag、地图、`rslidar`及`--start`，实时输入拒绝此选项。`/social_nav_interactive/session_markers`在`map`中发布界面提示，无需局部坐标变换；提示不是传感器测量，也不参与规划或定位。绿色起点箭头只代表对应bag时刻的已保存初值，当前配准是否成立仍由新定位观察决定。

`social_nav_rviz/GroundInitialPose`和`GroundGoal`继续发布标准`/initialpose`与`/move_base_simple/goal`消息。位置来自鼠标视线与`/social_nav_interactive/ground_map`有效格子的最近交点，格子大小由会话所选静态地图分辨率设置；工具要求地面消息坐标系与RViz固定坐标系一致，没有地面时拒绝选点，不退回Z＝0。拖动方向由选中高度的水平面计算，不能改变已选位置。消息时间是用户意图时间，Z是地面显示高度；初始化仍仅取XY/yaw，雷达高度按现有初值规则处理，导航目标仍为`base_link`的二维位姿。

交互会话额外接受`session_status`、`playback`和`arm`。`playback.value.paused`为布尔值，只用于bag；暂停在扫描边界确认，等待地图完成后计算冻结预览。`session_status`返回冻结源时间、当前观察和预览，查询不刷新它们。恢复播放撤销冻结目标，迟到预览必须匹配会话修订才能发布。`arm.value.enabled`只在显式实机模式有效，其确认表示请求收到，实际串口状态由`chassis.state`给出。

`session_status.goal_intent`是控制调度已处理的当前请求副本，用于核对目标位置，不是到达或执行反馈。交互界面据此发布`/social_nav_interactive/accepted_goal`；有朝向时绘制紫色箭头，只有XY时绘制球体，位置查询静态地面并加显示偏移。取消或播放阶段切换后清除；若没有该处高度，则不补零绘制。该标记不参与路径可行性检查，也不修改请求坐标或朝向。

启用显示时，冻结预览另含`display`，仅保存曲线分段、连续前缀、坐标系、源时间和文字位置；该字段在规划完成后生成，不改写参考或DWA结果及其摘要。每次新冻结查询单独读取所需显示层，不与显示线程共用可变缓存，也不通过命令通道传输整张地图。有图参考按所选静态地面绘制，局部轨迹按该冻结观察的有效地面绘制。`/social_nav_interactive/preview_paths`使用`MarkerArray`保留未知高度断口，`preview_reference/preview_trajectory`的`Path`仅含连续有效高度前缀。静态`ground_map`使用建图地面，原`map`保留为默认关闭的二维诊断图；二者均不代表当前现场占据。界面文字和已保存初值箭头缺少邻近地面时，可使用初值、地图高度统计或实测雷达高度定位提示；这种退化只用于界面注释，不用于导航曲线或车体。

### 可选显示与录制路线

RViz显示分别限制扫描、人物、地图、RGB与导航曲线的墙钟发布频率。每类最多保留一份最新待发布数据；扫描、RGB和人物使用独立主机副本。地图保留封存设备引用，由显示线程按需将`occupancy/ground_z/ground_support`及存在的`navigation_occupancy/navigation_source`一次复制到CPU，同一快照的导航图、基础图和曲线共用下载结果，缓存最多两份。CPU地图直接只读引用；派生显示高度保存在独立数组中。该传输以`optional_ros_display`单独计量，不扩展安全胶囊或恢复内部ROS通信，也不持有输入共享槽。发布、重绘和重新展示旧参考均不能刷新原观察时间，配置频率也不代表新的测量频率。

默认`height_mode=ground`时，车体足迹、历史和导航曲线按各自XY位置查询同一局部生命周期内、时间有效的地面，再加`display.path_z_m`及各图层的微小显示偏移，具体显示规则见[运行手册](感知导航运行手册.md#显示与提交目标)。局部`ground_z/ground_support`优先；已接受静态支持的格子在局部高度缺失时，可使用下述静态显示高度，并标为`static supported cells`。仍缺高度时，仅在雷达周围配置半径内允许使用`ground_tracking.status=tracked`的当前观测平面，标为`fitted near vehicle`。其余缺少高度的点不绘制，不能补零；支持高度不代表当前占据为空闲。历史保存每次测量当时的高度，不用当前地面重投影整条历史。显式`height_mode=plane`才使用固定Z平面。所有投影只影响显示，不改变定位、地图或规划输入。

默认`navigation`的`MarkerArray`使用分段线绘制全部有效历史、参考和预测，遇到未知高度会断开；稀疏空间参考先按地图分辨率加密，每条最多2000个显示点，再查询地面，避免跨过中间缺测格。`ground_map`为带`rgb`字段的`PointCloud2`，显示同次生产者输出的`navigation_occupancy`，没有导航派生层时使用基础`occupancy`。它只绘制有有效高度的格中心：局部高度缺失且`navigation_source`为3或10时，核对静态资产和原观察时刻的关联后，复用`prior_floor()`将静态地面转换到局部系。该补充仅保存于`display_only`视图，不改写原地面、占据或自由证据；其余缺高度格仍不绘制。

辅助`path`为车体地面投影历史的最新连续片段，`reference/trajectory`为从路径起点开始具有连续有效高度的前缀，类型均为`nav_msgs/Path`，不跨接高度未知处。这些话题仅用于显示诊断，不能当作完整的算法输出。`occupancy`提供Z＝0的完整导航占据图，`raw_occupancy`在有订阅者时提供基础局部图；两者均为`OccupancyGrid`，默认RViz关闭这两个平面图层。原始雷达三维历史由`lidar_path`提供；扫描与人物不做高度投影。

有图参考使用DWA相同的平面转换：先用当前定位和`map_from_local`分别计算局部与地图中的车体位姿，再从两个SE(2)位姿求出地图到局部的变换。显示端不发布虚构的`map→odom`TF。缺失或失效的关联会清除相应曲线，不能直接把地图坐标当作局部坐标。

显示复制当前请求、定位、关联和几何状态等小型元数据，复用封存结果，不传输整个场景。参考检查当前请求、局部生命周期、时钟和地图身份；DWA另检查其对应的控制提议、参考及源时间。空`Path`和标记删除用于清除无效曲线，后台到期检查在没有新扫描时仍生效。车体、目标和曲线缺少高度时省略对应标记，状态文字保留并说明高度来源。历史路径每个点保留测量时间，参考和预测的路径头部及线标记保留各自输入时间；状态说明不刷新这些时间。目标与预测均不构成执行许可。

显式`--route`只接受同bag的录制开发参考，`--route-floor`选择本轮楼层。几何段窗口使用原包时间，进度由截止前的实际位姿匹配；局部目标锚点只从过去有效地图关联得到。路线请求保留`route_binding/route_segment_id/route_source`，原录制轨迹不作为本轮执行反馈。手动目标、取消或接管抢占后，录制调度不能恢复覆盖它们。电梯过渡不生成到层确认，接口和运行日志始终保留影子属性，见[路线专题](navigation/技术实现-任务与路线.md#录制行程的分段目标回放)。

### 时钟与可选决策历史

直接运行时在 `run.json` 和定位记录中明确使用 `runtime_bag/runtime_live`。旧记录只按已知来源推断，不能统一改成 ROS 回放时钟。

可选决策历史把原扫描和 RGB 复制到有界主机槽，并记录用途。历史缓存和异步三帧消费者分别持有引用；定位或跟踪重置可以清理历史索引，但不能覆盖仍被读取的数组。

每个窗口保存原二维关联、图像像素、人物结果、当前场景摘要，以及 `PID → [tracker_session,generation,track_id]` 映射，不下载整套 GPU 地图。下文 ROS 消息用于诊断和传感器或显示适配，不是内部必经通信。

### 底盘诊断记录

显式实机模式在`run/chassis/events.jsonl`保存下表事件。串口进程只向有界队列提交，后台线程写盘；这些记录用于复核，不作为新的控制输入或实机完成反馈。

| `kind` | 主要字段与含义 |
|---|---|
| `wire_target` | `mono`为成功完成串口写入后的主机单调时间，`write_started_mono`为写入前时刻；`units=[线速度mm/s,角速度mrad/s,模式]`，另存`velocity_mps_rps`。重复写入也记录，`changed`说明目标是否改变，不表示车辆响应。 |
| `feedback` | `mono`为串口数据的主机接收时间，`timestamp_source=host_receive_monotonic`，`device_measurement_stamp_s=null`。`feedback`保存解码的速度、模式、摇杆、候选校验与原始帧；同次读取的多帧共享接收时间，不能据此计算设备采样间隔。 |
| `authorization` | `mono`为驱动收到安全授权的时刻；`packet`保留原授权发送时间、期限、使能修订和速度整数。`diagnostics`保存安全序号、拒绝原因、候选身份、源时钟及定位估速的原始时间，不为重发更新测量时间。 |
| `state` | 驱动使能状态、修订与停止原因；`execution_feedback=false`、`task_completed=false`。 |

定位估速的`stamp_s`与`decision_stamp_s`属于记录中的源时钟，不能直接减去主机单调时间。底盘上报速度仍带原协议验证属性，不因写入日志就升级为真实执行反馈。

`telemetry_summary.json`按事件类型记录`seen`、`dropped`，另给出`written`、队列容量、`finalized`、`complete`与错误。只有排空且没有丢失或错误时`complete=true`。`status.json`由后台写入，包含`status_mono`；交互状态检查超过0.5秒或未来时间时返回`state=unavailable`，原报告状态放在`reported_state`。该显示处理不参与底盘授权，也不替代独立看门狗。

## 数据方向与所有权

下表说明共享类型草案表达的数据方向，实际接入状态仍以前文和对应专题为准。

| 提供方 → 使用方 | 类型及职责 |
|---|---|
| 感知 → 决策与导航 | `PerceptionSnapshot`、`PersonTrack`、`PoseEstimate`、`MapReference` 表达观察、人物、自车位姿和地图引用。 |
| Agent → VLM 与导航 | `AgentIntent` 表达任务模式、描述或目标及模式版本，不是底盘指令。 |
| VLM → 导航与 Agent | `VLMResultEnvelope` 将结果对应到原观察、请求、身份映射、模式和候选版本。 |
| 规划 → 控制 | `PathPlan` 仍为类型草案。现有[局部轨迹与跟踪接口](#仿真控制安全门与执行反馈)提供带时间和运动约束的候选轨迹、速度目标及独立复核。 |
| 导航 → Agent | `NavigationFeedback` 表达执行、停止、完成或失败的反馈。真实任务不能使用伪造的成功反馈。 |

显式实机模式已有独立串口出口，要求本车确认参数及人工使能。受控基本动作已有现场证据，完整目标导航和任务反馈仍待验证，见[实机问题](感知导航实机问题.md)。沿用现场已确认的执行档案；几何路径、影子建议和仿真反馈不能代替实际执行结果。

### T3目标点选择

T3 的调用方提供自然语言指令、场景和候选目标点，模型只返回 `p,s`，其中 `p` 是本次候选 ID。研究设计包含倒退让行与就座，当前离线实现以就座为主。

候选明确记录坐标、位置、必要朝向、到达方式、几何状态和集合版本。位于车后的点不自动表示允许倒车，仍须由运动意图和导航约束决定。

候选集合保存 `instruction/observation_id/stamp_s/frame_id/clock_domain/session_id/generation/revision/candidates`，可附 `context`。最多 8 个候选，ID 为 0～7，每项包含：

- `pose=[x,y,yaw]`，单位为米和弧度。
- `motion=forward/reverse/wait`，表达运动意图。
- `geometry=unknown/feasible/blocked`，`blocked` 不进入模型可选枚举。

输出只包含以下两字段：

| 输出示例 | 语义 |
|---|---|
| `{"p":3,"s":"v"}` | 选择本次候选3，仍需实际几何与执行验证 |
| `{"p":-1,"s":"n"}` | 现有证据排除了本次全部候选，不代表全场景无解 |
| `{"p":-1,"s":"u"}` | 缺少判断所需证据，不构成等待位置或默认运动指令 |

接收结果时核对原指令、模式、观察和候选集合，几何与运动约束仍由本地导航检查。`n/u` 时 `p=-1`，不能把它当坐标或运动指令；若等待可供选择，应提供显式候选。实现见 [VLM 手册](decision/VLM部署与调用.md#t3目标选择与就座)。

当前已有 T3 候选绑定、三帧专用请求、同观察只规划检查及阶段反馈适配。倒退让行、自动服务调度与实际导航反馈源仍未接通。

阶段输出的导航或停止请求不是底盘动作，候选选择也不是完成反馈。工具和类型草案的存在不证明真机闭环已实现。

#### 桌边候选的辅助上下文

辅助桌边候选可以携带专用 `context`。候选集合摘要同时包含历史资产、`base_link_hypothesis` 目标参考、足迹与雷达变换、来源观察和截止时间。来源不能晚于当前观察，局部会话和代次必须一致。

这些信息只用于原始扫描的离线复核，不是当前车体标定、可达性证明或执行反馈。

辅助输入可以保存采样策略和桌沿下方回波，包括观察时间、总数及假设自车过滤后的数量。零回波不能代替未知的完整净空，带符号桌边间距只有在明确允许桌下探索时才可为负。

`selection_context` 把当前车体位姿对应的 Prompt 模式和阈值写入输入指纹。模式切换不读取模型答案，也不改变候选可达性或阶段完成状态。

近似轮廓使用 `table_outline_hypothesis`，记录先验多边形、假设来源、最早可用时间和当前因果回波。三帧按过去到当前排列，每幅图保存摘要、原观察、RGB 时间和位姿，当前候选只画在最后一幅，旧单图资产仍可读取。

地图标注的正式跨坐标接入尚未完成，生成观察位姿不等于发出导航请求，更不等于执行反馈。

## 接入与校验边界

[`DecisionRequest`](../decision/vlm/navigation.py) 已实现进程内单请求响应检查。它保存原窗口、场景、任务票据和动态 Schema，接收时核对期限与当前生命周期，拒绝取消、重复、迟到或旧映射响应。原响应保留，不修复也不重试。自动模型调度和真实导航执行仍需另行接入。

`PersonTrack` 保留 `confirmed/score/covariance_order`，感知快照说明 `health/reason`。`Header.timestamp_source` 解释时间来源，定位头保留自己的测量时间，不冒充点云采集时间。未知速度仍为 `None`，缺可靠定位只输出传感器坐标检测。

共享 RGB 字段仍是资产引用，ROS 图像关联另外记录图像时间、标定与像素框来源，见[图像关联](#图像框与三维轨迹关联)。检测消息在 `perception/detection_tracking/ros/msg`，定位消息在 `perception/mapping_localization/ros/msg`，有效位、时间和坐标与共享语义对应。接口变更与原实现分别测试，类型存在不表示集成完成。

## 图像框与三维轨迹关联

可选 [`ImageAssociations`](../perception/detection_tracking/ros/msg/ImageAssociations.msg) 与原 People 并行发布，不修改 TrackState。消息的时间和坐标需要分别解释：

| 字段 | 含义与有效条件 |
|---|---|
| `header.stamp` | 原三维观察的采集时间。 |
| `header.frame_id` | 相机光学坐标系。 |
| `rgb_stamp`、原图宽高 | 只有 `has_rgb=true` 才有效。 |
| 内参时间、`camera_model_fingerprint` | 由 `has_camera_info` 限定有效性。 |
| `rgb_box=[x1,y1,x2,y2]` | 实际配对原图的像素框，原点在左上，不是米制坐标。 |

- 通过`observation_id/sequence_id/session_id/generation/clock_domain`及`perception_input_fingerprint`连接原People，通过`track_id/lifecycle_generation`连接轨迹；短PID不作为传输关联键。
- `has_rgb_box`、`has_detection_score`和`has_cost`分别限定字段有效性，默认数组及零值不能当作框、分数或代价。`status`保留未匹配、歧义、缺输入、时差超限和失败，`compensation`说明几何是否经过去时刻补偿。
- 消息`status=complete`仅表示本次关联处理完成；逐轨迹状态与`has_rgb_box`才决定是否有有效框，不表示全员匹配或整机健康。
- `calibration_sha256`及`detector_identity`绑定来源。图像检测分数不是身份正确概率，成功关联不改变原`observed/confirmed`或健康状态。
- 仅已有三维轨迹进入关联数组，未匹配二维人物不获得三维身份。队列有界；繁忙／迟到丢弃分别计数，旧结果不得覆盖新观察、重置后的轨迹或另一张RGB。

离线缓存保存原图像素、内参、标定、观察和模型实现，标注预览、审核与导出共用它。工程元信息登记默认路径、冻结身份和就绪状态，读取入口不临时覆盖。只有完整覆盖工程观察才可登记为就绪，待准备或来源变化时不回退到投影框。

主进程与数据工作进程要核对同一工程、资产和图像来源，切换后需重启。登记不修改原观察或人工答案，标签重审见[标注手册](decision/决策任务标注.md#rgb框来源)。

二维运行记录用原三维观察身份与输入指纹对应，不用标注工程短 PID 作键，并保留实际 RGB 时间、像素摘要和当时可用内参。导入只映射工程帧 ID，缺记录标为 `not_processed`，不造匹配或换图。缓存覆盖全部观察，也不表示所有推理都成功。

保存用 `/records` 可以包含迟到历史结果，实时消息和叠图仍不能覆盖新观察。叠图 Image 使用原 RGB 头时间，仅是显示资产，不能重新作为原始相机输入。

## 定位状态与连续位姿

定位提供连续局部位姿，并单独表达地图位姿。ROS 诊断由所选 ROLL＋FAST-LIO、无图 FAST-LIO 或 PIN-SLAM 发布 `/localization/state`，类型为 [`LocalizationState`](../perception/mapping_localization/ros/msg/LocalizationState.msg)，包身份保留为 `social_nav_localization`，源码在 `perception/mapping_localization/ros/`。

一条消息同时记录扫描结束时间、位姿、健康、来源、会话、重初始化代次和配准状态。下游读取对应记录，不再把旧的无时间戳 String 状态与任意最新位姿拼在一起。直接运行时通过内部记录传递相同的时间和身份语义，不要求先发布 ROS 话题。

### 坐标与有效性

| 字段 | 坐标与含义 |
|---|---|
| `header.frame_id=odom`、`child_frame_id=rslidar`、`pose` | 把雷达坐标转换到连续局部世界。ROLL 和无图 FAST-LIO 使用 FAST-LIO 前端，PIN 累计相邻有效配准增量，不使用编码器里程计替代可靠定位。 |
| `map_pose/map_frame=map` | 单独表达地图位姿；回环修改 `map_revision`，不把地图跳变带入人物速度。 |
| `has_map_pose=false`、空 `map_frame` | 无图状态，没有有效地图位姿。默认 `map_pose` 不能使用，也不发布 `map→odom`。 |
| `source` | 明确区分 `roll_fast_lio/fast_lio/pin_slam`，下游显式选择，不凭名称推断质量。 |
| `has_covariance=false` | 协方差未知，不使用默认矩阵。 |

前端 `lidar` 与配置 `rslidar` 明确指向同一物理传感器。`VALID` 要求对应配准有效且误差有限；无图 FAST-LIO 检查局部地图有效点、内点比例、残差和位姿有限性。初始化与失败输出 `INVALID`，纯预测不是有效定位。这些条件不是完整可观测性分析、外部精度或安全保证。

新进程创建新 `session_id`。切换后端应重启会话，并隔离旧位姿与身份。ROLL 已接受的 RViz 重初始化增加 `generation`，PIN 首版不接 RViz 重初始化，改起点或时间回退需要重启。

#### ROS初值确认

ROLL 人工初值经 `/initialpose` 提交，坐标必须属于已加载地图。`/roll/initial_pose_accepted` 以 `geometry_msgs/PoseWithCovarianceStamped` 返回规范化初值，头时间是选点请求时间，不是扫描时间，也不表示有效定位。

等待选点时前端不启动，没有定位输出，只提供地图显示参考，不发布车体定位 TF。新扫描开始处理时才进入新 `generation`，配准通过后才能输出 `VALID`。PIN 固定地图首帧同样需要真实配准。

#### 首帧与运动初始化

FAST-LIO 通过锁存的 `/fast_lio/initial_lidar_pose`（`geometry_msgs/PoseStamped`）向 ROLL 提供首个扫描在内部 `camera_init` 中的雷达位姿，时间为该扫描结束时间，坐标与 `/OdometryLidar` 一致。该字段是初值参考，不是定位输出或 TF。

ROLL 按 `首帧地图初值 × 首帧局部位姿逆 × 当前局部位姿` 传播初值，防止把初始化结束时的车辆位置误作首帧。初始化期间不输出有效世界轨迹，内部重力对齐也不表示已标定水平导航坐标。

配准误差与内点比例是诊断，不是外部精度真值。TF 只在有效状态发布，使用方仍需检查年龄，旧 TF 存在不能证明当前定位有效。

实时扫描显示使用同次定位或检测结果中的明确位姿，失效或超时就清空。显示点云不是新的算法输入。缺定位的检测只能在显式传感器视图展示，不能借旧 TF 放到世界中。

结果回看合并原定位与检测的观察时刻，缺失位姿仍保留缺失，不用未来或邻帧补齐。

### 定位失效时的处理

检测使用的位姿必须同时满足以下条件：

- 与当前观察属于同一时钟域。
- 测量时间不晚于该观察。
- 定位结果尚未过期。

等待上限和允许年龄由 [inference.json](../perception/detection_tracking/configs/inference.json) 维护，处理方式见[检测与跟踪](perception/技术实现-检测与跟踪推理.md#定位与时间)。

当前估计失败时，不回退到旧有效位姿。缺定位、LOST、非法位置或断流都会使世界跟踪降级或失效，可用点云仍能进行传感器坐标检测。

会话或重初始化变化时，旧位姿与新世界隔离，并重置人物生命周期；时间回退通过回放序列重置处理。没有确认车体外参时，不输出假车体位置。

ROS 建图和有图定位使用唯一 TF 链 `map → odom → rslidar`，无图只发布 `odom → rslidar`。本次选定后端独占发布，不能同时启动两个后端发布同一变换。ROLL 中 FAST-LIO 的旧 TF 与旧车体偏移 TF 关闭，未来接入 `base_link` 需确认固定外参。

这些消息已用于实机 bag 回放，失效与生命周期处理有 CPU 检查。真实遮挡下的 LOST 与恢复、现场时钟仍需验证，交互操作见[建图与定位](perception/技术实现-建图与定位.md)。

## 地图与派生对象的身份

地图类型见[对象分类](perception/技术实现-环境地图与场景表示.md#地图与非地图对象)。环境数据先用 `entity_type` 区分 `map/view/scene`，再用对应字段说明用途：

| 对象 | 类型字段与来源 |
|---|---|
| 地图 | `map_type` 说明定位、静态环境或局部环境用途。 |
| 先验视图 | `view_type/source_map_type` 说明派生角色，并保留源快照摘要。 |
| 场景 | 组合一份观察的地图、人物与可用图像。 |
| `GridSnapshot` | 只是数组容器，不能仅凭类名认定内部一定是地图。 |

三维定位地图的角色写在新 `run.json`，不改变后端地图格式。静态环境地图写入 manifest 和图层，局部图与先验视图写入自己的图层元数据及场景摘要。类型字段仍不能替代健康、时间和来源检查。

兼容读取继续保留 `kind=static_environment`、场景 `geometry/prior_geometry`、ROS 话题和原资产 ID，`prior_geometry` 明确表示先验视图。读取旧产物不回填字段或修改指纹。PGM/YAML 是占据导出格式，可信区域 YAML 是关联约束，都不是新的地图身份。

## 可选环境状态与地图关联

直接运行时默认使用公共定位上下文。ROS 诊断在 `--environment` 下启用相同处理：前端与地图估计分别发布 `/localization/frontend_state` 和 `/localization/map_state`，唯一 `localization_context` 再发布公共 `/localization/state` 与 TF。

消息类型仍是 `LocalizationState`，`source` 保持显式选择的 FAST-LIO 或 ROLL，局部 `pose` 来自前端。以下 `--allow-local-only` 等选项属于 ROS 诊断，直接运行时已允许有效局部位姿独立于地图关联使用。

### 局部健康与地图关联

建图与无图任务的健康由局部配准决定。ROS 固定地图定位默认还要求先验关联；显式允许 `--allow-local-only` 后，先验匹配失效不会使有效局部 `pose` 失效。真实局部定位失败时，仍须隔离世界几何和人物轨迹。

公共 `session_id/generation` 对应前端连续世界的生命周期。地图重新关联使用独立代次，所以地图匹配变化不会重置 `odom` 人物轨迹。ROS 未启用环境上下文的任务继续沿用原有代次语义。

`/localization/map_association` 的类型为 `social_nav_localization/MapAssociation`。它分别保存当前观察时间和实际配准测量时间，同时记录地图资产指纹、后端修正 `revision` 和独立关联代次。每次重新接受关联时增加关联代次，不能用后端 `generation` 代替。

关联失效后须重新收集连续匹配，历史修正也只能在年龄预算内传播。候选、无效或过期关联不产生有效 `map_pose` 和新地图 TF。

地图修正不进入局部速度估计。公共消息中的配准诊断来自局部前端，地图匹配的有效性和来源由独立关联消息表达；局部误差不能称为全局定位精度。

### 可信区域

可选覆盖多边形对应明确的地图资产和坐标帧，并保存覆盖指纹。`coverage_status` 区分未配置、无法判断、有覆盖和覆盖外四种情况。

覆盖区域同时约束 ROLL 地图匹配修正与公共先验关联。系统根据最后可信修正和当前局部位姿判断是否离图，返图时要求新的、连续一致的配准。覆盖外局部定位仍健康时，维持 `LOCAL_ONLY`。

覆盖只约束地图关联，不说明地面、自由空间或可达性。

### 环境网格与查询

环境 Grid 的 `header` 和 `snapshot_id` 对应整套数组。`occupancy` 使用 `-1/0/100`，缺失高度与距离使用 NaN，观测掩码和时间独立保留。字段尺寸与 `MapMetaData` 一致；地面支持或到障碍的距离不能证明完整车体可以通过。

ROS 查询要求提供已缓存的 `snapshot_id` 和正确坐标，并分别处理快照淘汰、越界和未知。历史快照只说明原时刻，在线消费者仍须检查健康、时效和地图关联。

`EnvironmentGrid.metadata_json` 保留原快照元数据，必须与消息头、身份和尺寸一致。数组按声明类型解码。ROS 消息位于 `perception/environment/ros/`，Python 数组查询位于 `perception/environment/context.py`。

### 人物证据与场景时间

局部环境在组装场景前，可以用同源可靠人物观察生成点掩码。人物必须早于截止，并与定位生命周期和时钟一致。`metadata.dynamic_filter` 记录人物观察、状态和统计，基础数组不变，当前人物命中仍是占据，只给旧人物证据较短期限。

缺人物时退回普通几何，不能生成自由空间。静态过滤另外要求人物来自同一建图运行、bag 和位姿，未通过的障碍也不能自动变成空闲，见[过滤机制](perception/技术实现-环境地图与场景表示.md#人物过滤与独立观测复核)。

`perception_scene` 用 `observation_id/as_of/clock_domain` 标识局部定位、几何、RGB 引用、人物和可选先验。直接运行时按需组装和保存，ROS 诊断用 `--scene` 发布。几何时间为截止，各模态保留原始观察时间，不允许未来数据，也不把旧预测叫作当前实测。

人物 JSON 的 `localization_binding` 记录所用定位会话、代次、帧和来源，与人物自身 `session_id/generation` 分开。缺该字段的旧 JSON，不能直接当作当前统一场景的人物输入。

场景指纹对应元数据、实际图层和 RGB 像素。查询先指定缓存场景 ID，也可指定指纹，`get_scene/get_rgb/query_geometry/crop_map` 必须读取同一场景，未知保持未知。

`state/status.current` 根据最新定位和年龄说明当前是否就绪，旧有效快照不能覆盖新的失效或局部重置。ROS 场景 JSONL 保存引用，默认只为末帧另存可独立复现的数组和图像；显式场景归档按运行选项处理。

### 静态先验与离线证据

`--static-map` 指定与定位地图同源的静态环境包。`prior_geometry` 保存原生 `map` 系裁剪、包来源、完整变换与独立关联代次，时域为 `offline_final_prior`，与当前 `geometry` 分开。

`get_prior/query_prior_geometry/crop_prior_map` 读取当前场景的先验。关联无效时不提供对齐数组，也不借旧变换或修改局部观察。`state/status.prior.ready` 根据最新定位、关联和年龄判断当前可用性，历史空闲不表示当前可通行。

末帧有效先验另存为 `prior.npz`。给旧场景显式补接先验时生成新指纹，不重写原对应关系。

统一场景由`perception/environment/scene.py`组装，供决策数据适配及只读查询；现有`PerceptionSnapshot`记录和VLM HTTP任务协议未自动替换，不把几何查询返回当作导航执行反馈。

静态包的 `manifest.yaml` 记录 `layers.npz` 身份、内容摘要和同源地图与扫描。`STATIC_ENDPOINT_CANDIDATES` 只有最终端点和地面支持，`free_space_supported=false`。有同源扫描时，`STATIC_SCAN_OBSERVED` 才能用实际射线生成高度覆盖与空闲，未对应扫描另行计数。

缺原始格子观察时间时保留 NaN，不用导出时间补齐。无图最后的滚动快照也不表示完整行程地图。PGM/YAML 只作为可选占据导出。

环境场景不包含视觉记忆、地点索引或历史图像引用，新静态包也不要求图像索引或相机标定。兼容读取旧包时不加载附加索引，旧场景按原指纹读取，退休字段不参与消费，不修改旧资产来适配新接口。

当前 RGB 仍记录采集时间、坐标、像素摘要和来源，与正式人物关联分开核对。离线最终先验不能回填为同次建图时已经知道的在线观察。

环境自定义配置中的当前图像话题由`scene.rgb_topic`维护，几何位姿查找参数由`poses`维护；旧冻结包内的配置只作来源记录，不直接作为新运行配置载入。具体参数仍以环境YAML为准。

### 近场历史与导航支持字段

因果补算先核对原四元数位姿属于同次观察，再按与 Slerp 一致的单位四元数转换，记录方法，原记录不改。

近场历史通过 `near_field_free`（bool）与 `near_field_free_classified_at`（float64 秒）区分原生自由和历史复用，非复用格的分类时间为 NaN。复用格保留缓存高度、覆盖和原观察时间，`last_observed` 不刷新；分类时刻也不是整列体素重新扫描时间。

`metadata.near_field_memory` 记录原快照、圈模型、参数、失效统计与后端，场景按实际图层计算摘要。字段已进入环境节点和场景，不意味着局部 VLM 与导航真实执行已经完成。

临时障碍另用`near_field_obstacle`（bool）、`near_field_obstacle_stamp`和`near_field_obstacle_expires_at`（float64秒）保存，缺失时间为NaN。这些输出只覆盖近场处理范围，圈外不保证有末次命中时间。整格均为可靠人物时使用较短期限；人物更新不能缩短此前尚有效的普通命中保护。到期不表示获得了新自由射线。

`ground_tracking.clear_ground_history`由当前地面跟踪在参考冲突时发出，局部地图据此清除旧地面与近场记忆，二维支持重新确认楼层。近场历史还比较逐格实际地面与已存地面，超过配置高差即撤回该格背景。

覆盖到期恢复背景时，仍保留原自由依据与末次障碍时间。恢复不是新测得自由，也不能成为永久清除静态先验的新反证。

二维导航支持接收同次观察的世界系端点及逐点人物掩码，核对原时间、定位会话、代次和坐标帧；普通与人物命中分别保留期限。它不以人物消失作为自由证据，输出继续保留原静态支持时间。

启用`--trace-timing`时，每次地图更新额外记录`navigation_support`诊断事件，包含原测量时间、地面跟踪、关联变换、楼层模型、重置原因、确认候选与通过格数，以及端点总量和其中人物端点的数量。字段不足时保留缺失值；已确认楼层后的事件不伪造新的确认数量。记录不改变地图、源时间或支持判定，也不额外下载GPU图层。端点总量不能直接证明具体阻挡格属于行人。

导航派生层的来源枚举及适用限制由[地图技术实现](perception/技术实现-环境地图与场景表示.md#静态自由支持的导航派生图)统一维护。映射模式的参考查询另在结果中记录`reference_overlay`，说明哪些静态未知格被已有局部自由证据临时支持。`source_scene/source_layers/source_prior`分别对应原场景、原图层内容与输入先验，`source_as_of`是原观察截止时间；`local_from_map`记录查询所用的二维变换，`unknown_to_free`统计本次补充数量。它不是新测量，不增加安全胶囊字段、不刷新时间，也不写入静态资产或永久修订记录。具体相交检查见[路径规划](navigation/技术实现-路径规划.md#局部证据进入全局参考)。

`EnvironmentGrid` 携带上述五个可选数组，近场关闭时为空。有历史元数据却缺相应数组时必须拒绝，不能静默丢失来源。新节点按当前消息定义构建，旧 bag 则按原定义读取 11 层并保留摘要。查询返回 `historical_free/free_source` 与相关时间。

环境 Grid、标准占据和显示扫描保留输入整数纳秒，没有纳秒的旧记录继续按原浮点时间读取。

基础决策适配使用 `environment_context`，统一场景使用 `environment_scene_context`，都保留场景指纹、人物映射及观察或预测状态。两者拒绝未来、过期、不同局部生命周期和冒充当前观察的最终先验，不改变既有三帧协议或人工标签。

T3 离线也可以直接读取 `SceneInputs` 并核对候选。Agent 另有影子循环，这些接口仍不能表示真实导航执行完成。

`conditional_obstacle` 仅表示可以附加路线代价的小型历史占据，不是测得空闲或语义“可移动”标签。当前局部完整自由可以修订历史占据，`revised_free_stamp` 保存实际时间，`prior_revision` 保存会话、来源观察和修订表摘要。当前占据覆盖不写回长期背景。

修订只在同一地图及定位、关联生命周期内复用，显式回退清空，静态原数组和摘要不变。普通障碍、人物、自由与地面证据有不同期限，过期本身不是自由证据。

## 只规划结果

显式分段路线由 `navigation/planning/route.py` 适配为下述请求。`route_id` 及内容指纹、`segment_id`、楼层身份和各段来源独立保存。

有图折线对应明确的地图身份，局部折线则相对明确的锚点。锚点使用离图前的有效关联变换，并保存当前局部生命周期、时钟与观察指纹；它只用于目标坐标转换，不更新定位有效性。

换层段只返回等待外部确认，不推断电梯是否到层，不自行推进任务或产生执行反馈。目标仍明确参考 `base_link`，前视目标变化必须使用新的 `goal_revision`。完整格式与操作见[导航专题](navigation/技术实现-任务与路线.md#室内室外与换层路线)。

`navigation/planning` 提供离线 JSON、ROS 只规划和影子适配，不替换 `PathPlan` 类型草案，也没有接通底盘控制或 T3 真实反馈。

每个请求给出 `request_id/task_id/goal_revision`、模式、目标坐标、`target_reference=base_link` 和米制位置及弧度朝向，地图目标另带 `map_snapshot_id`。静态查询使用显式起点，场景查询使用同次定位与有来源的车体关系，不能覆盖实际起点。

路线请求的`route_target`保存本次匹配进度、目标弧长位置、是否为该段末端及横向偏离，距离单位均为米。显式候选选择另带`route_goal_selection`：`batch_id`标识一轮候选，`candidate_index`从0开始，`search_budget_s`是该候选可使用的原生搜索秒数，`max_path_length_m`是中间路径的长度上限，末端不限制时为`null`。它们是路线策略和计算约束，不是测量或执行反馈；规划请求预算只能缩小配置预算。切换候选须生成新的`goal_revision/request_id`，不修改旧请求或结果摘要。

参考失败交给路线适配器时保留原`request_binding/as_of/job_id/reason`，只接受与当前请求一致且不来自未来的失败。候选选择始终使用当前合格场景，不能因为旧查询已经失败而绕过输入时效。

| 字段 | 语义 |
|---|---|
| `status` | `path_found/no_path/invalid_input/unavailable`；均不是导航任务`succeeded`。 |
| `path/frame_id` | 请求坐标中的几何参考位姿`[x,y,yaw]`，检查足迹和配置的有限曲率，不证明速度、制动或实车可执行。 |
| `reference_continuity` | 可选的历史路线尾段来源与当前网格复核绑定；`origin_result/origin_as_of`保留最初来源，`verified_as_of/current_scene_binding`描述本次重新检查。`start_is_actual=false`时路径从附近参考位姿起步，`current_path_valid=false/global_reference_only=true`，须由局部轨迹从同观察真实位姿接入，不能直接执行。 |
| `input_binding` | 场景指纹／观察时间／时钟域、局部生命周期、完整关联身份，以及静态包快照和图层摘要。 |
| `geometry_source/geometry_assumed/executable` | 车体及外参来源、是否为假设；当前一律`executable=false`。 |
| `current_path_valid` | 是否通过本次输入的全部适用几何检查；不是执行许可，静态诊断也不证明在线当前可用。 |
| `prior_revision/reference_policy/conditional_reference` | 会话内历史占据修订、全局参考搜索策略及路线是否依赖条件障碍。条件层不修改测得占据；只有当前局部复核才能确认当前局部段。修订表的内容摘要参与派生快照及路线缓存身份。 |
| `local_check/current_local_path` | 前者始终诊断原静态参考；后者为已验证前缀或局部重规划，`source`区分来源。`valid`表示当前局部段有效，`complete`仍表示原全局路线通过局部检查，`executable`为false。未知／越界不能由先验空闲填充。 |
| `local_replan` | 必要时生成的局部几何子查询：目标取当前参考线的有界弧长位置，绑定父请求、原场景、关联及参考路径。子查询成功不改变全局目标或宣称任务完成；其`current_path_valid`仅对应局部子目标。 |
| `search_backend/search_attempts` | 记录实际搜索和尝试。默认使用曲率 Hybrid A*，显式研究入口另记录 Noetic 或可选 SciPy 足迹状态图；后备 Dijkstra 不能记为 A* 成功。 |
| `local_start_evidence/needs_observation` | 当前足迹的格子证据诊断，以及是否因未知／图外需要更多观测；不清空起点或用静态先验代替当前证据。 |
| `goal_evidence` | XY目标提前拒绝时记录`orientation_invariant_inner_disk`及阻挡状态；只证明端点不可行，不把未被拒绝的端点标为完整车体自由。 |
| `request_binding/result_binding` | 原请求及完整结果内容绑定；接收还核对当前在途请求、场景与地图身份。 |

调用方在串行调度循环中管理一个当前查询。新观察、新目标、取消或失效都会撤销旧结果，相同目标修订不能改变目标内容，迟到结果也不能覆盖新状态。定位重置后需要新目标修订，回放倒退使用显式 `seek` 并清空派生状态。

`generated_at_unix_s` 和处理耗时与 `as_of` 分别保存。离线按记录时钟判断年龄，旧场景不能直接用于当前在线运行。

`timing_ms` 分开记录代价图、原生搜索、可选足迹状态图、最终足迹和局部检查，`local_replan` 包含必要的子查询。`total` 只计算规划调用内部工作，不包含外部加载、最外层摘要和序列化、绘图、检测或通信，不能当在线端到端延迟。

### DWA速度提议与预测JSON

默认 `online` 和反馈仿真使用 DWA 直接选择速度，异步参考只提供空间引导。`ReferenceRuntime` 保存参考来源与上下文，复用时仍逐次检查当前网格、人物和运动反馈，并确认能从实际位置按曲率接入。参考与预测都不是运动许可。

| 字段 | 语义 |
|---|---|
| `status/control_mode` | 预测结果为`control_ready/dwa`；提议为`candidate`或`unavailable`，始终`executable=false` |
| `velocity` | 车体纵向速度与yaw角速度目标`[m/s,rad/s]`；保留真实初速及有界响应，零目标表示制动请求 |
| `input_binding.as_of/geometry_as_of` | 前者为反馈状态时刻、后者为网格观察时刻；不能给旧网格刷新时间 |
| `trajectory.points/trajectory_as_of` | 连续局部帧中的`[相对秒,x,y,yaw]`；时间原点绑定反馈，包含状态年龄传播，当前开始的预测点位于相应相对时间 |
| `reference_binding/reference_as_of` | 原空间参考及来源截止；不延长局部图、人物或反馈有效期 |
| `configuration_binding/result_binding` | 实际规划、DWA、运动、目标保持及安全配置、几何与相关实现内容绑定；结果保留完整指纹 |
| `candidate_count/valid_candidates/certification_attempts/rejections` | 有界采样数、实际通过完整检查数、排序后尝试数与拒绝原因；未复核候选不计为通过 |
| `timing_ms/compute_ms` | 输入／参考、候选生成、排序及完整认证阶段和总计算；安全进程另外测量，不能用CUDA内核耗时代替完整处理 |

DWA 先用只能拒绝的粗筛和软代价排序，再完整认证首个可行候选，独立安全另外终审一次。评分时域不截断完整停车检查。

取消、重置、目标变化、来源不匹配或过期会撤销提议。没有候选则请求停车，不自动启用旧优化器。

### 空间参考的来源与生命周期

`ReferenceRuntime` 通过一个工作进程生成 Hybrid A* 空间参考。`reference_envelope` 保存完整几何结果、原观察截止、时钟与内容摘要；`context_binding` 对应任务、目标修订、局部定位生命周期、地图资产和关联代次。

新扫描不自动撤销同一上下文中的空间参考，但 DWA 必须用当前地图、人物和反馈重新选择并认证速度。参考复用不会延长这些输入的有效期。参考到期、目标或关联改变、取消和定位重置后，旧结果不能再作为当前参考。

后台结果按查询的 epoch、上下文和源时间检查。失败和超时会退避，迟到结果不能覆盖新任务；取消或定位重置后须提交新的目标修订。

### ROS规划诊断消息

ROS 规划节点订阅 `EnvironmentGrid`、`LocalizationState` 和人物 JSON，按网格截止选择最新的过去人物，再通过统一组装器生成独立场景指纹。缺人物时明确标记 `geometry_only_ros_planning`，不复用完整 RGB 场景的指纹。

| 消息 | 内容与时间 |
|---|---|
| `/navigation/planning/goal`、`/navigation/planning/cancel` | 用 `std_msgs/String` JSON 传递目标和取消。取消精确对应 `task_id/goal_revision`。 |
| `/navigation/planning/trajectory` | 类型为 `nav_msgs/Path`，坐标属于该观察的连续局部帧。DWA 头时间为反馈状态时刻，各位姿时间为该时刻加相对预测时间；网格截止另记为 `geometry_as_of`。Z 只用于二维显示。 |
| `/navigation/planning/state` | 保存目标、配置、输入、结果及候选时序，始终为 `executable=false/task_completed=false`。这是保留原摘要的精简展示，不能代替完整结果接纳。 |

新观察触发重新控制，失效时发布空 Path。墙钟看门狗不随暂停的 ROS 时钟停转。回放时间倒退会清空历史顺序及目标，定位重置也会清空目标；数据稳定后必须明确重发目标。

该节点没有 `cmd_vel`、机器人 TF 或成功反馈发布器，命令见[ROS只规划](archive/感知导航ROS诊断命令.md#导航ros诊断)。

起点拒绝的 `start_evidence/local_start_evidence` 区分 `occupied_intersecting_footprint` 和 `occupied_only_in_margin`。它解释原占据与足迹如何相交，不能据此清格或缩小车体。

只规划可以读取缺 RGB 的 `geometry_only_causal_replay`，但几何、定位、时间和所需关联仍须有效。缺模态保持缺失，这类场景不能自动用作完整 VLM 输入。

RViz的`navigation_review`只是所选起点居中的显示坐标，所有地图／路径／扫描按明确变换摆放，并在切样本时清空；不向机器人TF链发布该坐标，也不作为算法或执行接口输入。

### 仿真控制、安全门与执行反馈

这组Python接口不替换`PathPlan`草案。安全适配器必须明确选择`simulation=True`、`shadow=True`或受控实机的`execution=True`；检查结果本身均为`executable=false`。只有实机运行时的独立CPU进程可以将通过检查的整数速度转为短时串口授权，要求实时测量、已确认车辆参数、有效目标和人工使能。

仿真会推进虚拟执行器并取得积分反馈；影子模式只观察真实输入，录包车辆不会响应建议。两者不能使用相同的完成表述。

#### 轨迹与反馈

`DwaController.command` 核对参考、请求、场景和反馈，输出本周期的速度目标 `velocity=[vx,omega]`，单位为米／秒和弧度／秒。该目标不是已实现的实际速度；预测轨迹只用于候选认证，不交给另一套轨迹跟踪器。

`source_scene_binding/trajectory_binding/trajectory_as_of` 分别记录预测所用场景、结果摘要和反馈时刻，网格观察截止单独保存。重新控制不刷新原始测量时间。

反馈的 `pose=[x,y,yaw]` 是连续局部帧中的车体位姿，`velocity=[vx,omega]` 是车体纵向速度和 yaw 角速度，单位为米／秒和弧度／秒。反馈保留 `stamp_s/clock_domain/local_identity/source/status`，缺失或失效不能补零。仿真源 `synthetic_differential_drive_plant` 表示实际积分得到的虚拟状态，不能当作实车测量。

#### 独立安全与完成判断

`LocalSafety.gate` 独立核对当前图、反馈和请求。通过后也只返回模拟速度目标。停止请求的目标为零，模型中的实际减速和延迟另行积分。新目标不能清除本地保护，接管和急停优先于轨迹，拒绝原因保留。

`GoalMonitor` 要求活动任务、目标、局部及关联生命周期和时钟一致，再用新鲜反馈连续检查位置、所需朝向、停车及保持时间。局部目标可以直接计算，有图目标须通过同观察的有效关联转入连续局部平面；重新关联会重置保持计时。

`completion_policy=goal` 可以输出导航目标的 `task_completed=true`，不表示外层就座等任务完成。`continuous` 只报告 `distance_held` 和 `completion_criteria_sustained`，持续跟随不会因靠近中间目标而结束。规划端点、bag 中的运动和缺失反馈均不构成执行成功，真实底盘状态尚未接通。

`navigation.simulation` 从当前虚拟世界与已经推进的执行器生成二维观察，规划看不到未来障碍，也不借用偏离原路线后的 bag 视角。物理碰撞按推进后的仿真足迹检查，失败和超时保留。

固定步长、理想定位和假设制动只能支持对应仿真结论，不证明实车实时性、舒适性或安全性。

### ROS影子运行契约

ROS 影子链通过[私有话题](navigation/技术实现-局部控制与安全.md#ros诊断边界)传递原观察、提议和独立复核。`TwistStamped` 只是可记录建议，禁止重映射到底盘。消息始终保持 `executable=false/task_completed=false/execution_feedback=false`。

packet 内容摘要用于核对传输和来源，不是身份认证或硬件安全证明。直接运行时采用内存和本机通道，沿用相同的非执行语义。

#### 触发与状态来源

默认 DWA 在新反馈、参考或控制周期到来时重新选择速度并发布提议。安全进程由新候选、取消等事件唤醒，普通心跳只刷新监督。控制与安全均保留原观察时间。

影子反馈来自截止当前 ROS 时间的有效算法定位历史，保留姿态、估速窗口摘要和 SLAM 生命周期。反馈可以比网格更新，但不能改写网格位姿和截止时间。缺失状态不补零，也不用原始里程计或建议速度替代。`recorded_goal_diagnostic` 只是原录包与当前观察的条件诊断。

`velocity_raw/stationary_evidence` 保存过去位姿窗口支持的近静止噪声模型。原估速与所属结构同维：规划初值为 `[vx,vy,omega]`，影子反馈为 `[vx,omega]`，线速度与角速度界分别用米／秒和弧度／秒表示。

纵向速度的负值表示倒车，路径 yaw 始终表示车体朝向。DWA提议中的 `reference_motion` 记录当前参考段的 `direction`（前进为1，倒车为-1）、从0开始的 `section`，以及段末是否需要换向停车的 `stop_at_cusp`；没有进入参考段处理的提前拒绝可以缺失此字段。它描述控制器正在跟随的空间参考，不是已执行的运动或底盘挡位反馈。

名义零速仍有运动误差包络，轨迹和独立停车检查会按预测时间扩大足迹。这不表示已经测得硬件静止，也不能把缺失或失效状态补零；有效的真实低速运动继续保留。

#### 独立复核与停车预测

安全进程独立读取原始 Grid、人物和定位，核对原提议上下文后，可以使用最新的同生命周期场景重新复核。`proposal_scene_binding/trajectory_source_scene_binding/scene_binding` 分别保留提议、轨迹和复核场景来源，不更改原规划或提议。新关联、定位重置、取消和过期不能使旧提议重新有效。

放行检查期间若到达新几何或截止前的人物消息，在预算内最多重查一次。发布前仍须检查原轨迹、提议、位姿和网格年龄。`revalidation_attempts/trajectory_as_of/remaining_trajectory_validity_s` 保存重查次数和剩余有效期。CPU 与 CUDA 只改变执行方式，不改变未知格或人物包络语义。

独立安全在假设的命令延迟阶段保持观测速度，不能把上次未执行的影子建议当作实际在途指令。之后才预测“若下达当前提议”会如何运动。停止路径通过不证明底盘已经停止。

`stopping_sweep` 保存假设停车的 `[相对秒,x,y,yaw]` 序列、坐标系、`prediction_start_s` 和原 `feedback_stamp_s`，其范围为 `scope=hypothetical_not_executed`。DWA 从反馈时刻起传播状态年龄并检查完整制动，只终审一个速度目标。安全层拒绝其他 `control_mode`，不会修改速度后再次搜索。

`response_envelope`仅在真实执行的名义检查通过、并完成响应范围检查时提供。它记录相对反馈时间的范围时长、平移与旋转界、车体坐标系中的旋转外包矩形、平移附加余量、所用物理上界，以及静态地图和人物的检查结果；没有运行该检查时为`null`。这些数据反映车辆档案中声明的上界与预测条件，不是对实车停止或人员安全的反馈。

实际初速保持原值。`velocity_filter` 保存请求速度、一次终审的原因和净空，通过时 `selected_scale=1`，拒绝时为 `null`，不能延长轨迹期限。外层预算或时效拒绝时仍输出零建议。

#### 超时与隔离测试

墙钟下检测到时钟停滞、提议断流、网格超龄或复核超周期时，输出零建议。故障注入只作用于隔离测试创建的回放与规划进程组。测试记录的是停止建议响应，`actual_stop_verified=false`。

### 导航人物与任务适配

#### 人物预测

人物来自同观察截止前的有效统一场景。`world_motion` 的速度和行优先 10×10 协方差按下节顺序解释。框可以带第 8 维检测分数，该维不参与几何计算。

预测身份为 `[tracker_session,generation,track_id]`，独立于 SLAM 身份。最后实测时间、协方差来源、未知速度和预测时域均显式保留。未补偿或未知速度不能假定静止，预测结果也不能清除当前占据图。

默认 `deterministic_world_CV` 使用世界系速度，以配置身体半径为下限，并覆盖本帧已移交的所有人物点，`uncertainty_applied=false`。原协方差保留，但不用于膨胀。未知速度保持缺失，明确使用当前占据代理处理，不宣称实测静止。

`people_check` 保存预测起止、相对起点的首次冲突区间、`hard_horizon_s/full_forecast_clear/future_conflict_duration_s` 和包络分项。通过段规划可以只硬约束近期冲突，对远期冲突计入代价；完整终点停车和独立停车检查不使用该截断。

轨迹检查和独立安全门都使用带时间的车体运动与人物包络。缺失人物时按配置拒绝或标明 `geometry_only`，有效空轨迹另行表述。速度界、加速度界、匀速与停车模型都是开发假设，不能保证实际行人或底盘一定符合模型。

#### 动态碰撞视图

`GridSnapshot.metadata.person_objects` 表示本帧已从背景占据更新中分离的可靠人物点。存在该字段时，基础 `occupancy` 和 `navigation_occupancy` 只描述背景及未分离的障碍，不能单独用于当前接触检查。`navigation_geometry()` 默认叠加本帧人物圆；仅显式逐人接管的预测消费者可请求背景视图。

记录采用 `method=tracked_person_circles`，`stamp_s` 必须等于地图原测量时刻，`local_identity=[session_id,generation,frame_id]` 必须等于地图身份，`people_source` 为参与分点的原人物输入指纹。`objects` 至多128项，每项含 `identity=[tracker_session,generation,track_id]`、局部世界系 `xy`（米）、`radius_m`（米）和已归属点数 `points`。圆半径覆盖本帧归属点，不表示完整人体真值。

导航逐项核对来源、身份及位置。匹配项交由带时间的圆检查，未知速度仍使用当前占据代理；不匹配项保留为静态圆障碍。当前接触始终检查背景加本帧圆，普通占据和原有未知不被清除，测量时间不因预测刷新。`dynamic_geometry` 记录接管数、回退圆及原场景和人物来源，`people_check.spatial_margin_m` 保留实际空间余量。

`EnvironmentGrid.person_background_free` 继续用于异步输入等未完成逐人移交的情况，是可选逐格 bool 来源标记，表示纯人物占据与历史自由依据相交。混有普通障碍或背景未知的格子不标记，`dynamic_navigation` 声明该层时，缺层必须拒绝。这个兼容分支要求来源匹配且所有人物速度有效，使用 `projection_margin_m=resolution/√2` 补偿栅格面积，不改写输入占据或摘要。

#### 任务票据

`TaskPolicy.observe` 票据对应任务、原观察指纹、时钟、局部生命周期，以及该次输入的 PID 映射和候选集。`respond` 只接纳最新、未使用且未过期的票据，并保留原响应。调用方不能重建或猜测 PID 映射。

T1 的 `request.social` 包含 `source/stamp_s/clock_domain/local_identity/groups/binding`，群组成员使用稳定跟踪身份，不使用当前显示 PID。过期后不再应用群组关系，空间按当前人物重新计算；群组关系只影响软代价。

T2 目标请求携带 `local_identity/clock_domain/valid_until_s` 和连续完成策略。各规划、控制和安全入口核对生命周期与期限，先按发送时冻结的 history 验证响应，再用当前场景核对身份。响应接纳期限与身份保持期分别处理。

遮挡不会刷新最后视觉确认时间，轨迹断流、丢失或过期时必须撤销运动。等待新响应期间保留上一次接纳票据的来源，不能把新输入冒充新决策。

T3 只接收同观察、连续局部坐标中的候选，并保留候选对应关系、ID 和前进、倒退或等待意图。每次仍由规划核验几何。冻结的传感器坐标须由上游使用原观察位姿转换，不能直接当作局部世界坐标。该 API 不代替就座阶段状态机，也未接入实际模型服务或真实运动。

## 检测消息与协方差

`People.header` 保存采集时间和轨迹坐标系，原传感器检测另用 `detection_frame_id`。`has_localization/has_velocity/has_pose_age/has_rgb` 明确哪些字段可用，默认零值不能代替缺失。

`TrackState` 协方差是行优先 10×10 矩阵，顺序为 `x,y,z,dx,dy,dz,yaw,vx,vy,vz`，单位对应米、弧度及其导数。预测保留最后真实观测时间，confirmed 只说明轨迹已确认，不表示当前又观测到。空轨迹和 valid 状态都不能证明自由空间或可行驶。

可选 `detection_index` 只为真实观测轨迹引用同次 `detections` 的零起始下标，预测为 `null`，不是跨帧身份。`tracking_policy` 保存匹配指标与执行后端。

保存结果重新跟踪会创建新会话，原观察与定位对应关系保留，旧二维关联和决策标签不会自动转移到新轨迹。

类型字段以 [contracts.py](../interfaces/contracts.py)和实际 ROS 消息定义为准，本文维护跨模块语义，不复制全部字段定义。
