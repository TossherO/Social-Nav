# 接口约定

[contracts.py](../interfaces/contracts.py)提供Python类型记录；检测跟踪核心已有`to_snapshot`转换，其余跨域仍待接入。
它本身不是ROS消息、序列化协议、调度器或安全实现。dataclass不校验数值、时间、坐标变换和响应Schema。
现有VLM的v/dt/ts/e/o/d及object不变，不把这些草案字段偷偷塞进HTTP输入。

[环境地图与场景表示](perception/技术实现-环境地图与场景表示.md)已接入显式启用的局部环境与先验关联，见[可选环境状态](#可选环境状态与地图关联)；另有[静态环境与离线视觉记忆](perception/技术实现-环境地图与场景表示.md#静态环境与视觉记忆)，完整决策适配仍待实现。下面原有定位段落描述默认任务，环境选项的差异单独说明。

## 单位、身份与缺失值

所有模块应明确米、弧度、秒，观察ID、坐标系、时钟域、源序列及版本。
缺位姿/速度/协方差为None，不当作零或单位位姿。空地图不表示自由空间。
TrackIdentity包含源轨迹与生命周期；模型窗口短PID不是长期人物身份。

## 数据方向与所有权

- 感知 → 决策/导航：`PerceptionSnapshot`、`PersonTrack`、`PoseEstimate`、`MapReference`。
- agent → VLM/导航：`AgentIntent`任务模式、描述/目标及模式版本，非底盘指令。
- VLM → 导航/agent：`VLMResultEnvelope`绑定观察、请求、映射/模式/候选版本。
- 规划 → 控制：`PathPlan`；控制的动力学轨迹与底盘指令协议在车辆参数明确后再定义。
- 导航 → agent：`NavigationFeedback`真实执行/停止/完成/失败，不能模拟成功。

### T3目标点选择（设计）

调用方提供自然语言指令、场景观察和候选目标点，当前用于倒退让行与就座；复用`GOAL`的`p,s`输出，`p`是原始候选ID。候选记录坐标系、位置、必要朝向、可用到达方式、几何可行性与集合版本；“车后一个点”本身不等于倒车约束。

结果接收绑定原指令／模式、观察与候选集合，几何和运动约束由本地导航复核。`n/u`时`p=-1`，不作为坐标或直接运动指令；等待若可供选择，应是显式候选。详细任务定义由[系统方案](系统方案.md#53-t3目标点选择与无解未知设计未接入当前客户端)维护。

上述是待接入的T3输入设计，当前HTTP客户端仍只实现REL；本次不改变现有类型草案或T1字段白名单，静态GOAL Schema不证明目标点选择管线已实现。

## 接入与校验边界

未来适配器需独立验证响应、输入版本、源观测年龄和TTL，拒绝迟到/旧映射结果。
RGB资产目前只是引用，逐相机时间/标定/同步容差与ROS传输需在真实接入时扩展。
PersonTrack新增confirmed/score/covariance_order；感知快照明确health/reason。
Header记录timestamp_source，定位头保留定位测量时间，不伪装成点云采集时间。
检测跟踪协方差顺序见下方消息说明，未知速度仍为None。
缺可靠定位时只有传感器坐标检测，不输出伪造的世界轨迹。
ROS 1 检测消息位于 `perception/detection_tracking/ros/msg`；定位消息位于 `perception/mapping_localization/ros/msg`。消息中的采集时间、坐标系和缺失值有效位与共享类型对应。
接口版本升级与原实现分开测试；不可把类型文件存在当作三域集成已完成。

## 定位状态与连续位姿

选定的 ROLL＋FAST-LIO、无图模式FAST-LIO或PIN-SLAM后端输出 `/localization/state`，类型为
[`social_nav_localization/LocalizationState`](../perception/mapping_localization/ros/msg/LocalizationState.msg)。
ROS包名和消息类型保留已有身份，源码位于`perception/mapping_localization/ros/`。
消息与对应扫描结束采集时间绑定，包含位姿、健康、来源、会话、重初始化代次和配准状态，
无需把无时间戳的旧 String 状态与任意最新位姿拼接。

### 坐标与有效性

- `header.frame_id=odom`、`child_frame_id=rslidar`，`pose`将雷达坐标变换到前端连续局部世界。
  ROLL与无图FAST-LIO的`odom`来自FAST-LIO前端，PIN的`odom`累计隐式地图配准的相邻有效位姿增量；
  各后端均不使用编码器里程计作为可靠定位来源。
- `map_pose`与 `map_frame=map`单独表达当前算法的地图位姿；回环更改 `map_revision`，
  不让地图跳变进入人物速度估计。原前端 `lidar`与本配置 `rslidar`明确对应同一物理传感器。
- 无图模式只提供连续局部位姿，`has_map_pose=false`、`map_frame`为空，不发布`map → odom`；
  不得将消息中未启用的`map_pose`默认值当作有效地图位姿。建图和有图定位保留上述地图修正语义。
- `VALID`要求当前地图匹配有效且误差有限；FAST-LIO无图模式检查当前局部地图匹配的有效点、
  内点比例、残差与位姿有限性，初始化和失败均输出`INVALID`，预测本身不作为有效定位。
  这些判据不等于完整可观测性分析、外部精度或安全保证。
  `source`区分`roll_fast_lio`、`fast_lio`与`pin_slam`，使用定位结果的模块须显式选择来源。
  切换定位来源应重启会话，继续执行原有失效与身份隔离规则；来源标记不能替代实际配准健康。
  新进程使用新 `session_id`；ROLL 已接受的 RViz 重初始化增加 `generation`。
  ROLL人工初值经`/initialpose`提交，须在已加载地图坐标系中；
  `/roll/initial_pose_accepted`使用`geometry_msgs/PoseWithCovarianceStamped`确认规范化后的初值，
  头部时间属于选点请求，不能当作扫描观察时间或有效定位。初始化等待期间不启动前端、没有定位输出，
  仅声明地图的显示参考，不发布车体定位TF；
  初值在处理新扫描时才进入新的`generation`，后续配准通过才能输出`VALID`。
  PIN 首版不接 RViz 重初始化，改起点或时间回退须重新启动会话，固定地图定位首帧也须真实配准。
- FAST-LIO自适应初始化使用锁存的`/fast_lio/initial_lidar_pose`（`geometry_msgs/PoseStamped`）向ROLL传递首个扫描在前端内部`camera_init`系中的雷达位姿，时间为该扫描结束时间，坐标与`/OdometryLidar`一致。它是起点绑定参考，不是有效定位输出或TF；ROLL用`首帧地图初值 × 首帧局部位姿逆 × 当前局部位姿`传播首次初值，避免将初始化后的车辆位置误当首帧。初始化期间不输出有效世界轨迹，内部重力对齐也是估计，不能当作已标定的水平导航系。
- 未知协方差使用 `has_covariance=false`。配准误差和内点比例只作为诊断，不能当外部定位精度真值。
  TF只在有效状态发布，使用TF的模块仍须检查其时效；旧TF的存在不证明当前定位有效。

感知实时显示扫描使用同观测定位或检测结果的显式位姿，失效／超时清空；显示专用点云不作为新的定位或算法输入。缺定位的检测仅在显式传感器视图展示，不借旧TF放入世界坐标。结果回看合并原有定位和检测观测时刻，仍保留缺失位姿，不用未来或邻帧位姿补齐。

### 定位失效时的处理

检测只接受与观察同一时钟、采集时刻不晚于观察且未过期的定位；有界等待及年龄阈值由 [inference.json](../perception/detection_tracking/configs/inference.json)维护，节点处理见 [检测与跟踪](perception/技术实现-检测与跟踪推理.md#定位与时间)。

失败的当前估计不回退到旧有效位姿。缺定位、LOST、非法位姿或断流时，世界跟踪降级或失效；有可用点云时仍可进行传感器坐标检测。会话/重初始化变化隔离旧位姿并重置人物生命周期，时间回退由回放序列重置处理。未确认车体外参时，不输出假车体定位。

建图和有图定位的唯一TF链为`map → odom → rslidar`，无图定位只发布`odom → rslidar`，
由本次选定的后端独占；不得同时启动两个后端发布这些变换。
ROLL 中 FAST-LIO 的旧 TF 和旧车体偏移 TF 关闭。未来接入 `base_link` 需提供经过确认的固定外参。

定位/检测消息已用于实机 bag 离线回放，失效与生命周期边界有 CPU 测试；
真实遮挡下的 LOST/恢复与现场时钟仍待验证，交互初始化操作及验证范围由实机感知手册和本机记录维护。

## 可选环境状态与地图关联

启用`--environment`时，估计器分别发布内部`/localization/frontend_state`和`/localization/map_state`，由唯一`localization_context`发布公共`/localization/state`及TF。消息类型仍是`LocalizationState`；source维持显式选择的FAST-LIO／ROLL来源，局部pose来自前端。

- 建图与无图任务的健康由局部配准决定；固定地图定位默认仍要求先验关联，显式允许`--allow-local-only`时，先验匹配失效不把有效局部pose变成失效。真实局部失效仍隔离世界几何和人物轨迹。
- 公共`session_id/generation`绑定前端连续世界生命周期，地图重新关联使用独立代次，故地图匹配变化不重置odom人物轨迹。默认未启用环境的任务继续沿用原有代次语义。
- `/localization/map_association`类型为`social_nav_localization/MapAssociation`，区分当前观察时间与实际配准测量时间，记录资产指纹、后端修正revision和独立关联代次；重新接受关联时递增，不能用后端generation代替。失效后须收集新的连续匹配。历史修正只在年龄预算内传播；候选、无效或过期的关联不产生有效map_pose和新地图TF。
- 可选覆盖多边形绑定实际地图资产及坐标帧，`coverage_status`区分未配置、无法判断、有覆盖和覆盖外，另保留覆盖指纹。覆盖同时控制ROLL地图匹配修正与公共先验关联，以最后可信修正和当前局部位姿判断离图，返图须新鲜且连续一致的配准；不声明地面、自由空间或可达性，覆盖外局部健康有效时维持`LOCAL_ONLY`。
- 地图修正不进入局部速度估计。公共消息的配准诊断来自局部前端；地图匹配有效性与来源由独立关联消息表达，不把局部误差称为全局定位精度。
- 环境Grid的`header`和`snapshot_id`绑定各数组：occupancy为`-1/0/100`，高度与距离缺失为NaN，观测掩码／时间独立保留；字段尺寸与`MapMetaData`一致。快照中的地面支持或到障碍距离不等于完整车体通过性。
- 环境ROS查询要求已缓存的`snapshot_id`与正确坐标，淘汰、越界和未知分别处理。指定历史快照仅说明该时刻，不免除在线消费者的健康、时效及地图关联检查。

`EnvironmentGrid.metadata_json`保留原快照元数据，须与消息头、身份和尺寸一致；各数组按声明类型解码。ROS消息位于`perception/environment/ros/`，Python数组查询位于`perception/environment/context.py`。

显式`--scene`发布独立`perception_scene`输入：`observation_id/as_of/clock_domain`绑定局部定位、几何摘要、RGB引用、人物结果、可选先验和有界记忆。几何是时间锚点，各模态保留原始观察时间，不能使用截止后的数据或将旧预测称为当前实测。人物JSON新增`localization_binding`记录所用定位会话／代次／帧／来源，与人物自身`session_id/generation`分开；缺少这项绑定的历史JSON不能直接当作当前统一场景人物。

场景指纹绑定元数据、实际图层和RGB像素；`query`请求指定缓存的场景ID，可再指定指纹。`get_scene/get_rgb/query_geometry/crop_map`返回同一场景事实，未知保持未知。当前运行就绪由`state/status.current`结合最新定位和年龄判断；历史快照不覆盖更新的失效或局部重置。场景JSONL保存引用，只有最后一帧另存可独立复现的数组和图像。

显式`--prior-map`加载与定位地图同源的静态环境包。可选`prior_geometry`绑定原生`map`系裁剪数组、包来源、完整地图变换、独立关联代次和历史观察引用，时域为`offline_final_prior`，与当前局部`geometry`分开。`get_prior/query_prior_geometry/crop_prior_map`读取同一场景的先验；关联无效时无对齐数组，既不借用旧变换，也不改局部观察。`state/status.prior.ready`根据最新定位／关联及时效决定当前可用性；返回的历史空闲不作为当前自由空间或导航通过性。末帧有效先验另存`prior.npz`；中性视图显式补接旧场景时生成新指纹，不重写原绑定。

统一场景由`perception/environment/scene.py`组装，供决策数据适配及只读查询；现有`PerceptionSnapshot`记录和VLM HTTP任务协议未自动替换，不把几何查询返回当作导航执行反馈。

离线环境包将`layers.npz`快照身份和内容摘要与`observations.sqlite`的来源绑定登记于`manifest.yaml`。`STATIC_ENDPOINT_CANDIDATES`只表达最终地图端点及地面支持，`free_space_supported=false`；有同源扫描记录时，`STATIC_SCAN_OBSERVED`用实际射线生成高度覆盖／空闲，未绑定扫描单独计数。缺失的每格原始观测时间保留NaN，导出时间不替代观察时间。无图包标记为`local_session_memory`，末次滚动快照不表达完整行程地图。

视觉记录分别保留`image_stamp_ns`、bag记录时间`receipt_ns`、`pose_stamp_s`及`pose_age_s`，位姿只使用不晚于图像的有效记录；最终地图修正保留`final_keyframe`及原局部位姿。相机矩阵只在显式同安装标定下派生，表达对应位姿时刻的光学相机位姿。`time_scope`区分离线最终先验、局部历史和`causal_observation`，不把最终优化结果倒灌为同一次建图的在线输入。历史`observed_transition`与人工地点不代表导航验证关系。

实时记忆的`memory_id`绑定索引，查询还须指定`session_id/generation/frame/as_of`。局部重置产生新的坐标生命周期，重新关联地图只更新独立关联。图像在ROS中没有bag记录时间，因此`receipt_ns=null`，回放索引靠原头时间及内容摘要查原bag；真实输入的精选RGB以无损PNG嵌入同一索引。图像读取、处理和队列丢弃不混入几何计数，跨定位失效不建立经过关系。

基础决策适配使用独立`environment_context`，统一场景消费使用`environment_scene_context`，保留场景原指纹、人物身份映射与观察／预测状态。两者均拒绝未来／过期输入、不同局部生命周期及离线最终先验作为当前局部观察。中性视图、只读agent工具不改变现有REL协议或人工标签绑定，不证明已接通模型、agent循环或导航执行。

## 检测消息与协方差

`People.header` 保留采集时间及轨迹坐标系，传感器检测使用独立的 `detection_frame_id`。`has_localization/has_velocity/has_pose_age/has_rgb` 区分缺失与零。

`TrackState` 协方差为行优先 10×10，顺序为 `x,y,z,dx,dy,dz,yaw,vx,vy,vz`，单位包含米、弧度及其导数。预测保留最后真实观测时间；confirmed 不等于当前观测到。空轨迹或 valid 状态均不证明自由空间或可行驶。

类型字段以 [contracts.py](../interfaces/contracts.py)和实际 ROS 消息定义为准，本文维护跨模块语义，不复制全部字段定义。
