# 数据与评测

本文维护数据来源、划分、标注、指标与验收组织，包含可选的公开数据验证路线。研究任务及冻结VLM原则见[系统方案](../系统方案.md)，资源定位见[开发指南](../开发指南.md)。JRDB冻结窗口已用于开发与延迟对照，原始数据仅在相应生成／审核任务需要时准备；字段与工具见[JRDB参考](JRDB参考.md)。数据源替换不自动继承旧标签或盲测资格。

当前新增数据与工具优先T1（暂不含排队）和T2。独立[决策任务标注](../decision/决策任务标注.md)已提供基础本机／HTTP操作与导出，真实Windows试用、小批人工标注及推理接入待完成；T2仅导出固定事实，不伪造五状态历史金标准。下文排队、T3及对应公开数据路线保留作后续参考，不作为本轮采集、标注或验收要求；现有JRDB工具仍按原协议解释历史数据。

## 1. 验证目标与范围

依次回答：可观测真值能否可靠标出；冻结模型能否在合理输入下作出正确决策；结构化接口能否稳定运行；每2秒一次的远程决策能否在连续公开视频回放中保持时效。

公开阶段可验证语义、输入输出设计和回放状态，不证明轮椅碰撞安全、完整500m成功率或最终停靠精度。语义质量、接口合法率和延迟是三条独立结果线，不能相互替代。

当前工具分属感知和决策模块。检测/定位已有实机bag离线链路，但连续社会状态回放、P1决策输入、行为价值及导航闭环仍需各自验收；实际实现总览见根README。

### 1.1 验证问题与最小交付

| 问题 | 所需证据 | 不足以回答该问题的结果 |
|---|---|---|
| 当前观察是否足以理解关系？ | 同输入人工一致性、未知比例、分歧案例 | 全景原标注与前视输出看起来接近 |
| 渲染/Prompt是否有效？ | 冻结模型、隔离事件上的配对消融 | 多轮调同一批24窗口后选最好成绩 |
| 输出能否被其他模块可靠使用？ | 完整流、Schema、PID/结构校验与失败日志 | HTTP 200或JSON可解析 |
| 0.5Hz远程语义是否可用？ | 因果连续回放、信息年龄、忙丢弃、状态失效 | 串行平均延迟小于2s |
| 语义是否有导航价值？ | 相同几何/感知条件下的行为回放或后续受控实机对照 | 高群组F1或单段静态图预测 |

最小交付包含：根来源划分清单、版本化输入协议、人工审核规约与金标准、冻结配置、指标定义、全请求日志及代表性失效案例。前三项可在完全不采集实机数据的条件下完成；不以“必须先训练模型”为前提。

“公开可获取”不等于许可一致或可随意再分发。JRDB基础数据和同源扩展不是独立测试集；不能把同一录像的新标签当作新的独立来源。新增数据先核验许可证、版本、实体关联和下载可用性，再加入。

已有SUB目录 `data/public/socialnav_sub_proxy_smoke`：版本 `7810d71a0da1c56f99e0e17439fab118d150a0a3`，场景 `101_Spot_1_155`，31文件、11,053,203字节；固定版本索引含58场景，不是58个问题。当前只完成下载/文件审计，没有原生QA成绩，不加载未知pickle。

数据默认通过`data/datasets`中的JRDB、SUB和冻结输入链接访问，原目录与字节保留。链接重定位不产生新数据版本，也不能改变split或绕过源hash；检测器使用同一入口中的原始/预处理资源。入口检查和迁移方法见[开发指南](../开发指南.md#数据入口与迁移)。

### 2.1 SocialNav-SUB的具体使用方式

已核验场景有51个有效问题、4个问答标注ID，轨迹文件却有7条轨迹；原生问答要使用 `tracking_id_to_obj_label_filepath` 的映射，不能把所有轨迹都当被提问对象。部分答案文件有空键，应按合法问题定义过滤。

CSV字段包括sample_name、human_answers_filepath、human_raw_answers_filepath、n_people_filepath、human_tracking_filepath、tracking_id_to_obj_label_filepath、odometry_filepath、raw_img_filepaths和bev_img_filepaths。下载器保留真实文件与metadata，但不反序列化未经信任的.pkl。

保留原生空间、运动、阻挡与机器人—行人交互问题，先评估冻结VLM的基础社会理解。人工答案按分布保存，不能总取第一项；原生PA/CWPA按[官方代码](https://github.com/LARG/SocialNavSUB)和[论文](https://proceedings.mlr.press/v305/munje25a.html)实现，不能换成T1群组合法率。

SUB可以承担两种角色，选定后记录在根来源清单：

- 独立外测：不根据其结果调Prompt，并排除与开发源无法排除的同源录像。
- 开发/诊断源：可补标派生问题与调整输入，但该根录像及同源片段不再算盲测。

由于当前模型冻结，不再沿用旧文档的SUB-T参数训练计划。即使不用它训练参数，也要防止Prompt开发污染外测。若无法追溯与SCAND/SNEI的家族关系，保守按同源处理，而非宣称独立泛化。

原生10帧、全跨度稀疏三帧和严格最后1秒三帧是不同观察协议。裁掉开头后，“起始位置”“全程变化”题不能沿用原答案；需保留原问题观察跨度或重新补标。人的社会意见分歧不自动等于T1的证据不足，两个任务的unknown定义独立。

## 3. 先划分，后生成与调Prompt

按JRDB完整序列及重复地点、ScanNet物理房间及重复扫描、SUB/SCAND/SNEI原始bag或根录像分组。所有派生窗口、描述、辅助题和标签继承同一split。相邻帧不随机分割。

VLM验证使用“开发/验证/盲测”，不需要VLM训练集；若保留数据集原train称谓，说明它是原发布分区，不代表VLM参数训练。Prompt、图像布局、阈值和运行时均只能依据开发/验证集选择，盲测不参与修改。

如果随后训练或选择检测器，其训练/验证数据、checkpoint和选择标准需要单独登记；不能在JRDB盲测序列上微调检测器再报告端到端泛化。CODa/Wheelchair已有检测训练资源不必加入当前纯公开P0测试；P1若使用非公开训练资源，需披露其来源，不能再称为“所有训练均只用公开数据”。检测器身份在P1消融前冻结，同一感知输出用于各决策方法。

当前clark、gates、memorial的24个窗口已用于多轮开发，不能重新命名为盲测。先在剩余序列按地点建立独立清单；不能在看模型结果后筛选容易样本。SUB若用于调Prompt，该根录像及无法排除的同源SCAND/SNEI片段不能算外测。

### 3.1 划分记录与冻结规则

每条样本记录dataset、release/revision、root_recording、location_family、sequence/room、时间区间、split、任务及派生协议。相同地点的重复采集优先归到同一组；确实要测试同地不同日时，单列协议，不混称跨场景泛化。ScanRefer继承ScanNet房间划分，RSTPReid先遵循官方身份划分。

先写根级清单，再选择事件/窗口，最后生成模型输入、描述和人工标签。辅助题、同一事件的不同图像布局、自然/人工干预版本都继承根split。开发用于规则和Prompt探索，验证用于最终配置选择，盲测只运行冻结版本；在盲测后调整的版本需要新的未使用留出集。

划分清单可采用以下**设计字段**，当前没有自动split生成器：

```json
{
  "dataset": "JRDB-2022-train",
  "root_recording": "<原始序列>",
  "location_family": "<经人工核对的地点家族>",
  "split": "development",
  "tasks": ["REL"],
  "provenance": "<版本、许可、根来源及划分理由>"
}
```

split冻结不等于排除了大模型预训练见过公开数据；本项目只能保证不使用留出标签进行自己的Prompt/界面开发，应如实说明预训练污染不可完全审计。

### 3.2 感知和几何层级

| 层级 | 定义 | 可验证与限制 |
|---|---|---|
| P0 | 标注2D/3D框与身份关联，仅几何进入输入 | 语义感知上界；身份/插值可能依赖全序列，不是完整因果系统 |
| P1 | 实际检测＋在线关联，仅使用过去/当前观测 | 端到端错误下的语义与状态稳定性；不得用隐藏ID事后修好输入 |
| P1中间诊断 | 标注检测框＋在线关联 | 分离检测和关联误差；不能当最终P1成绩 |
| G0 | 完整重建和离线优化位姿生成候选 | T3的oracle几何上界，可能含未来证据 |
| G1 | 只用历史/当前RGB-D构建几何 | 更接近在线；若位姿仍为全序列优化，另标oracle定位 |

因果选帧只证明没有读未来图，不证明源标注、轨迹、定位都因果。真正G1需过去前缀定位/重建，真正P1需在线关联；所有报告写清这些层级。

P1输出契约见[接口约定](../接口约定.md)，ROS检测操作见[检测与跟踪](../perception/技术实现-检测与跟踪推理.md)。未来决策适配器读取真实感知快照并生成中性窗口；JRDB prepare仍是P0，不自动启用检测器，也不宣称完成JRDB P1评测。行为评测需等待规划、控制和安全实现。

## 4. T1：先验证可观测社会关系

### 4.1 输入与真值

先用P0：标注2D/3D框和关联，只保留几何；三帧前视RGB＋BEV，中性PID，默认无全景和真值边。原始标签独立保存，禁止将social_group、social_activity、H-interaction或动作答案写进图、Prompt或动态字段。

人工先只看模型可见的同一输入，标注成员、w/t/q/p/o/u、结构k和归属未知。标注人员可以另看原视频解释分歧，但不能把宽视场/未来证据当成短窗口里可观测的答案。保留输入指纹、标注者、时间、来源和分歧理由。

补标使用当前代码新生成的带源审计bundle；`reviewed/compare`会检查输入指纹与渲染源码版本。旧运输包可以原样测速，但没有源manifest就不能重建审核图，版本不符也不能绕过检查直接复用旧标签。具体校验与两类指纹见[JRDB复现链](JRDB参考.md#52-输入标签与指纹隔离)。

同组ID可作为成员候选；不能直接充当完整T1真值。HHI是两两交互，可能跨组，不能取连通分量造群组。排队或拍照结构没有可靠证据时标未知，而不是靠站位、手机或动作关键词自动生成。

建议先建立事件索引，再按事件采样，而非均匀取每N帧后直接补标。候选可用原动作/群组/HHI检索，但最终由人工确认；保留随机抽取的独行、近距离陌生人、重叠框、分组边界和证据不足负例，避免只收容易群组。

人工规约遵循[整体方案的T1定义](../系统方案.md)：成员已知而活动未知输出组内r=u；成员归属未知放顶层u；确认独行者省略；排队/拍照结构可见才k=1。如果裁剪让群组只剩一个可见成员，不从视野外隐藏成员补成两人组。

用于正式评分的第一遍标注应尽量不看模型预测和native答案。原视频、全景或未来用于来源解释时另记“上下文身份/原生关系”，不能覆盖“模型输入可判关系”。多种布局改变可读性时，标签也应审核观察协议，不能仅复用最后一帧的native group。

### 4.2 最小人工投入

第一轮建议50–100个开发窗口验证标签规约与可读性，覆盖移动/静止相机、远近、人群密度、遮挡和独行负例；不要只选清晰成对同行。若q/p独立事件不足，明确“未验证该类”，继续找合适公开视频，不能复制少数事件扩充样本数量。

规约稳定后建立约200–400个隔离窗口和5–10段20–60秒连续片段，具体规模由独立事件覆盖决定。盲测关键难例双人标注并仲裁，报告一致性；同序列窗口数量不作为独立样本数量。

工具已提供指纹绑定的draft模板和人工真值预览，**尚未完成这批补标**。`review_status=reviewed`且reviewer、reviewed_at、label_provenance齐全才能导出gold；改标签字段必须由真正人工审核支持，不由脚本代填“已审核”。

### 4.3 人工质量控制与工作量

先用约30个覆盖不同难度的窗口试标，修正歧义规约，再扩至50–100个开发窗口。关键类按独立事件计数：如果所有拍照窗口来自同一事件，应写“1个事件”，不能写数十个独立拍照样本。

双人独立标注后进行仲裁，保留原答案和分歧原因；成员用pairwise一致性，关系在共同可判成员上看一致性/混淆，q/p结构单列，unknown看双方可观测性判断。重复由同一个人标只能估计标注内一致性，不能称双人一致性。

不直接沿用旧版0.85/0.90等训练时期质量门槛。试标后根据分歧类型、unknown覆盖和任务风险确定准入条件，并在盲测前冻结。若人体动作在图中根本不可辨，先改输入或标未知，不要求标注者强猜关系。

估算工时按实际试标记录：300窗口、每人每窗口30–60s、双人审核，纯判断约5–10人时；还不含事件筛选、规约修订、角色核验、仲裁和文件管理。此值只是预算示例，实际复杂窗口可能显著更慢。冻结模型路线不再要求先制作数千条SFT样本。

标签侧保留事件ID、观察协议、输入指纹、reviewer、reviewed_at、label_provenance、分歧和仲裁说明。后三类扩展元数据由标注文件单独管理，不加入当前模型字段白名单。校验脚本可检查格式，但不能证明某个字符串“reviewed”背后真的完成了人工工作。

### 4.4 小预算消融

以当前对象输出、三帧RGB＋BEV为基线；一次只改一个因素：

- 时序：单帧与三帧，观察跨度变更需重新评估可观测标签。
- 模态：RGB-only、几何-only和联合，识别坐标捷径和视觉贡献。
- 布局：必要的人物裁剪、更紧凑BEV、不同分辨率；不加入真值颜色。
- Prompt：完整规约与精简规约；保留未知、排队顺序和拍照角色约束。
- 传输/运行时：图片编码、固定前缀、可选MTP；语义和延迟分开验。

先用少量不同事件淘汰不合适方案，再固定一版进行隔离评测；不全组合穷举、不反复重跑同样24窗口。保留所有失败，不以格式修复或隐藏重试提高合法率。

比较三帧与单帧时分别报告输入可判覆盖和正确率；比较RGB-only与BEV-only时不要给后者额外社会真值。人框裁剪、图像压缩和历史降采样都可能改变动作证据，必须同时检查结构类与unknown，而不是只看输出短了多少token。

对照包括距离编组、可靠运动条件下的方向/速度编组、冻结VLM完整输入与关键消融。几何基线使用相同P0/P1层级，不为它额外提供源语义；没有运动补偿则不实现伪速度基线。所有算法比较使用同一独立事件集、相同失败口径。

## 5. T2：外观选择与连续身份复核

JRDB源身份只用于隐藏真值关联；模型输入PID是当前轨迹的局部编号，不告诉它“这个编号就是目标”。由人工从初始可见图生成外观描述，并标出可见确认、短遮挡可保持、歧义、丢失和尚未找到。

先静态验证描述匹配，再回放自然遮挡与交叉。在线状态只来自过去已接受的结果；不把全轨迹ID或未来再次出现的事实提前注入历史。人工模拟的LAST_TARGET错误和ID交换单列，不当作自然失败率。

可用RSTPReid做图文匹配辅助诊断，但其原生检索成绩不证明当前多人物场景的状态判断或重捕获。T2固定事实标注与共享视觉窗口已提供，描述／真实历史到推理请求的正式适配及连续回放尚待实现，不能把当前T1测速称为联合任务成绩。

### 5.1 可完全基于公开数据构造的T2样本

1. 从JRDB初始可见图中选目标物理身份，人工写衣着/随身物等描述；描述不包含PID、源ID、未来外观和不可见细节。
2. 抽取描述成立、多人相似、目标不在场等静态窗口，先诊断匹配可读性；RSTPReid可补充图文匹配，但保留其原生身份划分。
3. 从真实序列选交叉、转弯、遮挡、重现和出视野事件；隐藏源ID只用于确定物理目标和错误归因。
4. 按时间回放，LAST_TARGET来自本方法之前已接受的输出，不能每帧用gold重置历史。必要时输出T1/T2联合REL_FOLLOW。
5. 另做明确标记的干预实验：错误历史身份、过期历史、错误关联等。修改输入时同步检查图像PID、几何表、轨迹及历史，不产生自相矛盾的样本。

纯PID置换且所有证据同步变化只是编号不变性测试，不是身份切换；只改标签或历史、不改相应几何/身份会变成数据损坏，不能据此声称系统抗跟踪错误。

### 5.2 五状态金标准与连续回放

物理目标固定不变；v/o/a/l/n需结合当前可见证据、可靠跟踪连续性与该方法的因果历史审核。v是可见确认；o需要过去确认和当前短遮挡保持依据；a是合理候选歧义；l是曾确认后丢失；n是从未确认且当前没有合理匹配。a/l/n的id=-1。

由于不同方法的历史接受状态不同，n/l等状态不能一律按oracle历史套同一逐帧标签。保留固定的目标物理ID与可见性标签，状态标签由版本化规约和真实历史导出/审核；报告物理身份正确性和状态正确性两条结果。

遮挡保持阈值、确认次数和重捕获规则由开发回放确定，2秒调用下必须检查确认时间；不能原样使用旧版每1秒判断的状态参数。诊断静态Top-1不能替代完整连续身份复核。

## 6. T3：自然语言目标点选择

统一输入为自然语言指令、场景观察与给定候选目标点，输出沿用GOAL的`p,s`。先用固定的、可追溯的候选集合评测VLM选择，候选可人工提供，不以完成自动生成器为前提；自动生成器另测覆盖率。候选保持同一坐标系、必要朝向及到达方式，先按明确的足迹与运动规则核对可用性，不给VLM提供隐藏的首选答案。

| 场景 | 需要的观察与指令 | 人工审核重点 |
|---|---|---|
| 狭窄通道倒退让行 | 连续人物／自车观察、前后可观测空间与候选；例如“请通过通道，优先礼让迎面行人” | 当前是否适合继续、等待或后撤，哪些后撤点能释放会车空间；朝向和倒车可行性不能由车后XY点代替 |
| 就座 | 目标桌边等场景的RGB／几何、就座指令与候选 | 哪些轮椅停靠位置满足指令、空位、朝向和进出通路，不把桌面／椅面中心当目标 |

让行数据从确有对应观察的连续bag或可追溯片段选择，不因某包含行人就认定覆盖迎面会车。ScanNet仅作为就座候选来源之一，接受许可后按需使用；静态重建不能替代行人运动与后方空间证据。完整重建／全序列优化位姿标为oracle几何或定位，与因果输入分开报告。T3专用管线及闭环执行尚未实现。

### 6.1 数据生成与人工审核

每个样本绑定指令、原始观察时刻、候选集合和来源划分。自然语言不包含答案编号，不用“最佳退让点”等候选名称泄漏结论。可置换候选编号诊断序号偏好，但所有图、表、gold和候选版本必须同步。

人工依据与模型相同的观察审核每个候选，标注可接受cid集合、确认无解`n`或观察不足`u`；允许多个正确点，不强制唯一首选。评价自动生成器时，另标独立于生成器的参考区域和朝向。隐藏对象标注或未来行人轨迹只供来源核验，不能成为输入答案或当前可观测真值。

两类场景均覆盖多解、单解、几何可达但不符合指令、全候选无解和观察不足。让行额外覆盖后方空间缺失、无可用后撤点、等待候选及行人来向不明；就座覆盖位置被占、朝向不符及进出通路受阻。无解只限当前候选集合，unknown须有证据不足依据，不由缺失标注自动生成。

### 6.2 候选生成与选择分开验收

给定候选时报告含解选择准确率、无解／未知判断及不可接受点选择率。评价自动生成器时，候选召回的分母是场景本来存在可接受目标的样本；检查最多8个候选是否覆盖人工参考区域及朝向，并同时报告端到端可用选择率，防止用筛选掩盖生成器失败。

倒退让行与就座分别报告结果。几何最近／最短路径基线与VLM使用相同候选；有明确可选项时，不能以其他候选未知为由把整例标为未知。离线选点、几何复核与真实执行分开验收：行人是否顺利通过、让行后继续行进、最终就座姿态等属于行为／执行指标，不能从静态选点准确率推断。

## 7. 辅助任务：用于定位瓶颈，不限制为三类

| 诊断任务 | 公开来源/构造 | 它能回答什么，不能替代什么 |
|---|---|---|
| 人物—PID对应、跨帧匹配 | JRDB真实图及隐藏身份；人工审核 | 判断渲染编号/关联可读性，不直接证明社会关系 |
| 两人同组判断、群组集合恢复 | JRDB候选＋可观测补标 | 区分局部关系判断与全局组划分错误 |
| 空间QA | JRDB可靠同帧几何、SUB原生题 | 远近/左右/遮挡；几何自动标签需单位/投影核验 |
| 运动QA | SUB原生题或运动补偿后的历史 | 判断时序理解；无位姿的原坐标差不能造速度真值 |
| 队列顺序、摄影角色 | 人工审核的独立q/p事件 | 检查动作/结构细节；HHI不自动给队首和摄影者 |
| 身份复核/历史错误发现 | JRDB连续片段＋一致的干预 | 评估错误发现，不将干预频率当自然失效率 |
| 物体指代 | ScanRefer描述/对象关联 | 分离指代能力；物体中心不是停靠姿态 |
| 候选可供性/可接受集合 | ScanNet几何＋人工补标 | 分离候选判断与生成；与完整停靠不同 |
| 原生社会QA | SUB原协议与答案分布 | 检查社会理解迁移，不转换成w/t/q/p真值 |

每项先写假设、观察协议、真值来源与分母。辅助题可采用独立接口和答案格式，不必硬套REL；当前HTTP客户端仍只支持REL。生成题不自动成为高质量标签，尤其涉及意图、交互和可供性时必须审核。

如果辅助任务已经定位到图太小、PID错绑或候选缺解，应先修输入/接口再复测主任务；不通过添加大量容易QA拉高一个与主任务无关的总体分数。

## 8. 评测与验收

| 结果线 | 必须报告 |
|---|---|
| T1语义 | 成员pairwise/B-cubed F1、含漏组/错组的关系macro-F1、结构与角色、未知覆盖与错误接受率 |
| T2语义 | Top-1身份、五状态、错误身份持续时间、错配发现与重捕获延迟 |
| T3语义 | 倒退让行／就座分别报告：含解选择准确率、n/u、不可接受点选择率；使用自动生成器时另报候选召回 |
| 接口 | 完整Schema/语义约束合法率、越界PID、截断、思考内容、失败类型；拒答不删除 |
| 时效 | 全请求与合法请求P50/P95、TTFT、完整延迟、上传/渲染预算、0.5Hz丢弃、迟到及信息年龄 |
| 连续性 | 群组翻转、状态抖动、错误是否积累、模式与PID映射改变后旧结果是否被拒绝 |

先由双人一致性和开发数据决定可接受语义门槛，再固定盲测方案；不沿用旧版训练奖励或未经验证的F1硬阈值。结构类、未知或严重遮挡缺覆盖时，只声明已覆盖能力。

未知预测不能从已知真值的召回分母移除；格式失败、超时和忙丢弃保留在系统级分母。若给定输入本身不可观测，采用审核后的未知标签，不用全景原标签强行处罚合理拒答。

### 8.1 语义指标的口径

T1成员pairwise：在gold可判人物上，将同组两人对作为正例，预测同组为预测正例，统计TP/FP/FN；漏组、错误拆组和已知成员被输出unknown均保留漏检惩罚。确认独行者按单例组处理；gold不可判归属不强行当负例，另报不可判覆盖。B-cubed需预先定义单例、失败与unknown映射，不能沿用未说明的工具默认值。

关系评测先按成员匹配预测组与gold组，再报告w/t/q/p/o/u混淆和macro-F1；只看成功匹配组的分类分数会掩盖漏组，必须另报含漏组/错组的端到端关系成绩。匹配方法、成员相似度阈值和失败惩罚在盲测前固定，完整gold评分器尚未实现。

q/p需分别评估k是否正确、可判队列次序、队首/队尾及摄影者/主要被拍者；不能把k=1本身当角色预测正确。每类报告独立事件数、可判样本数和拒答比例，避免大量同行类淹没结构类。

T2报告目标身份Top-1、五状态混淆、接受v/o时错误身份率、所有观察的错误率及覆盖率；无接受时错误率记N/A并报覆盖0。错误身份持续时间、首次错误发现延迟和重捕获延迟按事件算。只有一个输出ID的接口不宣称Rank-5/mAP，除非另设检索协议。

T3按倒退让行／就座及自然语言指令切片，报告含解时选中可接受集合的准确率、n/u混淆与不可接受点选择率；接入自动生成器后再报告候选召回和端到端有效选择。多个可接受候选任取一个都正确，不能因未选择标注者首选而判错；让行的后方证据缺失与就座的区域被占等边界单独统计。

### 8.2 接口、时效与分母

```text
接口合法率 = 完整且通过全部校验的请求数 / 已提交请求数
按时合法覆盖 = deadline内完整合法结果数 / 全部计划到达数
忙丢弃率 = dropped_busy / 全部计划到达数
语义覆盖 = 给出可判决策的观察数 / 该协议全部观察数
接受风险 = 已接受决策中的错误数 / 已接受决策数
```

同时报告提交前失败、提交后格式/语义契约失败、网络错误、截断、思考内容、越界身份、busy丢弃、迟到和停止后未提交数量。unknown不等于格式失败，迟到合法不等于按时可用；JSON Schema通过也不等于语义正确。

全请求与合法子集的P50/P95分开，声明计时是否包含感知/渲染/上传/校验。当前工具P95是nearest-rank，24例的P95是第23个排序值，只是小样本描述统计。TTFT是第一段最终文本，不是完成JSON的时间；SSE第一事件也可能只是元数据。

serial测逐请求完整耗时；paced测计划时刻到完整结果，单请求在途、忙时丢弃。现有24窗口交错三个场景的paced只验证调度/延迟，不是连续群组状态回放。连续回放须同一根序列按时间推进，并模拟源观测时刻、PID生命周期、模式和结果接纳。

### 8.3 统计与风险—覆盖分析

既报样本micro，也报根序列/地点macro；根录像/房间作为bootstrap聚类单位生成95%区间，不把几十个相邻窗口当几十个独立事件。少量事件只给探索性结果，不夸大显著性。

报告gold未知比例、模型unknown比例、可判样本上的错误接受和已知关系召回；比较拒答策略时看风险—覆盖关系，不仅看“回答的那部分准确率”。分移动/静止、近/远、人群密度、遮挡、缺3D与q/p结构切片；切片规则先定，不能只报告后来发现的清晰片段。

盲测前固定：输入版本、模型/运行时、Prompt、Schema、合法性规则、匹配评分、超时、状态/年龄策略和指标门槛。若人工一致性不足或某类观测不可判，先修规约/输入，不能靠模型调参弥补不可信真值。

### 9.1 建议执行顺序与停止条件

| 步骤 | 产物 | 进入下一步的条件 |
|---|---|---|
| A：来源/协议核验 | split草案、许可/版本记录、事件覆盖表 | 对齐与数据族可追溯，不泄漏社会答案 |
| B：人工试标 | 约30试标→50–100开发窗口、分歧规约 | 同输入可判关系足够，一致性问题可解释 |
| C：低预算开发 | 小规模配对消融、固定渲染/Prompt/Schema | 主要输入瓶颈已定位，格式与拒答规约稳定 |
| D：隔离T1评测 | 约200–400窗口，独立事件切片及全失败记录 | 所声明类别均有覆盖，质量门槛预先固定 |
| E：连续回放 | 5–10段20–60s片段、0.5Hz及年龄/映射失效测试 | 不累积旧请求，不错用身份，不隐藏丢弃/迟到 |
| F：T2/T3扩展 | 专用输入、约各100例起步的试标/诊断 | 真值与接口成立再扩规模，不把Schema存在当完成 |

规模是工作预算，不是统计充分性的保证；q/p稀缺时寻找其他合适公开视频并人工补标，不能复制同一事件凑数。调用先离线dry-run与3个跨场景smoke，再在确有比较价值时扩大；每次配置只做必要复测，不继续大规模重复速度诊断。

停止/回退条件包括：人工无法一致标关系、观察本身不足、输入泄漏或标签错绑、只在P0有效而P1崩溃、候选召回过低、unknown被滥用、错误身份长期保持、迟到结果被接受。对应修正数据/协议/状态逻辑后再评测，不默认为需要微调模型或先采集实机数据。
