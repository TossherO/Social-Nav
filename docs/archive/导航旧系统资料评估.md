# 旧导航系统资料评估（归档）

本文保存已完成的旧镜像及ZIP源码审阅，用于追溯复用依据。配置和源码存在不代表相应二进制已运行或通过验收；下文的“首轮”“后续”保留当时评估语境。当前实现与操作以[导航专题](../navigation/地图与几何导航.md)为准，待办只在[后续开发计划](../navigation/导航规划实现计划.md)维护。

原镜像／ZIP保持只读，身份、提取范围和本机检查见[本机记录](../../ENVIRONMENT.local.md#旧导航资料)。车体与雷达关系的长期来源仍保存在[来源JSON](../../configs/wheelchair_geometry_reference.json)，不依赖输出目录。

## 1. 资料结论与复用选择

两份资料来自不同镜像，不能互相推断配置和能力：

| 来源 | 已确认的导航组织 |
|---|---|
| ZIP，来源为`nav_gpu_backup` | GlobalPlanner配置选择Dijkstra，TEB巡航与停车MPC耦合；另有航点寻路、路径跟踪、共享控制、串口、楼层切换和任务状态机。 |
| `navigation_zhao`工作区源码 | GlobalPlanner配置选择A*；不同launch分别选择标准DWA、定制DWA和TEB。所查工作区包清单未见ZIP中的`plan_base`、`parking_path_planner`或`route_planner`。 |

二者均为旧ROS 1环境；部分Python节点使用Python 2，目录内也包含声明支持Noetic的第三方代码，不能将全部源码视为同一个已验证版本。下文的launch选择只说明源码配置，不表示确认过当前运行节点或源码与镜像内二进制一致。

**保留旧系统的算法经验，以当前ROS 1环境重新组合标准组件。复用已有有图／无图共享环境输入，先做只规划基线，再接TEB和独立安全层。** 不恢复整套旧状态机与启动脚本，不替换当前ROLL＋FAST-LIO。

| 资料中的实现 | 可用性与当前取舍 |
|---|---|
| `map_server`、`costmap_2d`、`global_planner` | 算法与接口可复用，采用适配当前ROS发行版的上游实现；旧包只作行为和配置参考，避免覆盖系统同名包。首轮以Dijkstra建立基线，同输入少量对照A*，不根据旧镜像的配置直接认定优劣。 |
| `teb_local_planner` | 适合作为首个局部几何基线。优先使用Noetic上游插件；旧版附加的朝向误差话题等功能按真实需求单独适配。旧足迹、速度和转弯半径不能直接沿用。 |
| `pcd2pgm` | 高度筛选、去离群和投影思路可参考；两份源码都将未落点栅格初始化为空闲。沿用当前感知地图导出，不另接旧投影器。 |
| `pointcloud_to_laserscan` | 标准投影功能可复用；先采用直接`PointCloud2`障碍输入，需要兼容LaserScan时再接投影。旧自定义低强度／离群过滤默认不迁移，避免未经确认地删掉细小障碍。 |
| 标准`dwa_local_planner`、定制`dwa_planner` | 保留为后续参考；`navigation_zhao`的定制版将独立DWA改为插件，绑定旧扫描、速度及车体假设。需要局部对照时优先标准DWA，首期不同时维护多套局部规划器。 |
| 定制`move_base`、`plan_base`、`parking_path_planner` | ZIP将TEB巡航和停车MPC耦合在同一控制链，`navigation_zhao`则修改了控制循环的触发机制。均不整体导入；停车算法可作后续终端停靠参考，不迁移旧OSQP二进制。 |
| `route_planner`、`path_pursuit` | 分别是基于航点邻域的A*和简易路径跟踪；不能替代带代价地图碰撞检查的导航。首期使用标准栅格全局规划，不增加骨架／航点路线图。 |
| `obstacle_detector` | 提供二维线段／圆形障碍及跟踪，可作几何参考；不代替当前三维行人检测跟踪，也不增加第二套人物身份。 |
| `odom_helper.py`、`pc_filter` | 分别拼接定位位姿与编码器速度、裁剪点云；时间、坐标与字段处理不符合当前接入要求，按现有定位契约适配所需功能。 |
| 共享控制、深度距离、串口脚本 | 保留控制模式和协议参考。后续拆到`navigation/control`与`safety`；先核对底盘固件、感知覆盖与车体参数，不执行旧串口程序。 |
| 多楼层地图、合图工具、地图切换、状态机和电梯逻辑 | 保留参考，不纳入首期。旧楼层拼接与场景目标不能迁移为当前的地图配准或任务反馈。 |

上游Noetic的[GlobalPlanner实现](https://github.com/ros-planning/navigation/blob/noetic-devel/global_planner/src/planner_core.cpp)提供Dijkstra／A*及未知区域策略；[TEB插件声明](https://github.com/rst-tu-dortmund/teb_local_planner/blob/noetic-devel/teb_local_planner_plugin.xml)提供`nav_core::BaseLocalPlanner`接口。这支持上述组件组合，但不证明旧叉版、依赖或参数已经适配当前机器。

### navigation_zhao的补充源码依据

以下路径相对镜像工作区的`src/`，用于定位参考，不是本项目入口。

| 路径／位置 | 确认的行为与取舍 |
|---|---|
| `navigation/move_base/config/global_planner_params.yaml`、`navigation/global_planner/bgp_plugin.xml` | 实际加载配置为`use_dijkstra=false`、`use_grid_path=true`、`allow_unknown=false`，即A*及栅格路径提取；同文件虽有`GraphPlanner/theta_star`参数，launch中该插件选择被注释，所查插件声明也未提供它，不能记为已用Theta*。 |
| `navigation/move_base/launch/` | `move_base.launch`、`move_base_fang.launch`选择标准DWA，`move_base_fang_second.launch`／`move_base_fang_third.launch`选择定制DWA，`move_base_lei.launch`选择TEB；不存在仅凭文件齐全就能确认的统一默认局部算法。 |
| `navigation/move_base/src/move_base.cpp`：`executeCb` | 每次控制周期后把`param_has_change_`置为false，再忙等外部Bool信号；等待中不睡眠，也不检查取消或退出。不能复用为当前实时控制主循环。与ZIP不同，该文件仍注册`make_plan`服务，没有强制加载停车插件。 |
| `navigation/dwa_planner/src/dwa_planner_ros.cpp`、`dwa_planner.cpp` | 速度话题硬编码，部分网格／显示坐标硬编码为`odom`；TF失败后仍继续计算，局部栅格到障碍列表的更新被注释，默认依赖`/scan`。`isGoalReached`只检查位置，不检查终点朝向和停止，不能作为T3就座完成反馈。 |
| `navigation/dwa_planner/src/dwa_planner.cpp`：`init_footprint`，以及TEB与costmap配置 | 定制DWA硬编码居中的1.20×0.60米矩形，costmap为偏置的1.10×0.66米矩形，TEB为0.80米线段。三者不一致，继续按唯一车体模型重新适配。 |
| `navigation/move_base/config/local_costmap_params.yaml`、`pointcloud_to_laserscan/` | 局部图使用`map`并加载静态层，未知跟踪关闭；投影可将无命中方向设为Inf，旧障碍层配置允许用Inf清除。这不能直接承担当前无图`odom`窗口，也不能把稀疏三维投影的无命中解释为已观测空闲。 |

定制DWA的README指向[amslabtech/dwa_planner](https://github.com/amslabtech/dwa_planner)，可追溯其独立DWA来源；镜像又增加了ROS插件包装、前瞻目标及评分等改动，不能用上游说明替代本地审阅。其候选轨迹、预测足迹和前瞻目标显示值得参考，但显示必须绑定实际坐标及输入观察，不能替代完整路径碰撞检查。

这次核对支持保留当前阶段顺序：**先用标准GlobalPlanner完成只规划，再接标准TEB与真实控制反馈。** 增加A*对照和上述输入／反馈适配要求即可，暂不增加MPC、Theta*或另一套定制DWA实现任务。

### ZIP中的关键源码依据

以下路径均相对于资料包根目录，仅用于定位审阅依据，不是当前项目运行入口。

| 路径／位置 | 确认的行为与影响 |
|---|---|
| `sources/ros_navigation/pcd2pgm/src/pcd2pgm.cpp`：`SetMapTopicMsg` | 栅格全初始化为`0`，未落点区域也变为空闲；尺寸向下取整，包围盒循环漏最后一点，填图跳过末行。过滤后的两个PCD还写回输入目录。不能只调高度参数后复用。 |
| `sources/ros_navigation/move_base/config/{global_costmap_params,teb_local_planner_params,mpc_tracking_params}.yaml` | 全局代价地图使用`odom`，扫描配置有重复`topic`键；TEB使用线段足迹，代价地图与MPC使用不同矩形尺寸。必须重新定义唯一车体模型与参数源。 |
| `sources/ros_navigation/move_base/src/move_base.cpp`：构造函数 | 强制加载停车插件；常规`move_base/make_plan`服务注册被注释，简单目标订阅改为旧状态机话题。不是可直接替换的标准`move_base`。 |
| `sources/ros_navigation/route_planner/src/AStar.cpp`：`isCanreach/getSurroundPoints` | 通过KD树连接附近航点，实际可达性检查未读取障碍栅格；不能保证连边不穿墙，也没有实现地图中轴提取。 |
| `sources/ros_navigation/parking_path_planner/src/parking_path_planner.cpp`：`checkTrackSecurity` | 内层循环到足迹末点时仍访问`j+1`，存在越界；其调用还在一处路径检查中被注释。停车模块需要单独修整和验证，不能因包含MPC就视为可直接部署。 |
| `sources/pc_filter/scripts/filter.py`、`sources/ros_navigation/move_base/scripts/odom_helper.py` | 前者将时间改为当前时刻、输出仅XYZ并使用固定自车屏蔽框；后者近似同步后直接拼接pose与twist，未证明两个消息的子坐标系和有效性兼容。 |
| `sources/shared_control/src/try1.cpp`：`ScanCallback` | 按固定180点和每点1°解释扫描，未按实际角度元数据换算；与包内另一套扫描角分辨率不一致，不能直接接入。 |
| `sources/ros_navigation/move_base/scripts/pub_odom.py` | 打开真实串口，保留停车输入，但收到的控制时间仅被赋值、未用于命令过期停车；失去发布者后不能依赖此脚本证明会自动停止。 |
| `sources/imu2imu/src/map_switcher/src/map_switch_node.py` | 启动新map_server后等待5秒又停止该新进程；没有管理旧地图，也没有同步切换定位地图。 |
| `sources/map_merge_tools/`、`maps/yanjiuyuan/floor2.yaml` | 合图脚本使用人为平移；二楼YAML的X原点比注释中的独立地图原点大400米。该偏移不是地图间标定结果。 |

### 旧地图怎样使用

`floor1_less_people.jpg`和`floor2.jpg`的房间、走廊和部分柱体清楚，可以参考呈现效果与场景布局。图像为JPEG，名称不能证明去人效果、几何精度或与哪份三维地图配套；`floor1_regions.json`等保存的是图像像素多边形，也不能直接当世界坐标区域。

按各自YAML阈值，两张图的外边界像素约99.98%／99.95%被判为空闲，不能从白底推断外侧已经观测。现阶段不把这些图注册为当前默认导航地图，也不靠修改origin消除配套关系的不确定性。新地图使用无损PGM与独立楼层身份，不沿用400米偏移。
