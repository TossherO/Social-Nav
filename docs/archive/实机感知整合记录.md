### 建图定位诊断与当时的验证范围

### 初始高度与重力方向

先分别查看连续`odom`与地图位姿，再核对同一扫描的配准初值、迭代更新和最弱方向。地图高度突变可能是累计误差集中修正，不能直接解释为车体升降；低残差、较高匹配比例或`VALID`也不保证所有方向均有足够约束。

ROLL退化投影在同一次匹配的各轮迭代中保持，输出包含最后一次更新。只读定位的退化特征值阈值由[localization.yaml](../../perception/mapping_localization/configs/localization.yaml)维护，针对当前16线扫描保留较弱但可用的高度约束；更换雷达、采样密度或地图后需重新核对，不能将某个特征值阈值视为通用精度标准。

FAST-LIO默认使用[fast_lio.yaml](../../perception/mapping_localization/configs/fast_lio.yaml)中的自适应初始化，有图、建图与无图任务共用。先用点云与陀螺仪建立短时几何运动，再对齐IMU积分，估计非零初速、重力方向和陀螺偏置；初始加速度尺度使用显式配置，不再由运动均值决定。加速度偏置仅估计轴向分量，其他分量保留不确定性，不同时标定外参、时差或完整IMU内参。

| 启动状态 | 行为 |
|---|---|
| 点云几乎不动、加速度稳定且低频角速度稳定 | 静止分支，估计零速与偏置；原始高频陀螺噪声不单独作为运动证据 |
| 点云已有位移 | 运动分支，以连续位姿估计初速、重力与有限偏置，检查残差、重力方向的拟合敏感度及连续窗口稳定性 |
| 输入不足、匹配或对齐质量不满足要求 | 保持初始化；不把零速猜测或纯IMU预测发布为有效定位 |

初始化从配置的最短窗口开始检查，条件满足就提前结束；否则继续积累，超过最长窗口后滚动更新，不按超时强行通过。运动分支以至少2厘米的几何位置扰动估算重力方向的线性化敏感度，避免短窗口仅因残差低就通过；该值是数值约束指标，不是真实姿态误差或传感器协方差。静止分支使用点云与低频IMU判据。两者都要求相对稳定区间起点的重力／偏置持续稳定，不能只串联相邻拟合的小变化。参数仅由上述配置维护。

初始化只使用已收到的数据，会增加启动等待；无图期间的状态为`INVALID/INITIALIZING`，ROLL尚无前端配准输入，联合检测按原规则降级。结果写入`run.json`的`initialization_result`，包括实际窗口、稳定区间时长和运动分支的敏感度指标；首帧参考写入`frontend_initial_reference`。人工起点仍属于首帧，后端通过参考位姿传播初始化期间的真实估计运动；后续RViz重定位不重复应用这段位移。

需要复现历史行为时可显式关闭配置中的`initialization.enabled`；当前自适应实现不与旧`load_pcd`／GT前端初值路径混用。雷达—IMU标定与时间同步按上述策略推进；保持静止启动仍有利于降低不确定性。排错不通过锁定Z、压平轨迹或改写人工初值消除现象。

### 人工帧号映射与伪框格式核验

### 12.1 人工标注帧号

人工标注键 `k` 不是原始点云帧号，而是同场景在
`wheelchair_infos_train_full_by_scene.pkl` 中 `frames` 列表的零基下标。正确映射为：

```text
raw_frame_index = scene_entry['frames'][int(k)]['frame_index']
```

不能再使用固定的 `k+1` 偏移。确认依据：

- 全部 9,705 个人工标注键都能作为对应场景 `frames` 列表的合法下标；
- 7,946 个键（81.88%）的 `frames[k].frame_index` 与 `k+1` 不同；
- 按目标数统计，旧映射使 18,066 / 21,984（82.18%）个人工中心落到错误点云帧；

## 15. 多卡动态体素显存优化

动态点数和体素数量会造成多卡显存差异。当前优化包括：

1. CUDA 设备绑定必须早于 NCCL process group 初始化，避免所有 rank 先在逻辑
   GPU 0 建立上下文。
2. EMA Teacher 生成并注入伪标签后，立即释放其 `batch_dict`、预测和 head 缓存，
   避免 Teacher 稀疏特征与 Student 训练图同时驻留。
3. `DynamicVoxelVFE` 必须真正执行数据配置中的 `MAX_NUMBER_OF_VOXELS`。此前
   `SKIP_RUNTIME=true` 会跳过 CPU voxel generator，导致该上限只参与网格初始化、
   并未限制动态非空体素。训练/测试分别使用配置中的 `train`/`test` 上限；超过
   上限时使用坐标哈希做确定性、无空间前缀偏置的选择，使 Teacher 与 Student 对
   同一输入保留一致的体素集合。
4. 提供可选的逐 rank 诊断日志，同时记录点数、限流前后体素数，以及 CUDA
   allocated/reserved/peak memory。诊断默认关闭，避免日常训练引入额外同步；可由
   `--log_gpu_memory` 或三阶段脚本的 `LOG_GPU_MEMORY=1` 开启。

实现保持未超过体素上限的数值路径，不逐iteration清缓存；仅在相关行为变动时运行体素限流测试，避免把专项诊断变成每次训练的固定开销。
