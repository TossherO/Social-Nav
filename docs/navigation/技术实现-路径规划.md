# 技术实现：路径规划

路径规划负责回答“从当前位置到目标，是否存在符合车体几何和转弯约束的路线”。它输出空间参考，供 [DWA 控制器](技术实现-局部控制与安全.md)选择速度。参考路径本身不表示轮椅可以立即运动，还需要当前环境和人物检查。

本文解释地图如何进入规划器、搜索如何进行，以及旧参考何时可以继续使用。任务目标和分段路线见[任务与路线](技术实现-任务与路线.md)，运行命令见[运行手册](../感知导航运行手册.md#导航离线查询与仿真)，后续工作见[共同清单](../感知导航实机问题.md)。

## 默认算法与实现

默认在线流程使用一个低频 CPU 工作进程运行 Hybrid A*，组合直线、有限半径圆弧和原地旋转，输出供 DWA 使用的空间路径。相关实现位于 `planning/planner.py`、`reference.py` 和 `native/pose_search.cpp`，参数由 [planning.yaml](../../navigation/planning/configs/planning.yaml) 和 [reference.yaml](../../navigation/planning/configs/reference.yaml) 维护。

搜索借鉴 [Smac 的位姿搜索设计](https://github.com/ros-navigation/navigation2/blob/main/nav2_smac_planner/README.md)：在连续 SE(2) 位姿上积分直线和圆弧，再将位置与朝向分桶，以限制搜索规模。分桶不会移动实际起点，也不会降低输入地图的分辨率。搜索有计算预算，预算耗尽只能说明本次未找到可用结果，不能证明连续空间中绝对无路。

`plan/replay` 另外保留 Dijkstra 和 A* 诊断。它们通过薄 C ABI 调用官方 `global_planner/costmap_2d`，先生成内接圆候选，再检查完整车体足迹；失败后可显式尝试曲线连接和有界 Hybrid A*。默认在线流程直接使用 Hybrid A*，不会逐次串行运行这些方法。

### 轮椅几何历史参考

碰撞检查需要完整车体足迹，以及雷达与车体的安装变换。历史数值、镜像身份和来源摘要保存在[几何来源记录](../../configs/wheelchair_geometry_reference.json)中，[关系图](../assets/wheelchair_geometry_reference.png)展示旧足迹和 Jetson 雷达位置。

用户已初步确认这些平面尺寸和安装关系。离线查询仍须显式选择 `geometry=historical`，结果保留 `geometry_assumed=true`，以说明它使用了历史参考。Jetson 配置与另一套仿真模型分别保存，不能混用；历史变换的 Z 值也不等于雷达离地高度。

载荷包络和运动能力仍需实测。这份几何资料尚未作为当前实车控制参数验收。

## 输入与地图模式

感知负责[构建环境地图](../perception/技术实现-环境地图与场景表示.md)，导航在这些输入上生成自己的代价视图，不改写原地图。

| 输入 | 规划器如何使用 |
|---|---|
| 静态环境地图 | 为全局搜索提供历史先验，不替代三维定位地图或当前观测。 |
| 实时局部环境地图 | 提供当前占据、未知和覆盖信息，用于足迹与局部路线检查；有图和无图任务都使用它。 |
| 算法位姿与地图关联 | 确定轮椅在连续局部坐标中的位置，以及它与哪份地图对应；保留原时间、健康状态和定位生命周期。 |
| 人物轨迹 | 提供观察截止之前的世界轨迹，用于有时间维度的运动检查。 |
| 目标 | 说明任务、目标修订、坐标系、参考点、必要的终点朝向和运动意图。 |

规划模式决定参考来自哪里：

| 模式或事件 | 处理方式 |
|---|---|
| `static` | 使用显式起终点进行地图诊断，不把人工起点当作录制时的真实位置。 |
| `mapped` | 临时用已有局部自由证据补充对应静态先验的未知区，再生成参考，并用当前局部图检查。 |
| `local` | 只使用有效局部图，目标必须由调用者明确给出。 |
| 离开地图或地图关联失效 | 暂停地图目标；只有另有明确局部目标时才继续。 |
| 返回地图、定位重置、换图或取消 | 重新核对目标与地图关系，或撤销旧结果，不直接恢复旧路径。 |

无图模式不会自动探索，也不会把地图中的远目标裁到局部窗口边缘。位姿或速度缺失时保留缺失状态，未知格子不当作空闲。

全局搜索可以利用感知提供的历史自由背景，并给可变的旧障碍增加条件代价。这样可以找到值得重新观察的路线，但不表示当前位置已经可通行。当前占据仍在原生局部栅格上检查，避免重复投影和膨胀误挡起点。人物背景层如何参与检查，见[人物运动与社会代价](技术实现-局部控制与安全.md#人物运动与社会代价)。

### 局部证据进入全局参考

静态图可能仍缺少完整自由依据，而实时局部图已经获得该处的自由证据。`planning/overlay.py`在映射查询内生成临时工作图，使全局起点检查和后续搜索也能使用这份证据。它复用已经送达CPU参考进程的局部栅格，不增加GPU下载，不改变地图生产规则或静态资产。

查询先核验场景、地图身份、关联和时效，再使用当前车体位姿对应的`local_from_map`二维变换；这与全局路径返回局部坐标时的约定相同。关联倾角超过既有平面适用范围时不提供补充。处理范围仅限当前局部窗口，且只检查静态未知格。

一个静态未知格只有在所有与它存在正面积重叠的局部格均为原始自由、且核验后的导航图也均为自由时，才在本次工作图中变为自由。只检查中心点不够；部分越出局部图、任一相交格未知或当前占据都会阻止补充。由静态支持得到的导航自由、或人物预测得到的背景自由，不能反过来成为补充静态未知的依据。原始局部自由可以含当前地图规则已经接受的近场历史，因此这不等于本帧重新扫描了所有位置。

该步骤保留已有静态占据，输出记录原场景、图层摘要、先验、变换和补充数量。下一次查询重新从输入先验和当前场景计算，没有永久累积或刷新观察时间。原有条件障碍参考规则继续独立生效；当前新障碍仍由局部完整扫掠、DWA与独立安全检查，不以全局参考通过替代运动检查。

工作图参与原有占据内容摘要与搜索缓存检查。局部支持变化可能导致全局代价图重建，这是补充证据的实际成本。该机制只处理“局部已自由、静态仍未知”的不一致；缺少局部自由、关联失效和运动学无解仍会拒绝。

## 搜索与完整足迹

搜索前先检查目标处是否确定放不下车体。指定朝向的目标使用完整足迹；只有XY坐标时，检查以实际目标位置为圆心、包含于车体所有旋转姿态的内接圆及安全余量。圆与未知、占据或地图外部相交，才能提前报告`goal_footprint_unknown/occupied/outside`。该推理要求车体参考点在凸足迹内部，不适用于参考点位于足迹外的几何。

检查直接使用目标坐标和格子的矩形范围，不用膨胀代价图的格中心代替。未发现阻挡只表示没有得到不可行证明，后续仍须搜索和检查完整足迹；有限个朝向都检查失败也不能证明全部连续朝向不可行。提前拒绝发生在代价图构建之前，减少对不可行端点的重复准备和搜索。

规划按以下顺序生成并检查路径：

1. 枚举圆弧—直线—圆弧及三圆弧连接，优先尝试终点直线进场。连接族参考 [OMPL Dubins 实现](https://github.com/ompl/ompl/blob/main/src/ompl/base/spaces/src/DubinsStateSpace.cpp)，项目没有引入 OMPL 依赖。
2. 如果直接连接不足，再用目标侧的二维距离场引导 Hybrid A*。完整距离场确认自由区域不连通、且车体参考点严格位于足迹内部时，可以直接拒绝该查询。其他情况继续搜索；距离场未完成只能记为预算不足。
3. 对最终候选独立检查曲率，以及完整车体沿整条路径的连续扫掠。未知、越界、无法认证或超预算都会保留原因并拒绝。

搜索期间只保留控制段，不为失败候选生成稠密位姿。解析连接使用至多四段的固定存储，只排列实际要检查的前十二个候选，同代价候选仍按原生成顺序处理。节点的最小代价和已扩展状态保存在同一张表中，避免重复哈希和分配。

找到较长的首条路径后，搜索仍会在预算内寻找更短的多转弯路线，不立即接受任意绕行。当前使用加权启发式和有限状态分桶，不保证连续空间中的最优解。以上优化保留原采样、转弯限制和最终独立认证。

轮椅支持倒车已由用户确认，当前运动配置允许前进和倒车。解析连接可以整段前进或倒车，Hybrid A* 还可以组合两个方向的直线和圆弧。路径中的 yaw 始终表示车体朝向，倒车时与行进方向相反；DWA 按方向分段跟随，在换向点先制动。路径通过几何检查不表示换向或制动已经执行。

用户已通过实机测试确认原地旋转能力，当前 [motion.yaml](../../navigation/planning/configs/motion.yaml) 开启 `allow_in_place_rotation`。搜索增加固定车体位置的旋转动作，以及转向、直行、终点转向组成的连接。每段旋转仍检查完整车体扫过的区域，端点空闲不代表中间转动安全；旋转中心是当前 `base_link` 模型原点，须继续核实它与实车旋转中心及雷达外参的关系。

配置中的 1.05 米来自用户选定的 `wheel_nav:v1` 容器参数，现在保留为移动圆弧的搜索半径，另加搜索余量。启用旋转后，控制与安全不再用该半径排除零线速度角运动，而是分别限制线速度、角速度及其加速度，使转动与平移之间可以连续过渡；禁止侧滑及有限时域的足迹检查仍保留。关闭旋转能力时恢复原有限半径约束。数值限值仍未实测验收。搜索与终点朝向采样有预算，不保证穷尽连续空间中的所有解；剩余失败见[失败溯源专题](../感知导航实机问题.md)。

导航代价图和安全净空按网格内容缓存；先验发生修订时，只生成导航需要的图层。`Planner.observe()` 可以只更新先验，不立即寻路。缓存不能替代当前局部检查，`reset/seek` 会清空派生历史。

目标侧距离场由原生搜索器单独缓存，通过 `pose_search.cache_heuristic` 控制，默认开启。只有占据、代价、尺寸、原点、分辨率和目标格均相同时才复用，而且只保存已经完整展开的距离场。它缓存的是搜索引导，不是上一条路径的有效性或无路结论。

缓存最多保留一份距离场和用于核对输入的数组副本，不持有共享场景的指针。参考工作进程因此可以在每次查询后释放场景，原生搜索器继续保留自有缓存。新查询仍检查实际起点、当前几何、来源和观察时间；显式重置会丢弃缓存。

全局参考由 CPU 生成，局部扫掠可以直接使用驻留 GPU 的地图。保守 GPU 检查不能确定时，仍允许精确 CPU 回退，并记录回退情况。

全局参考的最终认证继续使用原 CPU 扫掠检查。其成本与原生搜索分开记录，不能用原生搜索的局部提速代替完整查询的收益。诊断字段及联合负载见[推理速度](../感知导航推理速度.md)。

## 参考生命周期与局部段

`ReferenceRuntime` 保存已生成的空间参考。目标或上下文变化、参考到期、持续停止或没有可用候选时，它会在预算内重新查询。查询失败和超时各自退避，普通新扫描不会不断清空等待状态。后台返回结果时，仍要核对原任务和查询时的上下文，迟到结果不能覆盖当前任务。

输入暂时过期时，当前可用状态撤下，但保留最近参考的原始内容。新输入恢复后，按原时间及当前任务、地图和定位身份重新校验，符合条件才恢复为当前参考；DWA仍检查新观察下有限时域的运动几何。真实取消和上下文变化会清除保留结果，恢复过程不延长其测量寿命。

查询返回的完整结果通过身份与内容检查后，若失败原因只是导航关联或几何观察过期，不记为几何无路，也不交给中间目标策略作为无路证据。系统等待比该查询更新的原测量，再按正常查询最小间隔重试。真实无路、无效结果及工作进程超时仍保留失败退避；不对同一测量反复提交，也不刷新时间戳来绕过检查。

在同一定位生命周期内，旧路径尾段可以继续作为引导，但必须重新检查它在当前局部图中的完整扫掠，并确认轮椅能从实际位姿按曲率约束接入。如果尾段起点不是真实当前位置，结果标记 `start_is_actual=false/current_path_valid=false`。此时它只用于重新接入，不能作为当前可执行路径。

| 输出 | 含义 |
|---|---|
| `path` | 全局空间参考。 |
| `local_check` | 原参考在当前局部图内的有效范围。 |
| `current_local_path` | 已检查的前缀；前视不足时，也可以是局部几何重规划结果。 |
| `valid/complete/current_path_valid` | 分别描述当前段和原参考的可用情况，不表示导航任务已完成。 |

中间参考点的朝向只是引导。只有真正全局终点明确要求 yaw 时，局部段才继承该硬约束。几何有路之后，还要通过速度、人物和独立安全检查。

## 复用与验证边界

冻结场景用于同输入回归，修改配置不会自动更新旧场景。如果需要重建，应从原观察开始连续重放证据，并保留定位、地图关联、目标和新派生结果的指纹。近场表示依赖历史，不能用互不相连的短窗口替代。

原始 bag、登记地图和人工标签保持只读。搜索、局部控制与安全的耗时分别统计，见[推理速度](../感知导航推理速度.md)。几何通过、同源回放、反馈仿真和实机验收支持不同结论，报告时分别说明。
