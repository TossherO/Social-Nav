# 导航地图与几何导航设计

本文依据轮椅镜像导出的 `docker_navigation_reference.zip`，评估旧实现并确定导航接入范围。共享地图、无图局部环境与决策查询统一由[环境地图与场景表示](../perception/技术实现-环境地图与场景表示.md)维护，本文只维护旧资料评估和导航集成。当前仍是设计，规划与控制尚未实现；源码审阅不等于编译通过或实机可用。系统职责与集中待办见[系统方案](../系统方案.md)，坐标与有效性遵循[接口约定](../接口约定.md)。

## 1. 资料结论与复用选择

资料包含 ROS 1 Navigation、TEB、定制停车MPC、航点寻路、路径跟踪、共享控制、底盘串口、楼层切换、任务状态机，以及二维地图和历史定位配置。镜像环境为 Ubuntu 18.04／ROS Melodic，部分Python节点使用Python 2；目录内也包含声明支持Noetic的第三方代码，不能将全部源码视为同一个已验证版本。

**保留旧系统的算法经验，以当前ROS 1环境重新组合标准组件。先补齐有图／无图共享环境输入，再做只规划基线，随后接TEB和独立安全层。** 不恢复整套旧状态机与启动脚本，不替换当前ROLL＋FAST-LIO。

| 资料中的实现 | 可用性与当前取舍 |
|---|---|
| `map_server`、`costmap_2d`、`global_planner` | 算法与接口可复用，采用适配当前ROS发行版的上游实现；旧包只作行为和配置参考，避免覆盖系统同名包。旧启动配置实际选择Dijkstra，A*可配置切换。 |
| `teb_local_planner` | 适合作为首个局部几何基线。优先使用Noetic上游插件；旧版附加的朝向误差话题等功能按真实需求单独适配。旧足迹、速度和转弯半径不能直接沿用。 |
| `pcd2pgm` | 高度筛选、去离群和投影思路可参考；原实现的未知语义、边界处理与输出方式需要重写，不能直接生成当前正式导航地图。 |
| `pointcloud_to_laserscan` | 标准投影功能可复用；先采用直接`PointCloud2`障碍输入，需要兼容LaserScan时再接投影。旧自定义低强度／离群过滤默认不迁移，避免未经确认地删掉细小障碍。 |
| 标准`dwa_local_planner`、独立`dwa_planner` | 保留为后续对照。后者绑定编码器与旧扫描话题；首期不同时维护多套局部规划器。 |
| 定制`move_base`、`plan_base`、`parking_path_planner` | TEB巡航和停车MPC被耦合在同一控制链。停车算法可作后续终端停靠参考，暂不整体导入定制主程序和旧OSQP二进制。 |
| `route_planner`、`path_pursuit` | 分别是基于航点邻域的A*和简易路径跟踪；不能替代带代价地图碰撞检查的导航。首期使用标准栅格全局规划，不增加骨架／航点路线图。 |
| `obstacle_detector` | 提供二维线段／圆形障碍及跟踪，可作几何参考；不代替当前三维行人检测跟踪，也不增加第二套人物身份。 |
| `odom_helper.py`、`pc_filter` | 分别拼接定位位姿与编码器速度、裁剪点云；时间、坐标与字段处理不符合当前接入要求，按现有定位契约适配所需功能。 |
| 共享控制、深度距离、串口脚本 | 保留控制模式和协议参考。后续拆到`navigation/control`与`safety`；先核对底盘固件、感知覆盖与车体参数，不执行旧串口程序。 |
| 多楼层地图、合图工具、地图切换、状态机和电梯逻辑 | 保留参考，不纳入首期。旧楼层拼接与场景目标不能迁移为当前的地图配准或任务反馈。 |

上游Noetic的[GlobalPlanner实现](https://github.com/ros-planning/navigation/blob/noetic-devel/global_planner/src/planner_core.cpp)提供Dijkstra／A*及未知区域策略；[TEB插件声明](https://github.com/rst-tu-dortmund/teb_local_planner/blob/noetic-devel/teb_local_planner_plugin.xml)提供`nav_core::BaseLocalPlanner`接口。这支持上述组件组合，但不证明旧叉版、依赖或参数已经适配当前机器。

### 关键源码依据

以下路径均相对于资料包根目录，仅用于定位审阅依据，不是当前项目运行入口。

| 路径／位置 | 确认的行为与影响 |
|---|---|
| `sources/ros_navigation/pcd2pgm/src/pcd2pgm.cpp`：`SetMapTopicMsg` | 栅格全初始化为`0`，未落点区域也变为空闲；尺寸向下取整，包围盒循环漏最后一点，填图跳过末行。过滤后的两个PCD还写回输入目录。不能只调高度参数后复用。 |
| `sources/ros_navigation/move_base/config/{global_costmap_params,teb_local_planner_params,mpc_tracking_params}.yaml` | 全局代价地图使用`odom`，扫描配置有重复`topic`键；TEB使用线段足迹，代价地图与MPC使用不同矩形尺寸。必须重新定义唯一车体模型与参数源。 |
| `sources/ros_navigation/move_base/src/move_base.cpp`：构造函数 | 强制加载停车插件；常规`move_base/make_plan`服务注册被注释，简单目标订阅改为旧状态机话题。不是可直接替换的标准`move_base`。 |
| `sources/ros_navigation/route_planner/src/AStar.cpp`：`isCanreach/getSurroundPoints` | 通过KD树连接附近航点，实际可达性检查未读取障碍栅格；不能保证连边不穿墙，也没有实现地图中轴提取。 |
| `sources/ros_navigation/parking_path_planner/src/parking_path_planner.cpp`：`checkTrackSecurity` | 内层循环到足迹末点时仍访问`j+1`，存在越界；其调用还在一处路径检查中被注释。停车模块需要单独修整和验证，不能因包含MPC就视为可直接部署。 |
| `sources/pc_filter/scripts/filter.py`、`sources/ros_navigation/move_base/scripts/odom_helper.py` | 前者将时间改为当前时刻、输出仅XYZ并使用固定自车屏蔽框；后者近似同步后直接拼接pose与twist，未证明两个消息的子坐标系和有效性兼容。 |
| `sources/shared_control/src/try1.cpp`：`ScanCallback` | 按固定180点和每点1°解释扫描，未按实际角度元数据换算；与包内另一套扫描角分辨率不一致，不能直接接入。 |
| `sources/ros_navigation/move_base/scripts/pub_odom.py` | 打开真实串口，保留停车输入，但收到的控制时间仅被赋值、未用于命令过期停车；失去发布者后不能依赖此脚本证明会自动停止。 |
| `sources/imu2imu/src/map_switcher/src/map_switch_node.py` | 启动新map_server后等待5秒又停止该新进程；没有管理旧地图，也没有同步切换定位地图。 |
| `sources/map_merge_tools/`、`maps/yanjiuyuan/floor2.yaml` | 合图脚本使用人为平移；二楼YAML的X原点比注释中的独立地图原点大400米。该偏移不是地图间标定结果。 |

### 旧地图怎样使用

`floor1_less_people.jpg`和`floor2.jpg`的房间、走廊和部分柱体清楚，可以参考呈现效果与场景布局。图像为JPEG，名称不能证明去人效果、几何精度或与哪份三维地图配套；`floor1_regions.json`等保存的是图像像素多边形，也不能直接当世界坐标区域。

按各自YAML阈值，两张图的外边界像素约99.98%／99.95%被判为空闲，不能从白底推断外侧已经观测。现阶段不把这些图注册为当前默认导航地图，也不靠修改origin消除配套关系的不确定性。新地图使用无损PGM与独立楼层身份，不沿用400米偏移。

## 2. 共享感知输入

地图生成、局部几何、视觉／地点记忆和有图／无图衔接统一按[感知实现方案](../perception/技术实现-环境地图与场景表示.md)实施。导航消费这些事实，在`navigation/planning/`增加静态／局部／社会代价、足迹与运动约束；`control/`负责控制模式与真实反馈，`safety/`负责独立停车、时效和接管。

占据地图是共享环境包的一种导出，膨胀不烘焙进原几何；map_server不负责定位变换。地图／关联改变使相关全局目标、路径与缓存失效，不能继续按旧绑定执行。无先验地图时依靠有效局部几何，目标须有明确的局部参考或转换依据。

## 3. 导航接入顺序

| 阶段 | 实现与验收边界 |
|---|---|
| A：共享环境 | 按感知方案形成有效局部几何、可选先验及明确状态，地图导出与观察查询不在导航侧重复实现。 |
| B：只规划 | 适配Noetic的map_server、静态costmap及GlobalPlanner，输入明确坐标的起终点，输出路径和RViz叠加，不连接底盘。未知区域禁止穿行；核对新规划路径不切墙、不穿未知。 |
| C：局部几何与TEB | 接入共享环境的实时障碍、局部定位与关联状态，需要时用`PointCloud2`兼容已有插件；无先验时使用明确的局部目标。回放中只输出候选控制，核对障碍与路径；bag里的人工行驶轨迹不是规划器控制后的轨迹，不能据此报告导航成功率。 |
| D：控制与安全 | 车辆参数与协议确认后，接连续车体速度、命令仲裁与独立停车监督；完成静止／台架检查后，才安排另行授权的低速实机测试。 |
| 后续任务 | 在几何基线之上接个人空间与社会代价、跟随、终端停靠；再按需要实现楼层拓扑、地图协同切换与电梯任务。 |

### C／D阶段的明确前提

- **车体模型**：统一测量雷达—车体外参、足迹、驱动形式、转弯能力、速度／加速度和制动余量；不能复制旧TEB的线段足迹与最小转弯半径。
- **TF发布权**：当前定位链是`map→odom→rslidar`。引入车体后按[REP-105](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)明确改为`map→odom→base_link→rslidar`，相应调整现有发布方；不能保留`odom→rslidar`又给rslidar增加另一父节点。无图模式不伪造地图定位。
- **局部障碍**：消费感知提供的几何与观测覆盖，保持未知和过期语义。Noetic的[ObstacleLayer](https://github.com/ros-planning/navigation/blob/noetic-devel/costmap_2d/plugins/obstacle_layer.cpp)支持点云输入，但需确认代价地图的清除规则不会扩大感知所证明的自由空间。
- **位姿与速度**：连续定位和地图修正分开，编码器只作为有来源的速度反馈；`Odometry.twist`须符合子坐标系约定，不能无条件拼接。人物速度继续遵循当前感知的有效性与自车运动补偿规则。
- **控制出口**：规划器与手动模式先输出候选命令，经唯一仲裁和独立安全监督后才到驱动；失效、断流及过期不能保留上一条非零速度。旧`/stop`等信号可以适配，但不替代完整时效处理。
- **倒车与低矮障碍**：核对实际传感器可观测范围，未确认后方覆盖前不开放自主倒车；当前行人模型不承担非人物障碍及地面落差的完整识别。

以上是导航接入条件，不作为重开既往感知问题的清单。当前标定适用边界仍只维护在[建图与定位](../perception/技术实现-建图与定位.md#标定与数据边界)。

## 4. 资料保留与实施边界

原ZIP保持只读，现阶段不把整套旧导航仓库、重复消息包、旧依赖库或二维地图复制到项目。后续确需移植的代码保留原许可证及包内`provenance/SOURCE_MANIFEST.json`来源记录；标准组件优先使用适配当前ROS环境的上游发行版，不混用Melodic二进制。

资料位置、身份及本机检查仅记录在忽略的环境记录中。实际实现后以本专题承接设计和边界，操作命令进入相应手册，不另外积累开发流水文档。
