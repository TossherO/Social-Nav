# 技术实现：任务与路线

导航接收的是明确的目标和运动要求。局部决策可以提出跟随或停靠目标，外层 Agent 当前优先组织完备地图下的室内点、区域及有序串联。Agent 读取空间信息后直接选择连续位置和朝向，导航检查原始目标，不替它生成终点候选；这些目标都要先经过几何规划，再进入控制和独立安全检查。Agent 的任务与输入见[技术实现](../decision/Agent技术实现.md)。

本文解释两类接口：`TaskPolicy` 将局部 VLM 响应转换为导航输入，`RoutePlan` 将有来源的分段路线转换为目标。几何算法见[路径规划](技术实现-路径规划.md)，速度与执行限制见[局部控制与安全](技术实现-局部控制与安全.md)。运行命令见[运行手册](../感知导航运行手册.md#导航离线查询与仿真)，待办见[共同清单](../感知导航实机问题.md)。

## 决策目标适配

`navigation/tasks.py` 中的 `TaskPolicy` 只处理调用方已经取得的响应，不请求模型，也不运行 Agent 主循环。为了知道响应对应哪一次观察，它先生成一张单次使用的票据，再核对响应：

1. `observe(scene, pid_to_track=..., candidates=...)` 保存原观察、时钟、定位生命周期、实际渲染使用的 PID 映射和候选集，返回票据。调用方必须提供真实映射，不能根据 PID 数值猜跟踪身份。
2. `respond(ticket, raw_response, scene=..., now=...)` 复用决策侧的 Schema 与语义检查。过时、被修改、已取消、重复使用或不再是最新的票据都会被拒绝，原响应不会被修复或静默重试。
3. `update/cancel` 随新观察更新或撤销目标。调用方把 `plan` 请求交给导航，用 `stop` 撤销活动运动；社会关系本身不能授予通行许可。

| 任务 | 转换后的导航输入 |
|---|---|
| T1 群组 | 有来源和有效期的软关系。成员身份包含跟踪会话、代数和 `track_id`；关系过期后退回个人空间。 |
| T2 跟随 | 根据可靠运动方向或当前方位，生成保持距离的局部停车目标。位移滞回减少无必要的修订，遮挡不刷新视觉确认时间，丢失、失效或重置时请求停车。 |
| T3 选点或让行 | 只接受同一观察、连续局部坐标下的显式候选，保留候选 ID 和来源，生成带朝向的停车目标。`wait` 表示停止，倒退仍需单独许可和可靠后向证据。 |

历史候选标记 `geometry=feasible`，也不能跳过当前规划。相机或雷达坐标中的候选，须由上游使用原观察位姿转换；本接口不会猜坐标。几何到达不是就座或长程任务完成，后者仍需要真实桌椅关系、停止状态和阶段反馈。

局部 VLM 的自动在线请求与持续导航执行尚未接通。外层 Agent 已有独立的 runtime 影子适配，它不等于 `TaskPolicy` 已接入局部 VLM 在线流程，见[Agent 技术实现](../decision/Agent技术实现.md#观察与导航适配)。

### 响应期限与任务反馈

决策侧的 [`DecisionRequest`](../../decision/vlm/navigation.py) 保存单次请求、原窗口的身份映射、Schema 和接收期限。取消或迟到的响应不能覆盖当前任务。

跟随响应的接收期限与已确认身份的保持期是两件事。默认保持期由 VLM 配置中的 `tasks.follow.visual_memory_s` 维护，冻结离线实验仍读取自己的 settings。保持期间，每次更新都需要新鲜场景和连续有效轨迹；轨迹断流会撤销保持，遮挡不会刷新视觉确认时间。等待下一次响应时，目标仍引用上一次已接受票据，不能把新输入称为新决策。

T3 的 `check-navigation` 对每个候选调用当前参考规划器，检查足迹、未知、人物和运动限制。检查结果另存，不修改原候选，也不宣告执行成功。`SeatingStage.observe_navigation` 只接收对应任务、目标修订和请求摘要的执行反馈，并区分仿真与机器人，拒绝影子提议和命令 ACK。字段及操作见[阶段与完成反馈](../decision/VLM部署与调用.md#阶段与完成反馈)。

## 室内、室外与换层路线

`planning/route.py` 中的 `RoutePlan` 接收有来源的有序折线和分段身份，为已有规划器生成目标。它不负责建图，也不生成执行反馈。路线 JSON 包含 `route_id/source/anchors/segments`。

| 字段 | 含义 |
|---|---|
| `segment_id/mode/source` | 每段的身份、运行模式和来源。 |
| `floor_id/points_xy` | 几何段所属楼层，以及按行驶顺序排列的米制折线。 |
| `map_id/frame_id` | 地图段对应的资产与坐标系。 |
| `anchor_id` | 局部段使用的锚点，例如门口。 |
| `anchors` | 包含 `map_id/map_frame/map_from_anchor/source`，变换为 XY 平面 3×3 齐次矩阵。 |
| `from_floor/to_floor/confirmation_source` | 换层前后楼层，以及真实外部确认的来源。 |

各段的运行要求如下：

| 路线段 | 使用条件 |
|---|---|
| `mapped` | 当前地图关联必须指向同一地图，并核对静态环境包；关联失效则暂停。 |
| `local` | 离图前通过有效关联把锚点转换到连续局部坐标。离图后，这个旧变换只用于目标参考，不作为新的地图定位。 |
| `transition` | 只返回 `waiting_for_external_confirmation`，不能根据录制时间、折线终点或规划成功判断已经到层。 |

不同楼层即使都把坐标系命名为 `map`，地图资产身份仍独立。没有测量依据时，不构造跨层米制变换。局部坐标重置、会话或时钟变化、路线修改后，都要重新确定锚点关系；返回地图后也要重新核对地图关联。

## 进度、状态与反馈

`RouteSession` 保存当前显式选择的路线段、目标修订、几何进度和锚点。折线匹配只在已有进度前方的有限弧长内进行，防止在交叉路口跳到远处的后续段。前视目标仍须检查完整足迹、占据和未知区域，几何进度不等于实际执行反馈。

换层确认必须对应任务、路线段、修订、楼层和外部来源。收到确认后，调用方仍需显式选择下一段。当前没有在线楼层识别或电梯控制，定位重置后也不会自动跨段推进。

`route_reference.json` 保存匹配进度与目标，`results.json` 保存几何结果。离线可用人工选点或录制演示准备路线，但须说明它是开发参考。不能用同一行程的未来扫描填充当前地图，也不能把该回放报告为盲测或闭环成功率。

## 统一运行时接口

`runtime.command` 通过本机私有 Unix socket 提交目标、取消和接管或急停意图。接收确认只表示意图收到，不表示运动已经执行。请求保留任务、目标修订、坐标和参考点，取消后恢复需要新的修订。

路径、控制和安全分别核对目标所属的任务与定位生命周期，迟到结果不能覆盖新任务。在线路线和 `TaskPolicy` 仍由调用方组织，runtime 不会自行调度长程任务。外层 Agent 可通过既有影子接口提交目标与取消，但不能绕过几何和独立安全直接驱动底盘。

### 录制行程的分段目标回放

`--route`显式启用`planning/route_replay.py`，`--route-floor`指定本轮楼层。适配器复用`RoutePlan`，要求路线来源的bag指纹与当前原包一致，并明确声明为开发参考。窗口使用原包的测量时钟，不因`--start`而重新从零计时。它既不识别楼层，也不接收录包轨迹作为本轮运动执行反馈。

每次有效场景到来时，适配器在已选择的折线上匹配有界、单调的几何进度，生成前视目标。目标更新间隔与位移门限由`configs/runtime.yaml`的`route_replay`维护，避免逐扫描修改目标而反复取消后台搜索。生成目标仍经过原参考规划、DWA和独立安全，地图未知或曲率不满足时可以拒绝。

对滚动中间目标，`RoutePlan`可以沿同一折线生成少量逐步缩短前视的候选。直接运行时的`--route`适配器先用当前导航图筛除已能证明足迹受阻的候选，再提交一个目标到后台参考进程。每次选择都生成新的目标修订和请求摘要；规划器不会静默改变请求终点。手动目标、Agent目标以及明确的路线停车终点不走这种替换。

参考进程返回经过原任务、场景、时钟和地图核对的失败后，路线适配器才尝试下一候选。原生搜索预算在一轮候选间分配，额度总和不超过原单次预算；输入准备、最终认证和等待调度的耗时另计。候选步长、数量及绕行上限由[规划配置](../../navigation/planning/configs/planning.yaml)的`route_goals`维护。中间路径超过相应长度上限时报告`route_candidate_detour`，表示该候选不符合路线策略，不是证明环境无路。路线末端不套用中间目标的绕行上限。

较短目标选中后，轮椅需要取得相应路线进展才恢复普通前视，避免静止时在长短目标间反复切换。已通过的非末端中间目标，在横向偏离合格时可以提前更新；这不报告任务完成或推进楼层。候选耗尽后保留当前目标，由参考进程按原失败退避在新场景上重试。路线层不保存额外的阻塞候选集合，也不因地图恢复重新生成一批目标；因此静止时不会重新尝试此前跳过的其他目标。原目标的迟到失败不能修改新目标。

每个候选仍须接受路径、人物和有限时域运动检查。短几何路径不保证当前初速下可执行；全部候选受阻时保留明确的失败目标和任务，不通过取消目标减少失败统计。该候选切换目前接入录制路线影子回放，通用`RouteSession`仍由调用方显式组织。

有图段必须保持正确地图关联；失去关联时取消当前目标。进入局部段前，使用过去有效关联把入口锚点转换到连续局部坐标，离图后不刷新为新的地图定位。锚点缺失时等待，定位生命周期或时钟重置后停止调度，要求重新开始该回放。手动目标、取消或接管会持续抢占录制路线，不自动恢复。

同一路线段内，只有地图或导航静态支持的测量时间暂时不合格时，回放保留目标并暂停更新，控制和安全继续拒绝失效输入。新输入恢复后沿原任务核对，不为一次短暂过期额外取消和重新下发目标。路线换段、真正失去关联、外部取消和定位重置仍走原来的撤销逻辑。

| 楼层 | 路线段 | 录制窗口与目标模式 |
|---|---|---|
| 一楼 | `f1_to_door` | 5–45秒，有图目标。 |
| 一楼 | `outdoor_loop` | 45–345秒，门口锚点下的局部目标。 |
| 一楼 | `f1_return` | 345–355秒，重新关联后的有图目标。 |
| 一楼 | `f1_lift_approach` | 355–367秒，电梯口锚点下的局部目标。 |
