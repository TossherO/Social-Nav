# 轨迹规划模块重构方案

重构的目标是让轮椅能稳定地通过走廊、窄门和转角，并根据行人与轮椅到达同一位置的先后顺序，选择保持速度、提前减速、局部绕行或更换通道。第一版保留 Hybrid A*、DWA 和独立安全监督，先改它们之间传递的信息和采用结果的条件。本文是开发方案。现行算法和运行参数分别见[路径规划](技术实现-路径规划.md)和[局部控制与安全](技术实现-局部控制与安全.md)。

## 为什么先改规划与控制的衔接

11 月 25 日，车载机原速回放 10 月 23 日一楼行人 bag，使用人工修订静态图、18 m 窗口、0.10 m 栅格和 `trial` 运动档。同一固定目标的 24 次查询全部返回路径。23 次进入原生搜索，其中 19 次实际展开了状态。原生搜索耗时中位数为 24.6 ms，完整后台计算为 71.8 ms，最大为 342.5 ms。相邻查询提交和结果返回的间隔中位数分别为 1.01 s 和 1.04 s。二楼更困难的固定目标回放中，默认 RViz 下含原生搜索的完整规划 P50/P95 为 407/793 ms，DWA 实际生成候选的周期为 13.4/19.0 ms。调度等待、搜索计算和控制采用结果应分别计时。[车载测速](../推理速度记录.md#二楼导航优化回放)

一楼同期 245 个有控制提议记录的周期中，195 个给出候选，4 个等待后台参考，1 个因预测人物碰撞而无可用速度。另有 **45 个周期全部在首段要求原地旋转时报告 `rotation_anchor_not_reached`**。现有 DWA 接到新参考会回到第 0 段，车体距旋转点超过 0.12 m 即退出，尚未进入速度采样。影子回放的车体沿录包轨迹移动，这个计数能定位拒绝发生的环节，无法推算实车停顿次数。复查入口为 `outputs/navigation/floor1_bag_replay/20261125_175018/run/` 下的 `reference.jsonl` 和 `control.jsonl`。[DWA 分段跟踪](../../navigation/control/dwa.py)

动态场景还暴露出两处设计限制。全局查询把当前人物圆投到工作图上，缺少对“轮椅到门口时人是否还在那里”的判断。局部控制已经按世界系匀速预测人物中心，并评价个人空间，但轨迹协方差尚未用于描述未来位置的分散程度。如果全局先撤掉一条短暂被人占用的通道，局部即使能找到合适的通过时机，也可能失去可跟踪的参考。[全局工作图](../../navigation/planning/planner.py) · [人物预测](../../navigation/planning/people.py)

## 目标、参考路径、速度与执行反馈

保留现有目标入口、车体轮廓、公共安全余量及底盘保护。重构按下面的职责接入现有模块。

| 模块 | 负责的决定与输出 |
|---|---|
| 任务层 | 指定目标、坐标系、是否要求终点朝向和途经点顺序。普通目标足迹被占据时接收明确反馈，由任务层决定是否换目标。 |
| 全局参考规划 | 在静态图和可核实的背景修订上选通道，给出满足车体几何的位姿序列。标出前进、倒车、原地转向及必须停稳的换向点，同时标明哪一段正在等待行人让出。 |
| 局部轨迹规划与控制 | 从最新实测位姿和速度接入参考，预测候选车体随时间的运动，选择本周期速度。向参考层分别报告正常让行、首段接不上、局部绕行失败和通道持续受阻。 |
| 独立安全与执行 | 独立 CPU 进程用自身最新的定位、地图、人物和运动反馈复核本周期速度。当前车体接触、近端碰撞、超时、急停与接管继续按既有机制处理。任务完成仍依据相应执行模式的真实反馈。 |

先用有图固定目标验证。仅给 XY 的目标保留终点朝向自由度，指定朝向的停靠保留末端姿态。多点任务沿用点序及途经或停车要求。T2 连续目标沿用跟随身份与目标修订，跟随对象也参与碰撞检查。T3 沿用桌体禁入区和停靠朝向。无图模式在局部坐标系内使用同一套人物预测和控制逻辑。有图任务丢失地图关联后暂停，换图、换目标或定位重置后重新核对参考和跟踪进度。[任务与路线](技术实现-任务与路线.md)

### 让控制器从当前位置接入参考

后台生成的路径到达控制端时，轮椅可能已经移动。首次采用时应按当前位姿、行驶方向和最新局部图检查首段。同一目标、同一定位会话下，如果只是对原路径重新验证，且能确认当前动作段对应，则继承进度。确需接回时，从实际位姿尝试一段短连接，对连接和接入处执行完整车体扫掠。无法接入就反馈原因，以更新位姿重算。轨迹有自交或前进倒车重叠时，按已完成的动作段和运动方向选接入点，防止跨过必须停车的换向点。靠墙侧偏和向走廊中心侧偏即使距离相同，也应由实际扫掠给出不同判断。

## 用同一份行人预测决定速度和路线

### 随时间变化的高斯风险图

从已有 `PeopleModel` 扩展，每条轨迹携带身份、定位会话、坐标系、状态对应时刻、最近实测时刻，以及位置、速度和可用的协方差。在连续的局部世界坐标系预测，在需要投影到楼层时使用同一观察对应的地图关联。全局与局部查询同一种预测。安全进程独立读取其输入，不依赖控制器传来的评分或 GPU 热图。

第一版可试从轨迹状态时刻起 **3 s、每 0.25 s 一个时间切片**。这是离线试验起点。速度可靠时，未来中心取当前位置加世界系速度乘预测时长。将位置与速度协方差传播到各切片，再用近期预测残差补充沿行走方向和侧向的误差。直行稳定时分布可以较窄。转向、减速、短时遮挡时应覆盖继续前进和较小位移的可能。速度未知时保留最近观测位置，并用离线估计的误差范围描述不确定性。后续预测帧和迟到结果都保留最近实测时刻。误差过大、身份不符或输入过期时，撤销依赖“人将离开”的选路依据，回到当前有效几何和既有输入失效处理。

高斯描述**人的中心可能在哪里**，人体仍有独立的物理半径。第一版可在每个时刻用人体圆扩展轮椅足迹，取该范围内最高的高斯核值作为相遇风险。核值在预测中心取 1，随距离和方向衰减，这样范围变宽时不会仅因峰值下降而偏好穿过不确定区域。多人先取同一时刻最不利的相遇，再沿候选轨迹比较峰值和累计代价。原有个人空间代价只表达舒适性。实验图和日志均称“风险代价”。经 bag 检查预测误差和椭圆覆盖率后，才有依据解释概率数值。[现有人物运动与社会代价](技术实现-局部控制与安全.md#人物运动与社会代价)

### 局部控制按轮椅到达的时刻评分

对每个候选，在该候选到达某位置的**同一时刻**查询人物风险。例如，人预计 1 s 后已经离开门口，轮椅保持当前速度约 3 s 后才到，且途中有足够净空和制动空间，保持速度应优于无益的减速。若双方会同时到达，较早平缓减速可让轮椅从人身后通过。走廊足够宽时，也可以选择提前偏移后接回原参考。人停在窄门或运动方向不稳定时，应能等待后重新观察。

候选排序同时考虑相遇风险、沿路进度、速度变化和偏离参考的距离。用同一段预测时间比较所有候选，停等也要累计这段时间内的风险和通行延迟。两个候选都能低风险通过时，优先保持当前行驶节奏。预测不确定时，等待下一帧或平缓减速比依赖行人一定让路更合适。

保留 DWA 的近端动力学、车体扫掠和人物硬碰撞检查。现行轨迹预测时域为 1.5 s，人物硬碰撞时域为从当前检查时刻起 1.0 s。为比较更远的交汇，在近端候选末状态上沿可接入的参考段推演保持速度、平缓减速或等待，考虑转角限速、制动和必须停稳的动作段。延伸到预测范围末端的部分只用于评分。每周期仅提交通过近端检查且由独立安全复核的速度。输出应记录哪种候选胜出、最接近哪个人、预计何时相遇，以及候选被淘汰的原因。[DWA 实现](../../navigation/control/dwa.py) · [独立安全复核](../../navigation/safety/guard.py)

### 全局参考比较等候与改道

保留两种视图。当前接触检查使用背景加本帧人物圆。全局比较通道时，仅对能够与同一观测可靠匹配的人物单独查询时变风险。墙、门板、未知区域和归属不明的障碍沿用现有规则。已确认人物走过的格子也须有有效的背景自由证据。这样既不会把所有未来切片叠成封路的静态墙，也不会因为预测某人会走开就放行其身后的未知区域。[同帧障碍保留测试](../../tests/test_environment_support.py) · [行人附近障碍确认测试](../../tests/test_navigation_overlay.py)

首先评价现有参考的剩余路段，依据车速、转角和换向停顿估算轮椅的到达时间范围。只比较预测有效范围内的交汇，远段仍按地图几何选路。结合新增障碍与剩余车体扫掠的关系，按下表反馈。

| 连续观测与局部反馈 | 全局动作 |
|---|---|
| 障碍变化发生在路线以外 | 更新工作图，保留当前路线及既有时效复核。 |
| 行人短暂横穿，原路稍等或局部偏移即可恢复 | 保留通道意图，受阻段标为待复核。每周期由局部决定是否可以继续，并单独记录正常让行。 |
| 人群持续阻塞，或短距离绕行多次接不回 | 比较原路预计等待与少量替代路线的通行代价。替代路线连续显示优势时才切换，减少左右反复改线。 |
| 门关闭且剩余通道确已被整车几何截断 | 立即请求改道。再次观测到门打开并获得更新的空闲证据后，重新评价通道。 |
| 起终点足迹受阻、地图关联失效或规划超时 | 分别报告几何、定位或预算原因，交给对应层处理。查询超时本身无法证明目标不可达。 |

当前调度在保留障碍记录变化、或控制持续约 1 s 无候选或近乎停滞时会请求刷新，普通失败通常等待 3 s 再试。重构时应优先替换这些笼统触发条件。后台仍按目标修订、场景和地图会话核对结果。返回前通道已发生变化时，重新检查将被采用的路段。[参考调度](../../navigation/planning/reference.py) · [调度配置](../../navigation/planning/configs/reference.yaml)

## 路径形状、计算与显示

Hybrid A* 已能搜索前进、倒车、圆弧和原地旋转。当前解析直连分支通常从按长度和倒车代价排序的前 12 条候选中取首条通过扫掠的连接，较短连接可能在进入栅格搜索前返回。拟对预算内少量可行的解析连接与搜索路径使用一致的偏好，比较最小整车净空、转向与换向次数、能否顺着当前运动进入，以及相对旧路线的偏离。宽走廊优先选容易跟踪的向前圆弧，窄门中唯一可行的低净空走法和指定朝向停靠所需的旋转仍须保留。沿用本车既有轮廓和公共余量。[原生位姿搜索](../../navigation/planning/native/pose_search.cpp)

计算上，每个场景只准备一次附近行人的预测参数，局部控制批量查询候选足迹，全局后台只查询近段路线和少量替代路线。先以 CPU 给出的时间对齐和风险排序作为对照，再接入现有 DWA 的 GPU 批处理。RViz 有订阅时才按需绘制选定时刻的局部热图，标注预测源时间、预测时距和人物身份，并分别显示当前人物轮廓、参考路径、选中轨迹与预计交汇位置。关闭显示后，规划仍可用相同输入重现结果。[DWA 设备实现](../../navigation/control/device.py) · [导航显示](../../perception/visualization/navigation.py)

## 实施顺序与验收

各阶段沿用同一份基线配置，分别对照固定场景、录包和闭环结果。每次只切换正在比较的环节，保留原算法作为回退选项。

1. **先打通首段接入。** 固定一条首段旋转的路径，在闭环仿真中分别让车体向空旷侧和门框侧偏移。前者应在可扫通时接回，后者应拒绝碰墙连接。再覆盖旧路线复核、倒车换向和定位重置，记录首段接入率、无计划停顿及拒绝原因。
2. **用 bag 验证预测与取数。** 在轨迹时刻封存输入，仅用其后的实际行人位置作离线评估。在分开的调参与验证片段上，分别看直行、突然转身、停步和遮挡后的中心误差、椭圆覆盖率及宽度。覆盖率与宽度一起报告，防止把整条走廊都染成高风险也取得表面好成绩。核对 CPU 与 GPU 同输入的风险排序及 RViz 时间切片。
3. **先验证局部行为，再接全局改道。** 在同一路口保持轮椅初态相同，只改变行人到达时间或是否在门口停下。闭环中应分别出现保持速度、提前减速和等待。宽走廊增加可偏移绕行的对照。再以短时横穿和持续堵门对照全局触发。记录无益减速次数、首次减速距离、最小人车及墙边净空、恢复原路时间、改道时间和无必要的换路次数。bag 可比较相同观察下的候选评分，车辆响应和实际通行须用闭环仿真及获授权的实车复测。[现场采集与复测](../系统实机问题.md#现场导航六项反馈)
4. **按瓶颈决定是否替换算法。** 在同图、同预算、同起终点且有已知可行走法的窄门、L 弯和带朝向停靠样本中，如果 Hybrid A* 仍反复耗尽预算或产生难以跟踪的动作，比较针对本车运动片段的 State Lattice。二维 A* 或 Dijkstra 可用于检查通道连通性。如果同一条净空充足、首段可接的参考下 DWA 仍难以完成连续转弯或平缓让行，则比较能优化多段速度序列的 MPPI。两组分别比较任务完成率、净空和运动连续性。[State Lattice](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/planners_plugins/smac/) · [MPPI](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/controller_plugins/mppi_controller/configuring_mppic/)

切换默认实现前，在车载机原速回放、感知与定位同时工作的条件下，对照无显示与开启风险图两组负载。分别记录预测生成、参考提交到可采用、局部候选评分和认证的 P50/P95，以及控制首次使用观察时的源数据年龄和预算耗尽次数。对照组应保持地图、运动档、人与车的起始条件一致。只有闭环行为改善、净空与既有保护检查通过且能维持车载时延预算，才将通过验证的环节设为默认。
