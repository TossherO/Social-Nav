# 技术实现：局部控制与安全

局部控制把空间参考转换为速度提议，独立安全监督决定这份提议是否通过当前检查。默认实现使用一个 DWA 控制器选择速度，再由独立 CPU 进程检查车体、人物、延迟和完整制动过程。

当前系统处于影子运行和反馈仿真阶段，没有真实底盘命令出口。影子运行只记录建议；反馈仿真由虚拟执行器响应建议，两者的完成含义不同。

空间参考来自[路径规划](技术实现-路径规划.md)，任务要求由[任务与路线](技术实现-任务与路线.md)转换。运行命令见[操作速查](../感知导航操作速查.md)，后续工作见[共同清单](../感知导航待办与数据采集.md)。

## DWA速度选择

DWA 使用最新有效算法位姿估计真实初速，再根据实际控制间隔计算这一周期能达到的速度范围。它不会把上一条未执行的提议当成实测速度。

一次速度选择分为四步：

1. 在可达速度范围中采样少量线速度、角速度和必要的平稳减速动作。去重后最多保留 24 个候选，并要求速度、加减速和 `abs(omega) <= abs(v)/R_min` 满足约束。
2. 批量积分候选运动，预测完整停车过程，计算几何、人物和参考路径代价。
3. 按代价排序，对候选逐个完整认证，返回首个合格动作。粗筛通过不能替代完整扫掠。
4. 把提议交给独立安全进程，用该进程自己的最新输入终审。DWA 提议只终审一次，安全层不再开启第二套速度搜索。

评分考虑参考偏离、沿路径的进度、车体朝向、净空、人物和控制变化。轮椅接近转弯时提前限速，接近终点时按剩余距离、制动能力和响应延迟限速。进入 XY 和必要 yaw 容差后保持制动，停下后不会原地旋转来补齐朝向。上一条提议仅用于平滑。

控制器根据相邻参考位姿的位移与车体朝向区分前进、倒车，按方向相同的连续段选择速度。倒车使用负纵向速度和独立的倒车限速；当前开发上限为 0.2 米／秒，仍来自历史运动资料，用户确认的是倒车能力。路径匹配比较车体 yaw，不能把倒车的位移方向当作车头方向。

参考换向点要求停车。前视和评分不会跨过换向点，只有反馈位置、朝向和速度均满足相应容差才切换下一段。CPU 与 CUDA 的运动响应采用相同规则：目标速度与当前纵向速度异号时，先将线速度和角速度一起降到零，再向另一方向加速，避免穿过零速时残留原地旋转。测得的超速初态保留原值，控制器仅在模型范围内生成减速目标。

默认 `forward_preferred` 请求允许跟随规划器产生的倒车段；当前仍不接受显式强制倒车的 `reverse_required` 请求。是否允许倒车最终由运动配置决定，目标在车后本身不能绕过运动与安全检查。

评分时域可以较短，完整停车检查仍覆盖整个制动过程。解析制动弧、向量化 SE(2) 细分和 GPU 批处理保持既有采样与误差界；未知、越界或无法认证的候选仍会被拒绝。

### GPU与CPU职责

直接运行时让环境地图与 DWA 共处 GPU 主进程，DWA 直接引用设备地图。CUDA 负责批量积分、制动预测、候选评分和几何粗筛。CPU 取回评分摘要后排序，再按顺序读取所需轨迹，调用完整扫掠认证。

DWA 的设备适配位于 `control/device.py`。它依次准备原生参数、合并上传参考与人物等小数组、调用 CUDA，再取回评分与制动采样数。结果读取只等待对应的完成事件，设备地图的就绪依赖仍由快照提供。

积分、制动和传输缓冲区按容量复用，由同一个控制线程使用。一次评价及所需轨迹读取完成后，才开始下一次评价；这些私有工作区不作为共享地图发布。数据仍使用原数值精度，候选和完整认证规则不变。复制统计按输入字段归因，不能把字段计数当作实际 CUDA 复制调用数。

CPU 保留小型状态、全局搜索和独立安全检查。保守 GPU 包络无法判定时，可使用精确 CPU 自适应回退，并计数。另有 CPU 算法用于回归和显式诊断；系统不会静默切换后端。

## 人物运动与社会代价

默认人物预测采用世界坐标系下的确定性匀速模型（CV）。检测框常受扫描范围影响而偏大，因此身体包络使用固定身体半径，不直接取检测框对角线。原协方差继续保存，但不参与膨胀，结果标记 `uncertainty_applied=false`。

| 情况 | 处理方式 |
|---|---|
| 人物速度有效 | 用世界系速度预测短时位置，近期冲突作为约束，远期交汇可以计入软代价。 |
| 人物速度未知 | 保留缺失状态，以当前占据代理处理；内部零位移不表示测得人物静止。 |
| 检查终点停车或独立制动 | 检查完整停车过程，不因评分时域较短而截断人物冲突检查。 |
| 收到有效 T1 关系 | 构造有来源和有效期的软群体代价，不改变碰撞许可。 |

模型不假定行人已经避让轮椅。人物转向、停步、速度误差和漏检仍需独立验收。

感知的 `person_background_free` 表示某格当前由人物占据，而历史上有自由空间证据。导航可以据此构造独立的动态预测视图，但保留原占据、人物身份和栅格面积裕量。混有普通障碍或背景未知的格子不会获得该标记。

当前车体接触检查仍使用原图，导航不会清除输入占据或重写摘要。字段含义见[人物与任务接口](../接口约定.md#导航人物与任务适配)。

## 独立安全与时间

安全进程独立接收算法状态、地图和速度提议。它先核对任务、时钟、定位与跟踪身份、地图来源和测量时间，再检查当前足迹、延迟期间运动、人物以及完整制动过程。倒车同样检查车后完整扫掠，后方未知、占据或人物冲突不会因为开启倒车而放行。输入失效、取消、接管、急停或超时都会返回零建议；控制连接断开后保持停车状态。

接收线程与完整复核并行工作。如果复核期间到达新图，安全进程最多重新检查一次。发布前还会核对位姿、地图、提议和轨迹是否过期；数据持续变化或已过期时，不能继续发布旧的非零建议。只有本次复核结束并释放引用后，共享槽才允许复用。

外推和重新检查都不刷新测量时间。新定位结果触发控制，控制保留频率上限和单调时钟看门狗。安全遥测由旁路线程接收，不等下一轮感知循环。CPU 安全胶囊下载原占据、对应人物背景及启用融合时所需的认证与来源字段。DWA和CPU安全分别核验[导航派生图](../perception/技术实现-环境地图与场景表示.md#静态自由支持的导航派生图)，当前障碍不能被历史自由覆盖，静态支持也不表示当前新观测。

### ROS诊断边界

以下话题用于旧 ROS 诊断，默认直接运行时的核心计算不经过它们：

| 话题 | 含义 |
|---|---|
| `/navigation/planning/{goal,cancel,state,trajectory}` | 目标、取消、只规划状态和预测 Path。 |
| `/navigation/shadow/{observation,proposal,state}` | 原观察记录、速度提议和独立复核结果。 |
| `/navigation/shadow/velocity` | `base_link` 纵向速度与 yaw 角速度建议，禁止重映射到其他话题。 |
| `/navigation/shadow/override` | 保持到明确解除的接管或急停状态。 |

预测 Path 的头时间为反馈时刻，各点时间为该时刻加相对预测时间，Z 只用于二维显示。影子输出始终保留 `executable=false/task_completed=false/execution_feedback=false`。

## 反馈仿真

仿真由独立虚拟执行器积分得到运动真值，不能直接用提议充当初速。`GoalMonitor` 只有在有效反馈持续满足位置、必要朝向和停车保持要求后，才报告目标完成。持续跟随只报告距离保持，取消或状态失效会重置计时。

测试可以显式扰动执行器延迟、加速度和反馈噪声，但不会随扰动放宽规划模型。合成传感器没有完整模拟真实遮挡、地形和动力学。bag 影子运行中的车辆沿原录制轨迹运动，因此只能检查观察与建议时效，不能当作执行闭环。

## 实车接入边界

轮椅支持倒车已由用户确认，当前影子导航和反馈仿真允许倒车，仍禁止原地转向。历史几何、速度、制动和响应限值仍是开发参考；载荷、雷达到车体外参、后向覆盖和实际运动限值须实测。倒车能力确认不等于这些数值已经验收。

接入车体时，需要明确 `map→odom→base_link→rslidar` 中每段 TF 的唯一发布者，不能让雷达同时拥有两个父节点，见 [REP-105](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)。位置来自定位算法；编码器可以提供有来源的速度，原始 ROS 里程计不能替代可靠定位。

真实底盘出口必须经过唯一命令仲裁、独立安全、接管、急停和硬件保护。当前尚无该出口，所有建议不可执行。实际运动还需要明确授权与安全准备。
