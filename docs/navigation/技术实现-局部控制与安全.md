# 技术实现：局部控制与安全

局部控制把空间参考转换为速度提议，独立安全监督决定这份提议是否通过当前检查。默认实现使用一个 DWA 控制器选择速度，再由独立 CPU 进程检查当前车体足迹以及有限时域内的车体和人物运动。

默认系统使用影子运行，反馈仿真由虚拟执行器响应建议；显式实机模式另有受控串口出口。轮椅端已取得单项低速动作的现场证据，完整自主目标导航仍未验收，见[实车接入](#实车接入边界)。

空间参考来自[路径规划](技术实现-路径规划.md)，任务要求由[任务与路线](技术实现-任务与路线.md)转换。运行命令见[运行手册](../感知导航运行手册.md)，后续工作见[共同清单](../感知导航实机问题.md)。

## DWA速度选择

DWA 使用最新有效算法位姿估计初速，再根据实际控制间隔计算这一周期的常规速度采样范围。它不会把上一条未执行的提议当成实测速度。

一次速度选择分为四步：

1. 在常规范围中采样少量速度目标和必要的平稳减速动作。车辆档案可设置非零指令的最低幅值；去重后候选数受 DWA 配置的预算限制。不允许原地旋转时，还要求 `abs(omega) <= abs(v)/R_min`；当前配置允许原地旋转，不施加这条曲率约束。
2. 批量积分有限时域内的候选运动，计算几何、人物和参考路径代价。
3. 按代价排序，对候选逐个完整认证，返回首个合格动作。粗筛通过不能替代完整扫掠。
4. 把提议交给独立安全进程，用该进程自己的最新输入终审。DWA 提议只终审一次，安全层不再开启第二套速度搜索。

启用最低非零指令时，每个常规线速度采样值还会配合零角速度目标；速度高于当前限速时，也提供零角速度的减速目标。零角速度是目标值，不表示当前转速瞬间消失：候选预测和独立安全仍从实际估计转速按运动模型积分。这样可以避免小幅非零转速被最低角速度过滤后，只剩最低线速度或零速。

车辆档案可设置 `minimum_command_speeds`，分别限制前进、倒车和角速度指令的最小非零幅值。限制适用于整个导航过程，零速始终保留。控制器增加符合限值的候选，并在评分前过滤低于限值的非零候选；所选目标仍需通过完整扫掠和独立安全检查。接近终点或换向点且尚未进入对应容差时，单纯按剩余距离或角度计算的接近限速可以提高到最低指令幅值；其他速度、曲率及安全限制仍然生效。若没有可用非零候选，输出 `minimum_command_blocked` 供诊断。

最低速度是用户指定的指令幅值，不是瞬时实际车速或已经测定的死区。接近终点、换向点或旋转目标时，控制器依据剩余距离或角度、朝目标的估计速度、单个控制周期和运动配置的加速度模型，计算名义停止余量；达到余量后请求零速，并在后续周期重新检查。静止滤波前的速度估计也参与停令计算，不能刷新原观察时间。该余量不是实测停车上界；独立安全仍重新预测并检查同一速度目标，实际车辆的响应速度、停车和预测假设仍须现场验证。

评分考虑参考偏离、沿路径的进度、车体朝向、净空、人物和控制变化。轮椅根据前视范围内的路径曲率限速，接近终点时按剩余距离除以预测时域限速；配置最低指令时采用上面的近目标规则。参考包含原地旋转时，先到达转向位置并降低线速度，再采样零线速度的角运动。进入 XY 和必要 yaw 容差后保持零速请求。上一条提议仅用于平滑。

控制器根据相邻参考位姿的位移与车体朝向区分前进、倒车，按方向相同的连续段选择速度。倒车使用负纵向速度和独立的倒车限速；当前开发上限为 0.2 米／秒，仍来自历史运动资料，用户确认的是倒车能力。路径匹配比较车体 yaw，不能把倒车的位移方向当作车头方向。

参考按前进、倒车和旋转分段，段间要求停车。前视和评分不越过当前段，只有反馈位置、朝向和速度均满足容差才切换。较长旋转继续按参考指定方向分段跟随，不用最短角替换可能绕过障碍的转向。CPU 与 CUDA 的运动响应一致：纵向速度换符号时先制动，再向另一方向加速；纯旋转单独比较终点朝向和转向位置偏差，不依赖不存在的平移路径长度。超速初态保留原值，控制器仅生成模型允许的减速目标。

默认 `forward_preferred` 请求允许跟随规划器产生的倒车段；当前仍不接受显式强制倒车的 `reverse_required` 请求。是否允许倒车最终由运动配置决定，目标在车后本身不能绕过运动与安全检查。

DWA 和独立安全使用[安全配置](../../navigation/safety/config.yaml)中共同的预测时域和采样间隔，默认分别为 1.5 秒和 0.1 秒。足迹对静态占据、未知和越界的检查覆盖完整预测时域。人物硬碰撞检查使用[规划配置](../../navigation/planning/configs/planning.yaml)中的 `people.hard_horizon_s`，默认从当前检查时刻起 1.0 秒。这个预测不覆盖时域之后的制动过程，也不能保证车辆在障碍物或行人前停稳。

### GPU与CPU职责

直接运行时让环境地图与 DWA 共处 GPU 主进程，DWA 直接引用设备地图。CUDA 负责批量积分、候选评分和几何粗筛。CPU 取回评分摘要后排序，再按顺序读取所需轨迹，调用完整扫掠认证。

DWA 的设备适配位于 `control/device.py`。它依次准备原生参数、合并上传参考与人物等小数组、调用 CUDA，再取回评分。结果读取只等待对应的完成事件，设备地图的就绪依赖仍由快照提供。

积分和传输缓冲区按容量复用，由同一个控制线程使用。一次评价及所需轨迹读取完成后，才开始下一次评价；这些私有工作区不作为共享地图发布。数据仍使用原数值精度。复制统计按输入字段归因，不能把字段计数当作实际 CUDA 复制调用数。

CPU 保留小型状态、全局搜索和独立安全检查。保守 GPU 包络无法判定时，可使用精确 CPU 自适应回退，并计数。另有 CPU 算法用于回归和显式诊断；系统不会静默切换后端。

### 认证预算与诊断

每次DWA调用为全部候选的预测扫掠和人物检查共享认证期限，另受调用开始后的总计算期限约束。自适应CPU扫掠还共享几何查询次数，避免把每条候选的上限重复使用。具体参数由[dwa.yaml](../../navigation/control/dwa.yaml)维护；该查询计数只统计精细CPU几何检查，不等于GPU工作量或候选数量。

`SweepChecker`在当前调用中保留各区间的包络认证结果，只对尚未证明自由的区间进行CPU细分。复用限定于相同地图、轨迹和安全裕量，不跨观察缓存认证结论。占据、未知、地图之外和无法证明间距充足的区间仍拒绝放行。

CUDA后端先用现有批量碰撞内核对不确定区间最多细分四级，每批不超过单次扫掠样本上限。只有覆盖原区间的全部子区间均证明自由，才复用该证明；未完成或仍不确定的区间继续交给CPU。每批之间检查共享期限，不修改原裕量、地图状态或连续扫掠范围，也不需要新增CUDA编译。`gpu_refinement_batches/enclosures`记录实际追加的批次和包络数。

期限检查进入细分循环，并在人物检查结束与结果发布前再次执行。超时或共享次数耗尽时返回`certification_time_budget_exceeded`或`certification_work_budget_exceeded`，清空本次结果及用于下一轮采样的上一目标速度缓存。独立安全复核另按自己的控制间隔检查预测认证期限，不信任DWA的证明；源观察时间和串口心跳期限沿用原语义。

提议的`certification`分别记录预测扫掠、人物检查、包络批处理和CPU回退耗时，并保存回退次数、复用区间数、精细查询数与预算原因。预测扫掠时间包含其内部包络和回退，不能再次相加。相关汇总仅为标量，不增加整图传输。

这些是协作式计算预算，GPU同步、单次原生调用和系统调度仍可能越过截止时刻；完成后发现超时的结果会被拒绝，不能因此宣称硬实时。预算也可能使原本最终可通过的候选在本周期未能完成认证，性能口径见[推理速度](../感知导航推理速度.md)。

## 人物运动与社会代价

默认人物预测采用世界坐标系下的确定性匀速模型（CV）。身体包络以配置半径为下限；当地图已将本帧可靠人物点交给该身份时，半径还须覆盖这些点并保留2厘米余量，不直接采用检测框对角线。原协方差继续保存，但不参与膨胀，结果标记 `uncertainty_applied=false`。

| 情况 | 处理方式 |
|---|---|
| 人物速度有效 | 用世界系速度预测短时位置，近期冲突作为约束，远期交汇可以计入软代价。 |
| 人物速度未知 | 保留缺失状态，以当前占据代理处理；内部零位移不表示测得人物静止。 |
| 独立安全复核 | 从反馈时刻复核至当前时刻，并硬检查当前时刻之后配置时长内的人物冲突；更远冲突保留为预测诊断。 |
| 收到有效 T1 关系 | 构造有来源和有效期的软群体代价，不改变碰撞许可。 |

模型不假定行人已经避让轮椅。人物转向、停步、速度误差和漏检仍需独立验收。

地图将同帧可靠人物点从背景占据更新中分离，并封存 `person_objects`。导航逐个核对人物来源、身份和位置，匹配后由带时间的圆承担碰撞检查；未知速度的单个人物保留当前占据代理，不影响其他人物接管。背景原有未知和普通占据不会因此变为空闲。

当前车体接触检查使用背景加本帧人物圆。跟踪记录缺失或不匹配时，对应圆继续作为静态障碍；GPU控制仅在这种回退时上传派生占据图。异步或旧式人物证据仍可通过 `person_background_free` 表示历史自由背景，只有来源匹配且人物速度均有效时才使用原有预测视图。导航不重写输入摘要，字段含义见[人物与任务接口](../接口约定.md#导航人物与任务适配)。

## 独立安全与时间

安全进程独立接收算法状态、地图和速度提议。它先核对任务、时钟、定位与跟踪身份、地图来源和测量时间，再从反馈时刻推算至当前时刻，检查当前足迹和有限时域内的车体运动。人物硬检查包含反馈年龄与当前时刻起配置的 1.0 秒；较远的预测冲突不会直接拒绝当前候选。倒车同样检查车后预测扫掠，后方未知、占据或硬检查时域内的人物冲突不会因为开启倒车而放行。输入失效、取消、接管、急停或超时都会返回零建议；控制连接断开后保持停车状态。

接收线程与完整复核并行工作。如果复核期间到达新图，安全进程最多重新检查一次。发布前还会核对位姿、地图、提议和轨迹是否过期；数据持续变化或已过期时，不能继续发布旧的非零建议。只有本次复核结束并释放引用后，共享槽才允许复用。

外推和重新检查都不刷新测量时间。新定位结果触发控制，控制保留频率上限和单调时钟看门狗。安全遥测由旁路线程接收，不等下一轮感知循环。CPU 安全胶囊下载原占据、对应人物背景及启用融合时所需的认证与来源字段。DWA和CPU安全分别核验[导航派生图](../perception/技术实现-环境地图与场景表示.md#静态自由支持的导航派生图)，当前障碍不能被历史自由覆盖，静态支持也不表示当前新观测。

### ROS诊断边界

以下话题用于旧 ROS 诊断，默认直接运行时的核心计算不经过它们：

| 话题 | 含义 |
|---|---|
| `/navigation/planning/{goal,cancel,state,trajectory}` | 目标、取消、只规划状态和预测 Path。 |
| `/navigation/shadow/{observation,proposal,state}` | 原观察记录、速度提议和独立复核结果。 |
| `/navigation/shadow/velocity` | `base_link` 纵向速度与 yaw 角速度建议，禁止重映射到其他话题。 |
| `/navigation/shadow/override` | 保持到明确解除的接管或急停状态。 |

预测 Path 的头时间为反馈时刻，各点时间为该时刻加相对预测时间，Z 只用于二维显示。影子输出始终保留 `executable=false/task_completed=false/execution_feedback=false`。

## 反馈仿真

仿真由独立虚拟执行器积分得到运动真值，不能直接用提议充当初速。`GoalMonitor` 只有在有效反馈持续满足位置、必要朝向和停车保持要求后，才报告目标完成。持续跟随只报告距离保持，取消或状态失效会重置计时。

测试可以显式扰动执行器延迟、加速度和反馈噪声，但不会随扰动放宽规划模型。合成传感器没有完整模拟真实遮挡、地形和动力学。bag 影子运行中的车辆沿原录制轨迹运动，因此只能检查观察与建议时效，不能当作执行闭环。

## 实车接入边界

轮椅支持倒车和原地旋转已由用户确认，规划、DWA 与独立安全已接入这两项能力。旋转仍检查预测时域内的完整轮廓，未知空间不能作为转向净空。能力确认和离线测试不表示导航到实机底盘的闭环已经验收。

接入车体时，需要明确 `map→odom→base_link→rslidar` 中每段 TF 的唯一发布者，不能让雷达同时拥有两个父节点，见 [REP-105](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)。位置来自定位算法；编码器可以提供有来源的速度，原始 ROS 里程计不能替代可靠定位。

默认规划候选与影子消息保持不可执行。`runtime.interactive --live --execute`另启用受控串口出口，要求本车已确认的轮廓、外参、运动和协议文件，并在初始化后人工使能。该出口尚未实机验收，实际运动仍需明确授权与现场停车条件。

独立CPU安全先将候选速度量化为实际串口整数单位，再检查当前足迹以及有限时域内的人物和车体运动。只有复核通过、目标仍有效且各源观察未过期时，才通过私有通道给独立串口进程授权。有效期取轨迹、地图、定位和提议剩余期限的最小值，最长0.15秒；重发心跳不延长原指令。默认影子链不加载这条输出路径。

当前不再计算完整停车轨迹或执行响应范围，故不能由预测通过推断真实制动距离内没有障碍。轮椅的实际延迟、减速与断发停车仍需现场验证；有限时域预测与实车响应可能不一致。旧模型见[停车预测归档](../archive/停车预测模型归档.md)。

串口进程以19200波特率独占设备，先确认零速与摇杆中立，再按模式3到模式1完成零速使能。它独立检查0.2秒安全心跳和0.25秒反馈期限，摇杆接管、反馈校验失败或模式异常会撤销使能。短时规划拒绝输出零速，取消和退出恢复零速与模式3。固件失联保护和实际制动仍需本车确认；串口接收时间不当作设备测量时间，也不发布真实到达结论。实现见[chassis.py](../../navigation/control/chassis.py)，操作见[交互测试](../感知导航运行手册.md#rviz交互测试)。

bag暂停预览直接复用规划器和DWA，在冻结场景的测量时刻使用因果定位历史。冻结结果有独立话题和身份检查，恢复播放即撤销，不进入安全授权或串口。其参考、轨迹与失败原因用于审查，不能当作真实反馈仿真。

串口诊断通过容量为2048条事件的队列交给后台线程，记录每次速度写入、底盘反馈、安全授权及状态变化。队列满时丢弃新增事件并计数，不等待磁盘；停止状态另行合并保存。退出先执行原停车流程，再有限等待日志排空。摘要缺失、不完整或有丢失时，不能据日志认定完整的速度与制动过程。DWA及独立安全仍使用定位历史估速，底盘上报速度用于驱动保护与诊断，本次没有切换估速来源。时间、单位与状态有效性见[底盘诊断接口](../接口约定.md#底盘诊断记录)。

部署使用只读`runtime.preflight`核对地图与资源、库加载、ROS和GPU可见性；本车试验候选使用运动配置中的 `trial` 档位。它们不建立实测参数、不启动运动，也不替代受控实机验收，步骤见[实机部署自检](../感知导航运行手册.md#实机部署自检)。

车辆档案使用 `execution_max_longitudinal_speed_mps` 和 `max_angular_rps` 作为执行时定位反馈速度的检查阈值。`controller` 明确区分控制帧的 `velocity_limit_field` 与底盘反馈速度门限；主机实际写入仍受运动配置中的速度上限约束。各阈值是配置值，不自动证明车辆实际响应。

### 旧底盘协议的离线诊断

[chassis_protocol.py](../../navigation/control/chassis_protocol.py) 根据旧容器导航串口驱动提供候选编解码，用来核对已有抓取文件，不打开设备，也不向底盘写数据。模块保留来源路径和源码摘要。候选控制帧为 12 字节，反馈帧为 32 字节；旧驱动按有符号字段值求控制校验和，没有把 LED 字段加入该和。这是对旧实现的复现，不能据此认定固件协议正确或修复校验规则。

抓取数据支持一个候选反馈校验规则：不含帧头和校验字节的载荷字节之和，取低 8 位。解析器以 `candidate_checksum_rule/candidate_checksum_matches` 记录该规则及当前帧是否符合；规则来自数据推断，固件协议、字段语义与失联停车仍待确认。因此解析状态仍为 `unverified_protocol`，保留原始字段和原帧，始终设置 `checksum_verified=false` 与 `execution_feedback=false`。字节流中没有测量时间字段，解析器保留 `device_measurement_stamp_s=null`；不能用解析时间替代传感器测量时间，也不能把编码器位置接成可靠地图定位。后续接入与验收由[实车待办](../感知导航实机问题.md#导航配置与执行)维护。

### 受控地面底盘检查

[ground_probe.py](../../navigation/control/ground_probe.py) 提供人工看护下的单次有界协议检查，默认直行。它使用每次明确选择的小速度和有限窗口，先在驱动禁用状态下检查，再根据现场准备情况选择一次实际运动检查。`--speed/--pulse-s` 在固定开发边界内选择前进目标上限与窗口；显式`--maneuver`另提供固定低速倒车及左右原地转向，转向大小可由`--angular-speed`明确选择，数值与操作由[底盘受控检查](../感知导航运行手册.md#底盘受控检查)维护。这些选项不改变导航运动配置。该工具不运行导航，不接收规划器建议，也不构成真实自主导航命令出口。默认只打印计划；显式 `--execute` 才打开串口，`--motion` 表示本次期待实际运动。

串口由独立子进程持有，打开后核对占用者并设置独占。子进程按自己的单调时钟限制发令窗口，心跳和新反馈都不能延长截止时间。父进程心跳保留发送时刻，过期、断连、取消、候选反馈校验失败或手柄输入都会结束非零发令，随后持续发送零速度并恢复原始模式 3。请求边界由模块中的 `LIMITS` 维护，默认参数及反馈阈值由 `PROFILE` 维护；父进程和串口子进程均检查所选参数。控制日志在收尾后写入文件，避免磁盘写入占用发令循环。

反馈线速度绝对值超过0.15 m/s，以及与直行方向不符的纵向反馈仍立即中止。直行的角速度反馈上限仍为0.15 rad/s；原地转向取0.15 rad/s与所选角速度大小1.5倍中的较大值，避免合法转向请求触发原有直行门限。纵向指令上限仍为0.10 m/s；另以0.4秒的接收时间窗口检查候选线速度，平均值超过0.11 m/s时中止。这些均为开发诊断阈值，不代表实测硬件限值。

直行发令的前 1 秒视为起步阶段，轻微转向反馈仍保留，但不触发平均偏转检查。之后独立累计稳定段反馈，至少 5 帧覆盖 0.4 秒，角速度有符号平均值的绝对值超过 0.05 rad/s 时中止。重复读取同一帧不会增加观察数量，超出反馈期限的间断会清空平均窗口。窗口按主机接收时刻计算，不伪称设备测量时间；这是对起步瞬态和反馈波动的诊断假设，不能证明瞬时读数没有物理运动。较大转向、过速、倒退、接管和失联保护始终生效，驱动禁用检查仍即时拒绝运动反馈。

显式倒车检查将预期纵向符号改为反向，横向转向仍受直行偏转保护。原地转向请求只允许所选符号，纵向目标保持零。转向中候选平移速度的绝对值超过0.06 m/s时立即中止；超过0.03 m/s但未超过0.06 m/s时，至少3帧连续覆盖0.20秒才中止。正常或近零反馈清除累计，超出反馈期限的间断重新累计，同一帧的重复读取不增加次数或时长。这允许记录短暂的小幅平移反馈，不表示这些读数必然是噪声，也不表示车体参考点在原地转向时完全不动。

转向方向仍按连续反馈判断：反向角速度超过0.01 rad/s、至少3帧覆盖0.20秒才中止；正常方向、近零反馈或超过反馈期限的间断都会清除累计。单帧反向仍被记录，但不直接中止。请求边界、实际写入与脉冲期限同时约束两个轴，父进程失联、手柄接管、候选校验、模式和绝对速度门限仍生效。以上变化只作用于地面检查工具，普通直行、断发检查和导航安全监督不随之放宽。

[response_probe.py](../../navigation/control/response_probe.py) 组织预先固定的六段低速响应计划，每段复用同一个串口独占与归零流程。完整且已停稳的低速无响应段可以按原计划继续，安全中止则结束整个批次。它记录已开始但中断的阶段，不自动递增请求、重试、确认协议或填写车辆能力；日志、反馈和人工观察需要分别检查。

结束或中止后，串口进程至少发零 1 秒，并最多等待 3 秒取得连续静止反馈。静止确认要求最近 0.3 秒内至少四帧、覆盖至少 0.2 秒，且模式、候选校验、手柄与速度条件均满足；超时保持未确认状态。`response_summary` 按起步、稳定和收尾阶段汇总候选反馈，其时间是主机接收时刻。

目标按线上毫米每秒整数记录，未量化的请求另存为 `requested_linear_mps`，不能将量化后为零的请求计入非零帧。`completed` 只说明命令序列完成；`stop_feedback_observed` 只说明候选反馈满足静止条件，`motion_verified=false` 与 `operator_observation_pending=true` 要求另行核对现场观察。没有检测到运动响应时不自动提高速度或延长窗口。

显式`--silence-s`增加有界的固件断发观察。只有发令末尾存在前进反馈和非零目标才进入该阶段，直行阶段末尾不发送通常的零速帧。串口保持连接，继续读取反馈与父进程心跳，截止时间固定为最后一次实际写入加所选断发时长。断发阶段允许固件自行退回模式3，并保留速度、倒退、手柄与输入期限检查；进入后永久禁止本轮再次发非零目标。观察结束或任何异常都会进入原有零速恢复流程。参数范围与操作由[固件断发检查](../感知导航运行手册.md#固件断发停车检查)维护。

断发阶段对小于等于0.03 m/s的反向反馈使用连续0.20秒、至少3帧的判据，记录短暂反向样本而不单帧中止；正常或近零反馈重置累计，重复帧不增加次数或时间，超出反馈期限的间断重新累计。较大反向仍即时中止，主动发令阶段的方向保护及连续静止门限不变。这仅是诊断判据调整，没有确认这些读数的噪声或回弹来源。

结果将“补发零速前取得连续静止候选反馈”与“主动恢复零速后停车”分开。断发期间不插入零帧、模式帧或心跳控制帧；父进程心跳只在本机IPC中传递，不发送给控制器。候选静止条件仍需多个反馈覆盖有效时间窗，不能用单帧零速度、进入测试前已静止或上位机主动发零冒充固件失联停车。该结果不自动证明固件看门狗参数、设备制动能力或协议已验收。

这些保护只能处理本机进程和通信中的部分故障，不能代替物理停车、固件失联保护或真实制动验证。驱动禁用检查也不能证明运动中的停车距离。没有台架时，只能在获得明确授权、无人乘坐、平整空旷且现场人员能直接操作物理停车开关的条件下开展受控检查；原手柄不能正常电动行驶或车体制动未按正常操作要求准备时，先解决整车状态，再进行上位机检查。操作见[底盘受控检查](../感知导航运行手册.md#底盘受控检查)。
