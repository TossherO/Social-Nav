# 导航地图与参考路径待修事项

2026 年 11 月 24 日离线审查发现以下问题，均待修复。前两项影响实机直接运行入口，优先处理。下列复现使用合成扫描和场景，未做实车验收。

1. **长时障碍何时恢复空闲**（`perception/environment/obstacle_memory.py`）。障碍在 14.0 秒到期，14.1 秒格子变为未知。14.2 秒只有一个地面端点，没有新自由射线，旧的高度覆盖却使整格恢复空闲。反过来，若首个到期后的扫描已扫清整列，这一帧也可能因时间等于程序登记的到期时刻而被拒。修复后应以实际保留截止时间为界，按碰撞高度范围核对新射线。另测格子移出窗口再返回的情况：当前待复核标记会丢失，静态先验可再次将其填为空闲。需要明确待复核状态的保留范围。

2. **参考搜索遗漏历史空闲**（`runtime/control.py` 的 `_search_scene`）。普通帧可以没有 `obstacle_expiry_unknown`。此时搜索会重新从 GPU 取图，丢失 CPU 场景中的 `confirmed_free_stamp`。合成场景的 3,600 个已确认空闲格在进入搜索时整层缺失。验收时分别传入有、无到期标记的同源场景，检查搜索收到的空闲格、观测时间和到期标记，并确认已有所需图层时没有额外下载。

3. **ROS 参考规划的行人附近障碍确认**（`navigation/planning/overlay.py`、`online.py`）。障碍持续出现 31 帧，行人在前两帧后离开。直接运行时保留了障碍，ROS 地图缺少 `current_obstacle_hits`，始终无法确认。另有两项复现：同一帧先收到地图或先收到人物消息会改变保留结果，单条人物轨迹缺少 `last_observed_stamp_s` 会使规划循环抛出 `KeyError`。修复后用相同输入对照两个入口，交换消息到达顺序，每次扫描仍只计一次命中。无效人物记录应能降级处理。复核历史搜索时优先使用保存了实际输入的规划记录，普通场景导出也可能缺少本帧命中层。

4. **部署预检和回放外参**（`runtime/preflight.py`、`runtime/__main__.py`）。预检漏查原生库的 `sn_occupancy_uncertain_person_hits`、`sn_occupancy_refresh_view_distances` 及 ROS 消息字段 `obstacle_expiry_unknown`。预检应分别用旧库和旧消息类验证，确保启动前就能发现版本不匹配。回放另有一项差异：省略 `--vehicle-profile` 时，程序仍会用历史外参启用近车短期占据策略。修复后应分别用有、无车辆档案的回放验证，缺少当前车辆外参时使用普通障碍确认。
