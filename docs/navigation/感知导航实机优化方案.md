# 感知导航实机优化方案

先用本车近期的故障及正常片段，找出地图、参考路径、DWA 和独立安全之间最先出现延迟或异常的环节。局部建图、导航代价图更新、Hybrid A* 搜索耗时和路径形状的优化优先级由本车测量决定。在同一台车载机上用相同输入比较修改前后，再按相同路线和运行条件复测。采集沿用[现场导航六项反馈](../系统实机问题.md#现场导航六项反馈)，只补与当前问题有关的缺失记录。

## 固定本车输入和基线

使用本车最新相关的原始 bag、同次定位及运行日志、当次定位图和人工修正的静态环境图。按会话记录核对实际加载的地图路径、坐标系和资产指纹。配置参考[一楼人工驾驶观察](../../navigation/commissioning/interactive_agent_floor1.yaml)及[二楼交互导航](../../navigation/commissioning/interactive.yaml)，以车载机实际选择的文件和参数为准。缺少当次地图、关联或源时间时，先确认哪些比较仍有同源输入。

每轮登记源码、涉及模块的本地差异、原生库摘要、车载 CPU 和 GPU、地图与包的指纹、源时间或查询编号。固定实际负载，包括地图窗口、分辨率和目标频率、检测与跟踪、显示、Agent、记录开关及车速档。参考查询另固定目标、场景、车体几何、关联和已有参考。需要历史状态的实验按原时间顺序重放同一段预热；核对行人离开后的残留时，从扰动前开始恢复人物和地图历史。

## 沿处理链计时

实机观察或执行会话可用 `--trace-timing` 保存现有时序事件。`environment_device` 记录包含 GPU 等待的主机墙钟，现有传输统计按方向和用途累计字节。只有现有记录无法区分当前瓶颈时，才给相应操作补充下面的分项计时。

- 用单调时钟量 CPU 墙钟，用同一 CUDA 流上位于实际工作前后的事件量设备耗时。多个 CUDA 流分别记录，跨流依赖和主机同步等待单列。参考工作进程的累计 CPU 时间另记。计时开关与同步方式在对照两组保持一致。
- 按消费者和字段记录实际 H2D／D2H 复制方向、次数、字节数和耗时，同时记录主机复制、封存及进程间交接。从提交、开始、完成、发布到首次消费保留各自时间，用场景或查询标识对齐，单列排队、待处理替换和过期。地图原始测量到控制和安全首次使用的年龄按各自实际消费的快照计算。
- 分开统计冷启动、同一观察上的重复请求和连续新观察，报告样本数、P50、P95 和最大值。等待参考、场景过期等提前退出单列。异步阶段的 P95 不相加。旧服务器结果和合成输入只用于可选回归，可复用 10 月 23 日 `2026-10-23-11-19-34.bag` 对应的影子规划归档。查询 2、13、15 分别覆盖直连成功、路线绕行门槛拒绝和起点足迹占据。用本车测量建立基线、排序和评估收益。[统计口径](../推理速度记录.md#统计口径)

## 参考工作图和代价图

- 把输入准备拆成场景复核、先验修订、历史占据投影、当前占据投影、数组封存和摘要。把端点检查与代价图构建分开计时。记录每个阶段读取的格数、临时分配和复制字节数，按是否进入搜索分别统计。优先用本车地图准备耗时高的直连和端点拒绝样本区分两种成本。
- 同一观察重复查询时，比较是否能复用内容完全相同的参考工作图和代价图。缓存身份包括静态地图、关联会话、当前观察和保留占据版本，以及栅格尺寸、原点、分辨率和影响代价的参数。新观察仍投影并核对其证据。只有确认工作图的占据和代价值等搜索输入逐格相同时，才复用相应计算结果。量化全图哈希和比较的开销，确认缓存本身产生净收益。
- 主进程继续按源时间更新保留占据账本，将本次查询所需的不可变证据交给参考工作进程。工作进程持有私有工作图和缓存。换图、定位或关联会话重置、回放跳转时使相关缓存失效。门板离开视野后继续阻挡，只有更新的实测空闲可以解除。逐格比较工作图、代价图和端点拒绝原因，并检查开门、半关、遮挡和重开这一组时序。当前局部图的完整车体扫掠、控制和独立安全照常检查最新有效观察，参考结果仍携带自己的源时间。
- 再处理相邻观察。当前先验修订已限制相交格的投影范围，但仍会分配整图掩码、复制图层并计算整图摘要。试验在静态底图上按块保存变化，更新上一帧和本帧窗口覆盖的并集，撤掉已移出的临时覆盖，单独应用历史账本的增减。只有占据或条件障碍的实际内容改变时才作废相应的几何缓存。现有代价图已把距离变换限制在空闲区包围框及其外围，移除一个障碍仍可能改变远处净空。先消除几何未变时的重算，局部更新须逐格对照完整重算，无法确定影响范围时走完整计算。

## 局部环境地图的构建与更新

分别测量地面拟合、历史地面对齐与支撑、射线和体素更新、三维证据投影、二维距离场、静态支持及设备与主机交接。用相同的本车连续扫描和当次位姿，逐帧比较窗口原点不动、移动一格和连续移动时的地图。冻结人物记录只用于有对应时序的对照。[现有 CPU／CUDA 对照](../../tests/test_environment_cuda.py)

1. 先验证窗口原点两轴位移均为零时，能否跳过 `ground_z`、`ground_seen`、`ground_conflicts` 和 `ground_conflict_heights` 的四次平移复制。当前帧的写入继续发生在地图所有者持有的工作数组上，发布快照在消费者释放前保持只读。分别核对零位移、窗口移动、过期、地面下降和重新观察。
2. 用更新写入前的地面支撑判断本次地面冲突，用更新后的支撑投影当前碰撞柱。先比较输入种子、高度、时效和冲突状态完全相同时的复用，覆盖拟合拒绝、支撑刚过期、冲突暂停和恢复。更换地面平面时仍按当前规则保留未被可靠观测解除的冲突。
3. 二维距离变换先试同尺寸、同原点、同占据与未知掩码的复用。当前 CUDA 实现对每格扫描整行和整列。若本车确认这一步占时明显，对照可按行、列线性计算的精确欧氏距离变换。障碍删除、未知边界变化或窗口移动可能改变远处格子的最近距离。逐格比较距离和 `NaN` 掩码，覆盖无占据、未知格和窗口外侧按未知处理的情况。规划代价图和环境图距离层各自沿用原边界语义。
4. 指标确认三维窗口的全量准备、更新或投影占时明显后，再评估分块。当前射线沿途打标后，更新和投影仍会遍历整个窗口。候选方案先记录活跃块、射线经过的块和本次到期的块，只跳过已确认无需处理的部分。除射线与命中外，更新还需覆盖移入窗口的区域、过期的障碍与人物证据，以及地面高度或冲突改变后需要重新投影的列。按连续帧核对有效体素数、过期后恢复未知的时刻和超限撤图结果。无法确定影响范围时保留全量计算。

## 原生搜索和路径形状

**先定位搜索的时间。** 从本车确实进入搜索的请求中选择长尾样本。记录距离场、状态展开、解析直连、运动碰撞检查和最终独立认证的耗时，以及扩展数、直连数、碰撞检查数、缓存命中和预算耗尽原因。某些碰撞检查包含在直连计时内。若大量重复直连或扫掠确实占时，先在相同候选和判定顺序下对照缓冲复用、几何预计算的收益。已有目标侧距离场缓存只在地图和代价、地图几何及目标格一致且距离场完整时可用。部分展开后预算用尽仍应报告未完成。

**再定位弯折出现在哪一步。** 用本车相同起终点、朝向和占据环境画出原始参考和局部前缀，标出解析直连、离散搜索和旧参考接续各自生成的段，和 DWA 建议及实测轨迹按原时间对应。对开阔地稍偏离车头的 XY 目标，用符合转弯半径的单圆弧加切线直段作对照。硬性终点朝向、绕障和窄弯可能确实需要回转，仅在与改动有关时纳入对照。可选的 10 月归档中，查询 88、91 分别覆盖直连和旧参考接续，查询 2 用于检查形状指标是否对末端短弧过于敏感。

**每次只改一种候选策略。** 当前直连优先按长度和倒车权重筛选，原语搜索对转弯幅度计价，未单独惩罚左右快速切换。在开阔 XY 目标上先试“圆弧加直线”候选并用统一代价比较，核对原有较短直连的提前返回条件是否掩盖更平顺的解。若弯折确实出在离散搜索段，再试短间隔反向转弯代价，同时把必要的上一步转向信息纳入状态区分并测量扩展数。若来自接续，只调整接续候选。每条候选仍验证终点约束、曲率和完整车体连续扫掠。

按固定弧长重采样，在同一行驶方向内统计有效曲率换号次数、累计曲率变化和总转角。测前固定忽略微小曲率与极短弧段的阈值并保留原图，同时报告路径长度、最小全车净空、原地转角、倒车距离及换向次数。先证明轻微转向样本有几何更简单且通过同等扫掠的路径，再比较改后能否选中它。硬性朝向与绕障样本保留必要的回转。

## 同机对照与整链复测

在同一台车载机上固定输入和配置，每次只引入一个候选。纯性能候选要求占据及未知、地面支撑和冲突、有效时刻、规划或安全拒绝语义一致。浮点图层在测前登记允许的数值误差，并保证 `NaN` 掩码和影响判定的阈值结果一致。路径形状候选要求摆动样本改善，已知可行样本的路径可用性及独立认证无退化，需要绕障时保有足够的全车净空。先用基线重复运行估计波动，再交错运行修改前后的版本，检查收益是否大于波动。出现安全相关差异、稳定复现的可用性退化或无可测收益时，停止推进该候选。

单项通过后，在车载机上用同一段最新本车 bag 原速重放完整运行负载，再按相同地图、路线、目标和驾驶条件做对应的现场复测。比较有效地图发布频率、待处理替换、失效数量、地图源测量到控制与安全首次使用的时延、目标发出到首条可用参考的时间，以及重规划次数、无候选原因和安全响应。自主运动与车辆响应沿用现场授权、急停、手柄接管和实机验收条件。出现观察变旧、参考可用性或安全行为退化时，回到单项定位。阶段结果集中保存一份配置、输入索引、基线与候选对照和必要失败片段。
