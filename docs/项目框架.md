### 1.2 依赖与配置边界

数据/渲染使用既有python312中的NumPy、Pillow、OpenCV、PyYAML、Matplotlib等，MP4使用PyAV/H.264；PCD压缩与RLE解析由代码处理，不要求安装Open3D或pycocotools。远程客户端只需要httpx与jsonschema，个人电脑不需要Torch、CUDA、vLLM或SGLang。

不要为运行便携客户端升级项目GPU环境。包内requirements.txt只用于新的隔离客户端环境；远程SGLang由用户在已配置环境手动运行，当前文档不执行安装或版本迁移。

| 配置/来源 | 谁使用 | 当前设置与注意点 |
|---|---|---|
| configs/system.json | system_status | 三域目录与状态登记；不是自动加载各模块的运行配置 |
| training/source_snapshot.json | 显式检测源码审计 | 迁移时内容与排除项；不要求日常工作树永远等于快照 |
| project.json.dataset_roots/development | VLM数据入口、benchmark、packager | JRDB/SUB及冻结输入均指向data/datasets别名；相对配置路径按仓库根解析，CLI支持覆盖 |
| project.json.model/deployment | print-only launcher | FP8路径、别名、loopback:30000、12288上下文、并发1、显存比例0.85、XGrammar |
| project.json.inference | benchmark默认值及固定策略校验 | period/rate/deadline、max_tokens、response_constraint；固定非思考、T=0、单在途、零重试、object |
| project.json.benchmark | benchmark预算/调度默认值 | mode=serial、limit=3、warmups=0、timeout_s=60 |
| 便携benchmark_defaults.json | 新便携客户端 | 打包时从同一公共配置导出的默认值，读取前检查manifest哈希 |
| benchmark_vlm CLI参数 | 实际测速覆盖 | 优先于上述默认值；最终生效值记录在settings.json |
| vlm_server.local.json | 实际HTTP连接 | 仅base_url、api_key、model、allow_insecure_http；不是GPU启动配置 |
| jrdb_t1_rel.txt / 每case response_schema | HTTP请求 | 固定前缀及动态PID Schema；属于输入版本的一部分 |

仓库客户端读取project.json，新便携客户端读取打包时的默认值快照，命令行参数优先。修改公共rate_hz时须同步period_s，使二者互为倒数；deadline_s单独保存。只用CLI覆盖`--rate-hz`而不传`--deadline-s`时，沿用旧用法，将deadline设为1/rate；同时传入两者则独立控制。只覆盖deadline不改变到达率。dry-run显示来源和主要生效值，真实运行完整记录settings.json。

timeout=60s是HTTP等待上限，不是2秒完成deadline或机器人TTL。改变公共配置不会回写已发行便携ZIP；需要新包时用新目录重新打包。非思考/T=0/单在途/零重试/object是当前客户端固定策略，改成不支持的值会报错，不能在配置中写了另一种策略却仍静默执行旧行为。图像布局/近距阈值属于代码和协议，改动需生成新输入、更新人工绑定与回归测试。

上表中的project.json是[决策域配置](../decision/vlm/configs/project.json)。检测训练使用复制版YAML，不从VLM配置读取训练参数；DATA_PATH/RAW_DATA_PATH都通过复制版data别名定位共享入口。`configs/system.json`只登记数据别名与绑定状态，system_status不自动创建链接、读取数据内容或加载checkpoint。

本机参考模型配置是Qwen3.5架构类，保留真实config；模型目录名、served-model-name和检查端点的ID都不能证明远程权重字节相同。

## 2. 操作工作流

以下系统检查和VLM命令从仓库根目录执行，使用既有python312。输出目录必须是新的，避免覆盖固定样本与用户结果。实际检测训练使用其独立环境与工作目录，不在python312中安装检测依赖。

可在终端先激活 `conda activate python312`，或使用 `/root/miniconda3/envs/python312/bin/python`。命令中的*_new是示例名称，若已存在请另取新名称，不删除已有结果后重跑。

### 2.0 系统结构与检测训练源码

```bash
python -m scripts.system_status
python -m scripts.dataset_links
python -m perception.detection_tracking.training --check
python -m perception.detection_tracking.training --print-command \
  --checkpoint /path/to/verified_coda_checkpoint.pth \
  --conda-env simpledet3d --run-tag social_nav_detection_new
```

system_status仅核验注册目录和状态，即使layout_valid=true，online_system_ready也明确为false；加`--require-online`会返回非零。dataset_links只检查10个数据集软链接及检测data桥接，不读取pickle或验证训练。training --check只对历史清单中的源码计算hash；检测副本已做数据路径与无编号命名适配，因此会报告changed并返回非零，这是迁移快照差异，不等于训练体系失效，也不是日常必须通过的门槛。--print-command仍只打印`DRY_RUN=1`命令，不执行、不选择权重，也不验证示例环境存在。

复制版保留122个原文件，共982,403字节。包括simple_det3d包、8份YAML、11个工具、10个原测试、3份原文档、setup.py和编译/训练脚本。未复制data、output、build、权重、pickle、已编译扩展、Git及原项目代理指导文件。详细源码结构见[原体系框架](../perception/detection_tracking/training/simpledet3d/docs/code_framework.md)，操作与数据准备见[使用指南](../perception/detection_tracking/training/simpledet3d/docs/usage_guide.md)，三阶段语义见[轮椅训练设计](../perception/detection_tracking/training/simpledet3d/docs/wheelchair_training_design.md)。

真正训练前必须逐项确认：

1. 检测环境中的PyTorch/CUDA/spconv及GPU数量，不修改VLM环境的重要库。
2. 数据链接已经建立；仍需核验`data/coda_downsample`和`data/wheelchair_weak`中实际info/数据库与配置匹配，不能把目录可达当内容正确。当前共享原仓库的预处理资源，不复制整棵data/output，不反序列化未知pickle。
3. 经核验的CODa初始化checkpoint；目前未自动选定任何权重。
4. 在复制版重新编译CUDA扩展，确认不加载原目录的.so；相应build产物不提交。
5. 原脚本默认8GPU、单卡batch16等训练参数必须按设备修改或显式覆盖，不因源码迁移而视作本机适用。弱中心不是完整3D真值，stage1混合适配、stage2 EMA/室内监督、stage3室内固化的语义原样保留。
6. 使用新的RUN_TAG和复制版output目录，不自动续训原仓库结果。先阅读打印命令，再决定是否手动执行原脚本的DRY_RUN；本次没有执行它。

这不是训练编排器：源码检查不证明训练就绪。原`tools/test.py`仍用于评估；实际推理现在由`perception/detection_tracking/inference/`维护，ROS 1使用同一核心。配置、离线命令、输入/输出格式及验证边界见[检测跟踪模块说明](../perception/detection_tracking/README.md)。

根目录日常测试只检查历史快照格式、审计器行为和系统边界，不强制当前源码永久保持迁移状态，也不禁止训练准备产生data、output、build或.so。新增资源/构建产物不在历史hash清单中，仍由忽略规则保护；不要为了让显式快照审计通过而重写历史基线。

### 2.3 手动部署与远程测试

只打印基础SGLang命令，用户在远程已配置环境执行；不会自动启动进程或安装库：

```bash
python -m decision.vlm.project_config --model-path /remote/path/Qwen3.8-27B-FP8
```

基础配置不强制Hopper专用内核或MTP；版本/显存/内核兼容性由实际服务器检查。优先使用HTTPS或SSH转发至loopback。服务别名不等于已审核权重身份。

launcher可用 `--python /remote/env/bin/python --port 30000` 选择已配置远程环境；它只输出命令字符串，不启动GPU进程。默认不加入Hopper专用Attention/FP8 GEMM选项，不自动开启MTP、刷新缓存或改模型config。实际启动参数以该远程版本help为准。

SSH转发可将远程loopback服务映射到个人电脑loopback，客户端base_url填写本地转发端口的 `/v1` 地址。避免公网明文HTTP；allow_insecure_http=true只是显式承担传输暴露风险，不是加密措施。

创建私有配置：

```bash
cp -n decision/vlm/configs/vlm_server.example.json configs/vlm_server.local.json
chmod 600 configs/vlm_server.local.json
```

本地填写base_url、可选服务token和精确model ID，不改已有千问API凭证。本机Key不自动发送到另一服务，当前客户端也不自动调用官方付费API。

```bash
python -m decision.vlm.benchmark_vlm --dry-run --limit 24
python -m decision.vlm.benchmark_vlm --check --out outputs/t1/check_new
python -m decision.vlm.benchmark_vlm --out outputs/t1/smoke_default_new
python -m decision.vlm.benchmark_vlm --limit 24 --out outputs/t1/serial_new
python -m decision.vlm.benchmark_vlm --mode paced --rate-hz 0.5 --limit 24 --out outputs/t1/paced_2s_new
python -m decision.vlm.benchmark_vlm --dry-run --rate-hz 0.5 --deadline-s 1.5
```

dry-run读取公共默认值和输入，零网络、零私有配置/凭证读取；check只GET，不推理。默认3任务，完整24例需明确选择。一次失败立即停止，无自动重试/修格式/换服务。serial测每个样本完整延迟；paced每2秒到达，单请求在途，忙时丢弃而非排队。两者分母不同；首字延迟不等于完整结果延迟。最后一条仅演示独立覆盖deadline，不代表已更改默认两秒目标。

可选 `--server-info` 额外GET已脱敏服务元数据，应用代理不暴露该端点时仍可测试；元数据可达也不证明模型来源。model留空只在存在唯一匹配27B模型ID时自动选择，多个ID或别名不匹配时需明确填写，不静默换模型。

HTTP默认复用连接、单连接、忽略环境代理、不跟随重定向。确需可信代理时显式传 `--proxy http://<可信代理>:<端口>`；仅export http_proxy/https_proxy不影响该客户端。不要把api_key放URL、命令行、截图或公开日志。

默认warmups=0； `--warmups 1` 只发一次纯文本前缀预热，不重复测量图像，单独记录且不混入任务延迟。json-object仅为兼容诊断降级选项，不是当前默认硬Schema；使用该选项必须在报告中标明约束能力变化。

benchmark在首个已提交失败处停止，因此summary可能含cancelled_after_error；这是测试预算控制，不是实机遇错后的状态策略。迟到但合法不视为接口失败，继续记录；机器人是否接受则需未来TTL/版本适配器决定。

新生成bundle可加 `--bundle outputs/t1/dev_new`。带源审计的bundle可生成预测/native审核图：

```bash
python -m decision.vlm.benchmark_vlm --bundle outputs/t1/dev_new --out outputs/t1/smoke_new
python -m decision.vlm.jrdb_t1 compare --bundle outputs/t1/dev_new --requests outputs/t1/smoke_new/requests.jsonl --out outputs/t1/compare_new
```

运行smoke时务必指定同一个dev_new bundle；客户端记录输入指纹，compare拒绝跨输入版本的结果及缺少指纹的旧日志。compare不对无源manifest的旧固定输入伪造几何，也不把native称为T1 gold。

prepare/reviewed/compare输出不得位于原JRDB源目录；reviewed/compare还禁止输出到输入bundle内部，符号链接按真实目标检查。compare在创建目录前检查所有可接受结果、渲染版本和路径；重复case_id或没有合法预测均报错，不覆盖同名图片或生成误导性的空比较目录。

### 2.5 产物结构与复现链

新T1 bundle结构如下；模型传输资产与本地审核资产虽然同目录组织，但由白名单隔离：

```text
bundle/
  manifest.json                   cases、文件SHA、协议及非gold声明
  system_prompt.txt               实际固定前缀
  cases/<case_id>/
    model_input.json              三图路径、fields、user_prompt、动态Schema
    image_0.png, image_1.png, image_2.png
    manifest.json                 源序列/帧、PID映射、逻辑数据引用、源hash、几何签名
    annotation_template.json      全未知draft，人工审核起点
    system_prompt.txt             case本地重建/审核用前缀
    input_contact_sheet.png       仅显式contact-sheet时生成
  references/<case_id>.native.json 原生成员诊断，非HTTP资产
```

默认通过data/datasets/jrdb_t1_dev链接读取固定data/benchmarks/jrdb_t1_dev。它只保留运输资产，没有完整case源manifest，适合接口/延迟复测，不能直接重建源图。重新prepare的新bundle才同时支持源重建和指纹审核。

每次HTTP运行产物：

| 文件 | 内容 |
|---|---|
| model_check.json | GET状态、可用/选择模型ID、可选安全服务信息；不证明权重身份 |
| settings.json | mode/rate/deadline、任务数、约束、max_tokens、非思考、连接/代理和计时范围 |
| requests.jsonl | 每到达状态、输入/请求hash、完整响应、局部校验、usage、失败阶段和时钟 |
| summary.json | 全计划/已提交/合法/丢弃/取消数量、全请求与合法延迟分布、有效决策覆盖 |
| warmup_00.json | 仅warmups=1时存在；纯文本预热，不是场景任务 |

失败日志保留error_type、failure_stage以及Schema关键词/路径；HTTP错误不保存整段服务错误正文，思考内容不落盘，认证值会脱敏。不应将日志当无隐私公开数据：最终响应仍含人物关系，安全server_info也可能含远程模型路径。

复现需同时保留输入文件hash、Prompt/Schema版本、case源审计、人工标签版本、客户端源码与运行settings。case本地审核指纹和HTTP加载器的运输指纹是不同定义：前者绑标签，后者绑requests/compare；不要跨用途比较字符串，详见[JRDB实现说明](./JRDB数据与测试实现.md)。

新便携包额外包含benchmark.py、vlm_api_common.py、benchmark_defaults.py和benchmark_defaults.json，均列入包内文件hash；最后一项采用`settings`封装，不含项目版本编号，来源是打包时的公共配置。server_config.json仍为空凭证且不加入不可修改资产清单，供用户本地填写。

## 3. 跨域边界与验证

### 3.1 模块依赖与共享记录草案

```text
传感器 → 感知快照 ─────────────→ 本地规划/控制/安全
             └→ VLM窗口/请求 → 经校验语义 ─→ 规划中的社会代价/目标
任务指令 → 外层agent ─────────→ 子目标与任务模式
                      ←──────── 导航反馈
```

检测跟踪离线链路和ROS 1源码已提供，定位算法与跨域在线箭头仍未接通。共享记录不依赖任何域；感知不读取社会真值或依赖VLM；导航不把网络结果作为避碰唯一来源；agent不能绕过本地安全层。VLM输出不是电机指令。

[contracts.py](../interfaces/contracts.py)提供共享记录，感知已有`to_snapshot`转换，其余仍为适配草案，尚未接入现有object：

| 记录 | 核心内容 | 实现时必须验证 |
|---|---|---|
| Header / TrackIdentity | 观察ID、采样时刻、坐标系、时钟域、序列/版本；轨迹ID＋生命周期代次 | 重连、ID复用、坐标变换和时钟基准 |
| Detection3D / PersonTrack | 3D框、类别/分数；观测/预测/丢失、最后观测时刻、可空速度/协方差/RGB框 | 检测模型框定义、坐标轴/yaw、缺失值和因果关联 |
| PoseEstimate / MapReference | 方向明确的4×4变换、定位健康、地图ID/版本/图层 | map/odom/base_link转换、过期位姿和地图失效 |
| PerceptionSnapshot | 轨迹、位姿、地图、RGB资产、标定版本、来源与PID映射版本 | 同步误差、单帧时间、实际运动补偿，禁止语义泄露 |
| VLMResultEnvelope | 原观察头、请求ID、输入指纹、任务/PID/模式/候选版本、短响应 | 本地接收时效、完整Schema、当前身份映射和任务版本 |
| AgentIntent / GoalPose2D | 任务ID、模式/版本、子目标或目标描述 | 不包含底盘速度；目标先通过几何可达性检查 |
| PathPlan / NavigationFeedback | 地图/任务版本、路径姿态、执行/停止/成功/失败及原因 | 足迹/运动学、陈旧路径、停止与恢复条件 |

这些dataclass不做数值校验、序列化、变换、调度或安全保障，也不是ROS消息。传感器逐帧时刻、同步误差、TTL、底盘动作类型等细节需在设备与运行时确定后补齐；不能据此宣称契约已验证。当前VLM图像、字段、响应Schema和两类输入指纹均不因增加草案而改变。

未来agent可先用明确的任务状态机，再按需求选择框架；目录存在不表示已采用某个agent SDK。故障恢复不自动等于调用更多模型，导航失败原因、本地安全状态和人工接管优先于语义重规划。

### 3.4 常见问题与安全排查

| 现象 | 优先检查 |
|---|---|
| Bundle integrity check failed | 是否手改已冻结Prompt/metadata/图或混用旧客户端；新配置生成新bundle，勿绕过hash |
| input_overflow | 末帧超过20人或窗口短PID超限；明确新协议/范围，禁止静默截断关键人物 |
| Insufficient real past frames | 末帧太早/缺历史，换有足够真实历史的窗口，不复制图像 |
| Source changed / label fingerprint mismatch | JRDB源、标定、几何或输入已变化；重新生成并人工复核标签 |
| Rendering implementation changed | 当前渲染源码与case记录不一致/缺hash；匹配旧源码审核，或重新prepare并人工复核，不改manifest蒙混 |
| Portable benchmark defaults changed | 新包默认值缺失、变动或不在hash清单；重新提取原ZIP或重新打包，不与旧包拼接 |
| period_s/rate_hz不互为倒数 | 公共配置须同步修改；CLI单次覆盖见1.2，不把deadline与HTTP超时混为一谈 |
| Model check failed | base_url应为API根/v1，服务端口与隧道可达，精确ID来自models；无推理重试 |
| 400/422 Schema错误 | 该版本多模态/结构化接口是否支持；先读服务端日志，不宣称json-object同等保证 |
| invalid_response | 查看failure_stage：JSON、Schema、成员、模型身份、截断或思考；不抽取/修补内嵌JSON |
| TTFT很短但完整结果慢 | 生成长度/服务流结束成本；完整JSON校验前不能接受半个决策 |
| paced丢很多但serial合法 | 请求跨下一计划时刻，单在途busy丢弃；看全到达分母，不增加并发伪装时效 |
| Panoptic视频只有1fps | 原标签稀疏，属预期；查source_frame_ids与总览缺标占位 |
| compare无法处理旧固定24例 | 缺case源manifest/运输指纹，不伪造；用prepare的新bundle重新测必要样本 |

排查先离线、后GET、再最多3个不同场景smoke。只有具体假设值得验证时才追加推理，避免为同一错误反复消耗token；GPU内核与环境兼容问题交由用户远程部署环境处理，不修改python312的重要库。
