# 后续开发测试汇总

本页记录仍需开发或验证的工作。现场已观察到的问题及本车运行配置见[系统实机问题](系统实机问题.md)；已实现机制与操作分别见[系统总览](系统总览.md)和[系统运行手册](系统运行手册.md)。

## 感知与地图

- 在不同光照、遮挡、人流及楼层中验证检测、三维跟踪、定位和二维关联。IMU 时间异常、地图关联稳定性和实车性能以现场记录为准。
- 验证人工修正静态图、动态行人清除、局部未知区域及地面冲突的实际效果。静态空闲与人工编辑不是当前观测，不能替代局部地图。
- 按采集来源、地点及物理人物划分开发、验证和留出数据，避免相邻帧或同一事件跨划分。草稿、伪标签、未标注区和人工金标准分别记录。

## 导航与安全

- 在现场检查目标到达、路径重规划、狭窄区域未知格、DWA 可行候选与停车连续性。具体故障和试车优先级集中在[系统实机问题](系统实机问题.md)。
- 确认固件失联、串口中断、看门狗、人工接管及实际停车响应。当前有限时域检查不能证明完整制动过程安全。
- 用同一地图与几何条件比较算法收益，分别记录候选计算、提前退出、完整反馈和人工干预；离线 bag 或影子规划不代表实机完成。

## 局部 VLM

- T1 群组关系和 T3 就座已有绑定观察的内存请求接口，但尚未接入自动调度、控制链或完整实机反馈。T3 仍需实时桌沿依据、候选生成、坐标变换及几何验证。
- T2 已实现首次选人、连续跟随、丢失后重识别与有限搜索。需以实际 DSPARK 服务和现场数据检查身份误认、遮挡、失效及找回；托管 API 的少量对照不能代替当前后端验收。
- T1 需分别检查成员与活动、错组漏组和未知覆盖；T2 需区分身份、可见状态、覆盖和历史因果性；T3 分开评估候选召回、语义选择、几何可行和真实执行。保留原始响应，不修复或借助未来标签。

## Agent 与长程任务

- 在完备地图中验证导航、观察与跟随的任务拆分、语义条件、阶段切换、人工接管和真实停稳。实机执行反馈不能由目标接收、影子结果或 bag 原驾驶轨迹替代。
- 接入并验证 T1／T3 与 Agent 的任务组合；乘梯、换层与重新定位需要真实外部反馈和有效地图关联。简单图、无图和跨区域任务尚无明确设计，保持待开发。
- 复核模型对任务要求、进展和失败的判断。保留独立样本，分别统计任务完成、无依据推进、澄清、取消和人工介入，不能用合法 JSON 代替任务成绩。

## 性能与现场测试

- 更新当前版本感知、导航、VLM 和 Agent 的现场或代表性数据，区分硬件、输入、配置及观察年龄；见[推理速度记录](推理速度记录.md)。
- 现场按用户授权和已有保护直接进行必要实验；保留配置、来源和关键故障片段，阶段完成后集中更新，不重复堆积中间报告。
