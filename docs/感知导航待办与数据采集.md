# 感知导航待办与数据采集

本文只维护尚未完成的开发、验收和数据需求。当前实现见[总览](感知导航总览.md)，运行命令见[操作速查](感知导航操作速查.md)，性能依据见[推理速度](感知导航推理速度.md)。

原生定位、内部直接通信、GPU 环境地图、DWA 和独立 CPU 安全已经整合。后续工作主要是改善持续可用性，并用独立数据和真实设备验收，而不是重复重构这些入口。

## 可继续实现与优化

### 输入时效与持续导航

关联及时交付、参考查询复用已有局部自由证据，以及按已确认能力开放倒车，均已有短段验证。倒车缓解了部分绕行和车后目标失败，但扩大了剩余失败查询的搜索量。当前优先验证目标的完整足迹可行性和有界短前视，再处理局部地图来源、分类退避、场景老化和ROLL匹配长尾；局部证据进入全局参考的机制仍需完整两层与独立场景验证。新地图触发控制的试验影响反馈时效，未采用。规划等待、拒绝与连续可用性统一按下方[规划专题](#规划持续可用性专题)推进，日志证据与最小对照见[失败溯源](感知导航规划连续性与失败溯源.md)。

补做带分段路线目标的完整两层影子回放，并用同输入对照分别量化场景归档、ROS显示发布和实际RViz渲染的开销。短片段消息频率与旧场景目标检查不能替代完整负载或执行验收。

状态反馈继续遵守 150 毫秒上限，不能为了增加候选而放宽，也不能刷新旧测量时间。需要更及时的状态时，再接入有来源的 IMU 传播结果或底盘反馈。

### 雷达—IMU 会话时差确认（暂缓）

暂缓开展新的时差标定与验证。默认固定偏移及其适用会话仍以 [lidar_imu.yaml](../perception/sensors/calibration/lidar_imu.yaml) 为准，历史会话的结果尚未证明适用于新的实时会话。现有启动检查只能核对声明的设备会话，不能自动估计时差，也不能因会话名称匹配就认定数值准确；机制见[标定与同步说明](perception/技术实现-建图与定位.md#雷达imu标定与同步实施策略)。

旧 Docker 容器的普通与 YGF 两套入口均关闭 `time_sync_en`，没有额外固定时差补偿。其 FAST-LIO 按消息时间戳等待并组装雷达和 IMU 数据；旧 Livox 回调中的粗略自同步片段已被注释，实际标准点云回调不估计时差。上述结论来自源码与配置检查，不能证明驱动端已同步，也不能据此将当前偏移改为零。

恢复此项工作时完成以下内容：

- 建立导航前的采集与复核流程。在传感器和驱动持续运行期间，采集包含转速变化的标定数据，并另留独立验证片段；原始消息和逐点时间保持不变。
- 固定当前空间外参，复用独立纯雷达轨迹与 IMU 角速度拟合时差。在独立片段上比较零偏移、原配置和候选值的对齐误差，再用回放检查去畸变与定位表现。验证数据不参与求解，候选不自动覆盖默认配置。
- 补充设备或驱动重启前后的对照，以及持续运行期间的分段结果，确认参数复用条件和固定时差模型的适用范围，再决定是否需要导航前自动标定或运行中的漂移监测；这两项自动能力当前均未实现。

### 规划持续可用性专题

本专题集中解决参考中断、DWA无候选和异常绕行。10月29日样例的证据、处理顺序、诊断字段与验收指标统一由[规划连续性与失败溯源](感知导航规划连续性与失败溯源.md)维护；以下是共同清单中的未完成入口：

1. 按[拟议目标方案](感知导航规划连续性与失败溯源.md#拟议的目标处理方案)优先提前排除足迹不可行的目标，再验证少量短前视候选、绕行长度与通过判定。倒车启用后仍失败的查询14、15、19为最小复核集；目标调整尚未接入运行。保留目标修订和真实完成语义，短路径另查制动。
2. 对包开头0–13秒补齐楼层确认与投影原因，对47–53秒核对普通命中和人物归属；分类处理启动盲区、静态未知、地面高差与无关联区域。地图修改前补齐台阶、负障碍及新障碍反例，静态资产保持原样。完整两层、关联重获、显示负载与反馈仿真另行验收。
3. 地图剩余问题继续按[地图诊断](感知导航规划诊断与改进.md#当前处理顺序)推进，包括静态地面高差、无有效关联时的局部未知，以及背景到期后的新障碍保护。补齐检测采样和短暂障碍召回验收；启动净空和自车区域仍需确认实体模型及外参。
4. 用户已确认倒车能力，后续实测倒车速度、制动、转弯和后向覆盖，并检查实际换向反馈。继续核对急转和初速模型拒绝的来源；当前观测不能裁剪成合法初态，也不能仅为匹配bag而放宽运动限值或开放原地转向。

### 环境与人物

检查人物局部漏掩码是否来自地面偏高、支持缺失、框覆盖不足或点簇断开。修复时保留墙柱和细障碍，不能靠删除整个框或伪造地面支持来放行。

当前使用单平面地面跟踪。坡面、凸起和多片区地形还缺少独立验证，需要结合16线点云覆盖及实测车辆能力，区分地面缺失、自由覆盖不足和真实障碍，再决定是否需要扩展表示。

### 决策与长程任务

局部 VLM 已有三帧记录、单请求响应接口和 T3 只规划适配，下一步需要自动模型调度，并联调 T1 软关系、T2 持续跟随与重新匹配、T3 导航及真实停止反馈。记录器开销和响应时效应放在完整负载下测量，输入变化后重新核对标签与观察的对应关系。

外层 Agent 已有工具、任务内核和 runtime 影子接口。剩余研究、真实执行接入、主动观察和短程无图语义引导按 [Agent 技术计划](decision/Agent技术开发计划.md)推进，具体任务与验收见[长程任务计划](decision/长程导航任务与评测计划.md)。它独立于局部 T1、T2、T3，换层仍须真实外部确认。

### 部署端性能

在轮椅的实际 CPU 和 GPU 上运行完整负载，分别测量设备计算、GPU 排队、跨进程切换和同步等待。定位局部加速还没有按比例降低整链时延，需要按 CPU 余量和实际延迟决定部署端的 ROLL 后端。当前本机四核亲和测试不能代替部署设备验收。

固定同一份位姿输入，分别检查定位数值、稀疏检测和阈值附近的数量变化，再量化它们对图层与导航输入的影响。当前完整负载只测默认后端，不能从中分离这些因素或推断逐位等价，性能依据见[推理速度](感知导航推理速度.md#当前完整负载)。

## 独立验收与所需数据

| 内容 | 需要提供的数据 | 用来回答的问题 |
|---|---|---|
| 地图与混合定位 | 独立区域或路线，改变起点、朝向和边界；包含较长的离图返图过程，并附大致起点。定量误差另需独立轨迹参考。 | 静态结构、盲区、重新关联和近场背景能否推广到新场景？ |
| 反馈与导航行为 | 窄门、多人穿行、静止人物、坡道、临时遮挡和拥挤终点，另附可靠人物轨迹及车辆反馈。 | 确定性预测、停车恢复、舒适性和无进展处理是否有效？录包原运动不能作为执行反馈。 |
| 检测增量训练 | 更多完整复核的任务帧、无人背景帧，以及独立室内和室外留出。 | [任务场景适配](perception/技术实现-检测训练.md#任务场景增量适配)能否减少误检，且不过度增加各距离段漏检？同源训练回代不作独立精度。 |
| 跟踪与 RGB 关联 | 少量带连续身份和二维框对应的片段，覆盖交叉、遮挡和中心跳变；另做 Windows 审核与导出测试。 | 身份、速度、中心和关联是否准确？匹配数量本身不表示准确率。 |
| 长期并发运行 | 长时间真实传感器输入、设备负载，以及扫描封存开关记录。 | 时效、排队、丢帧、内存和显示是否稳定？ |
| 雷达—IMU 精标 | 保持组件刚性关系的多方向激励，补足俯仰和横滚，并另留验证包。 | 能否改善平移及弱约束方向？不要求重做已经接受的安装标定。 |

后续过滤变更或独立验收时，再把人物残影、墙柱和细障碍保留集中到一份材料中审查。已接受的审查不重复提交，审查结论不自动变成训练真值。“证据不足”不等于算法故障，灰色未知也不能直接填成空闲。

## 实车接入前

### 人工目标实车接入

人工目标已能从 RViz `2D Nav Goal` 经桥接进入直接运行时，也可按目标身份取消；入口见[显示与提交目标](感知导航操作速查.md#显示与提交目标)。它仍复用影子规划和独立安全，不代表真实底盘已接通。

11 月 5 日，用户在轮椅本机空旷地面执行一次目标上限 0.10 m/s、窗口 2 秒的单次直行检查，观察到移动且未见明显偏转。候选编码器净位移约 3 厘米；当时程序约在 0.93 秒因转向反馈提前中止，严格停车确认未通过。原始记录保存在采集机器本地，不随源码提交。这是单次诊断，不证明稳定直行、制动或自主导航通过。此后分阶段判断和延长停车确认只做了模拟验证，尚未实机验证。

- 核实实际控制器固件使用的收发帧、校验、模式和故障字段。旧容器驱动与协议表存在差异，目前只有[离线候选解析](navigation/技术实现-局部控制与安全.md#旧底盘协议的离线诊断)，不能将原始模式或异常电量值直接解释为可执行状态。
- 使用[受控底盘检查](navigation/技术实现-局部控制与安全.md#受控地面底盘检查)核对起步响应、方向和归零，并与现场观察对应。候选字节校验匹配和单帧微小速度不能替代稳定运动验证；低速无响应时，先核对原手柄、车体制动、使能及控制模式，不自动提高速度。没有台架时须按操作要求确认空旷场地和现场停车条件。
- 确认物理接管和独立急停，再实现唯一真实命令出口、单调时钟超时停车、断连处理与反馈检查。软件进程内的停车请求不能替代控制器失联保护；旧脚本不得直接作为执行出口。
- 用当前设备的新观察验证选定测试路线的地图、初始配准和持续定位。静态路径查询与同一建图 bag 的影子回放只能用于开发诊断，不能代替独立定位、非零速度执行、目标停车或真实接管验收。

### 现场验证顺序

1. 测量当前载荷包络、驱动与转弯能力、速度、加减速、制动、响应延迟、雷达到车体关系和后向覆盖。镜像参数继续作为开发参考。
2. 接入真实底盘状态与唯一命令出口，完成仲裁、接管、急停和硬件看门狗，并明确 TF 发布者、速度坐标、单位和时间。
3. 获得明确运动授权并做好安全准备后，先检查驱动禁用状态，再根据现场条件开展台架或空旷地面的受控低速验证。私有影子话题不能重映射成底盘出口。

## 数据提交约定

- 按[采集与 bag 处理](感知导航操作速查.md#采集与bag处理)录包，保留逐点时间、真实 IMU 和原始时间戳。
- 说明地点、楼层、用途、路线、各包起点，以及是否由同一长包切分。安装变化、驱动重启和断流也要记录，固定时差不能默认跨驱动会话复用。
- 预先区分建图、开发和独立留出。冻结后，定位或混合测试观察不能回灌到先验。
- 标签保留采集与地点归属，复用已有标注库，不随机拆分相邻帧。人工中心只支持中心级监督，不能当作完整 3D 框真值。
