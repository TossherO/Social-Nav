# 感知导航待办与数据采集

本文只维护尚未完成的开发、验收和数据需求。当前实现见[总览](感知导航总览.md)，运行命令见[运行手册](感知导航运行手册.md)，性能依据见[推理速度](感知导航推理速度.md)。

原生定位、内部直接通信、GPU 环境地图、DWA 和独立 CPU 安全已经整合。后续工作主要是改善持续可用性，并用独立数据和真实设备验收，而不是重复重构这些入口。

## 可继续实现与优化

### 输入时效与持续导航

继续检查地图生产长尾、发布后的交付等待和重复消费过期，保持原始测量时间和150毫秒状态反馈上限。需要更及时的状态时，再接入有来源的IMU传播结果或底盘反馈。具体失败时段与对照方式见[失败溯源](感知导航规划连续性与失败溯源.md)。

补做带分段目标的完整两层与独立场景验证，并分别测量场景归档、ROS发布和实际RViz渲染开销。现有短段消息测试不能代替完整负载或真实执行验收。

### 雷达—IMU时间一致性

直接runtime默认使用传感器时间戳，已移除启动时差估计和强制确认步骤。二层恢复包的[250秒对照](../outputs/perception/time_offset_comparison/report.md)支持这项简化，但未证明跨设备重启和不同运动条件下的偏移均可忽略。仍需核对驱动时间来源，并用少量独立数据检查固定补偿是否有稳定收益，机制见[标定与同步说明](perception/技术实现-建图与定位.md#雷达imu标定与同步实施策略)。

旧Docker容器所查雷达入口关闭`time_sync_en`，没有额外固定时差补偿。FAST-LIO按消息时间戳等待并组装数据，实际标准点云回调不估计时差。上述源码与配置只能说明其运行假设，不能证明驱动端已经严格同步。

后续验证集中在以下内容：

- 核对雷达逐点时间和D435i时间戳到主机时钟的转换，区分测量时间、传输延迟与处理耗时。
- 固定空间外参，在包含明显转速变化的独立片段上比较零偏移与有来源的固定补偿，再检查去畸变、重访及定位连续性；仅在出现稳定收益时采用非零补偿。
- 补充设备重启和长时间运行结果，确认上述选择的适用范围。原始消息和逐点时间保持不变，不通过在线调整掩盖时钟异常。

### 规划持续可用性专题

当前以10月20日第二段有图与无图路线为开发输入；10月29日旧先验问题另案处理。共同清单只保留任务入口，具体计数与案例由专题维护：

- 检查无图段局部缺口、旧先验静态高差及自由缺口，见[地图诊断](感知导航规划诊断与改进.md#当前处理顺序)。保留墙柱、新障碍、台阶、负障碍与换层反例。
- 核查参考等待、旋转段接入和剩余无候选周期，见[失败溯源](感知导航规划连续性与失败溯源.md)。用响应速度建议的反馈仿真验证提前减速和恢复，不裁剪bag中的真实估计初速。
- 在独立路线、横向偏离、端点证据恢复和关联重获时验证[有限目标策略](感知导航规划连续性与失败溯源.md#当前目标处理与剩余限制)，保持目标修订与真实完成语义。
- 实测已确认倒车、原地旋转能力对应的数值运动限值、制动、旋转中心和后向覆盖，按[实车接入要求](#实车接入前)验收。

### 环境与人物

人物归属已摆脱逐格地面支持前提，优先使用同帧跟踪地面平面，缺失时采用检测框高度限制。65帧真实点云已做数量、耗时和投影检查，用户审查所选动态片段后认为基本正确，暂不扩张删除范围。仍缺逐点真值；框覆盖不足、地面偏高、近墙连通及稀疏肢体断开可能错分或漏分。后续补充独立点级标注及靠墙、门框、静止人物和漏检反例，不能把更多归属点当作精度提升，也不能删除整框或伪造背景自由。

当前使用单平面地面跟踪。坡面、凸起和多片区地形还缺少独立验证，需要结合16线点云覆盖及实测车辆能力，区分地面缺失、自由覆盖不足和真实障碍，再决定是否需要扩展表示。

11月5日实验室二层bag的服务器副本存在压缩块损坏和后段异源结构，目前只能恢复连续前348秒。该片段已生成[诊断地图与检查报告](../outputs/perception/lab_floor2_mapping/report.md)，当时显式使用历史偏移。后续零偏移对照未发现明显退化，已取消启动估计，但未重建或重新验收该地图。仍需核对采集端原包及中转介质，检查轨迹附近未知与局部地面突变，再用独立数据验证定位。用户确认安装未变，暂时无法核对原包；旧地图与原先验问题的统计保持原样。

### 决策与长程任务

局部 VLM 已有三帧记录、单请求响应接口和 T3 只规划适配，下一步需要自动模型调度，并联调 T1 软关系、T2 持续跟随与重新匹配、T3 导航及真实停止反馈。记录器开销和响应时效应放在完整负载下测量，输入变化后重新核对标签与观察的对应关系。

外层 Agent 已有完备地图下的点与区域要求、空间图像、连续位姿接口和 runtime 影子适配。当前先测试室内单段及多段导航，再接实车反馈；简单地图、无图、跨条件及长程任务后置。研究与实现待办见 [Agent 技术计划](decision/Agent技术开发计划.md)，任务和验收见[导航任务计划](decision/长程导航任务与评测计划.md)。它独立于局部 T1、T2、T3，后续换层仍须真实外部确认。

### 部署端性能

在轮椅的实际 CPU 和 GPU 上运行完整负载，分别测量设备计算、GPU 排队、跨进程切换和同步等待。定位局部加速还没有按比例降低整链时延，需要按 CPU 余量和实际延迟决定部署端的 ROLL 后端。当前本机四核亲和测试不能代替部署设备验收。

固定同一份位姿输入，分别检查定位数值、稀疏检测和阈值附近的数量变化，再量化它们对图层与导航输入的影响。当前完整负载只测默认后端，不能从中分离这些因素或推断逐位等价，性能依据见[推理速度](感知导航推理速度.md#最近一次完整负载基线)。

## 独立验收与所需数据

| 内容 | 需要提供的数据 | 用来回答的问题 |
|---|---|---|
| 地图与混合定位 | 独立区域或路线，改变起点、朝向和边界；包含较长的离图返图过程，并附大致起点。定量误差另需独立轨迹参考。 | 静态结构、盲区、重新关联和近场背景能否推广到新场景？ |
| 反馈与导航行为 | 窄门、多人穿行、静止人物、坡道、临时遮挡和拥挤终点，另附可靠人物轨迹及车辆反馈。 | 确定性预测、停车恢复、舒适性和无进展处理是否有效？录包原运动不能作为执行反馈。 |
| 检测增量训练 | 更多完整复核的任务帧、无人背景帧，以及独立室内和室外留出。 | [任务场景适配](perception/技术实现-检测训练.md#任务场景增量适配)能否减少误检，且不过度增加各距离段漏检？同源训练回代不作独立精度。 |
| 跟踪与 RGB 关联 | 少量带连续身份和二维框对应的片段，覆盖交叉、遮挡和中心跳变；另做 Windows 审核与导出测试。 | 身份、速度、中心和关联是否准确？匹配数量本身不表示准确率。 |
| 长期并发运行 | 长时间真实传感器输入、设备负载，以及扫描封存开关记录。 | 时效、排队、丢帧、内存和显示是否稳定？ |
| 雷达—IMU 精标 | 保持组件刚性关系的多方向激励，补足俯仰和横滚，并另留验证包。 | 能否改善平移及弱约束方向？不要求重做已经接受的安装标定。 |

后续过滤变更或独立验收时，再把人物残影、墙柱和细障碍保留集中到一份材料中审查。已接受的审查不重复提交，审查结论不自动变成训练真值。“证据不足”不等于算法故障，灰色未知也不能直接填成空闲。

## 实车接入前

### 人工目标实车接入

人工交互统一使用[RViz交互入口](感知导航运行手册.md#rviz交互测试)，支持选起点、目标位置或位姿及bag暂停预览。受控串口出口已实现并经过模拟测试，实机导航仍需以下确认与验收。

服务器侧已准备[部署自检](感知导航运行手册.md#实机部署自检)、独立低速候选配置和有界底盘反馈日志。当前矩形轮廓与雷达到车体外参已由用户确认，数值和确认来源保存在[本车档案](../configs/wheelchair_vehicle.yaml)；后续沿用这两项，车体轮廓或安装发生变化时重新核对。该档案的运动和协议部分仍待补全，尚不能用于执行。底盘上报速度尚未成为规划估速来源，当前先对照定位估速与实际响应确定是否需要接入。

11 月 5 日，用户在轮椅本机空旷地面执行一次目标上限 0.10 m/s、窗口 2 秒的单次直行检查，观察到移动且未见明显偏转。候选编码器净位移约 3 厘米；当时程序约在 0.93 秒因转向反馈提前中止，严格停车确认未通过。原始记录保存在采集机器本地，不随源码提交。这是单次诊断，不证明稳定直行、制动或自主导航通过。此后分阶段判断和延长停车确认只做了模拟验证，尚未实机验证。

- 核实实际控制器固件使用的收发帧、校验、模式和故障字段。旧容器驱动与协议表存在差异，目前只有[离线候选解析](navigation/技术实现-局部控制与安全.md#旧底盘协议的离线诊断)，不能将原始模式或异常电量值直接解释为可执行状态。
- 使用[受控底盘检查](navigation/技术实现-局部控制与安全.md#受控地面底盘检查)核对起步响应、方向和归零，并与现场观察对应。候选字节校验匹配和单帧微小速度不能替代稳定运动验证；低速无响应时，先核对原手柄、车体制动、使能及控制模式，不自动提高速度。没有台架时须按操作要求确认空旷场地和现场停车条件。
- 确认物理接管和独立急停，现场验收已实现的独占串口、单调时钟超时停车、断连处理与反馈检查。软件停车请求不能替代控制器失联保护；旧脚本不得直接作为执行出口。
- 用当前设备的新观察验证选定测试路线的地图、初始配准和持续定位。静态路径查询与同一建图 bag 的影子回放只能用于开发诊断，不能代替独立定位、非零速度执行、目标停车或真实接管验收。

### 现场验证顺序

1. 沿用已确认的车体轮廓与雷达到车体外参，核实驱动与转弯能力、速度、加减速、制动、响应延迟和后向覆盖。其他镜像参数继续作为开发参考。
2. 接入真实底盘状态与唯一命令出口，完成仲裁、接管、急停和硬件看门狗，并明确 TF 发布者、速度坐标、单位和时间。
3. 获得明确运动授权并做好安全准备后，先检查驱动禁用状态，再根据现场条件开展台架或空旷地面的受控低速验证。私有影子话题不能重映射成底盘出口。

## 数据提交约定

- 按[采集与 bag 处理](感知导航运行手册.md#采集与bag处理)录包，保留逐点时间、真实 IMU 和原始时间戳。
- 说明地点、楼层、用途、路线、各包起点，以及是否由同一长包切分。安装变化、驱动重启和断流也要记录，固定时差不能默认跨驱动会话复用。
- 预先区分建图、开发和独立留出。冻结后，定位或混合测试观察不能回灌到先验。
- 标签保留采集与地点归属，复用已有标注库，不随机拆分相邻帧。人工中心只支持中心级监督，不能当作完整 3D 框真值。
