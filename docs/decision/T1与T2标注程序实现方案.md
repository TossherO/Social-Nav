# T1与T2决策标注程序实现方案

状态：基础标注链路已实现，真实Windows多机试用与小批人工试标待完成。当前操作统一见[决策任务标注](决策任务标注.md)。本文保留设计与阶段安排供审阅；任务总体设计见[系统方案](../系统方案.md)，划分与评分原则见[数据与评测](../experiments/数据与评测.md)。审阅稳定后移除本方案，避免长期重复维护。

## 1. 目标与范围

为实机rosbag建立可用于冻结VLM输入输出设计、Prompt开发和隔离评测的人工标签。

| 范围 | 本轮安排 |
|---|---|
| T1社会关系 | 同行、交谈、拍照、其他明确共同活动，以及活动未知／归属未知 |
| T2目标身份 | 初始描述、真实人物身份、当前匹配证据、遮挡／重现及连续身份复核 |
| 排队、T3 | 暂缓，不出现在新程序的任务编辑器中 |
| 既有检测标注 | 保持原程序与数据独立，作为可选的只读来源 |
| 模型调用 | 标注不依赖VLM服务，不在界面中运行检测或生成语义建议 |
| 导航控制 | 不执行机器人运动，不标注路径或控制量 |

采用独立的`decision/vlm/annotation/`包、SQLite工程与HTTP接口。复用原工具的交互经验、远程供数方式和第三方依赖，不导入、继承或复制整套`perception/detection_tracking/annotation/`实现，不共用其服务、数据库或客户端缓存。不为两套工具建立通用标注框架。

现有JRDB工具主要提供T1输入、调用和标签预览，尚无实机T1/T2标注链路；检测标注只提供单帧XY中心，不能直接提供稳定人物身份。已有`q`／`GOAL` Schema和历史JRDB数据保留，本方案不改变旧请求或结果的解释。

## 2. 使用流程与工作单位

### 2.1 一次准备，反复标注

1. Linux导入已有感知结果及bag头信息，建立轻量时间索引，原始RGB与点云按需读取；默认不重新运行检测。
2. 在程序中选择子bag，圈定事件起止时间，填写事件名称与地点／采集来源。一个bag可有多个事件，重叠事件保持同源划分。
3. 必要时关联人物身份，再切换T1或T2编辑页。两个任务引用同一事件与人物资料，各自保存审核状态。
4. Windows经Tailscale读取轻量资产并本地绘制；Linux也可直接打开工程，使用同一套新标注界面与规则。
5. 按已标样本导出开发／验证／留出数据。导出不调用模型，不自动运行评测。

不要求先给整包所有人物制作长轨迹。优先核对T1选定窗口内的人物，以及T2目标、相似干扰者和关键交叉位置。

### 2.2 四种对象

| 对象 | 含义 |
|---|---|
| 来源序列 | 子bag及其采集根来源、时间范围和感知结果绑定 |
| 事件 | 一段供筛选、关联身份和连续回放的区间，不复制原bag |
| T1样本 | 一个决策时刻及其历史观察窗口，答案针对最后时刻 |
| T2任务实例 | 一个事件内的目标描述与隐藏目标身份，包含多个有序观察点 |

T1和T2可以独立标注。T2实例无需先完成该事件所有T1；仅两者均已审核的共同观察点用于联合`REL_FOLLOW`评测。

## 3. 界面与交互

### 3.1 布局

```text
┌ 子bag／事件选择 ── T1关系 | T2身份 ── 保存／同步状态 ┐
│                                                   │
│       当前RGB，可缩放、点选人物      │ 米制BEV       │
│                                    │ 人物／轨迹列表 │
│                                    │ 当前任务编辑器 │
├ 过去观察缩略图：较早 → 较晚 → 当前 ─────────────────┤
├ 事件区间＋样本状态＋遮挡／重现等事件刻度时间条 ───────┤
│ 原始帧浏览／样本导航／播放   待标 | 跳过 | 已标      │
└───────────────────────────────────────────────────┘
```

- 默认同时显示大幅RGB和BEV。RGB支持平移、缩放、隐藏编号和按需查看原分辨率；BEV支持缩放、平移、点径调节及高度明亮色带。
- RGB、BEV和列表联动高亮同一人物；人工身份、当前局部PID、源轨迹片段分栏显示，避免混为一个ID。
- 人物局部裁剪可用于身份核对；只有明确进入所选观察协议的裁剪才算模型证据。
- 首轮集中实现二维交互，不依赖OpenGL。三维点云旋转查看作为后续可选诊断视图，不阻塞T1/T2标注。
- 页面仅显示当前任务按钮。准备数据、修改来源绑定和导出放在独立入口，不挤入日常标注面板。

### 3.2 两种观察模式

**上下文浏览**用于划定事件、查看完整录像和核实物理身份，允许访问未来帧；始终显示“上下文”提示。

**输入审核**固定决策时刻，只显示该协议允许的历史图、几何与中性PID。标注颜色、目标真实身份、未来画面和人工关联均不进入模型输入预览。T2的历史区在没有绑定具体回放历史时明确显示“未绑定历史”，不虚构`LAST_TARGET`。

两种模式共用原始资产，但审核答案与上下文事实分开保存。已经看过上下文的标注者不能据此宣称完成独立盲标；需要盲标时使用未看过上下文的审核者。

### 3.3 导航、状态与保存

| 操作 | 拟定规则 |
|---|---|
| `A / D` | 上一／下一原始观察帧，仅浏览 |
| `W / S` | 上一／下一已有任务样本，止于当前事件，不自动创建样本 |
| `空格` | 暂停／播放上下文；输入审核仅播放当前窗口允许的帧 |
| `1 / 2 / 3` | 当前样本标记为待标／跳过／已标，不跳转、不弹确认 |
| `Q / Esc` | 应用当前任务编辑／取消未应用的选择 |
| `Ctrl+Z / Ctrl+Y` | 撤销／重做标签编辑，已确认修改同步记录新修订 |
| `F1` | 显示当前任务快捷键与图例 |

文本框、下拉框和数值框获得焦点时，不触发导航快捷键。建组、设目标、关联片段等操作保留可见按钮，初轮不继续分配大量全局快捷键。

浏览、预读、播放和切换任务都不创建标注。首次实际编辑或显式“加入样本”创建待标；批量取样仅在明确选定事件与步长后执行。修改采样步长不删除、移动或重建已有样本。

时间条用黄／灰／绿表示待标／跳过／已标，同时提供不同形状与悬停文字；T1/T2状态分轨展示。未加入样本的位置保留空白，跳过不表示无人或未知。

标签自动保存，状态与保存成功分别显示。修改已标内容回到待标；标记已标只确认当前任务，不自动接受未分类人物。删除事件、清空任务标注需要确认；首轮不提供一键清空整个工程。

## 4. 人物身份与感知误差

维护三类互不替代的身份：

- **物理人物ID**：事件内稳定的人工身份，用于隐藏真值；跨bag默认不关联。
- **源轨迹身份**：保留来源、会话、生命周期和片段边界。相同数字ID在重置后不是同一轨迹。
- **模型局部PID**：由所选输入协议的因果轨迹生成，绑定具体窗口和映射修订。

界面允许把一个轨迹片段关联至人物、在某帧拆开错误关联，以及将多个片段关联至同一人物。传播范围必须明确；人工核实不了的重现保留身份未知，不根据衣着相似自动合并。

这些人工关联只建立答案映射，不修复原P1模型输入。未来重现可以帮助核实物理身份，不能把其前后的轨迹自动连成模型已知的历史。

漏检人物可在RGB补一个辅助人物框，用于记载目标可见、选定身份或说明漏组；它不自动成为完整3D框，不凭空补BEV位置。需要人工修正感知的上界诊断时另建输入协议，不把人工框或人工跨帧关联混入P1成绩。

## 5. T1关系编辑

### 5.1 日常操作

1. 选择决策时刻，查看固定历史窗口及当前有效人物。
2. 点选两人或多人，建立群组，选择同行、交谈、拍照、其他或活动未知。
3. 拍照群组按可见证据指定摄影者、主要被摄者；角色不可判时保留无结构群组。
4. 将其余人物逐个或多选标记为“确认未成组”或“归属未知”。
5. 标为已标；程序只核对成员覆盖、互斥和角色引用等必要约束，不替人判断关系。

| 标签 | 操作含义 |
|---|---|
| 同行`w` | 有共同移动、协调队形等证据，距离近／同向本身不足 |
| 交谈`t` | 有相互交流的证据，站在一起本身不足 |
| 拍照`p` | 有拍摄另一成员的证据，拿手机本身不足 |
| 其他`o` | 共同活动明确但不属于以上类别，填写简短活动说明 |
| 组内`r=u` | 群组成员明确，活动不可判 |
| 归属未知 | 无法可靠判定成员关系，导出为顶层`u` |
| 确认未成组 | 是明确结论，导出时从`g/u`省略 |

同一人物不能同时属于两个群组，或既在群组又在归属未知中。同组多活动按拍照＞交谈＞同行＞其他取主关系。拍照角色可判时导出`k=1`，否则`k=0`；其他活动均为`k=0`。排队主导且不适合当前任务的样本可标跳过并记录“范围外”，不强行归为独行。

### 5.2 减少重复操作

支持“复制上一已标样本”和“应用到指定区间”，通过已核对的物理人物关联给出草稿。覆盖已有人工内容须确认；传播结果全部待标，人物缺失或身份不确定时提示人工处理，不按PID数字复制。单成员不能导出成两人群组。

每个已标样本覆盖所选协议的全部当前有效PID，显示阈值或隐藏图元不缩小标注范围。未处理不等于未知，无人样本也需明确确认。

## 6. T2目标与连续证据编辑

### 6.1 建立目标任务

在参考时刻选定物理目标，填写基于当时可见外观的自然语言描述，绑定参考图和描述修订。目标可在事件中稍后才出现；“目标始终不在场”支持显式无目标实例，并记录描述来源。

一个事件可建立多个目标任务，分别保存描述与审核状态；人物关联共用。描述不能包含PID、隐藏身份或未来细节。参考时刻以前若没有合法描述来源，不自动生成回溯样本。

### 6.2 固定事实与状态分开

逐观察点记录以下内容，稳定区间可批量填写后复核：

| 内容 | 取值或说明 |
|---|---|
| 目标可见性 | 清晰可见、部分遮挡、完全遮挡、视野外、无法确定 |
| 真实目标对应 | 对应的RGB人物／源轨迹；不知道时明确未知 |
| 描述匹配证据 | 合理候选集合，当前可唯一确认／有歧义／无合理匹配／证据不足 |
| 感知覆盖 | 已被表示、漏检、关联错误、缺RGB等，独立于真实可见性 |
| 连续性依据 | 关联片段及是否支持短遮挡保持，区分人工事后身份与在线可用依据 |
| 事件标记 | 首次出现、交叉、遮挡、重现、离场及ID切换等 |

物理真值唯一不代表模型当前可以唯一识别；合理候选有多个时不能任意选一个作为正确输出。看不清、漏检、目标不在场也不能混成同一标签。

首轮导出这些固定事实，用于外观匹配和连续回放。`v/o/a/l/n`的最终状态金标准需要绑定具体方法真实接受的历史：`o`要求先前确认和可靠保持依据，`l/n`由是否曾确认区分，不能给每个方法套人工完整录像的历史。

后续可在同一T2页增加“绑定回放记录”的审核入口，保存历史摘要、输入绑定和状态结论；该功能须在真实T2回放接口建立后接入，不在首轮模拟成功历史。仅完成固定事实标注时，不宣称已具备完整五状态评测。

### 6.3 感知与协议不能表达的情况

若目标在RGB可见但没有可选PID，记录真实目标与覆盖失败，不把它改成“不在场”，也不编造合法ID。此类样本进入端到端失败统计；模型语义子集的排除范围和覆盖数必须显式报告。T1漏检导致的不可表达群组同样保留，不靠过滤掩盖感知问题。

## 7. 输入协议与导出

先参考现有三帧历史RGB＋BEV协议，默认选取不晚于决策时刻的真实观察。当前JRDB专用渲染器不能直接当实机适配器；新程序的实机窗口构造需独立实现，并与后续推理入口共用同一份决策侧输入定义。

- 记录原始采集时间、时钟来源、实际配对时间差和缺失值；不使用未来RGB或未来位姿补齐。首帧历史不足时明确标记，不复制当前帧伪装历史。
- BEV统一使用明确的米制坐标与方向。缺可靠定位时只展示当前传感器几何，不绘制虚假的世界轨迹或速度。
- RGB投影记录相机内参、外参和同步规则来源，失败可在原图手工核实人物，但不冒充自动投影正确。
- 人工审核层与模型预览层分开渲染。分组颜色、真实身份和目标答案不能进入导出的模型图、Prompt或几何字段。
- 沿用当前最多20名有效人物、局部PID为0～99的接口边界；超限样本须按事先确定的中性选人规则处理并记录覆盖，不按人工答案筛选人物，也不静默截断。
- 保存观察协议、资产内容指纹、局部PID映射和审核修订；有实质输入变化时，受影响样本回到待审核，不悄悄沿用旧金标准。无需每次打开都重读／哈希全bag。

常规导出仅含一份来源／划分清单和T1／T2标签JSONL，引用已有观察资产；需要跨机器模型测试时才显式生成输入图和几何包，不自动复制整包点云或所有截图。T1按现有对象式`g/u`导出但本轮类别不含`q`；T2固定事实文件明确区别于`REL_FOLLOW`响应金标准。

开发／验证／留出按采集根来源和重复地点组织。同事件的相邻窗口、多目标描述、不同布局继承同一划分；已用于调Prompt的数据不能改称盲测。未标、待标、跳过均不导出为已审核答案；已标但未完成服务器同步的草稿不进入正式导出。

## 8. 独立实现与数据组织

### 8.1 技术选择

客户端使用PyQt5、NumPy、HTTPX与轻量图像读写，优先复用现有Windows环境能兼容的第三方依赖。RGB／BEV使用Qt绘图和可复用图元，避免逐帧重建Matplotlib画布；不新增浏览器前端构建链。依赖清单由新包独立维护，实现时按实际兼容情况确认，不在本轮安装或升级。

Linux准备与HTTP服务使用现有项目开发环境；rosbag读取放在独立的系统ROS解释器子进程。准备只登记已有结果和少量头信息，日常按需读帧，复用bag句柄、原有索引、内存缓存和邻帧预读，不再把全量缓存作为启动前提。Windows客户端不需要ROS、Torch或CUDA；Linux本机客户端也不直接加载ROS扩展。

拟定模块按职责保持小规模，不预先引入插件系统：

| 位置 | 职责 |
|---|---|
| `decision/vlm/annotation/__main__.py` | `prepare / open / serve / export / package-client`独立入口 |
| `prepare.py`、`ros_reader.py`、`assets.py` | 轻量结果登记、系统ROS按需读包、有界缓存与进程管理 |
| `store.py`、`rules.py` | SQLite访问、事件与人物关联、任务约束和修订 |
| `app.py`、`views.py` | Qt窗口、T1/T2编辑页、RGB／BEV与时间条 |
| `backend.py`、`service.py`、`remote.py` | 本机／HTTP访问、独立服务协议、持久草稿与同步 |
| `export.py`、`package_client.py` | 标签／显式输入包导出，客户端固定清单打包 |

具体文件可按实现复杂度合并或拆分；不为凑目录提前创建空文件。跨模块只读取感知产物协议，导入器不调用检测标注程序来间接读数据。仅有XY中心而没有轨迹时，应明确缺失身份依据，不能把中心编号当轨迹ID。

### 8.2 工程文件

```text
data/annotations/vlm_decision/<工程>/
  observations.sqlite   # 来源、已有结果与轻量时间索引，完成登记后只读
  annotations.sqlite    # 事件、身份关联、T1、T2、审核与同步回执

客户端独立缓存目录/
  cache.sqlite          # 已读资产、个人设置、未同步草稿
```

原bag、感知结果、旧中心标签保留原处只读，不复制到新工程。观察库保存原始引用、绑定摘要和缺失记录；准备中断只留下明确未完成的派生库，完成标记前不能启动编辑服务。重新检测或更换标定不覆盖已有观察库，应显式准备新来源并迁移可审核标签。

原分辨率RGB、预览和点云只在查看对应帧时读取并进入有界缓存，不全量写入观察库；模型输入也只为选定窗口生成。完成的旧缓存工程保留原标签与输入绑定，通过同一界面兼容读取，不要求迁移或重新标注。

元数据放数据库，首轮通过入口参数登记工程，不要求用户手工维护额外JSON配置。客户端包只包含新界面代码与必要依赖声明，不打包旧标注器、原始数据、模型或个人路径。客户端缓存使用独立的`SocialNav/vlm_annotation`命名空间，不能指向旧工具缓存。

## 9. 远程访问与流畅性

### 9.1 Linux供数、Windows绘制

沿用Tailscale直接连接方式，不引入访问令牌；绑定当前设备的Tailscale地址，独立监听端口拟取`8766`，不复用检测标注服务的`8765`。实际地址与环境只在本机记录或启动参数中维护。

服务仅暴露登记工程的索引、观察资产、标签及写入操作，客户端不能提交任意服务器文件路径。原始SQLite不通过共享盘远程打开。一个工程同时一个写入会话，其他窗口只读；本机编辑入口也遵守同一写入锁。

保存采用有操作ID和预期修订的事务，标签与回执同时提交。网络中断保留本机持久草稿；写入结果未知时先查询原操作回执，再决定是否提交同一操作，不以新ID重复写入。过期修订或写入会话失效时保留草稿并停止覆盖，显式处理冲突。人物关联修改影响的已标样本需重新审核，不能只更新身份表。

界面区分“本机暂存”“待同步”“服务器已保存”“冲突／只读”；重开恢复草稿，正式导出只读取服务器已保存内容。首轮不实现多人合并、分布式数据库或复杂权限管理。

### 9.2 性能策略

- 准备阶段按实际扫描节奏建立浏览索引；已有10Hz感知结果可按10Hz浏览，任务样本默认按2秒间隔显式生成，可人工加密事件边界。
- 默认传RGB预览、少量人物几何和降采样点云BEV，不持续传完整三维点云。需要细节时单独请求原分辨率图；预览只是准备缓存，不自动成为模型输入协议。
- 固定协议审核图按需生成并缓存，首次审核前明确生成状态。审核实际输入时使用其对应分辨率与字节，避免拿低清浏览图代替模型图作判断。
- 当前帧优先，后台预读邻近约2秒；跳转时取消过期预读，带请求序号的迟到数据不能覆盖当前画面或标签。
- 网络、读库、解码与保存放后台，Qt主线程只更新图元。二维缩放、平移、选择与点径调整只用本机缓存。
- 时间条加载事件内轻量索引，任务详情按需读取。可淘汰图像／点云缓存，未同步编辑不得随缓存清理丢失。

性能验收分开测本机缓存切帧、首次远程取帧、预读后连续浏览。参考目标为代表性事件中缓存切帧中位数约100ms内、常用面板操作无可见阻塞；远程首次读取按实际Tailscale链路记录，不预先承诺固定延迟。这是待测工程目标，不是现有结果。

## 10. 实施顺序与最少验收

| 阶段 | 实现内容 | 必要验收 |
|---|---|---|
| A：数据与规则 | 独立工程、已有感知导入、事件／人物／T1／T2结构与只读预览 | 小型合成事件验证时间、身份和输入／答案隔离；只读检查少量真实帧 |
| B：本机标注 | RGB＋BEV、时间条、T1编辑、T2描述及证据、自动保存／撤销 | 一个真实短事件完成两类标注，重开和导出一致，旧数据未写入 |
| C：远程标注 | 独立HTTP服务、Windows客户端包、缓存／预读／持久同步 | Linux↔Windows真实连通；切帧、断网恢复、结果未知与修订冲突各做代表性检查 |
| D：小批试标 | 约20～30个T1窗口、5～10段T2事件试用，修正规约与操作 | 人工查看典型、歧义、无人、漏检及遮挡样本；记录实际操作与切帧耗时 |
| E：推理衔接 | 新实机窗口协议接推理入口，后续接T2因果回放历史审核 | 按实际任务另行安排少量模型验证；完整五状态与联合成绩分别验收 |

A～C按顺序形成可用程序，D用于确定是否扩大标注。E不作为开始采集和事实标注的前提，也不在本轮方案编写中执行。

只为上述关键规则编写相关测试，临时样本和日志放临时目录；交付保留一份简短验收汇总，不逐次积累截图、重复报告和整包副本。没有真实Windows检查时明确标记待测，不能用Linux模拟替代多机验收。

最终日常操作应收敛为：**一次离线准备 → Linux启动独立服务 → Windows打开工程 → 选择事件与T1/T2 → 标注并自动保存 → Linux导出**。具体安装和命令在实现后写入正式手册，本方案不提供尚不可运行的安装步骤。
