# T2 行人跟随

启用 `--agent-follow-candidates` 后，后台工作器在收到有效定位和相应观察后预热 YOLO，并在跟随开始前提供带编号的人物候选。Agent 根据当前图像和任务描述确认目标。系统保存候选的原图和人物裁剪，启动跟随时核对候选、观察和任务身份。裁剪作为持续跟随的固定参考。

跟随期间，局部决策和外层 Agent 共用同一源观察中的 RGB、人框和轨迹。T2 工作器保留最新一帧可供 Agent 查看，随即继续匹配或向 VLM 发起请求。外层 Agent 的状态和心跳轮询只读取观察标识。首次选人、监测需要读图或判断跟随结束条件时，运行时才把对应帧制成无损图像，同一帧可复用。Agent 核对图像和目标时沿用原始测量时间。

## 观察与后端

启用 T2 后，后台选人和持续观察优先使用曝光时间在扫描结束前 0 至 50 毫秒内、且内参匹配的图像。原配对不满足这个条件时，后台可以从相机缓存补取一帧。图像和内参最迟须在雷达消息到达后 30 毫秒内收到，内参的测量时间不得晚于曝光。实机以接收端的单调时钟计时，回放以 bag 的消息记录时间计时。补取的图像只供本次 T2 观察使用，定位、导航和独立安全继续处理原扫描。补取失败时，已有图像仍按原有时效和关联条件检查。缺少可用图像时等待新观察。

T2 在每帧有效雷达扫描后更新用于时间补偿的位姿与轨迹历史。DSPARK 和托管请求使用同源环境图准备三帧，`reid` 使用当前环境图对应的一帧。环境图频率可以低于雷达频率。定位失效或定位身份变化时清理历史。

T2 的 DSPARK 后端使用 `project.json` 中的服务地址和模型名，并检查服务是否启用 DSPARK。`hosted` 复用 Agent 私有连接配置和用量账本，发送相同的三帧与目标参考，关闭思考并要求 JSON 对象。客户端仍严格校验字段、候选和源观察。两种 VLM 后端均可用 `--t2-jpeg-quality` 编码观察图和参考图，实际发送的图像进入请求指纹。离线冻结三帧继续保存无损 PNG。

后端选择、图像编码和模型权重配置见[运行手册](../系统运行手册.md#启用持续跟随)。

## 跟随目标点

VLM 和 OSNet 确认跟随对象后，共用[导航侧的跟随策略](../../navigation/tasks.py)。导航在里程计坐标系中记录这个人实际走过的位置，从最新观测沿折线往回量 1.5 米，插值得到目标点。人物拐弯时，目标点会先沿入弯一侧前进，再绕过拐角。规划器仍需检查轮椅的完整轮廓和当前障碍。

刚建立跟随、行走轨迹还不够长时，导航用首次观测时从人物朝向轮椅的线段补足距离，最远取到当时的轮椅位置。默认每移动至少 0.15 米才保存一个折线顶点，最新实测位置仍参与插值。候选目标与上次目标相距至少 0.25 米才更新目标。人物原地转身时，速度估计的方向变化不会移动目标。

同一三维轨迹连续时，后端再次确认人物会沿用已有折线。只有预测位置的帧可以在原有效期内保持目标；恢复实测后从新的观测段开始。人物身份、轨迹代次或定位发生变化时，须用重新核验的轨迹生成目标。

## VLM 匹配

[T2 在线请求](../../decision/vlm/t2/online.py)将三帧按源时间排列，再附上目标描述、固定参考和当前观察候选。预测轨迹与真实观察使用不同样式。选中人物的响应如 `{"target":"P0","observation":null}`，选择观察点的响应如 `{"target":null,"observation":"A"}`。程序严格检查两项互斥及本轮映射，并校验图像和场景来源，再构造供跟踪层核验的目标参考。

每次只处理一个请求，消费结果后使用最新可用观察。结果须在最后一帧扫描后 4 秒内应用，视觉确认最多保留 6 秒。遮挡后同一连续轨迹重新出现时，仍在有效期内则可以继续运动并尽快重新判断，原视觉时间照常到期。模型请求失败后等待处理。`project.json` 中的 `inference.period_s` 用于通用决策数据录制器，持续 T2 和在线 T3 的调用频率取决于新观察和模型返回速度。

非执行观察可选择原始 RGB 实验模式。首次选人仍使用 YOLO，随后各模型请求总共提供三组原始 RGB 和独立俯视图，让模型判断图像人物与已确认轨迹的对应。该模式缺少当前跟随结束检查所需的独立二维关联证据，仅用于预览和对照。

VLM 可以从导航提供的等待、原地转向和短距离接近候选中选取观察点。生成和应用时都检查地图与车体扫过的区域，原地转向还需要停稳证据。单次接近最多 0.8 米，搜索限制在起点周围 1.5 米内。

VLM 已通过合成控制联动和模拟回复的短 bag 影子回放。托管 API 的两组真实人物输入和一组移除候选人物的模拟输入均返回符合协议的两字段。DSPARK 的实际正则约束、两种匹配方法的现场识别及实机遮挡找回仍待验证。

## 本地身份匹配

[OSNet 匹配器](../../decision/osnet/reid.py)以固定裁剪为参考，对当前 RGB 中的 YOLO 人框做外观匹配，同时检查候选间的分数差、检测质量及位置连续性。二维人物须关联到本帧真实观察且已确认的三维轨迹。首次跟随、换轨和遮挡找回均需连续两帧支持同一身份与轨迹代次。匹配足够稳定时可以保存少量来自高置信当前观察的外观特征，固定参考在整个任务中持续参与评分。重复、含糊、低质量或无法关联的观察无法建立新身份。局部结果须在扫描后 0.5 秒内应用，最后一次视觉确认最多保持 0.75 秒。

匹配器在同一个 `reid` 后端下使用 OpenCV CPU 或 TensorRT CUDA 提取外观特征。两种方式共用裁剪预处理、身份判据和源时间检查。TensorRT 引擎由已导出的 ONNX 在目标设备上构建，构建和启动步骤见[启用持续跟随](../系统运行手册.md#启用持续跟随)。

## OSNet 失去目标后的导航

失去视觉确认时，最后一次下发的跟随目标和最后一次观测到的**人物位置**是两个不同的导航依据。[丢失判断](../../decision/osnet/search.py)区分以下三种动作。

| 动作 | 何时选择 |
|---|---|
| 继续已下发的跟随目标 | 等待下一次匹配时，原视觉确认仍有效，同一代三维轨迹在新的场景中仍有真实观测，路径仍可用。轮椅可以走完已规划的目标，目标位置和修订号保持不变。视觉确认的有效期仍从原 RGB 计时。 |
| 原地等待 | 有人横穿目标所在图像区域、候选身份含糊、图像与轨迹无法可靠对应，或缺少有效的定位和路径时，撤下运动目标。持续采集新观察，等待重新确认。 |
| 前往最后观测位置 | 目标离开前的连续观测支持其向视野边缘移动、转弯或逐渐远离。随后至少三张不同源时间的 RGB 跨越 1 秒，且相邻观察间隔不超过 0.5 秒，持续支持目标已经消失，才考虑使用最后一次由视觉和三维轨迹共同确认的人物位置。每次丢失只采用一个固定目的地。 |

离开视野的证据必须能接上最后一次确认，两者之间最多相隔 1.5 秒。判断目标走远需要连续看到距离增加和人框缩小。判断转角后的朝向还需要多次实测位移支持出弯方向；只有位置可靠时，导航只接收位置。

导航将人物最后位置转换到地图坐标系，检查通路。每次续行都要取得新观察，许可最多延长到该次扫描后 0.75 秒，且整个动作最迟在最后一次可靠观测后 45 秒结束。最后位置不可达、途中再度出现身份疑义，或到点仍看不到人时，轮椅停车等待。连续两帧重新确认人物就恢复跟随。到达历史位置只结束这次接近，T2 的完成条件仍由外层 Agent 判断。

## 已有身份匹配回放

在 `wheelchair_20261023` 的 3 个 bag 中，按 5 个跟随目标各自的初始裁剪连续回放了 981 帧，单帧最多有 10 个人框。CPU 和 RTX 3090 给出的前两名候选和身份决策逐帧一致。58 个标注点同时有可见目标、人工记录的目标轨迹和匹配到该轨迹的人框。其中 55 个点有多人候选，目标有 54 次排在首位，最终确认正确 37 次，其余 18 次未确认。

在全部 58 个点中，未确认的最常见原因是外观相似度低于阈值（16 次）。例如灰色帽衫目标的参考图是正面，转身后主要露出黑色背包，有一帧仍排第一，但得分 0.532，低于确认阈值 0.65。这些结果来自未复核的早期标注，衡量的是历史感知输入上的身份匹配。搜索动作及实车跟随仍须单独验证。
