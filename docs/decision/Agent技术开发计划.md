# Agent 技术开发计划

本计划记录 Agent 的研究依据、拟议创新、已有工程机制和后续开发。当前实现见[Agent 技术实现](Agent技术实现.md)，具体任务、对照实验和命令见[导航任务与评测计划](长程导航任务与评测计划.md)。

长期研究主题仍是：**面向部分已知环境的轮椅导航，持续维护任务证据，并选择符合运动约束的有效观察。** 当前先研究室内完备地图下的点、区域和语义朝向，将长程、简单地图、无图及跨条件任务保留为后续扩展。Agent 自身使用 VLM，但本项目不训练该模型，也不依赖局部 T1、T2、T3。

当前采用单 VLM 工具循环，仿真和影子入口统一调用 `AgentLoop.run()`，环境时间与输入推进由测试驱动处理。框架已增加任务要求、地图输入和完成检查，后续用真实闭环推动研究组件，不建设大型离线模拟器作为前置。Agent 尚未接通实车执行反馈，感知、导航和独立安全仍各自负责原有功能。

## 框架收敛方案

当前优先实现室内完备地图下的点目标、区域语义目标及两者的有序串联。完备地图包含场景建图结果和任务涉及的人工点、区域及对象标注。简单地图与无图分别保留输入能力接口，跨地图条件、跨模式、换层和原长程演示暂列后续。

区域内的位置和未明确指定的朝向由同一个 VLM 直接选择。工具提供全局地图、目标局部图、现场 RGB 与结构化坐标，检查模型提交的连续位姿，不生成候选终点或推荐朝向。任务要求与选定执行位姿分别记录，完成时同时核对几何反馈和必要的当前语义证据。

### 一个模型循环决定下一项工具

框架采用 ReAct 式的工具交互：通过原生工具协议，把原指令、助手调用和工具结果累积为对话，由同一个 VLM 选择下一项工具。每轮补充简短当前状态和有效观察，任务要求与执行依据独立保存。模型可以在上下文中规划长程任务，不先生成由另一执行器逐项运行的完整计划。

规划和场景审查合并为同一个决策入口。取得图像、导航失败、目标到达或用户补充后，仍由这个循环决定查询、观察、导航、等待、澄清或结束。框架只管理消息、工具参数检查、请求次数和结果是否仍适用于当前任务，不根据任务种类增加专用分支。

工具覆盖要求登记、地点和地图查询、场景观察、导航、状态查询、取消、等待、子任务检查、澄清与结束。导航工具检查 VLM 直接选择的位姿，返回调用句柄；请求被接收不等于到达，完成和取消必须有对应反馈。长时间导航在后台进行，等待期间不反复调用模型，用户暂停和取消不经过模型。

### 保留必要组件，移除重复编排

| 部分 | 当前处理 |
|---|---|
| 完整计划 Schema、独立审查 Prompt、自动逐步骤执行器 | 从当前默认链中移除，统一为一次选择一项工具的模型响应。 |
| 任务记录 | 独立保存原指令、有序点或区域要求、选定位姿和完成依据；仅限制顺序及完成判据，不自动运行下一项工具。 |
| 模型对话 | 使用原生 `tool_calls` 和对应结果积累交互，每轮仅补当前状态；裁剪保留完整调用配对，图像按当前有效性提供。 |
| 导航适配 | 保留实际几何检查、调用身份、反馈时间、停止和取消确认。执行细节放在工具内部。 |
| 证据记忆 | 保留带来源的历史判断；模型可主动保存、重读关键 RGB，最多两张历史图参与上下文，不作为当前执行证明。 |
| 模型客户端与落盘 | 复用托管 API、单个后台请求、预算账本和原始响应记录，不自动重试或更换模型。 |
| 实机接入与研究扩展 | 继续后置。主动移动观察和局部 T1、T2、T3 后续通过工具加入，不扩充核心任务状态机。 |

模型通过独立 `tools` 定义选择函数，客户端检查原生调用及各工具参数。不再把统一动作对象作为回复正文协议。允许简短进度文字，纯文字不构成任务成功；完成仍经过本地检查。不要求输出或保存内部思维链，也不沿用 simpleCC 的自动重试、自动换模型或无工具即结束任务的处理。

### 重构验收

当前原生协议和累积对话已通过定向检查与五项反馈场景。实际服务完成了两轮交互：模型先查询地图，收到原生工具结果和两张地图后再选择连续位姿，结果见[原生对话迁移报告](../../outputs/decision/agent/native_dialogue/report.md)。首次实际检查暴露的流元数据拼接错误已修复，失败记录保留；没有执行 API 选出的导航，也未将协议检查计为任务成绩。

此前的[室内导航适配报告](../../outputs/decision/agent/indoor_navigation/report.md)保留点、区域与语义朝向的来源，原单次 JSON 回复不作为新协议验收。

当前输入已增加绘制全部固定标注的高分辨率地图、带实测轨迹的概览和模型主动保存的关键 RGB。[六图检查](../../outputs/decision/agent/visual_context/report.md)验证输入协议与少量缓存复用，也暴露了重复登记要求的模型动作；这些属于工程及开发样本结果，尚未证明视觉记忆的任务收益。

独立上下文审查后，已将总规则、工具字段语义、适配器机器人资料和每轮状态分别组织，固定目录引用也明确保留来源与回退条件。修复了控制时间与观察时间不同造成显式裁剪丢失的问题，并保留全部已接受澄清。[审查与验证](../../outputs/decision/agent/context_review/report.md)属于可维护性和信息正确性的工程调整，尚未作为新的论文方法或精度增益。

此前真实观察上的两次图像工具交互保留在[旧循环报告](../../outputs/decision/agent/react_tools/report.md)，用于追溯原接入，不将旧工具协议视为当前版本验收。

框架不形式化证明任意自然语言要求。完整指令是否被理解和满足，仍需具体任务验证；导航工具只为实际执行提供证明门槛，不能把模型文字、影子状态或接收 ACK 记为执行成功。旧冻结输入和实验结果保持原样，当前实现和操作入口以新文档为准。

## 技术创新与当前进展

### 任务证据的选择性维护

研究问题是：观察不完整、地图关联变化或定位重置后，怎样保留有用知识，同时避免旧位置和旧完成判断误导后续任务？

拟用轻量依赖关系连接任务条件、目标位姿、源观察和执行事件，不另建图数据库。不同类型的依据需要分别处理：

| 依据 | 要记录和维护的内容 |
|---|---|
| 任务条件 | 用户要求的目标、先后顺序和等待条件。模型可以分解任务，但不能删除必达目标。 |
| 语义证据 | 支持、矛盾或未知判断，以及外观和源观察。没有看见目标不等于目标不存在。 |
| 空间依据 | 选定坐标依赖的位姿、地图关联和定位会话。旧坐标失效不表示历史图像内容错误。 |
| 几何与执行 | 当前通行、实际到达和停稳的判断，分别记录测量时间和所属目标。历史语义不能代替这些判断。 |

计划中的维护机制只更新受变化影响的依据。例如，地图关联失效时撤销地图目标；如果局部定位仍然有效，就保留局部依据。SLAM 重置后，再撤销旧局部坐标。已经发生的完成事件保留为历史，但“轮椅当前仍在此处”需要重新判断。

如果新旧观察互相矛盾，应同时保留两方来源，而不是在摘要中消除冲突。重定位即使恢复了坐标变换，也必须重新检查路径和阶段条件。

以离开走廊进入未建图门厅为例，系统可以保留“来时经过蓝色标识门”的外观和经过顺序，但不能把旧全局坐标直接发给局部导航。返回时需要确认地标、重建地图关联并重新检查几何。如果存在多个相似门口，应保留歧义，不能只按最近坐标或文本相似度合并。

当前已将任务要求、模型选定位姿和完成依据分别记录，并核对地图及观察来源。可关闭的证据记忆保存历史工具选择，定位或地图变化后撤销空间有效性；它不自动认证地标事实，旧任务不自动恢复。更细的语义依赖、最少缺失依据检索、重新关联及恢复决策仍待开发。

这项研究要验证的是：选择性维护和重新建立依据，能否改善恢复、减少错误阶段推进和重复探索。当前失效保护只是工程基础，还没有证明上述收益。

### 任务相关的主动观察

研究问题是：什么时候继续走、移动补看、检索历史或询问用户，才能在相同预算下完成更多任务？

后续考虑在同一个模型循环内比较查询地图、读取当前图像、移动补看、检索历史和询问用户的成本。移动观察的位置和朝向仍由 VLM 直接选择，导航只检查可行性。可研究以下有上限的效用描述：

```text
效用(a) = 任务推进价值(a)
          + Σ[条件重要度 × 预计新增有效证据覆盖(a, 条件)]
          - 移动与等待成本(a) - 模型请求成本(a) - 重复观察成本(a)
```

“预计新增有效证据覆盖”是代理量，不是真实信息熵，也不是完整 POMDP 求解。权重在开发集上确定后固定，安全要求不能由其他收益抵消。初版不做强化学习、大规模采样或逐位置独立调用模型。

观察决策拟按以下过程进行：

1. **明确缺失条件。** 判断当前不能完成任务是因为没有可靠空间位置、看不清目标，还是缺少执行反馈。后一种情况不能靠移动补看解决。
2. **提供足够空间信息。** 有图时查询全局和相关局部图，无图时使用当前可靠几何；视觉定位需要有效标定、同源 LiDAR 或实际可用深度。没有尺度和位置依据时不能从 RGB 猜米制坐标。
3. **由 VLM 选观察位姿。** 模型结合遮挡、视角、对象和任务选择连续位置及朝向。工具检查完整足迹、转弯和通行性，只返回结果，不生成或修正终点；倒车和原地旋转也须检查实际扫掠。
4. **控制图像和调用成本。** 当前将高分辨率固定地图与全部标注放在前部，末尾使用当前 RGB、低分辨率全局概览和局部图，历史 RGB 按模型主动保存或重读最多加入两张。后续比较关键帧选择的必要性、收益与费用，保留原时间及视角，不直接套用局部任务固定三帧间隔，也不无限增加输入。
5. **用新观察评价收益。** 事件触发后限制移动、模型和等待次数，取得动作后的真实图像才判断是否消除歧义。未知区域不算可见，稀疏点缺失不算空闲，预算耗尽时澄清或终止。

模型返回后，执行前仍须用最新几何检查动作是否可行，但不能把原语义判断的时间改成当前时间。未来 bag 视图和录制驾驶不能替代移动观察的实际反馈。

当前已能查询地图、读取现有 RGB、等待不同的新观察，并限制请求次数。主动移动观察、效用策略及关键帧选择尚未实现。拟议研究与 SeekVLN 的差异在于不训练模型、轮椅可达视角和异步成本；与 TANDEM 的差异在于联合选择移动观察和已有证据。是否有效仍需相同预算下的强对照，不能把这些设想当成已经成立的创新。

## 工程亮点与模型选择

### 已实现的工程机制

| 机制 | 实际解决的问题 |
|---|---|
| 单模型循环与导航工具分工 | 模型每轮选一项工具，导航工具内部检查几何和执行证明，不另设完整计划执行器。 |
| 原生调用与有界对话 | 工具定义、调用和结果各有协议位置，当前状态与历史交互分开，不在正文重复构造动作协议。 |
| 缓存与重复输入控制 | 固定前缀支持隐式或显式缓存，已保留的完整工具元数据可被当前消息引用；统计缓存创建和命中，不改变源时间。 |
| 要求与执行位姿分开 | 保留点、区域、硬朝向和语义条件；VLM 自行选连续位姿，检查器不修正答案。 |
| 多图空间输入可追溯 | 全局图、局部图和可选 RGB 保留坐标、时间、来源及实际图像，避免把静态先验当成当前测量。 |
| 子任务完成有对应依据 | 核对本次调用的实际位姿及停稳；视觉条件要求到达后、原模型请求实际读取的观察。 |
| 后台请求有数量和并发上限 | 状态轮询与取消不等 API；迟到结果按原任务和观察核对，不覆盖新状态。 |
| 起点、澄清和调用身份明确 | 起点来自本次有效车体位置；回答问题与替换任务分开；请求接收、停止意图和实际完成分开。 |
| 观察和证据可追溯 | RGB 来自观察时刻或之前，源摘要、矛盾和空间失效原因均保留，便于分析错误依据。 |
| 直接 runtime 接入 | 传递小型状态和资产引用，按需在后台复制 RGB，并提供取消处理回执，不恢复内部 ROS 话题链或传递整场景 pickle。 |
| 断连与费用处理明确 | 保留未确认调用，不自动重发或续跑；费用跨任务计提，原始响应和未决预留可检查。 |

这些机制已有代码和开发检查支持，但还不能据此声称实机可靠性已经验收，或论文方法已经取得收益。感知、CUDA、导航和独立安全是底层模块的成果，不重复计为 Agent 算法创新。

### 模型与调用

首轮使用 Qwen3.8-Flash 托管 API，模型标识为 `qwen3.8-flash`，不自行部署或微调。此前选型保留[模型文档入口](https://platform.qianwenai.com/docs/developer-guides/getting-started/latest-model)。实际请求设置由[技术实现](Agent技术实现.md#输入模型与工具)和客户端维护，本文不重复价格表或启动命令。

托管模型在同一个工具循环内负责长程规划、视觉地标判断和任务状态审查，导航与安全在本地执行。局部 SGLang＋DSPARK 服务及其配置不作为 Agent 的自动备用。当前关闭思考模式是为了完成低成本接入；后续应在少量开发样本上比较思考模式、图像策略和输出预算，再固定实验设置，不直接沿用局部 VLM 的调用周期或响应限制。

“冻结 VLM”只表示本项目不训练模型，托管别名并不保证服务商永久保持相同权重。实验须记录请求和返回的模型标识、日期、设置及可获得的服务版本。如果服务提供固定快照，应优先使用。

模型不可用时可以检查执行器，但不能把结果计为 VLM 成绩。当前服务已完成有限的原生多模态工具交互验证，参数仍在本地检查；未验证服务端硬约束、完整自然语言链或吞吐收益。换服务时重新检查协议，不根据同名模型推定兼容。

当前默认隐式缓存，并减少工具结果与当前附件中的重复元数据。显式缓存已经进行有限对照，未显示稳定优势，作为可选策略保留。缓存及输入开销属于工程优化，不作为导航方法创新；测量范围和失败输出见[缓存报告](../../outputs/decision/agent/cache_optimization/report.md)。

## 后续开发

下一阶段先固定完备地图下的室内任务，用少量代表指令检查空间选择，再接真实反馈。不强求继续增加离线原型，也不新增大型模拟器或重复标注程序。简单图和无图的接口存在，不表示能力已经实现。

| 顺序 | 开发内容 | 完成依据 |
|---|---|---|
| 1．完备地图室内任务 | 补实际任务区域和对象标注，检查点、语义朝向、区域位姿及有序串联。 | 模型自主选位姿，独立参考检查理解及选择；不靠工具候选收窄答案。 |
| 2．真实执行接入 | 接导航执行、活动调用、到达、停稳、取消及独立安全接管。 | 按[任务设计](长程导航任务与评测计划.md#任务设计)先单段后多段，执行和当前语义均满足。 |
| 3．简单地图 | 接简图或 BEV 图像及人工标注，区分拓扑关系、像素和可靠米制关系。 | 非等比例图不直接发出米制目标；明确位置转换与能力限制。 |
| 4．无图与主动观察 | 接地图无关文本、现场几何及模型自主观察位姿，复用导航。 | 使用动作后的真实新视图，未知不当作自由空间。 |
| 5．研究机制 | 按实际失败补充条件依赖、重新关联、观察策略、关键帧及证据回看。 | 按[对照实验](长程导航任务与评测计划.md#基线与消融)验证每项增量。 |
| 后续长程扩展 | 多站点等待返回、跨地图条件和模式、返图、搜索、人工辅助换层，之后再接 T1、T2、T3。 | 不作为当前室内任务前置，仍需定位、地图和必要外部确认。 |

接入时复用 [RoutePlan／RouteSession](../../navigation/planning/route.py)、[GoalMonitor](../../navigation/control/tracking.py)、[ControlLoop](../../runtime/control.py)和 [runtime 命令](../../runtime/command.py)。路线类管理几何进度，不会自动完成语义任务；前视点更新无需调用模型。有图与无图切换不等于重启 SLAM，真实运动反馈、命令幂等恢复和多地图编排仍需补齐。

实车恢复要分别识别定位失效、传感器失效、临时受阻、规划预算耗尽和真正不可达。恢复前先核对活动调用及是否停止，重启不能仅凭日志继续运动。任务等待使用任务时钟，失联检测使用单调时钟；漏事件时查询一致状态快照。Agent 不承担独立停车看门狗，也不能解除接管或急停。

代码集中在 `decision/agent/`，按核心循环、工具、外部适配和运行流程分为 `core/`、`tools/`、`adapters/`、`workflows/`，具体职责见[代码组织](Agent技术实现.md#代码组织与入口)。runtime 只提供状态、消息和观察出口，算法留在所属模块。观察策略和证据回看在主链稳定后增加；回看展示输入、短依据及结果何时被使用或拒绝，不虚构内部思维。

论文可按“问题与基线、证据维护、主动观察、系统闭环实验”组织。若没有稳定收益，应缩减方法主张，避免堆叠框架或反复调整留出集 Prompt。
