# Agent 技术开发计划

本计划记录 Agent 的研究依据、拟议创新、已有工程机制和后续开发。当前实现的工作流程见[Agent 技术实现](Agent技术实现.md)，具体任务、对照实验和测试命令见[长程导航任务与评测计划](长程导航任务与评测计划.md)。

研究主题是：**面向部分已知环境的轮椅长程导航，持续维护任务证据，并选择符合运动约束的有效观察。** Agent 自身使用 VLM，但本项目不训练该模型，也不依赖局部 T1、T2、T3 决策。

当前 Agent 已收敛为单 VLM 工具循环，仿真和影子入口统一调用 `AgentLoop.run()`，环境时间与输入推进由测试驱动处理。后续优先进入实机闭环，研究组件按实际需要增加，不要求先建设大型离线模拟器或完成全部论文实验。当前重构没有改变感知、导航或独立安全的职责，也没有接通底盘。

## 框架收敛方案

### 一个模型循环决定下一项工具

框架采用 ReAct 式的工具交互：把原指令、用户补充、相关历史及工具结果交给同一个 VLM，由它选择下一项工具；执行工具后，再把结果送回对话。模型可以在上下文中规划长程任务，但不再先输出一份必须由执行器逐项运行的完整计划。

规划和场景审查合并为同一个决策入口。取得图像、导航失败、目标到达或用户补充后，仍由这个循环决定查询、观察、导航、等待、澄清或结束。框架只管理消息、工具参数检查、请求次数和结果是否仍适用于当前任务，不根据任务种类增加专用分支。

初始工具覆盖地点查询、场景观察、导航、状态查询、取消、等待事件、询问用户和结束任务。导航工具内部完成几何检查并返回调用句柄；请求被接收不等于到达，完成和取消必须有对应反馈。长时间导航在后台进行，等待事件期间不反复调用模型，用户暂停和取消不经过模型。

### 保留必要组件，移除重复编排

| 部分 | 当前处理 |
|---|---|
| 完整计划 Schema、独立审查 Prompt、自动逐步骤执行器 | 从当前默认链中移除，统一为一次选择一项工具的模型响应。 |
| 任务记录 | 保存原指令、补充、已经发生的工具和执行结果，以及当前活动调用；不再充当另一套多阶段计划。 |
| 导航适配 | 保留实际几何检查、调用身份、反馈时间、停止和取消确认。执行细节放在工具内部。 |
| 证据记忆 | 作为上下文组件保留，可以按任务选择是否读取；不得把历史语义当作当前执行证明。 |
| 模型客户端与落盘 | 复用托管 API、单个后台请求、预算账本和原始响应记录，不自动重试或更换模型。 |
| 实机接入与研究扩展 | 继续后置。主动移动观察和局部 T1、T2、T3 后续通过工具加入，不扩充核心任务状态机。 |

模型工具调用先使用受限 JSON 和本地参数校验，不依赖尚未验证的服务端原生工具协议。该形式实现 ReAct 的行动与观察循环，不要求输出或保存模型的内部思维链。

### 重构验收

代码和测试已迁移。当前已用共用导航的合成反馈检查多站点、等待、暂停、替换、取消和完成证明，并用一份已有真实观察完成两次 API 决策，验证模型先读取图像、再使用图像选择工具。实际结果集中在[重构报告](../../outputs/decision/agent/react_tools/report.md)，不将固定工具决策的仿真当作自然语言任务成绩。

框架不形式化证明任意自然语言要求。完整指令是否被理解和满足，仍需具体任务验证；导航工具只为实际执行提供证明门槛，不能把模型文字、影子状态或接收 ACK 记为执行成功。旧冻结输入和实验结果保持原样，当前实现和操作入口以新文档为准。

## 技术创新与当前进展

### 任务证据的选择性维护

研究问题是：观察不完整、地图关联变化或定位重置后，怎样保留有用知识，同时避免旧位置和旧完成判断误导后续任务？

拟用轻量依赖关系连接任务条件、候选地点、源观察和执行事件，不另建图数据库。不同类型的依据需要分别处理：

| 依据 | 要记录和维护的内容 |
|---|---|
| 任务条件 | 用户要求的目标、先后顺序和等待条件。模型可以分解任务，但不能删除必达目标。 |
| 语义证据 | 支持、矛盾或未知判断，以及外观和源观察。没有看见目标不等于目标不存在。 |
| 空间依据 | 候选坐标依赖的位姿、地图关联和定位会话。旧坐标失效不表示历史图像内容错误。 |
| 几何与执行 | 当前通行、实际到达和停稳的判断，分别记录测量时间和所属目标。历史语义不能代替这些判断。 |

计划中的维护机制只更新受变化影响的依据。例如，地图关联失效时撤销地图目标；如果局部定位仍然有效，就保留局部依据。SLAM 重置后，再撤销旧局部坐标。已经发生的完成事件保留为历史，但“轮椅当前仍在此处”需要重新判断。

如果新旧观察互相矛盾，应同时保留两方来源，而不是在摘要中消除冲突。重定位即使恢复了坐标变换，也必须重新检查路径和阶段条件。

以离开走廊进入未建图门厅为例，系统可以保留“来时经过蓝色标识门”的外观和经过顺序，但不能把旧全局坐标直接发给局部导航。返回时需要确认地标、重建地图关联并重新检查几何。如果存在多个相似门口，应保留歧义，不能只按最近坐标或文本相似度合并。

当前保留可关闭的证据记忆组件，记录带源观察的历史工具选择并按地点检索，定位或地图变化后撤销空间有效性。它不自动提取或认证地标事实，旧任务也不会自动恢复。语义条件依赖、最少缺失依据检索、重新关联和恢复决策仍待开发。

这项研究要验证的是：选择性维护和重新建立依据，能否改善恢复、减少错误阶段推进和重复探索。当前失效保护只是工程基础，还没有证明上述收益。

### 任务相关的主动观察

研究问题是：什么时候继续走、移动补看、检索历史或询问用户，才能在相同预算下完成更多任务？

拟先检查足迹、转弯约束和已知自由空间，排除不可行移动，再对少量候选使用有上限的规则排序：

```text
效用(a) = 任务推进价值(a)
          + Σ[条件重要度 × 预计新增有效证据覆盖(a, 条件)]
          - 移动与等待成本(a) - 模型请求成本(a) - 重复观察成本(a)
```

“预计新增有效证据覆盖”是代理量，不是真实信息熵，也不是完整 POMDP 求解。权重在开发集上确定后固定，安全要求不能由其他收益抵消。初版不做强化学习或大规模采样，也不为每个候选单独调用一次模型。

候选生成和观察决策拟按以下过程进行：

1. **生成可行观察位置。** 有图时从路径或已知停车区生成，无图时从当前观测到的自由空间生成，初步保留约 3～6 个。候选同时考虑停下时的朝向和相机视野，不默认轮椅可以原地转向或倒退。
2. **把视觉线索变成候选。** VLM 提供地标或方向后，由有效标定、同源 LiDAR、可用深度、位姿和几何支持米制坐标。模型选择候选 ID，不直接根据 RGB 猜测坐标。无可靠位置时，只保留观察方向或请求帮助。
3. **估计观察能补充什么。** 根据遮挡、视角变化、目标大小和已观察方向，估计候选能够补齐哪些任务条件。未知区域不算可见，稀疏投影缺点不算空闲，也不能假定每个 bag 都有深度。
4. **选择模型输入。** 使用当前 RGB、同源局部视图或摘要及任务状态。必要时至多补充两幅相关且不重复的过去关键帧，并注明时间、视角和来源，不直接采用局部任务的固定三帧间隔。
5. **在预算内触发和验证。** 新任务、关键区域、子目标到达、证据失效或持续无进展时触发检查，合并重复请求，并限制移动和调用次数。取得新实拍后才评价是否消除了歧义；预算耗尽时澄清或终止。

模型返回后，执行前仍须用最新几何检查动作是否可行，但不能把原语义判断的时间改成当前时间。未来 bag 视图和录制驾驶不能替代移动观察的实际反馈。

当前只实现了读取现有视图、等待不同的新观察，以及请求次数限制。观察位姿、收益排序和关键帧策略尚未实现。拟议方法与 SeekVLN 的差异在于不训练模型、轮椅可达视角和异步成本；与 TANDEM 的差异在于联合选择移动观察和已有证据。是否有效，需要在相同预算下与最近可行视角、固定周期和仅事件触发方案比较。

## 工程亮点与模型选择

### 已实现的工程机制

| 机制 | 实际解决的问题 |
|---|---|
| 单模型循环与导航工具分工 | 模型每轮选一项工具，导航工具内部检查几何和执行证明，不另设完整计划执行器。 |
| 后台请求有数量和并发上限 | 状态轮询与取消不等 API；迟到结果按原任务和观察核对，不覆盖新状态。 |
| 起点、澄清和调用身份明确 | 起点来自本次有效车体位置；回答问题与替换任务分开；请求接收、停止意图和实际完成分开。 |
| 观察和证据可追溯 | RGB 来自观察时刻或之前，源摘要、矛盾和空间失效原因均保留，便于分析错误依据。 |
| 直接 runtime 接入 | 传递小型状态和资产引用，按需在后台复制 RGB，并提供取消处理回执，不恢复内部 ROS 话题链或传递整场景 pickle。 |
| 断连与费用处理明确 | 保留未确认调用，不自动重发或续跑；费用跨任务计提，原始响应和未决预留可检查。 |

这些机制已有代码和开发检查支持，但还不能据此声称实机可靠性已经验收，或论文方法已经取得收益。感知、CUDA、导航和独立安全是底层模块的成果，不重复计为 Agent 算法创新。

### 模型与调用

首轮使用 Qwen3.8-Flash 托管 API，模型标识为 `qwen3.8-flash`，不自行部署或微调。此前选型保留[模型文档入口](https://platform.qianwenai.com/docs/developer-guides/getting-started/latest-model)。实际请求设置由[技术实现](Agent技术实现.md#输入模型与工具)和客户端维护，本文不重复价格表或启动命令。

托管模型在同一个工具循环内负责长程规划、视觉地标判断和任务状态审查，导航与安全在本地执行。局部 SGLang＋DSPARK 服务及其配置不作为 Agent 的自动备用。当前关闭思考模式是为了完成低成本接入；后续应在少量开发样本上比较思考模式、图像策略和输出预算，再固定实验设置，不直接沿用局部 VLM 的调用周期或响应限制。

“冻结 VLM”只表示本项目不训练模型，托管别名并不保证服务商永久保持相同权重。实验须记录请求和返回的模型标识、日期、设置及可获得的服务版本。如果服务提供固定快照，应优先使用。

模型不可用时可以检查执行器，但不能把结果计为 VLM 成绩。服务端原生工具调用还需单独适配和验证，不能仅根据接口说明认定已经接通。

## 后续开发

下一阶段由实机闭环推动开发。先接真实反馈，再逐步增加任务复杂度和研究机制；不要求先完成所有离线研究，也不新增大型模拟器或重复标注程序。

| 顺序 | 开发内容 | 完成依据 |
|---|---|---|
| 1．真实执行接入 | 接导航执行、活动调用查询、到达和停稳反馈、取消及独立安全接管。 | 先完成[单目标任务](长程导航任务与评测计划.md#任务设计)，缺少反馈时不推进任务。 |
| 2．阶段闭环 | 接多站点、等待、返回及实际到达后的视觉审查，明确失败和恢复入口。 | 执行反馈与所需的新鲜语义共同满足完成条件，接管和未完成阶段有记录。 |
| 3．有限无图与补观察 | 实现视觉线索定位、局部候选和观察候选，复用导航而不复制 T3 算法。 | 使用动作后的真实新视图，几何未知不当作自由空间。 |
| 4．研究机制 | 按实际失败补充条件依赖、重新关联恢复、观察策略、关键帧选择和证据回看。 | 按[对照实验](长程导航任务与评测计划.md#基线与消融)验证每项增量。 |
| 后续扩展 | 增加有图、无图、返图接续，受限搜索、人工辅助换层，再接 T1、T2、T3。 | 每次增加一项能力，仍检查地图、定位和必要外部确认。 |

接入时复用 [RoutePlan／RouteSession](../../navigation/planning/route.py)、[GoalMonitor](../../navigation/control/tracking.py)、[ControlLoop](../../runtime/control.py)和 [runtime 命令](../../runtime/command.py)。路线类管理几何进度，不会自动完成语义任务；前视点更新无需调用模型。有图与无图切换不等于重启 SLAM，真实运动反馈、命令幂等恢复和多地图编排仍需补齐。

实车恢复要分别识别定位失效、传感器失效、临时受阻、规划预算耗尽和真正不可达。恢复前先核对活动调用及是否停止，重启不能仅凭日志继续运动。任务等待使用任务时钟，失联检测使用单调时钟；漏事件时查询一致状态快照。Agent 不承担独立停车看门狗，也不能解除接管或急停。

代码集中在 `decision/agent/`，按核心循环、工具、外部适配和运行流程分为 `core/`、`tools/`、`adapters/`、`workflows/`，具体职责见[代码组织](Agent技术实现.md#代码组织与入口)。runtime 只提供状态、消息和观察出口，算法留在所属模块。观察策略和证据回看在主链稳定后增加；回看展示输入、短依据及结果何时被使用或拒绝，不虚构内部思维。

论文可按“问题与基线、证据维护、主动观察、系统闭环实验”组织。若没有稳定收益，应缩减方法主张，避免堆叠框架或反复调整留出集 Prompt。
