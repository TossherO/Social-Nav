# 技术实现：Agent 长程导航

外层 Agent 在室内完备地图上组织点目标、区域目标和有序任务。每个会话使用一个托管 VLM，可选 `qwen3.8-flash` 或 `gpt-6.1-terra`。模型通过原生工具登记用户要求、查询地图和观察、自主选择位姿或途经点，再依据导航反馈复核任务。T2 跟随和 T3 桌边停靠由各自的局部决策后端处理，跟随的实机闭环与连续停靠效果待测。T1 群组更新仍待接入。

多点自动推进目前仅接入仿真。人工驾驶中，Agent 可提出路线，并根据定位估计核对实际经过情况。实机自动执行支持单目标和跟随意图，现场曾自主执行首目标的一部分，自主多目标闭环仍未验收。人工跨楼层任务在乘梯时使用独立的相机和雷达观察，目标楼层地图关联有效后继续原任务。切换逻辑见[人工驾驶跨楼层](#人工驾驶跨楼层)，现场记录见[系统实机问题](../系统实机问题.md)。

运行命令见[系统运行手册](../系统运行手册.md)，未完成事项见[后续开发测试汇总](../后续开发测试汇总.md)。

## 代码组织与入口

会话保存在 `core/session.py`，主循环在 `core/loop.py` 分派工具和应用反馈。`tools/` 定义工具参数、地图观察与导航接口，`adapters/` 区分仿真、影子、人工驾驶和实机权限。`workflows/` 组装入口，其中 `floor_handoff.py` 管理只读观察进程和各次定位尝试。

[cli.py](../../decision/agent/cli.py)选择后端，再由运行流程创建 `AgentSession` 和 `AgentLoop`。仿真与影子入口都调用 `AgentLoop.run()`；测试侧时间和输入推进留在 `workflows/drivers.py`，不进入 Agent 核心。

## 输入、模型与工具

### 地图条件与空间输入

地图条件表示任务开始时有哪些先验，区别于底层的定位地图、静态环境地图和当前局部地图。

| 条件 | 含义与当前支持 |
|---|---|
| `complete`，完备地图 | 具有整个场景的建图结果，以及任务涉及的人工点、区域和对象标注。当前实现目标提交与检查。 |
| `simple`，简单地图 | 人工简图或地图软件的俯视截图，主要通道和障碍大致可辨，未必具有比例尺。保留条件接口，尚不支持执行。 |
| `none`，无图 | 没有地图先验，任务依赖纯文本描述和现场观察。保留条件接口，尚不支持执行。 |

选择 `simple` 或 `none` 不会向模型暴露完备地图的标注，目标工具返回能力尚未实现。简单图不能直接当成米制地图，后续需要单独实现图像坐标、拓扑和实际定位之间的关系。

#### 地点目录与机器人资料

[Catalog](../../decision/agent/tools/places.py)用 `place_id` 和 `pose` 记录点，用 `region_id` 和二维 `polygon` 记录区域。点可表示对象位置、目标或面向参考，车体可达性仍须检查。坐标属于目录的 `frame_id`，位置单位为米，角度单位为弧度。加载时，旧目录的 `landmarks` 按原 ID 和位置转换为点，登记配置中的区域和旧格式对象也只覆盖本次目录副本。

机器人资料由当前适配器提供，显示在 `runtime_current_state.robot_context`。它说明 `base_link` 参考点、足迹及前后左右范围、速度向量 `[forward_mps,yaw_rate_rad_s]`，以及已加载的倒车、原地转向、转弯半径和速度限制。启用 runtime Agent 观察后，当前有效观察还会根据本车雷达到车体变换和仓库中的固定安装标定，提供雷达、相机、IMU 相对车体的位置和相机光轴，并记录各自来源。假设几何、过期观察或缺失数据保持不可用；标定组合不是新的安装或精度验证。仿真读取实际使用的运动配置；旧 runtime 未提供本车几何时，影子适配仍使用历史几何参考。几何来源和假设状态同时给出，不能据此宣称实机性能已经测定。

#### 固定地图

固定地图在会话创建时按地图比例渲染，最长边不超过 2048 像素。程序在静态图的已知栅格外保留一米边距，并扩大范围以容纳有坐标的固定点和区域。全图没有已知格时使用原范围。裁剪只改变显示，画面外仍须按原栅格检查。图上保留坐标刻度，颜色和符号由请求中的文字说明。

图上显示点和区域的编号、名称与区域轮廓，引线将名称连到点位置或区域边界。标签避让后仍放不下完整名称时只显示编号，完整名称和坐标可查结构化目录。中文名称需要系统字体。车辆位置、实测起点和任务进度在后续上下文中提供。

#### 当前观察与地图图像

每轮请求前，程序按当前有效观察准备末尾附件：当前 RGB、全局概览和附近放大图。两张地图按显示范围的比例自适应，最长边为 1024 像素，边缘只保留坐标刻度。全局概览使用相同的已知栅格裁剪，并在轮椅或实测轨迹超出范围时扩大显示；附近放大图默认以轮椅为中心，显示静态先验、车体足迹和标注。两张地图使用相同方向、坐标约定和标注身份。`query_map` 可用 `bounds=[xmin,ymin,xmax,ymax]` 查询静态先验的其他范围，不生成候选位姿。结构化摘要同时给出原坐标和来源，P、R 编号仅供阅读，工具仍使用对应的正式身份。

显式裁剪按观察身份、源时间、栅格或位姿的变化重绘，沿用原请求范围。成功提交导航或替换任务后恢复默认范围。橙色空心圆标出 `base_link` 原点，箭头指向车头，足迹按地图比例绘制。符合模型尺寸要求时，客户端直接封装渲染器输出且已校验的 RGB PNG。

在两帧有定位记录的 bag 上做过只读对照。给 `qwen3.8-flash` 每次一张全局概览图和同一个问题，要求估计位置和朝向，输入中省略定位数值。11 月 7 日的二楼帧记录朝向为 −85.3°，模型对旧图回答 +90°，对新图回答 −90°。10 月 29 日的一楼帧为 +175.0°，新旧图均回答 180°。两张新图的位置估计分别与定位记录相差约 1.04 米和 2.48 米。该对照仅覆盖这两帧的符号辨读。导航及几何检查继续使用已配准的数值位姿。

轨迹只采用已经发生的有效定位测量，不使用规划路径或未来录包帧，不在稀疏观察间插值。定位失效、测量间隔超过三秒或定位身份变化时分段；地图关联、时钟或坐标系变化时清空当前轨迹。轨迹按测量时间采样并限制容量，图像和轨迹来源摘要进入当前 `view_id`，实际样本另保存在同一会话的 `trajectory_snapshot` 事件中。

全局概览和附近放大图使用静态先验。实时局部占据由 `check_candidate` 单独检查，当前人物和遮挡需看同源 RGB。相机外参与对应 RGB 的 CameraInfo 可用且坐标系和图像尺寸匹配时，附近图用紫线表示针孔模型的近似水平视野。实际可见性仍须用 RGB 验证。

#### 候选位姿检查

`check_candidate` 分别检查静态栅格和同源局部栅格。普通停车传 `[x,y]`，车体在任何朝向都覆盖的内圈一旦碰到占据格，该点便可判为占据。只有整块容纳各个朝向车体及安全余量的方形都在图内且空闲时，才报告空闲。足迹能否放下取决于朝向时，工具返回 `undetermined`。局部图未覆盖的位置单独标记。

给出 `[x,y,yaw]` 时，工具按这个朝向检查完整车体轮廓及规划安全余量。观察任务还可以传入标注点 ID。工具根据候选朝向和安装外参求得相机位置，检查从相机到各点之前的二维静态栅格。有匹配的相机内参时，还会逐点估计是否落入水平视野。沿途遇到占据时报告首个占据格的距离，经过未知区也会标出。标注点所在格单列，方便区分标在门面上的对象和途中的墙体。普通停车可省略点 ID，此时只需依据车体检查结果选点。视线结果供 Agent 选择观察位置，导航器仍按原有条件检查目标和路径。栅格没有物体高度和实时遮挡信息，实际能看到哪些对象以停稳后的 RGB 为准。

最近一次检查仍对应当前观察时，附近放大图用洋红色标出候选。只给坐标时显示位置，给出朝向时显示车体轮廓和朝向。相机位置可用时，图中从相机向指定标注点绘制连线，橙色仍表示实际轮椅。

比较多个观察位姿时可分别调用 `check_candidate`。已经选好位姿时，`navigate` 可以携带同框标注点的 `point_ids`，在提交前用同一位姿和地图检查车体与相机水平视野。如果阶段只有硬性视觉要求，且位置由 Agent 自选或属于获准的视觉调整，明确落在水平视野外的标注点会随拒绝原因返回。指定的首停位置仍须前往实拍，偏好、混合优先级和缺少相机内参时的视野估计仅供参考。车体和导航路径照常检查。

候选在静态地图范围内但位于原裁剪范围之外时，图像范围会扩展以包含候选车体；原请求范围和实际显示范围分别记录。地图外的候选不扩大显示范围，结构化摘要仍保留其坐标。

`recent_candidate_checks` 保留最近八项候选检查摘要。同一地图和定位下，位置相距不超过 0.05 米、所给朝向相差不超过 0.05 弧度、检查的标注点与判断结果也相同时，摘要合并计数。只给坐标与指定朝向的检查分别保留。每次调用都重新读取栅格；如果新观察改变了占据或视野结论，可在摘要中对照两次结果。旧观察标记为 `historical_only`。地图或定位身份变化、输入失效、提交导航或替换任务时清空摘要。

单点 `navigate` 在适配器提供车体几何时，还会检查最终提交的实际位姿，即使模型先前检查过其他朝向。局部轮廓有占据时拒绝提交；静态轮廓有占据且局部没有完整空闲证据时也拒绝。局部的完整空闲证据可反映静态地图之后打开的通道。未知、未覆盖和空闲均不代表路径已验证，后续仍由导航规划与独立安全层处理。适配器没有车体几何时，此项辅助检查不可用，沿用适配器自己的规划检查。

`observe_scene` 可以显式读取当前 RGB 和同源场景。没有有效图像时返回不可用，不拿旧图代替。基础请求最多四张图；按需加入两张历史 RGB 后，总计最多六张。客户端检查实际图片尺寸，并使用同一经验公式估算输入量和费用：文本按 UTF-8 长度、图像按像素面积计算，不把 Base64 当成文本。该公式依据现有模型用量记录校准，并非服务端真实分词结果；不同内容、尺寸或服务可能偏离。估算输入超过本地 131072 限制时不发送请求，事件会记录原因和估算值。地图图像与目录、栅格、位姿、源时间和图像摘要共同生成 `view_id`，用于核对返回的位姿是否依据仍有效的空间输入；开头的 `reference_map_id` 不能替代它。

### 模型调用与响应

#### 请求阶段和上下文

[Model.decide()](../../decision/agent/core/model.py)把保留的对话和本轮当前状态交给所选模型。两个服务都通过 `tools` 接收本轮可用工具。客户端将 Qwen 的 `tool_calls` 和 OpenAI 的 `function_call` 交给同一套工具及任务校验，并把工具执行结果按原调用 ID 写入对话。

| 阶段 | 提示与可用工具 |
|---|---|
| 任务尚未登记 | [登记阶段提示](../../decision/agent/configs/registration_prompt.txt)说明如何识别和登记完整要求。模型可查询地点和地图、读取观察或询问用户；只提供登记所需的六个工具。关闭思考时使用 `tool_choice=required`，开启思考时按服务约束使用 `auto`。客户端检查返回的工具是否属于本轮列表；服务不支持该参数时报告错误，不自动降级或重试。 |
| 登记完成 | 每轮从当前阶段可用的工具中选一项。单点导航提供 `navigate`，多点路线提供 `navigate_route`，跟随阶段提供选人和启动跟随。观察、等待和询问等操作按当前状态提供。乘梯独立观察和目标定位各有工具清单。关闭思考时使用 `tool_choice=required`，开启执行思考时使用 `auto`。[执行提示](../../decision/agent/configs/system_prompt.txt) |

工具的字段单位、身份来源和返回状态由 [framework.py](../../decision/agent/tools/framework.py)维护。当前资料不足或能力未发布时明确保持未知，模型不能自行补成已完成或已验证。

每次 API 请求依次发送以下内容，不依赖服务端常驻会话：

1. 系统规则、固定高分辨率地图及全部固定标注。任务起点不进入这一前缀。
2. 原指令和目录引用。跨楼层任务在前部提供各楼层的标注目录。执行时的固定任务单保存已确认的澄清，并为每项要求列出主要工具 `execution_tools`、生效的监控设置 `monitor` 和可选的执行提示 `execution_notes`。例如跟随先选人，再用该人物的参考启动 T2。交接时清空规划对话，登记调用保存在审计记录中。
3. 程序追加的 `runtime_current_state`，包含登记进度、下一要求、已选位姿、最近工具反馈、全部已接受澄清、机器人资料和带位置的关键帧索引。
4. 本轮有效的 RGB 和空间图。计划内暂停定位时移除全局图，提供当前相机图及可用的车体坐标雷达俯视图。配置标准起点时额外发送本机保存的历史 RGB 和雷达参考图，此时最多随请求携带两张模型保留的乘梯历史 RGB，以满足图片数量限制。未配置标准点时，出梯选点须有出梯之后的扫描，另附目标等候区地图裁剪；重选时还能看到上一次使用的扫描在原候选位姿下的叠图，洋红点表示雷达回波。乘梯临时帧和逐次判断只保存在本次乘梯的内存中，标准参考图按本机配置持久保存。

#### 身份投影与引用

固定标注只在前部地图资料中定义一次。初始目录保留地图条件、坐标、单位和访问政策。固定标注、坐标及栅格对应时，目录用 `annotation_reference.reference_map_id` 引用该地图，另列动态 `mission_start` 点。参考图缺失或不匹配时，目录保留完整标注。

发送请求时，固定地图、当前空间图、RGB 观察、关键帧和跟随参考分别用 `m1`、`v1`、`o1`、`k1`、`r1` 这样的短编号表示。同一 Agent 会话内，相同来源使用同一编号。执行工具可从发出这次请求时的状态确定当前子任务、空间图和 RGB，模型只填写仍需决定的参数。需要选历史关键帧、标注点或人物参考时，模型显式选择对应对象。程序在应用回复时核对原观察、任务和地图的对应关系。

模型正文省略内部校验摘要。工具结果已完整描述同一视图或观察时，附件保留短编号、源时间和坐标约定，并用 `details_in_tool` 引用工具。该工具结果被裁剪后，附件恢复完整描述。普通请求在本地 `api_request.model_references` 保存短编号与原始身份的对应关系，供会话结束后复查。

#### 原生工具调用与回复校验

模型可以附带简短进度说明，每轮最多调用一项工具。例如，已经登记区域要求并读取地图后，返回消息的相关字段如下：

```json
{
  "role": "assistant",
  "content": "我选择停在区域内的开阔位置。",
  "tool_calls": [
    {
      "id": "call_example",
      "type": "function",
      "function": {
        "name": "navigate",
        "arguments": "{\"pose\":[7,4]}"
      }
    }
  ]
}
```

这些坐标仅为合成示例。实际位置和朝向由 VLM 根据地图、语义、视野及后续任务直接选择。工具检查原始连续位姿；不生成候选终点，不推荐朝向，也不吸附或改写模型输出。

[framework.py](../../decision/agent/tools/framework.py)维护完整工具接口，[model_projection.py](../../decision/agent/core/model_projection.py)根据当前阶段和观察生成当轮参数表。客户端拼接流式回复并保存模型原始调用，然后用这次请求中确定的字段展开参数，检查工具、类型、互斥字段和允许引用的来源。例如，给定坐标的朝向写作 `pose=[x,y,yaw]`；导航到标注点时才将 `yaw` 与 `point_id` 并列。模型填入冲突的字段会收到错误反馈。参数通过校验后，再检查当前执行条件。

#### 异步结果与源观察

普通执行工具结果通过 `tool_call_id` 与原调用配对。参数含重复键、非有限数或 Schema 错误时，客户端保存原始响应并返回字段错误。暂停、取消或替换会使在途判断失效，读取模型流时检查取消标记。已连接的 HTTP 流连续 120 秒未收到数据会结束请求。

| 结果 | 应用条件与处理 |
|---|---|
| 登记要求、查询等不驱动操作 | 在任务与观察身份仍匹配时继续，不因响应耗时拒绝。 |
| 点、区域或参考目标 | 使用当前空间图检查车体占据，同时限制自车位姿变化，记录模型原视图和实际检查视图；视觉条件与偏好仍需相应观察判断。候选检查也使用新视图重新计算。 |
| 撤销已确认受阻的原目标 | 同一目标和路段在等待新规划结果时，仍可采用模型依据此前确认的这一次阻塞给出的撤销动作。期间若出现明确的通路恢复、另一处阻塞、地图关联变化、人工暂停或目标切换，旧决定失效。提交替代目标时单独检查权限、停稳和当前地图。 |
| 多点路线 | 仅人工和仿真模式支持。原身份有效且位姿变化未超限时，用新空间图重新执行路线几何和导航适配检查。 |
| 视觉及朝向判断 | 保留模型实际使用的观察身份和源时间，记录判断应用时的观察年龄，不自动证明当前画面或环境未变化；到达及停稳仍须当前有效反馈。 |

没有活动导航句柄时，相同单点目标或路线连续三次因相同原因被拒绝或不可用，Agent 记录原因并等待用户处理。仅变更视图引用仍按同一目标计数。观察阶段收到导航请求时返回阶段不支持导航。重复消费调用 ID 或一轮返回多项调用会被拒绝。合法的回复结构仍可能包含错误的场景判断。

成功提交导航或输入过期后，程序清除本轮地图和 RGB 附件，下次请求从有效源重新准备。关键帧和旧工具结果保留原时间和标识。

同一阶段首次只返回文字时，只要还有请求次数，程序会自动纠正一次。登记阶段的下一次请求重述用户原指令，提醒模型结合已收到的澄清调用 `record_task` 登记要求。需要核对标注时可先查询。如果模型连续两次只返回文字，任务仍未登记，界面会等待用户答复或替换任务。若模型调用 `ask_user` 提出具体问题，程序当轮就等待答复。

执行阶段的纠正使用最新证据。乘梯独立监测等待下一次有效观察，逐帧回复只在内存中保留。执行模型连续两次只返回文字时，系统请求暂停，有活动导航时按原流程取消并等待确认。完成证据充分时，Agent 调用 `complete_subtask`。若本阶段已登记等候口令，完成后停在原处，收到“继续”才进入下一阶段或结束任务。

#### 服务配置与思考模式

人工驾驶和回放窗口在开始新任务前选择模型，命令行使用 `--model`。两个服务分别读取凭证，按下表连接。本机配置使用被 Git 忽略的 `configs/agent_api.local.json`，命令行可以用 `--api-config` 指定其他文件。

| 模型 | 接口与网络 | 凭证 |
| --- | --- | --- |
| `qwen3.8-flash`（默认） | 直连私有配置的 HTTPS `base_url`，使用 Chat Completions | 环境变量 `SOCIAL_NAV_AGENT_API_KEY`，或私有配置的 `api_key` |
| `gpt-6.1-terra` | 私有配置的 `openai_base_url`，默认 `https://api.openai.com/v1`。客户端使用 Responses 接口，支持系统 HTTPS 代理 | 在同一私有配置中填写 `openai_api_key`。省略时，官方地址可读取 `OPENAI_API_KEY`；也可通过 `openai_api_key_file` 引用本机密钥文件 |

首次请求时创建 HTTPS 客户端，后续请求复用该会话的连接。每轮最多有一个模型请求在途，退出时关闭连接。OpenAI 请求使用 `store=false`，客户端根据本机消息重建上下文。请求事件按统一的消息和工具结构归档，标明实际接口、模型、阶段和强度，方便查看历史或复用登记。乘梯期间沿用临时观察的保留规则。

核对一次决策的耗时时，按 `timing.call_id` 对齐会话中的 `api_response`、`model_result_consumed` 和 `model_tool_processed`。同一进程的单调时钟记录从准备观察和消息、开始发送、收到首个有效流片段、流返回，到主循环取走结果和实际执行工具的时刻。过期、被拒绝或仅返回文字的回复可能没有工具执行时刻。传感器源时间另行保存，用于判断观察年龄。

默认按阶段选择强度（`--thinking-mode planning`）。`--planning-thinking-mode` 用于登记与分解任务，`--execution-thinking-mode` 用于选点、提交路线和启动技能，`--monitor-thinking-mode` 用于到达、视觉或周期事件触发的复核，以及乘梯独立观测。例如，要求到达某地再检查相机画面时，选取导航目标用执行档，到达后查看画面用监控档。需要全程使用同一强度作对照时，可直接指定 `--thinking-mode off` 或所选模型支持的其他档位。

| 模型 | 可选强度 | 默认登记 | 默认执行 | 默认监控 |
| --- | --- | --- | --- | --- |
| Qwen | `off`、`low`、`medium` | low | off | off |
| GPT | `off`、`low`、`medium`、`high`、`xhigh` | low | low | low |

Qwen 的 low 和 medium 请求分别给推理与回答合计 6144 和 24576 token。GPT 开启推理时，各档均使用 6144 token 上限。档位影响等待时间，也可能改变工具选择。车载端的对照保留了每个任务的输入条件、成功与失败情况，见[推理速度记录](../推理速度记录.md#外层-agent-托管-api)。

服务器曾用 Qwen 对一条合成大厅逆时针绕行指令做单例对照。两次登记分别耗时 4.22 和 4.99 秒，均通过工具及任务约束检查。给定相同登记要求和地图查询结果后，关闭思考与 low 分别耗时 4.71 和 66.55 秒，均提交了通过几何检查的路线。另一次将 low 输出限制在 2048 token 时，模型达到上限，未产生可用动作。该对照未测实机绕行。

### 输入缓存

默认使用服务端隐式缓存。客户端保持系统规则、工具和字段顺序稳定，自车移动或替换任务时复用固定地图。地图与标注资产变更后应重新创建会话。固定地图仍会随请求发送，缓存命中由服务端决定。客户端不缓存或重放模型答案。

Qwen 另支持显式缓存策略，在系统规则、固定地图消息末尾和完整历史末尾设置 `cache_control` 标记。没有固定地图时，第二个标记使用初始目录。标记只添加到请求副本。GPT 使用隐式缓存。

响应保留原始 `usage`，另汇总输入、缓存命中、缓存创建 token 和命中比例。缺少的统计保持未知，不填零；共享费用账本继续按保守费率计提，没有按通用缓存折扣推算实际账单。参数和服务限制参考[缓存文档](https://www.alibabacloud.com/help/en/model-studio/context-cache)。

此前曾检查六图输入、真实观察切换和上下文投影；对应历史报告在当前本机未找到，无法重新核对原始结果。请求合法、缓存命中或历史图片可读均不能证明任务决策已经可靠。

## 任务执行与反馈

### 任务要求与执行位姿分别保存

[TaskGoals](../../decision/agent/core/tasks.py)保存模型通过 `record_task` 从原指令提取的有序要求。这是一份完成条件记录，不是另一套自动执行的工具计划。登记工具向模型提供统一的 `stage`、`target` 和 `conditions`，校验通过后明确映射为执行内部的 `kind`、`stage_type`、`target_id` 等字段。已有工具回放仍可使用旧字段，原始工具调用和转换后的要求分别保存在会话记录中，不根据推测补充用户要求。

人工驾驶会话可以从历史 SQLite 会话复用成功登记的要求。读取时核对登记事件与历史任务身份、版本和内容，并在启动时比较各使用楼层的静态地图内容、定位地图、坐标系及语义标注。新会话重新执行登记校验和起点绑定，重新生成任务身份，不继承历史目标、路线、进度或观察。来源和校验结果写入新会话；预览后历史登记发生变化时拒绝启动。新人工会话保存各楼层地图来源，较早的跨楼层会话若缺少部分楼层来源，不能直接复用。

| 字段 | 含义 |
|---|---|
| `goal_id`、`description` | 本任务中的稳定子任务身份及原意说明。 |
| `stage` | `point`、`region`、`reference`、`route` 和 `sequence` 指定导航要求；`follow`、`observation`、`seating` 和 `elevator` 指定相应技能。 |
| `target` | `id` 引用正式标注；匿名点使用用户指定的 `position`；`sequence` 使用按要求排序的 `checkpoints`。技能阶段不填写导航目标。 |
| `floor_id`、`to_floor` | 普通阶段用 `floor_id` 标明所在楼层。乘梯阶段用 `floor_id` 标明来源楼层，用 `to_floor` 标明目标楼层。 |
| `conditions` | 按需填写 `required_yaw`、`facing`、`max_distance_m`。用户明确要求轮椅在指定区域内结束时填写 `robot_inside_region_id`。乘梯时使用 `to_floor` 的区域 ID，直到目标楼层地图关联有效且取得新鲜位姿，才能判断是否在区域内。阶段完成后需等用户口令时，`wait_after` 填写用户等待条款的原话。`visual` 数组用 `required` 或 `preferred` 区分视觉硬条件和偏好。 |
| `monitor`、`execution_notes` | 可选的监控触发，以及执行时需留意的证据、工具和异常；`execution_notes` 不代替硬条件。省略 `monitor` 使用阶段默认值，空对象表示只订阅状态事件。 |

内部执行记录用 `semantic_conditions` 和 `visual_preferences` 区分视觉硬条件与偏好。旧回放保留原有的 `circuit` 字段，按[通用路线机制](#绕区域与指定顺序)复核绕行。

例如，“到电梯口附近，尽量看到电梯”可以登记为下列要求；`p-example` 仅表示假设的正式标注 ID，实际调用须使用当前目录中的身份：

```json
{"goals":[{"goal_id":"g1","stage":"reference","description":"到电梯口附近，尽量看到电梯","target":{"id":"p-example"},"conditions":{"visual":[{"description":"看到电梯","priority":"preferred"}]}}]}
```

目标位姿和路径由后续执行阶段选择，不在这个示例中预先固定。

不同目标要求使用各自的检查方式：

- **点和区域**。明确的标注点使用标注坐标，用户给出的坐标按原值处理。区域目标由 Agent 在标注范围内结合地图、观察和车体余量选点。“大厅中央”等要求保留在任务描述中，Agent 在到达并停稳后结合实测位置和原要求复核。历史任务重新登记时，旧的质心字段会被移除。
- **参考对象**。用户给出距离上限时，运行时按 `max_distance_m` 检查到点或区域边界的距离。用户只说“停在窗边”时，登记已标注的窗，由 Agent 在到达后用含当前车体位姿的地图说明停车点与窗的位置关系。观察要求和视觉偏好各自登记。
- **面向方向**：模型结合当前位置、墙、入口、可通行路径和可用观察选择方向，检查器不把目标点或区域质心当作必须朝向的几何点。例如区域中心被墙遮挡时，模型可能选择朝向通向该区域的走廊。

单点导航可以提交地图 `[x,y]` 或标注点 ID。普通目标由规划器确定可行的抵达方向，RViz 仅显示目标点。任务有朝向、面向或视野要求时，Agent 额外提交目标朝向及其来源。明确到某个标注点时，位置使用该点的标注坐标。点资产中的朝向只作为参考。

用户指定点目标的首次停车朝向时，登记为 `conditions.initial_yaw`。明确要求完成时保持的朝向登记为 `conditions.required_yaw`。位置和首次所需朝向均已确定，或普通精确点只要求位置时，状态会给出 `selected_goal.initial_pose`，模型可以用 `navigate({})` 提交。首次到达要核对实测朝向。视觉复核确认不足且允许调整时，模型可以重选朝向，完成阶段仍检查用户指定的最终朝向。历史任务中的 `required_yaw` 保留原有约束。区域内判断针对 `base_link` 参考点，车体和路径另由导航检查。

每个要求分别保存原始要求摘要、待完成或已完成状态、模型选定位姿、导航句柄及完成依据。完成当前要求之前不能操作后续要求；登记后不能删改要求来使结果通过。用户明确替换任务时，先确认撤销旧调用，再创建新修订和要求记录。模型仍可能误解或遗漏自然语言内容，必须通过独立任务评测检查。

阶段完成后记录下一阶段的进入时间，清除上一阶段的监测、临时观察与候选。跟随阶段还会清除当前人物和找回状态，原始参考图及完成依据仍保存在会话中，后续跟随须重新选择人物。模型请求上下文包含当前阶段身份，迟到的上一阶段回复不能用于新阶段。

#### 有序路线与人工驾驶

`navigate_route` 接收模型自行选择的有序地图 XY，路线至少包含两个点。终点朝向可省略；任务包含面向或视觉要求时仍需给出朝向，有用户明确的数值朝向时使用该数值。点是执行方案，可以与用户指定的 `checkpoints` 不同。仿真自动切换中间点，经过点不要求朝向或停稳；最后一个点需要到达并停稳，提交终点朝向时还需对齐。人工模式由操作者驾驶，根据有效定位识别建议点附近的经过情况，终点使用定位和持续停稳估计自动检查，人工确认是备用方式；是否检查朝向取决于用户任务要求。需要在中间停靠或观察的任务应登记为多个有序要求，不能仅使用经过点。一次活动路线仍占用一个导航句柄；模型无需在每个点发起新调用。

人工路线依次记录实际定位进入途经点的证据。首点、终点以及用于满足用户指定检查点的途经点使用 0.20 米容差，其他中间点使用 0.50 米。中间点无需停稳，终点还需取得持续停稳测量。完成时核对每次测量的源时间、地图及会话身份，由 Agent 结合原要求、实测轨迹和现场观察判断任务结果。RViz 连接线表示建议经过的顺序。

人工自动到达后，如果新鲜反馈显示再次运动、偏离目标或证据身份变化，当前到达证据会失效并记录原因。定位身份和全部路线证据仍匹配时，再次满足位置、必要朝向和持续停稳条件可以恢复证据，不重复添加末点。人工确认是备用入口，也须核对当前定位、停稳和已有路线证据。已通过任务复核的目标允许由后续目标替换，旧目标证据之后失效不会占住下一阶段；原完成记录和新证据分别保留。

实测轨迹用于展示和任务复核，样本达到容量后会降低采样密度，优先保留较早位置、近期位置及各段端点。定位中断仍会分段；若段数过多导致旧样本被丢弃，空间观察会标记截断。抽样轨迹不能证明每处细节，Agent 应结合其范围和缺口判断证据是否足够。

#### 绕区域与指定顺序

绕行使用通用多点路线：Agent 根据区域和任务选择少量有序途经点，要求返回起点时将该点明确作为末点。每个途经点检查静态栅格和可用的当前局部栅格；占据或未知且没有足够当前空闲依据的点不会提交。该检查不能证明完整车体姿态或路径可行。实际路径由参考规划器逐段生成。

通用路线的不同位置超过三个且没有填写 `waypoint_reason` 时，工具要求 Agent 先考虑精简；对于用户明确指定的 `sequence` 检查点，阈值至少为指定点数加二。点位因占据或未知被拒绝时，反馈也会提醒检查点数。确需较多自主选点时可通过 `waypoint_reason` 说明后提交，程序不会验证说明是否充分，也不自动删除或重排点。说明不代表路线可行，点位检查和导航检查仍需执行。

明确绕标注区域时，登记阶段将用户的方向、圈数和是否返回保留在文字要求中。程序只按通用多点路线核验有序实测途经点及终点停稳；Agent 根据原任务、实际轨迹和当前观察判断绕行要求是否满足。轨迹不足或中断时，Agent 应保留不确定性，不能把规划点或点间直线当作已完成绕行。人工模式的运动和停车由操作者控制。

`sequence` 的路线须按顺序包含用户指定的点或区域。若用户允许中间任选一个地点，`target.checkpoints` 的对应项可写成 `{"any_of":["地点A","地点B"]}`，末项始终是一个明确终点。Agent 首次提交一条实际路线。某段持续受阻时，Agent 可在撤销原路线、取得新的停稳测量后，从实际位置提交替代路线。系统保留原终点和用户要求的终点朝向，记录旧尝试中实际经过的地点。新路线的每个途经点用该次调用的测量验证，原指令中的必经地点按新旧尝试的实测顺序复核。

人工模式逐段生成参考路径。若先前的规划明确给出了阻点坐标，系统会在替代路线的每一段实际路径可用时核对其是否经过该坐标，并在人工驾驶界面提示冲突。门是否仍然关闭，需要用当前现场观察核实。此前的规划若只报告不连通，则只保留当时受阻的路段。执行结果根据操作者驾驶的实际轨迹和定位估计核对。

### 工具怎样配合

工具由模型选择并通过 `AgentSession` 调用。以下按用途分组，字段及参数 Schema 以 [framework.py](../../decision/agent/tools/framework.py) 为准。

**任务、地图与观察**

| 工具 | 行为 |
|---|---|
| `record_task` | 登记完整指令的有序要求，不自动提交导航。 |
| `lookup_places` | 查询点和区域的名称、身份及几何信息。 |
| `query_map` | 返回全局概览、静态先验局部裁剪及结构化空间信息，不生成位姿。 |
| `check_candidate` | 用地图检查候选停车位置或有朝向的位姿。另给观测点 ID 和朝向时，逐点报告相机水平视野及二维静态视线上的占据与未知情况。 |
| `observe_scene` | 取得当前 RGB 和同源场景，供下一轮模型使用。 |

**局部任务**

| 工具 | 行为 |
|---|---|
| `select_follow_target` | 在当前带编号的人物候选图中确认跟随对象，保存本次参考图；不启动跟随。 |
| `start_local_task` | 启动 T2 跟随或 T3 桌边停靠。跟随使用 Agent 已确认的参考；选择 `seating` 时还需当前 RGB 中的归一化桌沿范围 `table_roi`。 |

局部任务复用 `get_navigation_state`、`set_navigation_monitor`、`wait_for_event` 和 `cancel_navigation`，不建立另一套任务句柄或取消流程。状态摘要中的 `stage_type` 标识当前阶段；具体的跟随状态仍由 `follow_status` 提供。

**视觉记忆与导航**

| 工具 | 行为 |
|---|---|
| `save_keyframe` | 保存本轮模型实际读过的 RGB，记录保存原因、原时间、位姿及地图关系。 |
| `read_keyframe` | 根据保存身份重读历史 RGB，不刷新源时间。 |
| `navigate` | 检查当前要求、模型位姿和地图来源，再经导航几何检查异步提交。 |
| `navigate_route` | 一次提交模型自主选定的少量有序途经点；仿真自动切换，人工模式由操作者驾驶并确认终点。影子与实车自动执行接口不支持该调用。 |
| `get_navigation_state` | 查询当前调用摘要及最近完成反馈，不重复发送全部尝试记录，不刷新测量时间。 |
| `cancel_navigation` | 撤销活动调用并等待对应反馈。 |

**事件与任务完成**

| 工具 | 行为 |
|---|---|
| `wait_for_event` | 等待导航、新观察或已配置的监控触发。用户明确要求原地等候时可选择 `user_continue`，用 `instruction_quote` 引用原指令或用户答复中的等待条款，程序核对引文和停稳反馈。 |
| `set_navigation_monitor` | 调整当前子任务的触发条件。任务单的 `monitor` 在进入阶段时应用，未指定时跟随默认每 15 秒复核，乘梯默认每 5 秒等待独立传感器的新观察。 |
| `record_monitor_review` | 记录未满足或证据不足的判断。到达停稳后的视觉复核也可记录部分满足。存在多种视觉优先级或需区分持续区域复核时，明确指明本次复核对象。 |
| `pause_map_localization`、`record_elevator_observation`、`restart_map_localization` | 在人工跨楼层任务中暂停只读定位、判断整次乘梯是否完成，并按本轮目标地图与扫描提交初值。 |
| `complete_subtask` | 对照本轮 `completion_evidence` 提交完成决定和依据。要求到达后观察的任务须说明本次停稳后的 RGB 如何满足硬性视觉条件。 |
| `ask_user` | 保存问题并等待回答；有活动运动目标时须先取消，实机确认停稳的保持状态可以直接询问。 |
| `fail_task` | 记录任务无法继续的原因，并处理活动目标的停止。 |

#### 事件循环与导航反馈

[AgentLoop](../../decision/agent/core/loop.py)将导航完成、新观察和用户补充作为事件加入对话。接收后台模型回复后，经 `AgentSession.call()` 分派工具。任务修订、对话修订、活动导航、原观察或地图来源变化后，旧结果只记录。请求前检查输入状态，返回时按[结果对应的规则](#异步结果与源观察)决定能否应用。

导航工具一次只管理一个调用。`accepted` 确认收到请求，程序随后直接等待与目标、源时间、定位和地图身份对应的导航反馈。断连或 ACK 丢失时保留未确认意图，不自动重发。

参考规划在同一目标和路段上收到至少两份来自不同扫描的明确受阻结果，且首末扫描的源时间相隔至少 3 秒时，Agent 收到受阻事件。事件区分终点足迹占据和当前通路受阻。人工驾驶时，若同一路段正在等待后台参考路径，或规划期间障碍观测更新、需要重算，监控会在上一份受阻观测的有效期内保留计数。只有新的扫描再次报告同一受阻原因和位置，才会继续累计。重复扫描和等待均不增加计数，也不延长观测有效期。规划器确认通路恢复、有效期内没有后续证据、路段或地图关联发生变化时，需要重新累计。

实机局部控制连续 10 秒无法选出可用速度时，单独报告控制受阻。规划器的结果可以说明通路不可用，门是否关闭还需结合观察。实机撤销或底盘退出使能时仍执行原有的停止和接管流程。

对于指定点，只有用户允许在附近另停时才登记 `conditions.nearby_stop`，并引用许可原话。原点足迹已确认占据时可在许可范围内重选，未指定半径时采用 0.75 米。到达后以实测停稳位置核对允许范围及已选替代点。

每个已登记的当前子任务默认记录导航状态变化，并将事件提供给 Agent 复核。Agent 也可调用 `set_navigation_monitor`，组合周期、区域进入、无测量进展、累计距离、累计转角、持续停稳和超时触发。事件关联当前任务和导航句柄，检查反馈来源及定位时效后唤醒模型；观察阶段可在无导航句柄时等待周期或超时事件。事件保留源时间，不能推断收到事件时状态仍未变化。操作者也可请求立即复核。模型继续执行时不需要为了普通复核撤销活动目标。

条件式持续复核可在 `monitor` 同时指定 `continuous_region_id` 和 `review_mode: after_result`。轮椅进入指定区域后立即复核；Agent 用 `record_monitor_review` 记录尚未满足或证据不足的判断后，系统等待新的观察再触发下一次。轮椅离开区域或定位不可用时停止该复核，重新进入后再触发。模型一次只能有一个请求，区域状态变化会使对应的旧决策上下文失效。独立的 `conditions.robot_inside_region_id` 可表达用户要求完成时轮椅仍在指定区域：提交完成时重新检查当前定位和区域，不能仅凭此前进入事件完成。行人的动作仍由 Agent 结合 RGB 判断，不是程序硬编码的视觉结论。

连续复核会增加模型调用。单次运行默认最多 512 次模型请求，可用 `--max-requests` 显式设置 1 至 4096；达到上限后等待处理，调用次数限制与上下文裁剪独立。此功能已通过模拟状态和工具流程检查，实际图像识别与实机跟随仍待验证。

人工驾驶会话允许操作者跳过当前子任务。命令须匹配任务版本、子任务和活动句柄，活动目标取消确认后才推进；被跳过的阶段保留独立状态及操作者记录，并通知模型。若整项任务存在跳过阶段，最终状态为部分完成，不产生全部完成的证明。乘梯阶段不能跳过，自动执行模式不提供此操作。

无测量进展事件根据连续有效定位、位移、转角和可用的路径索引产生。当前位移达到 0.1 米、转角达到 0.15 弧度或路径索引变化会重新开始计时；定位中断超过 2 秒也会重新计时。该事件只说明这段测量没有达到上述变化，等待行人、定位误差或缺少路径反馈都可能影响判断，不等同于受阻。重复触发在模型推理期间合并；实际目标完成、取消或更换后不会把旧事件用于新目标。监测不控制速度、不判定语义，也不取代原有导航和安全检查；实机模型调用与效果尚待验证。

### 怎样确认一个子任务完成

#### 导航与人工驾驶到达检查

执行请求主动提供 `completion_evidence`。其中包括当前要求、来源、坐标系、测量时间、停稳状态和缺失项。导航到达时还包括实际位置与目标的距离、朝向误差，路线任务提供有序途经记录，实际轨迹另由当前地图观察提供。Agent 自行判断语义、绕行要求和偏好，满足要求时调用 `complete_subtask(goal_id, evidence)`。运行时在应用回复时重新核对任务、定位和所需观察。车辆移动或地图关联改变可使先前的证据失效。任务层点位容差为 0.20 米，控制器独立使用[导航完成配置](../../navigation/control/config.yaml)。

人工驾驶工作流在当前位置、必要朝向及定位估算停稳持续满足条件时，自动记录当前目标的到达证据；源时间不连续或数据失效会重新累计持续时间。运行时将当前定位与有效地图关联组合，向人工和自动 Agent 提供地图车体位姿，保留定位和关联的源时间，并检查坐标系、会话及关联有效期；到达检查不依赖低频 RGB 观察。人工确认仍作为备用入口，不能代替定位和停稳检查。对于多点路线，依据实时定位依次记录经过的途经点，并在末点检查到达和停稳；Agent 结合实际轨迹与原任务复核。执行请求列出尚缺的证据，后续判断使用新的定位反馈。

人工驾驶中，局部定位会话保持有效而地图关联中断时，Agent 保留当前阶段及未复核的导航目标，撤下参考路径，暂停模型工具执行。恢复要求同一地图、修订、关联会话及局部定位会话成立，并取得新代次的地图关联及中断后的定位和停稳测量。到达条件从新测量重新累计。多点路线保留已登记的途经点，按新关联重新记录途经证据。明确登记的等待口令及操作者取消继续按其原有流程处理。换图、地图修订变化、定位重启或断连仍按中断处理。

#### 观察、朝向与视觉条件

独立 `observation` 阶段不提交运动目标。Agent 读取本阶段开始后采集的 RGB 并给出结果和可见依据；程序核对输入来源、当前定位和图像位姿，应用判断时不限制模型响应耗时，仍要求同一时钟域和正确的先后关系。实机自动模式接受确认停稳的已有保持状态，或没有活动目标及控制所有者、且新鲜定位估速显示静止的空闲状态；人工模式在没有活动 Agent 目标、地图定位有效且新鲜定位估速显示静止时可进行观察；仿真使用其执行反馈。Agent 记录图像源时间和应用时的年龄，证据不足时可等待新观察。

有 `facing` 要求时，当前地图须来自到达后，实测车体朝向须落入选定朝向的容差。Agent 用本轮地图、可用图像和用户指令解释朝向。入口遮挡等视觉硬条件仍需当前 RGB。

有硬性视觉条件时，`completion_evidence` 必须包含本轮模型请求实际读过的停稳后有效 RGB。模型确认全部硬性条件满足且 `missing` 为空后，直接调用 `complete_subtask`，在 `evidence` 中说明画面里哪些内容证明要求已满足。条件要求同框时，依据须来自同一张画面。模型可以根据新信息重新选定位姿；检查器不会替它换点。同一 VLM 的视觉判断是任务证据，不是独立人工真值。

到达后可用 `record_monitor_review` 说明画面中可辨认的内容，并记录未满足（`not_satisfied`）、部分满足（`partly_satisfied`）或证据不足（`unknown`）。硬性视觉条件仍有缺项时，Agent 可等待新画面，或在同一阶段按许可调整位姿。严格点位可以原地转向，改变位置须有相应许可。每阶段最多接受两次视觉调整，每次都用重新停稳后的画面复核。

#### 跟随阶段与视觉偏好

Agent 按登记的监控条件观察目标人物。发现约定的瞬时动作后，完成决定保留当时的 RGB、人物轨迹身份和代次。与同一调用对应的停稳反馈到达后自动推进。

对于 `visual_preferences`，Agent 结合地图和相机资料选择位姿，并在完成依据中说明到达后哪些偏好可由当前 RGB 验证。未看到的对象保持未核实。

#### 实机保持与退出

保存 bag 的原驾驶、runtime 影子状态及图像中接近目标，都不能证明 Agent 导航到达。实机接口使用 `goal_observation` 关联目标身份与定位估计的到达、朝向和停止条件，并要求条件持续。条件成立后，运行时核对当前目标、地图和使能状态，将目标转入零速保持；在新的定位反馈中确认停稳后，才允许检查子任务和提交下一目标。保持期间保留人工使能状态，但不保留可执行目标；人工取消和接管仍会退出使能，整个任务结束时也会取消保持并退出使能。完成依据仍是定位估计，不冒充独立硬件验收。全部阶段完成并确认停稳后系统自动收尾。该流程通过合成反馈检查，尚未完成实机多任务验收。

模型请求异步执行，用户的暂停和取消不必等待模型返回。回答澄清保留原任务，明确替换才更换要求；恢复后由模型决定下一步，不自动重发旧目标。循环退出时请求撤销活动调用并短时等待，不能确认时保存停止未确认。

## 观察与导航适配

### 运行模式

| 后端 | 反馈和空间信息范围 |
|---|---|
| [SimulationNavigation](../../decision/agent/adapters/simulation.py) | 使用项目参考规划、DWA、独立安全和差速积分。全局概览与附近放大图来自已知合成静态地图，候选检查另用当前仿真局部占据，没有真实 RGB 渲染。 |
| [SavedShadowNavigation](../../decision/agent/adapters/shadow.py) | 读取保存的观察、原场景和登记静态地图，只提交目标建议。bag 驾驶不响应 Agent。 |
| [RuntimeShadowNavigation](../../decision/agent/adapters/shadow.py) | 通过私有 Unix socket 查询状态、按需读取 RGB 和有限的局部占据图、提交影子目标和取消，无底盘输出。 |
| [ManualNavigation](../../decision/agent/adapters/manual.py) | 只读连接不带底盘输出的在线观察会话；目标交由操作者驾驶，按当前定位和停稳估计自动检查到达，也可接受人工确认作为备用，不产生控制命令。工作流另行申请短时参考路径预览，不进入底盘或安全控制命令链。 |
| `RuntimeLiveNavigation` | 显式开启后向人工使能的实机运行时提交单个地图目标或跟随意图，使用定位估计和底盘状态推进子任务；不提供使能、安全管理或实机路线执行工具。 |

### 人工驾驶跨楼层

人工跨楼层任务使用同一执行 Prompt。进入已登记的乘梯阶段后，工作流关闭来源楼层定位，启动独立 RGB 和局部雷达观察。启用任务录包时，先等待录包就绪。切换无需停稳或来源地图关联有效。请求会告知模型定位已暂停，此时只提供乘梯判断、设置监控、等待和询问工具。Agent 默认每 5 秒结合当前观察和保留的历史帧判断，可以直接判定整次乘梯完成。

一楼有用户指定的标准起点。Agent 用当前 RGB、局部雷达图和历史参考图判断位置与朝向，随后工作流用新的出梯扫描和完整雷达初值尝试一次定位。启动失败或 30 秒内关联无效时，在原任务中打开 RViz 供操作者选点。人工确认后重新计时，配准失败可重选。执行模型等待有效的目标楼层地图关联，使用人工初值时，换层证据会注明来源。无标准起点的楼层由 Agent 根据目标地图和出梯后的扫描选点、重选。

一轮人工驾驶测试已用标准初值建立一楼地图关联。人工重选及完整任务连续性仍待实机验证。设置、现场操作和图像发送范围见[系统运行手册](../系统运行手册.md#agent-长程任务)。

### 观察与人工路线预览

[Observation](../../decision/agent/tools/observations.py)保留源场景、RGB 摘要、测量时间和位姿。RGB 的采集时刻不得晚于观察，跟踪缺失时人数保持未知。

启用 `--agent-observations` 后，runtime 在后台编码限频 RGB 和已封存场景的占据层，发布限幅压缩的占据数据及同源地图变换。整个流程无需等待模型，也不加载 YOLO。另启用 `--agent-follow-candidates` 后，T2 工作器检测并关联同源三维轨迹，操作见[运行手册](../系统运行手册.md#可选图像与决策输入)。为保持同帧对应，启用 Agent 观察会停用环境图异步工作线程，新增检测也会占用 GPU，现场性能尚需验证。

人工工作流通过独立的短期租约请求参考路径预览。该通道仅接受在线且未启用硬件输出的观察会话；进程失联后租约过期。runtime 复用当前参考路径工作器显示结果，但控制器和独立安全仍收到原本的空目标，停稳估计继续独立发布。已有普通观察目标时，普通目标优先，人工预览显示为等待。单点参考路径预览已有现场人工驾驶记录；预览不证明路线安全或自动执行能力，多点路线预览仍需现场验证。

### 人物选择、跟随与找回

Agent 从当前 RGB 中选定人物后，通过 `start_local_task` 提交参考 ID，人物描述从参考记录读取。所有 T2 后端共用任务句柄、三维跟随和完成证据，切换后端沿用同一任务登记与工具调用。

Agent 通过 `navigation.follow_phase` 监控当前子任务。跟随调用有效且连接及上下文仍有效时，搜索和重新确认由 T2 处理，Agent 继续等待和检查任务条件，重新选人、重启或取消工具不可用。操作者和本地安全仍可停止轮椅。用于复核的 T2 RGB 和同帧关联保留测量时间、跟踪身份和轨迹代次。人工驾驶时，动态目标仅用于参考路径预览。匹配方法、时限及搜索限制见[T2 实现](技术实现-T2行人跟随.md)。

### 起点与语义地图标注

`Catalog.bind_start()` 为本次任务创建目录副本，把有效测量起点保存为 `mission_start`，不写回共享资产。缺有效起点时不补零。合成返程测试的预设朝向与测得初始朝向分别记录。

[simulation.json](../../decision/agent/configs/simulation.json)提供合成点、区域和对象；[floor1.json](../../decision/agent/configs/floor1.json)引用真实一楼开发资产，缺资产时仅保留无坐标模板。原 R1、R2 草图继续禁用，没有将它们转换为新格式的有效区域。真实区域任务需提供与当前地图对应的人工区域及对象标注。

[地图标注器](../../decision/agent/map_annotation.py)读取静态环境地图，人工添加点和区域，另存语义目录。点也可以仅描述物体，不代表导航目标；用户要求到点时，目标位置才按车体 `base_link` 检查。目录记录静态地图快照和对应定位地图身份；地图修改或身份不符时不能沿用旧对应关系。点的朝向可以省略，目录中的参考朝向不会自动成为用户硬约束。标注和车体轮廓预览不证明当前位置可通行，操作见[系统运行手册](../系统运行手册.md#地图准备)。

## 记忆、记录与扩展

### 对话与澄清

[Conversation](../../decision/agent/core/conversation.py)按完整交互组维护消息，助手调用与工具结果一起保留或裁剪，不产生缺失配对的工具消息。默认保留最多 32 组，或序列化后的历史不超过 48000 字节；超过任一限制时移除最旧组，至少保留最新一组。通知也计入组数。原指令和初始目录始终保留，要求和当前进度另从本地任务记录生成，不依赖旧对话摘要。当前采用有界裁剪，不额外请求模型总结历史；替换任务建立新对话，旧事件仍留在数据库，不自动恢复旧任务。历史限制与单次请求的输入估算限制分别生效，历史变长会增加请求输入量。

已接受的澄清独立于这段历史保留，不再只取最后八条。澄清上下文最多 16,384 个 UTF-8 字节，超限的新回答明确拒绝，原有约束和待回答状态保持不变，用户可用简洁完整的新指令替换任务；不静默截掉早期硬条件。

### 历史选择与视觉关键帧

[EvidenceMemory](../../decision/agent/core/memory.py)记录带源观察的历史工具选择，按地点和源时间检索。模型输入将它明确标为 `recent_model_tool_choices`，不是长期环境知识，不自动认证地标事实，也不证明当前通行或已经到达。定位或地图关系变化后保留历史，撤销空间有效性。`--no-memory` 只关闭该组件，保留正常对话、任务要求和执行依据。

[Keyframes](../../decision/agent/core/keyframes.py)提供模型主动管理的视觉记忆。每个任务修订最多保存 24 个观察，重复保存同一观察复用原记录。模型须给出本轮已经读过的 `observation_id` 和保存原因；不能通过任意文件路径保存，也不能保存未来或已经失效的当前观察。保存及重读后，原 RGB 通过对应历史消息附带在后续请求中，默认最多两张，普通历史仍按完整交互轮裁剪。裁剪只移除上下文中的图片引用，已保存记录仍可按 ID 重读。替换任务后，旧修订的关键帧不能作为新任务工具输入。

关键帧保存在同一会话 SQLite 中，内容、观察和测量时间保持原值。它们只证明过去看到了什么，不能替代当前 RGB、有效定位、当前通行检查或真实到达反馈。`--no-memory` 不移除这些显式视觉工具。

### 会话存储与预算

普通请求的图像按原始数据 URL 的 SHA-256 保存在会话库中。每轮记录消息顺序、图像引用及原生响应，界面查看详情时校验摘要并还原图像，旧会话仍可按原格式读取。跨楼层期间的请求只持久化状态和用量；人工驾驶界面从内存显示实际请求、图像和模型响应，最多保留最近 32 次。判断乘梯完成后清除乘梯观察，目标楼层定位阶段产生的临时内容在该阶段结束后清除。共享费用账本保存模型、用量和结算资料。缺少服务端用量时保留估算。实现见[会话存储](../../decision/agent/core/store.py)。

### 扩展位置

新增模型工具时，在 `framework.py` 声明参数并在 `AgentSession` 增加处理方法。新的导航反馈来源放在 `adapters/`，沿用调用身份、测量时间和停止检查。简单图、无图、主动移动观察及局部技能的后续接口由工具和适配器增加，不另建模型调度层；当前 Agent 不提供任意 Shell、底盘速度、人工使能或解除安全保护的工具。

跨模块字段见[接口约定](../接口约定.md#外层agent开发接口)，当前测试与现场限制见[后续开发测试汇总](../后续开发测试汇总.md)及[系统实机问题](../系统实机问题.md)。
