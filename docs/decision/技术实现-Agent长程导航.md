# 技术实现：Agent 长程导航

外层 Agent 用一个托管 VLM 理解指令、选择导航位姿并审查任务结果。当前支持室内完备地图下的点目标、区域目标及有序任务，并可启动持续 T2 跟随。模型为 `qwen3.8-flash`，采用原生工具调用和累积对话，仍是单模型循环。跟随的真实模型和实机闭环尚待验证，T1、T3 的完整在线任务也尚未接通。

主要流程是：模型登记任务要求，读取空间信息，自主提交位姿或有序途经点，等待导航反馈，再检查当前子任务是否完成。任务要求单独保留，导航工具不会替模型选择途经点。多点自动推进目前仅接入仿真；人工驾驶模式可提交路线，并用定位估计检查实际经过情况，人工终点确认作为备用。影子和实机自动执行适配器不支持多点路线。实机单目标接口已接入定位估计、到达及停稳反馈，现场自主执行过首目标的一部分；自主多目标闭环仍未验收。

人工驾驶跨楼层模式为每个要求登记楼层，并将乘梯作为独立阶段。乘梯监控从与定位独立的相机流获取图像，通过通用周期观察机制交给 Agent 判断进出。通用机制支持不保留、保留最近若干条和 Agent 逐次决定保留；乘梯选择第三种策略，判断离开后清除图像及逐次判断。本机请求和用量记录只保存调用元数据，不保存该阶段的图像和判断。楼层切换根据用户确认的一、二楼电梯口对应关系拟合平面变换，将乘梯前测得的位姿转换为目标楼层定位初值；初值不构成定位证明。目标地图关联有效后才将原任务重新绑定到目标楼层并推进后续阶段。一次人工乘梯测试已进入目标楼层切换，但一楼地图关联未建立，任务未完成；当前尚无同一任务内的重新选点恢复，也不支持自主操作电梯。

运行命令见[系统运行手册](../系统运行手册.md)，未完成事项见[后续开发测试汇总](../后续开发测试汇总.md)。

## 输入、模型与工具

### 地图条件与空间输入

地图条件表示任务开始时有哪些先验，区别于底层的定位地图、静态环境地图和当前局部地图。

| 条件 | 含义与当前支持 |
|---|---|
| `complete`，完备地图 | 具有整个场景的建图结果，以及任务涉及的人工点、区域和对象标注。当前实现目标提交与检查。 |
| `simple`，简单地图 | 人工简图或地图软件的俯视截图，主要通道和障碍大致可辨，未必具有比例尺。保留条件接口，尚不支持执行。 |
| `none`，无图 | 没有地图先验，任务依赖纯文本描述和现场观察。保留条件接口，尚不支持执行。 |

选择 `simple` 或 `none` 不会向模型暴露完备地图的标注，目标工具返回能力尚未实现。简单图不能直接当成米制地图，后续需要单独实现图像坐标、拓扑和实际定位之间的关系。

#### 地点目录与机器人资料

[Catalog](../../decision/agent/tools/places.py)在完备地图中管理点和区域：点使用 `place_id` 和 `pose`，既可表示对象位置，也可按任务要求作为目标或面向参考；区域使用 `region_id` 和二维 `polygon`。点的位置不自动表示车体可以到达。坐标统一属于目录的 `frame_id`，位置单位为米，角度单位为弧度。旧目录的 `landmarks` 在加载时按原 ID 和位置转换为点，不修改原文件。新增区域和旧格式对象可以写在登记配置中，加载时覆盖到本次目录副本，不修改原地图资产。

机器人资料由当前适配器提供，显示在 `runtime_current_state.robot_context`。它说明 `base_link` 参考点、足迹及前后左右范围、速度向量 `[forward_mps,yaw_rate_rad_s]`，以及已加载的倒车、原地转向、转弯半径和速度限制。启用 runtime Agent 观察后，当前有效观察还会根据本车雷达到车体变换和仓库中的固定安装标定，提供雷达、相机、IMU 相对车体的位置和相机光轴，并记录各自来源。假设几何、过期观察或缺失数据保持不可用；标定组合不是新的安装或精度验证。仿真读取实际使用的运动配置；旧 runtime 未提供本车几何时，影子适配仍使用历史几何参考。几何来源和假设状态同时给出，不能据此宣称实机性能已经测定。

#### 固定地图

输入分为固定地图和当前观察。完备地图可用时，程序先按静态栅格中空闲与占据格的外接范围裁剪未知边框，向外保留一米边距；固定点和区域若在该范围外，显示范围会扩大以保留它们。全图没有已知格时使用原范围。裁剪仅影响图像，原栅格、米制坐标和地图身份不变；画面外不能视为空闲。固定全局图放在系统提示之后、原任务之前，画布按地图比例自适应，最长边不超过 2048 像素。图片边缘只保留坐标刻度，颜色和符号说明通过文本输入提供。尺寸在创建固定地图时确定，同一会话中不随自车移动或任务替换改变。

图上绘制所有有坐标的固定点和区域，显示编号、名称与区域轮廓。点和区域名称通过细线分别连接到点位置和区域边界；布局会根据相邻标注选择文字位置，尽量减少重叠与线条交叉，密集场景不保证完全消除。位置附近放不下完整名称时只显示编号；完整名称、坐标和其他字段保留在结构化目录中。地图不绘制当前自车和任务进度，本次测得的起点放在后面的任务上下文中。中文名称需要系统提供可用的中文字体。

#### 当前观察与地图图像

每轮请求前，程序按当前有效观察准备末尾附件：当前 RGB、全局概览和附近放大图。两张地图按显示范围的比例自适应，最长边为 1024 像素，边缘只保留坐标刻度。全局概览使用相同的已知栅格裁剪，并在轮椅或实测轨迹超出范围时扩大显示；附近放大图默认以轮椅为中心，显示静态先验、车体足迹和标注。两张地图使用相同方向、坐标约定和标注身份。`query_map` 可用 `bounds=[xmin,ymin,xmax,ymax]` 查询静态先验的其他范围，不生成候选位姿。结构化摘要同时给出原坐标和来源，P、R 编号仅供阅读，工具仍使用对应的正式身份。

显式裁剪根据实际观察身份、源时间、栅格和位姿判断是否需要重绘，不使用控制循环时间代替观察时间。来源未变时保留原图；来源变化后按原请求范围更新，成功提交导航或替换任务后恢复默认范围。全局图上的方向箭头有最小可见像素长度，只表示方向，不能按箭头长度估计距离。文本图例区分占据与未知，并说明附近放大图仅表示静态先验。

轨迹只采用已经发生的有效定位测量，不使用规划路径或未来录包帧，不在稀疏观察间插值。定位失效、测量间隔超过三秒或定位身份变化时分段；地图关联、时钟或坐标系变化时清空当前轨迹。轨迹按测量时间采样并限制容量，图像和轨迹来源摘要进入当前 `view_id`，实际样本另保存在同一会话的 `trajectory_snapshot` 事件中。

全局概览和附近放大图均使用静态先验，不叠加实时局部占据或人物，因此不能据此推断动态区域当前空闲。runtime 的可选观察出口仍传递限幅压缩的占据层及其同源地图变换，不传整个场景；`check_candidate` 独立检查可用的同源局部占据，当前视觉信息通过 RGB 提供。车体箭头表示 `base_link` 前向。相机外参与对应 RGB 的 CameraInfo 可用时，附近放大图用紫色线表示针孔模型近似水平视野；它没有检查遮挡，不能证明图中对象真实可见。相机内参、图片尺寸或坐标系不匹配时不绘制视野。

#### 候选位姿检查

`check_candidate` 对模型提出的候选位姿使用配置的完整车体轮廓，以及路径规划配置中的安全余量，分别检查静态栅格和同源局部占据栅格。候选不在局部栅格覆盖范围时明确返回未覆盖，不能当作当前空闲。可选的点 ID 用于计算这些标注位置相对候选相机的近似水平视野；相机中心按候选车体姿态和安装外参计算。该工具要求有效且来源未变化的当前空间图，不能证明动态障碍已排除，不检查整条路径、遮挡、目标高度或门体范围，也不证明实际可见。栅格空闲仅用于辅助选点，导航规划和独立安全检查仍然负责实际通行；真实可见性需要到达后的当前 RGB。

成功检查候选后，下一轮局部图用洋红色绘制最近一次候选的车体轮廓和朝向；相机位置可用时，从该位置向模型指定的标注点绘制连线。橙色仍表示实际轮椅，候选和连线只用于观察位置关系，不表示已移动或已经检查遮挡。

候选在静态地图范围内但位于原裁剪范围之外时，图像范围会扩展以包含候选车体；原请求范围和实际显示范围分别记录。地图外的候选不扩大显示范围，结构化摘要仍保留其坐标。

`recent_candidate_checks` 保留最近八个不同候选的静态与局部轮廓结果、相机水平视野结果和原始观察时间。相同位姿与点集的重复检查会更新次数。新观察到来后，旧结果标记为 `historical_only`，不再作为当前候选预览或当前占据证据，原始源时间保持不变。地图或定位身份变化、输入失效、提交导航或替换任务时清空摘要。局部图预览和摘要均不改变导航检查或独立安全层。

单点 `navigate` 在适配器提供车体几何时，还会检查最终提交的实际位姿，即使模型先前检查过其他朝向。局部轮廓有占据时拒绝提交；静态轮廓有占据且局部没有完整空闲证据时也拒绝。局部的完整空闲证据可反映静态地图之后打开的通道。未知、未覆盖和空闲均不代表路径已验证，后续仍由导航规划与独立安全层处理。适配器没有车体几何时，此项辅助检查不可用，沿用适配器自己的规划检查。

`observe_scene` 可以显式读取当前 RGB 和同源场景。没有有效图像时返回不可用，不拿旧图代替。基础请求最多四张图；按需加入两张历史 RGB 后，总计最多六张。客户端检查实际图片尺寸，并使用同一经验公式估算输入量和费用：文本按 UTF-8 长度、图像按像素面积计算，不把 Base64 当成文本。该公式依据现有模型用量记录校准，并非服务端真实分词结果；不同内容、尺寸或服务可能偏离。估算输入超过本地 131072 限制时不发送请求，事件会记录原因和估算值。地图图像与目录、栅格、位姿、源时间和图像摘要共同生成 `view_id`，用于核对返回的位姿是否依据仍有效的空间输入；开头的 `reference_map_id` 不能替代它。

### 模型调用与响应

#### 请求阶段和上下文

[Model.decide()](../../decision/agent/core/model.py)把保留的对话和本轮当前状态交给托管模型。工具定义通过 API 的 `tools` 参数独立提供，模型使用原生 `tool_calls` 选择工具；客户端不再要求回复正文生成统一的动作 JSON。

| 阶段 | 提示与可用工具 |
|---|---|
| 任务尚未登记 | [登记阶段提示](../../decision/agent/configs/registration_prompt.txt)说明如何识别和登记完整要求。模型可查询地点和地图、读取观察或询问用户；只提供登记所需的六个工具，并请求服务使用 `tool_choice=required`。客户端检查返回的工具是否属于本轮列表；服务不支持该参数时报告错误，不自动降级或重试。 |
| 登记完成 | 使用[完整系统提示](../../decision/agent/configs/system_prompt.txt)和完整工具列表组织导航、观察与证据检查。 |

工具的字段单位、身份来源和返回状态由 [framework.py](../../decision/agent/tools/framework.py)维护。当前资料不足或能力未发布时明确保持未知，模型不能自行补成已完成或已验证。

每次 API 请求依次发送以下内容，不依赖服务端常驻会话：

1. 系统规则、固定高分辨率地图及全部固定标注。任务起点不进入这一前缀。
2. 原指令、目录引用和累积对话。历史中只有模型显式保存或重读的关键帧附带图片，普通观察不自动累积。
3. 程序追加的 `runtime_current_state`，包含登记进度、下一要求、已选位姿、最近工具反馈、全部已接受澄清、机器人资料和带位置的关键帧索引。
4. 有效的当前三图。`visual_inputs` 按实际附件说明可用性、短引用、源年龄和缺失原因；RGB 元数据另给真实采集时间、相机坐标和原尺寸，不把场景时间当 RGB 时间。

#### 身份投影与引用

固定标注只在前部地图资料中定义一次。初始目录保留地图条件、坐标、单位和访问政策；仅在固定标注、坐标及栅格对应时，以 `annotation_reference.reference_map_id` 引用前部目录，并单独给出动态 `mission_start` 点。发送前对请求副本进行投影：去除模型不需要的校验摘要和内部身份，将需要模型在工具参数中原样返回的地图、观察、关键帧和候选身份转换为短引用。程序将本轮提供过的短引用还原为完整身份后，继续执行坐标和数据对应检查；未知引用或不同类型的引用被拒绝。短引用发生冲突时停止该请求。原始本地记录和模型原始响应不改，前部地图缺失或不匹配时保留完整标注。原生工具调用身份仍按服务协议保留，用于关联工具回复。

同一观察或视图投影若已经完整保留在当前工具结果中，附件还可通过 `details_in_tool_call_id` 引用它，同时保留当前观察身份、源时间和坐标约定。历史裁剪后找不到该记录时，附件发送完整的模型输入投影；需要的固定目录仍包含在本轮请求中。图像正常发送，不修改源摘要或测量时间。

#### 原生工具调用与回复校验

模型可以附带简短进度说明，每轮最多调用一项工具。例如，已经登记区域要求并读取地图后，返回消息的相关字段如下：

```json
{
  "role": "assistant",
  "content": "我选择停在区域内的开阔位置。",
  "tool_calls": [
    {
      "id": "call_example",
      "type": "function",
      "function": {
        "name": "navigate",
        "arguments": "{\"goal_id\":\"second_stop\",\"pose\":[7,4,0],\"view_id\":\"本轮地图返回的短引用\",\"orientation_source\":\"semantic\"}"
      }
    }
  ]
}
```

这些坐标仅为合成示例。实际位置和朝向由 VLM 根据地图、语义、视野及后续任务直接选择。工具检查原始连续位姿；不生成候选终点，不推荐朝向，也不吸附或改写模型输出。

[framework.py](../../decision/agent/tools/framework.py)维护每个工具的参数 Schema，并将原生回复转为经过检查的 `Reply`。客户端按流索引拼接函数参数，调用 ID 和类型属于固定元数据；收到重复值时核对一致性。完整调用仍检查工具名称、必填字段、类型和语义，不修复参数、不补调用身份、不把正文中的动作 JSON 转成调用，也不自动重试或更换模型。`record_task.goals` 和 `navigate_route.waypoints` 是原生数组，任务朝向 `facing` 是单个 ID 字符串。工具定义随请求提供，不能假定服务端会对所有参数约束实施强制检查；普通回复的 JSON Schema 模式也不能直接视为工具参数约束。

#### 异步结果与源观察

工具执行后，对话追加原助手消息和 `role=tool` 的结果，使用 `tool_call_id` 对应原调用。模型响应没有按耗时设置期限；任务、调用、定位或地图身份变化时，旧结果仍不会应用。原始观察时间保持不变，判断只反映图像采集时的状态，不能证明模型返回时现场没有变化。

| 结果 | 应用条件与处理 |
|---|---|
| 登记要求、查询等不驱动操作 | 在任务与观察身份仍匹配时继续，不因响应耗时拒绝。 |
| 点、区域或参考目标 | 使用当前空间图检查车体占据，同时限制自车位姿变化，记录模型原视图和实际检查视图；视觉条件与偏好仍需相应观察判断。候选检查也使用新视图重新计算。 |
| 多点路线 | 仅人工和仿真模式支持。原身份有效且位姿变化未超限时，用新空间图重新执行路线几何和导航适配检查。 |
| 视觉及朝向判断 | 保留模型实际使用的观察身份和源时间，记录判断应用时的观察年龄，不自动证明当前画面或环境未变化；到达及停稳仍须当前有效反馈。 |

没有活动导航句柄时，连续三次提交相同单点目标或路线并因相同原因被拒绝或不可用，Agent 记录原因并等待用户处理；仅视图引用变化不视为新目标。观察阶段收到导航请求时会明确返回阶段不支持导航。源时间和模型原始调用均不改写；重复消费调用 ID 或一轮返回多项调用会被拒绝。完整数据结构合法仍可能包含错误的场景判断。

普通地图和 RGB 作为本轮观察附在当前状态消息后，成功提交导航或输入过期后清除旧附件，下次请求根据有效源重新准备，不沿用旧的自车叠图。主动保存的关键帧按历史时间另行保留，对话中的旧工具结果也保留原时间和标识。纯文字回复会进入等待用户状态，有活动调用时先请求取消；尚未登记任务时界面明确提示模型只返回文字，原文仍保留，程序不将其解析成工具调用或自动重试。成功仍须调用 `finish_task`。

#### 服务配置与思考模式

API 连接来自被忽略的 `configs/agent_api.local.json`，密钥也可由环境变量提供。客户端使用 HTTPS，不继承无关 shell 代理；记录不含凭证、认证头或私有服务地址。Agent 使用独立托管服务，局部 SGLang 不作为自动备用。

默认关闭思考；`run` 和 `shadow` 可显式使用 `--thinking-mode low` 进行对照。该模式请求 `reasoning_effort=low`，关闭历史思考内容回传，并用 `max_completion_tokens=6144` 同时限制思考与最终输出。预计输出量采用同一模型和思考模式最近报告用量的均值，缺少记录时使用默认估算；请求的最大输出不变。服务拒绝参数或响应截断时不会自动重试或切换模式。请求、原始响应和用量按现有会话记录保存，其中原始响应可能包含思考内容；历史对话只传递正常回复与工具结果。模式支持以所配置的托管服务为准，低频 Agent 等待期间不改变导航、安全监督或数据时效检查。

### 输入缓存

默认保留服务端隐式缓存。系统规则、工具及字段顺序保持稳定，固定高分辨率地图和全部固定标注位于原任务之前，变化的当前状态和三张当前图位于末尾。同一任务内固定地图不会因自车移动或任务替换而重绘；地图与标注资产变更应重新创建会话。隐式缓存是否命中由服务端决定，客户端不缓存或重放模型答案。高分辨率图仍会随请求发送，不能把有利于前缀复用解释为已经命中或一定更快。

客户端另支持显式缓存策略：分别在系统规则、固定地图消息末尾和完整历史末尾设置 `cache_control` 标记；没有固定地图时，第二个标记使用初始目录。标记只添加到请求副本，不改变本地对话或观察。旧输入的小样本对照未显示显式策略优于隐式，因此未设为默认，旧命中比例也不作为新多图结构的成绩。服务拒绝显式参数时记录失败，不自动换策略或重试。

响应保留原始 `usage`，另汇总输入、缓存命中、缓存创建 token 和命中比例。缺少的统计保持未知，不填零；共享费用账本继续按保守费率计提，没有按通用缓存折扣推算实际账单。参数和服务限制参考[缓存文档](https://www.alibabacloud.com/help/en/model-studio/context-cache)。

此前曾检查六图输入、真实观察切换和上下文投影；对应历史报告在当前本机未找到，无法重新核对原始结果。请求合法、缓存命中或历史图片可读均不能证明任务决策已经可靠。

## 任务执行与反馈

### 任务要求与执行位姿分别保存

[TaskGoals](../../decision/agent/core/tasks.py)保存模型通过 `record_task` 从原指令提取的有序要求。这是一份完成条件记录，不是另一套自动执行的工具计划。

| 字段 | 含义 |
|---|---|
| `goal_id`、`description` | 本任务中的稳定子任务身份及原意说明。 |
| `kind`、`target_id` | `point` 表示明确点位置，`region` 要求进入标注区域；`reference` 将点或区域作为语义参考。`route` 保存多点路线的原始任务要求；`sequence` 依次经过用户指定的标注点或区域。`skill` 记录独立技能阶段，`target_id` 为空。匿名点使用空身份并提供用户明确指定的 `position`。 |
| `stage_type` | 阶段技能，省略时为 `navigation`。`follow` 使用持续 T2 跟随；`observation` 在停稳后检查本阶段的新图像；`seating` 目前只能记录要求，不能作为到点任务完成。 |
| `required_yaw` | 用户硬性指定的朝向，缺省表示没有数值朝向约束。 |
| `facing` | 用户要求面向的标注点或区域身份。模型根据当前位置、入口和连通关系选择车体朝向；目标中心不自动决定朝向。 |
| `position_rule`、`max_distance_m` | 分别表达区域面积质心和到参考对象的最大几何距离；两者适用的目标类型不同。 |
| `checkpoints` | 保存用户要求按顺序经过的正式标注身份，不包含模型自行添加的途经点；绕行方向等要求保留在任务描述中。 |
| `semantic_conditions` | 需要到达后通过当前 RGB 判断的条件，例如能看见某个入口。 |
| `visual_preferences` | 用户明确要求尽量满足的视觉偏好。模型选点时考虑它，不把偏好当作所有对象必须可见的硬条件。 |

不同目标要求使用各自的检查方式：

- **点和区域**：明确点目标保留原位置，区域目标默认只规定范围。用户要求区域正中时，`position_rule=region_centroid` 使用面积质心和导航位置容差；质心位于多边形之外时须澄清所需位置。
- **参考对象**：`reference` 不把对象中心当作车体目标。纯几何的靠近可登记 `max_distance_m`，与点或区域边界的距离均按米检查；用户未指定时该阈值是模型的近似选择。
- **视觉要求**：硬性条件登记为 `semantic_conditions`，尽力满足的偏好登记为 `visual_preferences`。需要判断时使用到达后的同源实时 RGB。
- **面向方向**：模型结合当前位置、墙、入口、可通行路径和可用观察选择方向，检查器不把目标点或区域质心当作必须朝向的几何点。例如区域中心被墙遮挡时，模型可能选择朝向通向该区域的走廊。

模型可以直接提交连续位姿，也可以指定标注点并自行提供朝向；两种方式都须遵守任务条件和导航检查。点资产中即使含有朝向，也不自动成为用户要求。

当前状态通过 `selected_goal.allowed_orientation_sources` 列出允许的来源：登记了 `required_yaw` 时使用 `user`，否则使用 `semantic` 或 `autonomous`。本地检查拒绝与登记要求不符的来源标签，不自动修改位姿；标签合法仍不能证明朝向适合现场。区域内判断针对 `base_link` 参考点，完整车体是否可停、路径是否可行仍由导航检查。

每个要求分别保存原始要求摘要、待完成或已完成状态、模型选定位姿、导航句柄及完成依据。完成当前要求之前不能操作后续要求；登记后不能删改要求来使结果通过。用户明确替换任务时，先确认撤销旧调用，再创建新修订和要求记录。模型仍可能误解或遗漏自然语言内容，必须通过独立任务评测检查。

阶段完成后记录下一阶段的进入时间，清除上一阶段的监测、临时观察与候选。跟随阶段还会清除当前人物和找回状态，原始参考图及完成依据仍保存在会话中，后续跟随须重新选择人物。模型请求上下文包含当前阶段身份，迟到的上一阶段回复不能用于新阶段。

#### 有序路线与人工驾驶

`navigate_route` 接收模型自行选择的有序地图 XY，路线至少包含两个点。终点朝向可省略；任务包含面向或视觉要求时仍需给出朝向，有用户明确的数值朝向时使用该数值。点是执行方案，可以与用户指定的 `checkpoints` 不同。仿真自动切换中间点，经过点不要求朝向或停稳；最后一个点需要到达并停稳，提交终点朝向时还需对齐。人工模式由操作者驾驶，根据有效定位识别建议点附近的经过情况，终点使用定位和持续停稳估计自动检查，人工确认是备用方式；是否检查朝向取决于用户任务要求。需要在中间停靠或观察的任务应登记为多个有序要求，不能仅使用经过点。一次活动路线仍占用一个导航句柄；模型无需在每个点发起新调用。

人工路线依次记录实际定位进入途经点的证据：首点和终点使用 0.20 米容差，中间点使用 0.50 米容差。中间点无需停稳或再次调用模型；终点还需满足到达和持续停稳条件。证据记录源时间、地图及会话身份，完成时逐项核对。路线的执行进度不等于任务语义完成，Agent 仍需结合任务要求、实测轨迹和当前观察判断。RViz 连接线仅表示建议顺序，不能证明实际通行。

人工自动到达后，如果新鲜反馈显示再次运动、偏离目标或证据身份变化，当前到达证据会失效并记录原因。定位身份和全部路线证据仍匹配时，再次满足位置、必要朝向和持续停稳条件可以恢复证据，不重复添加末点。人工确认是备用入口，也须核对当前定位、停稳和已有路线证据。已通过任务复核的目标允许由后续目标替换，旧目标证据之后失效不会占住下一阶段；原完成记录和新证据分别保留。

实测轨迹用于展示和任务复核，样本达到容量后会降低采样密度，优先保留较早位置、近期位置及各段端点。定位中断仍会分段；若段数过多导致旧样本被丢弃，空间观察会标记截断。抽样轨迹不能证明每处细节，Agent 应结合其范围和缺口判断证据是否足够。

#### 绕区域与指定顺序

绕行使用通用多点路线：Agent 根据区域和任务选择少量有序途经点，要求返回起点时将该点明确作为末点。每个途经点检查静态栅格和可用的当前局部栅格；占据或未知且没有足够当前空闲依据的点不会提交。该检查不能证明完整车体姿态或路径可行。实际路径由参考规划器逐段生成。

通用路线的不同位置超过三个且没有填写 `waypoint_reason` 时，工具要求 Agent 先考虑精简；对于用户明确指定的 `sequence` 检查点，阈值至少为指定点数加二。点位因占据或未知被拒绝时，反馈也会提醒检查点数。确需较多自主选点时可通过 `waypoint_reason` 说明后提交，程序不会验证说明是否充分，也不自动删除或重排点。说明不代表路线可行，点位检查和导航检查仍需执行。

多点路线不对标注区域设置专门的绕行几何或区域穿越门槛。Agent 应根据实际轨迹与任务要求判断绕行方向和是否完成；定位中断、轨迹缺失或信息不足时应保持未知。人工模式不会控制原车手柄或代替驾驶者停车。

`sequence` 的路线须按顺序包含用户指定的点或区域；Agent 结合实测途经证据与轨迹判断是否满足原要求。中间点通过不代表完成视觉观察或中途停靠。人工模式记录的是操作者驾驶和定位估计，不能据此认定实车自动多点接口已接通。

### 工具怎样配合

工具由模型选择并通过 `AgentSession` 调用。以下按用途分组，字段及参数 Schema 以 [framework.py](../../decision/agent/tools/framework.py) 为准。

**任务、地图与观察**

| 工具 | 行为 |
|---|---|
| `record_task` | 登记完整指令的有序要求，不自动提交导航。 |
| `lookup_places` | 查询点和区域的名称、身份及几何信息。 |
| `query_map` | 返回全局概览、静态先验局部裁剪及结构化空间信息，不生成位姿。 |
| `check_candidate` | 检查候选位姿的静态车体轮廓，并按需计算标注点相对候选相机的近似水平视野，不提交导航。 |
| `observe_scene` | 取得当前 RGB 和同源场景，供下一轮模型使用。 |

**局部任务**

| 工具 | 行为 |
|---|---|
| `start_local_task` | 指定当前阶段的 `goal_id`、`task_type` 和目标描述；跟随由运行时 T2 支路执行，就座返回尚不可用。 |
| `finish_local_task` | 根据本轮视觉依据请求正常结束当前局部任务；跟随须等待停稳后再检查阶段条件，就座返回尚不可用。 |

局部任务复用 `get_navigation_state`、`set_navigation_monitor`、`wait_for_event` 和 `cancel_navigation`，不建立另一套任务句柄或取消流程。状态摘要中的 `stage_type` 标识当前阶段；具体的跟随状态仍由 `follow_status` 提供。

**视觉记忆与导航**

| 工具 | 行为 |
|---|---|
| `save_keyframe` | 保存本轮模型实际读过的 RGB，记录保存原因、原时间、位姿及地图关系。 |
| `read_keyframe` | 根据保存身份重读历史 RGB，不刷新源时间。 |
| `navigate` | 检查当前要求、模型位姿和地图来源，再经导航几何检查异步提交。 |
| `navigate_route` | 一次提交模型自主选定的少量有序途经点；仿真自动切换，人工模式由操作者驾驶并确认终点。影子与实车自动执行接口不支持该调用。 |
| `get_navigation_state` | 查询当前调用摘要及最近完成反馈，不重复发送全部尝试记录，不刷新测量时间。 |
| `cancel_navigation` | 撤销活动调用并等待对应反馈。 |

**事件与任务完成**

| 工具 | 行为 |
|---|---|
| `wait_for_event` | 等待导航、新观察、已配置的监控触发或用户继续，期间不反复请求模型。 |
| `set_navigation_monitor` | 为当前子任务组合周期、区域、进展、停稳或超时等复核触发；不提交运动目标。 |
| `check_goal` | 由 Agent 提交任务判断和依据，再检查执行、实际位姿及必要语义证据。 |
| `ask_user` | 保存问题并等待回答；有活动运动目标时须先取消，实机确认停稳的保持状态可以直接询问。 |
| `finish_task` | 检查全部登记要求已完成后结束任务，或记录失败并处理停止。 |

#### 事件循环与导航反馈

[AgentLoop](../../decision/agent/core/loop.py)持续处理反馈和用户事件，接收后台原生回复，再调用 `AgentSession.call()`。导航完成、新观察和用户补充作为明确来源的事件加入对话。一次最多有一个模型请求。任务修订、对话修订、活动导航、原观察或地图来源变化后，旧结果只记录，不再应用。请求前仍检查输入状态；返回时不因模型耗时拒绝，目标应用前另行检查当前定位与环境。源时间不改成 API 完成时间。

导航工具一次只管理一个调用。`accepted` 表示请求已接收，不能推进任务；收到该结果后程序直接等待导航事件，不再要求模型用文字重复说明正在等待。目标、源时间、定位和地图身份必须与反馈对应；断连或 ACK 丢失时保留未确认意图，不自动重发。模型提交成功后清除缓存地图和 RGB，避免在移动中重复使用旧的自车叠图。

实机控制连续 10 秒没有可用速度时，Agent 收到一次 `blocked` 导航事件，可以结合当前反馈决定等待、取消或询问；这不修改导航候选或独立安全判断。速度候选恢复后发送恢复事件。人工取消或底盘退出使能会使当前 Agent 执行上下文失效，不再自动提交下一目标。明确拒绝的请求与接收状态不明的通信故障分别记录。

每个已登记的当前子任务默认记录导航状态变化，并将事件提供给 Agent 复核。Agent 也可调用 `set_navigation_monitor`，组合周期、区域进入、无测量进展、累计距离、累计转角、持续停稳和超时触发。事件关联当前任务和导航句柄，检查反馈来源及定位时效后唤醒模型；观察阶段可在无导航句柄时等待周期或超时事件。事件保留源时间，不能推断收到事件时状态仍未变化。操作者也可请求立即复核。模型继续执行时不需要为了普通复核撤销活动目标。

无测量进展事件根据连续有效定位、位移、转角和可用的路径索引产生。当前位移达到 0.1 米、转角达到 0.15 弧度或路径索引变化会重新开始计时；定位中断超过 2 秒也会重新计时。该事件只说明这段测量没有达到上述变化，等待行人、定位误差或缺少路径反馈都可能影响判断，不等同于受阻。重复触发在模型推理期间合并；实际目标完成、取消或更换后不会把旧事件用于新目标。监测不控制速度、不判定语义，也不取代原有导航和安全检查；实机模型调用与效果尚待验证。

### 怎样确认一个子任务完成

#### 导航与人工驾驶到达检查

对于导航阶段，Agent 依据当前任务、三图和反馈提交 `review_result` 与文字依据；未知或未满足不会推进。`check_goal` 还须找到当前选定位姿对应的导航完成记录，并确认本次修订仍有效、车辆已停、当前定位有效。随后使用反馈中的实际位姿检查点距离、区域范围、用户朝向及必要语义条件。任务层点位置容差在人工和自动模式均为 0.20 米；自动导航控制器仍使用[导航完成配置](../../navigation/control/config.yaml)中的独立到达容差。观察及跟随阶段可沿用已有视觉判断和依据。任务判断与触发记录不代表独立视觉真值或底盘验收。

人工驾驶工作流在当前位置、必要朝向及定位估算停稳持续满足条件时，自动记录当前目标的到达证据；源时间不连续或数据失效会重新累计持续时间。运行时将当前定位与有效地图关联组合，向人工和自动 Agent 提供地图车体位姿，保留定位和关联的源时间，并检查坐标系、会话及关联有效期；到达检查不依赖低频 RGB 观察。人工确认仍作为备用入口，不能代替定位和停稳检查。对于多点路线，依据实时定位依次记录经过的途经点，并在末点检查到达和停稳；Agent 结合实际轨迹与原任务复核。`check_goal` 复核当前目标、地图身份和有效停稳反馈，暂缺反馈时在本次调用内最多等待约 1 秒；仍无法确认时记录具体缺失条件。视觉判断保留图像源时间与应用时的年龄，不因响应耗时拒绝，也不能保证当前视觉状态与采集时一致。该复核流程仍需现场验证。

#### 观察、朝向与视觉条件

独立 `observation` 阶段不提交运动目标。Agent 读取本阶段开始后采集的 RGB 并给出结果和可见依据；程序核对输入来源、当前定位和图像位姿，应用判断时不限制模型响应耗时，仍要求同一时钟域和正确的先后关系。实机自动模式接受确认停稳的已有保持状态，或没有活动目标及控制所有者、且新鲜定位估速显示静止的空闲状态；人工模式在没有活动 Agent 目标、地图定位有效且新鲜定位估速显示静止时可进行观察；仿真使用其执行反馈。只有判断为 `satisfied` 才完成，`unknown` 和 `not_satisfied` 保留未完成状态。判断记录图像源时间和应用时年龄，不能证明回复时视觉场景没有变化，也不是独立视觉真值。

有 `facing` 要求时，先检查实际车体朝向与模型选定的执行朝向是否在导航容差内，再要求模型根据到达后、本轮实际读过的当前地图和可用观察给出 `facing_result` 与依据。该判断体现模型对用户意图的理解，不是独立几何或人工真值。静态地图只说明先验，不能证明当前入口没有遮挡。缺少足够依据时返回 `unknown`，不能将朝向条件记为完成。

有视觉条件时，还必须取得到达后的有效 RGB。语义结果必须对应本次模型请求实际读过的那份观察，并给出简短可见证据。`unknown` 和 `not_satisfied` 均不完成任务。模型可以根据新信息重新选定位姿；检查器不会替它换点。同一 VLM 的视觉判断是任务证据，不是独立人工真值。

#### 跟随阶段与视觉偏好

Agent 低频监测跟随及搜索状态，根据任务终止条件判断是否结束，并处理特殊情况。跟随完成检查保留停前与停后的视觉和停稳判据；视觉判断记录原始 RGB 时间与应用时年龄，不保证回复时场景未变化。

对于 `visual_preferences`，模型应结合地图、相机参数和可用观察自主选择尽量满足偏好的位姿。有到达后的当前 RGB 时，可在 `check_goal` 中提供 `preference_result` 和 `preference_evidence`，记录全部、部分、未满足或未知的视觉判断。若不提供判断，完成记录标记偏好未核实；偏好不使已证明的几何条件变成全都必须可见的硬要求。记录部分可见或未核实也不能声称全部目标可见，更不能证明已找到全局最优视角。

#### 实机保持与退出

保存 bag 的原驾驶、runtime 影子状态及图像中接近目标，都不能证明 Agent 导航到达。实机接口使用 `goal_observation` 关联目标身份与定位估计的到达、朝向和停止条件，并要求条件持续。条件成立后，运行时核对当前目标、地图和使能状态，将目标转入零速保持；在新的定位反馈中确认停稳后，才允许检查子任务和提交下一目标。保持期间保留人工使能状态，但不保留可执行目标；人工取消和接管仍会退出使能，整个任务结束时也会取消保持并退出使能。完成依据仍是定位估计，不冒充独立硬件验收；`finish_task(succeeded)` 要求全部登记要求通过检查。该流程通过合成反馈检查，尚未完成实机多任务验收。

模型请求异步执行，用户的暂停和取消不必等待模型返回。人工到达检查正在等待新鲜反馈时，循环会在本次短时检查结束后处理输入。回答澄清保留原任务，明确替换才更换要求；恢复后由模型决定下一步，不自动重发旧目标。循环退出时请求撤销活动调用并短时等待，不能确认时保存停止未确认。

## 观察与导航适配

### 运行模式

| 后端 | 反馈和空间信息范围 |
|---|---|
| [SimulationNavigation](../../decision/agent/adapters/simulation.py) | 使用项目参考规划、DWA、独立安全和差速积分。全局概览与附近放大图来自已知合成静态地图，候选检查另用当前仿真局部占据，没有真实 RGB 渲染。 |
| [SavedShadowNavigation](../../decision/agent/adapters/shadow.py) | 读取保存的观察、原场景和登记静态地图，只提交目标建议。bag 驾驶不响应 Agent。 |
| [RuntimeShadowNavigation](../../decision/agent/adapters/shadow.py) | 通过私有 Unix socket 查询状态、按需读取 RGB 和有限的局部占据图、提交影子目标和取消，无底盘输出。 |
| [ManualNavigation](../../decision/agent/adapters/manual.py) | 只读连接不带底盘输出的在线观察会话；目标交由操作者驾驶，按当前定位和停稳估计自动检查到达，也可接受人工确认作为备用，不产生控制命令。工作流另行申请短时参考路径预览，不进入底盘或安全控制命令链。 |
| `RuntimeLiveNavigation` | 显式开启后向人工使能的实机运行时提交单个地图目标或跟随意图，使用定位估计和底盘状态推进子任务；不提供使能、安全管理或实机路线执行工具。 |

### 观察与人工路线预览

[Observation](../../decision/agent/tools/observations.py)保留源场景、RGB 摘要、测量时间和位姿，RGB 不能来自观察之后。跟踪缺失时人数保持未知。runtime 显式启用 `--agent-observations` 时，在后台复制并编码限频 RGB 及已封存场景的占据层，不等待模型，也不传整套 GPU 地图；该选项本身不加载 YOLO。额外启用 `--agent-follow-candidates` 后，活动跟随任务的 T2 工作器在后台检测人物并关联同源三维轨迹，相关操作见[运行手册](../系统运行手册.md#可选图像与决策输入)。当前为保持同帧对应，启用 Agent 观察会停用环境图异步工作线程；新增检测也会占用 GPU，现场性能尚需验证。

人工工作流通过独立的短期租约请求参考路径预览。该通道仅接受在线且未启用硬件输出的观察会话；进程失联后租约过期。runtime 复用当前参考路径工作器显示结果，但控制器和独立安全仍收到原本的空目标，停稳估计继续独立发布。已有普通观察目标时，普通目标优先，人工预览显示为等待。单点参考路径预览已有现场人工驾驶记录；预览不证明路线安全或自动执行能力，多点路线预览仍需现场验证。

### 人物选择、跟随与找回

Agent 通过 `start_local_task` 以 `task_type=follow` 提交任务身份及人物描述。运行时持续调用 T2 选择和复核目标，并对选中的三维轨迹检查来源、时间和连续性；未能确认目标时转入有限范围搜索。Agent 监测运行状态和任务完成条件，不直接替代规划或独立安全层。具体时限和搜索限制见 [T2 实现](技术实现-VLM局部决策.md#t2持续跟随决策)。接收任务不代表已经跟随或实机完成。

### 起点与语义地图标注

`Catalog.bind_start()` 为本次任务创建目录副本，把有效测量起点保存为 `mission_start`，不写回共享资产。缺有效起点时不补零。合成返程测试的预设朝向与测得初始朝向分别记录。

[simulation.json](../../decision/agent/configs/simulation.json)提供合成点、区域和对象；[floor1.json](../../decision/agent/configs/floor1.json)引用真实一楼开发资产，缺资产时仅保留无坐标模板。原 R1、R2 草图继续禁用，没有将它们转换为新格式的有效区域。真实区域任务需提供与当前地图对应的人工区域及对象标注。

[地图标注器](../../decision/agent/map_annotation.py)读取静态环境地图，人工添加点和区域，另存语义目录。点也可以仅描述物体，不代表导航目标；用户要求到点时，目标位置才按车体 `base_link` 检查。目录记录静态地图快照和对应定位地图身份；地图修改或身份不符时不能沿用旧对应关系。点的朝向可以省略，目录中的参考朝向不会自动成为用户硬约束。标注和车体轮廓预览不证明当前位置可通行，操作见[系统运行手册](../系统运行手册.md#地图准备)。

## 记忆、记录与扩展

### 对话与澄清

[Conversation](../../decision/agent/core/conversation.py)按完整交互组维护消息，助手调用与工具结果一起保留或裁剪，不产生缺失配对的工具消息。默认保留最多 32 组，或序列化后的历史不超过 48000 字节；超过任一限制时移除最旧组，至少保留最新一组。通知也计入组数。原指令和初始目录始终保留，要求和当前进度另从本地任务记录生成，不依赖旧对话摘要。当前采用有界裁剪，不额外请求模型总结历史；替换任务建立新对话，旧事件仍留在数据库，不自动恢复旧任务。历史限制与单次请求的输入估算限制分别生效，历史变长会增加请求输入量。

已接受的澄清独立于这段历史保留，不再只取最后八条。澄清上下文最多 16,384 个 UTF-8 字节，超限的新回答明确拒绝，原有约束和待回答状态保持不变，用户可用简洁完整的新指令替换任务；不静默截掉早期硬条件。

### 历史选择与视觉关键帧

[EvidenceMemory](../../decision/agent/core/memory.py)记录带源观察的历史工具选择，按地点和源时间检索。模型输入将它明确标为 `recent_model_tool_choices`，不是长期环境知识，不自动认证地标事实，也不证明当前通行或已经到达。定位或地图关系变化后保留历史，撤销空间有效性。`--no-memory` 只关闭该组件，保留正常对话、任务要求和执行依据。

[Keyframes](../../decision/agent/core/keyframes.py)提供模型主动管理的视觉记忆。每个任务修订最多保存 24 个观察，重复保存同一观察复用原记录。模型须给出本轮已经读过的 `observation_id` 和保存原因；不能通过任意文件路径保存，也不能保存未来或已经失效的当前观察。保存及重读后，原 RGB 通过对应历史消息附带在后续请求中，默认最多两张，普通历史仍按完整交互轮裁剪。裁剪只移除上下文中的图片引用，已保存记录仍可按 ID 重读。替换任务后，旧修订的关键帧不能作为新任务工具输入。

关键帧保存在同一会话 SQLite 中，内容、观察和测量时间保持原值。它们只证明过去看到了什么，不能替代当前 RGB、有效定位、当前通行检查或真实到达反馈。`--no-memory` 不移除这些显式视觉工具。

### 会话存储与预算

[Store](../../decision/agent/core/store.py)把会话状态、原生消息轮、工具事件、要求、完成依据和原始请求响应保存在一个 `session.sqlite`。对话裁剪不删除原事件。地图元数据记录在事件中，实际输入 PNG 存入同一数据库的 `map_images` 表，便于复核输入。`Budget` 使用跨会话共享账本，发送前记录预计费用并按返回用量更新；结果不明时保留估算。共享账本不设置费用上限，旧的 `configs/agent_budget.local.json` 不再控制调用，也不会删除既有记录。计费金额按配置费率估算，不是服务商账单。进程重启后只能只读查看，不自动续跑。

### 扩展位置

新增模型工具时，在 `framework.py` 声明参数并在 `AgentSession` 增加处理方法。新的导航反馈来源放在 `adapters/`，沿用调用身份、测量时间和停止检查。简单图、无图、主动移动观察及局部技能的后续接口由工具和适配器增加，不另建模型调度层；当前 Agent 不提供任意 Shell、底盘速度、人工使能或解除安全保护的工具。

跨模块字段见[接口约定](../接口约定.md#外层agent开发接口)，当前测试与现场限制见[后续开发测试汇总](../后续开发测试汇总.md)及[系统实机问题](../系统实机问题.md)。
