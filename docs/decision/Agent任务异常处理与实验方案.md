# Agent 任务异常处理与实验方案

轮椅执行长程任务时，局部模块先处理短时遮挡、临时障碍和小幅位姿调整。异常持续且局部策略无法继续时，由任务监控唤醒 Agent。Agent 结合原指令、当前任务和新观察，决定继续等待、重选位姿或路线、执行用户指定的预案，或者停稳后询问。终点占据、路段受阻和到达后视野不足已接入同一子任务的恢复流程。下列实验说明如何检验模型在现场作出的选择。

现有 Agent 已能接收导航状态和监控事件，使用到达后的 RGB 复核视觉条件，并在证据不足时重选位姿。T2 已有局部等待、受限搜索和原身份确认。T3 已有同桌候选更新，以及桌沿失效等情况下的停止与交接。当前实机自动接口支持单目标，有序多点由仿真或人工驾驶验证。详见 [Agent 长程导航](技术实现-Agent长程导航.md)、[T2 行人跟随](技术实现-T2行人跟随.md)和 [T3 桌边停靠](技术实现-T3桌边停靠.md)。

## 交接与执行权限

保留两套 Prompt。初始规划沿用任务登记 Prompt，保留用户指定的地点、桌子、人物、路线、视觉条件和预案，区分硬性要求、偏好及允许的替代方案。Agent 在统一执行 Prompt 下使用这份任务单，结合监控反馈决定如何恢复。程序核对动作权限、证据来源、实测位姿和停稳等条件，Agent 根据原指令及有效证据判断任务是否完成。用户许可不清楚且恢复会改变任务要求时，停稳后询问。

复用任务监控的状态变化、无测量进展、停稳和超时事件。局部阶段报告尝试过的动作、剩余能力和终止原因。导航提供能区分终点占据与通路受阻的反馈。无测量进展触发状态复核，单帧缺失和短时异常由局部继续观察。根据连续有效观察、局部尝试及其预算判断是否唤醒 Agent 处理。定位失效、通信状态不明或独立安全禁止运动时，按现有保护等待、撤销或交给操作者。持续条件和尝试预算随任务及验证配置确定，重复事件不重置预算。

异常与原任务版本、子任务、活动调用、定位地图和源观察对应。Agent 在受阻得到确认时可以决定撤销原目标。模型答复前若规划器正在等待下一次观测，同一目标的撤销决定仍可生效。若期间已有明确的通路恢复反馈，或操作者已暂停任务，该回复会被丢弃。

原目标撤销并取得对应的停稳测量后，Agent 才能提交替代动作。多点路线的当前路段已确认受阻时，后台重新计算参考路径期间仍保留这次受阻的路段、位置（若已知）和原始观测时间。撤销前如果规划器明确报告通路已恢复，或当前路段、地图关联已改变，就不能沿用这份记录。改道时仍须根据当前地图检查新路线的途经点。对于允许附近另停的单点任务，若撤销时只有历史占据记录，还需用当前地图重新确认原停车点被占，并检查新位置是否在用户许可范围内。控制与独立安全继续决定能否运动。达到预算、没有合规候选或无法确认状态时，系统保留当前要求和原因，等待用户处理或明确结束。

T2 和 T3 的替代动作需要补齐执行权限。仅在对应局部阶段完成交接后，允许按已登记的范围或预案提交恢复位姿，并将结果记回原子任务。局部仍在处理时沿用现有调度。恢复导航到达后，按该阶段的证据判断是否完成。

## 场景与完成条件

| 异常与交接条件 | Agent 恢复动作 | 完成条件 |
| --- | --- | --- |
| T3 在桌沿已确认、服务正常的连续新观察中持续无合适候选，或候选均未通过接近检查。局部结束选点并停稳。桌沿证据不足和服务故障沿用各自的停止或交接原因。 | 在当前证据中确认仍是同一张桌子，选择附近朝向合适、能安全到达且不挡通道的位姿。优先考虑符合桌边关系的候选。普通停车须有明确许可。 | 桌边停靠须有有效的桌沿关系、到达、朝向及停稳证据。普通停车按预案单独记录为替代结果。 |
| 导航终点持续被人或物体占据，当前地图和足迹检查支持终点不可用。 | 指令允许时，在原区域或参考对象附近换点，保留距离、朝向和视觉等适用条件。确切点位不可更改时等待或询问。 | 以新目标的实际到达和停稳核对原要求中的允许范围及其余条件，保留原点和换点原因。 |
| 终点仍符合占据检查，但通往终点的路线持续受阻，本地规划未能恢复。 | 保持原终点，选择指令允许的另一条通路，并保留指定经过点、区域限制和顺序。只有当前执行模式支持所需路线时才提交。 | 取得原终点的到达和停稳证据。若有经过顺序或禁行要求，结合实际轨迹复核。 |
| T2 在现有局部等待、搜索或最后观测位置策略结束后仍未确认目标，且已停稳。 | 有明确预案时直接去指定地点。没有预案时，用人物最后确认的位置、证据支持的离开方向和候选相机视野选一次安全、可达的观测位姿。到达停稳后用新观察和原人物参考确认身份，确认后继续跟随。仍看不到或身份不清时停稳询问。 | 预案按其指定地点和停稳等条件验证，记录跟随中断。恢复跟随须取得原人物身份的新确认，随后按原跟随任务的结束条件完成。 |
| 已到达并停稳，后续有效 RGB 显示目标被遮挡或当前视角不足。 | 先判断原位转向能否改善视角。转向不足且指令允许移动时，在本阶段最多调整两次位置或朝向。画面不足以判断时等新观察。 | 使用最后一次调整并停稳后采集的有效 RGB 核实指定内容，同时复核位置与朝向要求。单纯到达只完成运动部分。 |

## 有图人工驾驶的三个实验

1. **停靠点被占据。** 可下达“到停靠点1停车。如果停靠点1被占了，可以在它周围1米内另选位置停车”。在原点放置固定障碍，依次核对原点足迹报告占据、原目标撤销、该次停稳测量和新目标被接受这四项事件。再核对新目标距原点的距离，以及轮椅最后实际停在哪里。`check_candidate` 只检查候选。出现 `navigate` 且结果为 `accepted` 才表示导航已接受新目标。另用“只停在停靠点1”核对模型是否保留原点。现场相机中能看到障碍而规划尚无有效占据反馈时，应记录这种差异。
2. **门关闭后改道。** 下达“经过门1或门2，到中转等候区内停下”。Agent 登记一个有序多点子任务，自选一扇门和等候区内的停车位置。确认首条路线已被接受后，让所选门的通路受阻，保持另一扇门可通行。在人工驾驶界面核对受阻路段、撤销反馈和新的停稳测量，再检查 Agent 是否提交了经另一扇门的路线，以及停车坐标是否与首条路线一致。用新旧路线各自的实测经过记录、最终停稳和现场经过的门核对结果。预览按段更新，尚未规划的路段仍需沿途检查。
3. **电梯口视野不足。** 可下达“到电梯口附近，找个位置，让相机同时看到四个电梯口”。在第一个实际停稳的位置记录画面及可见门数。若距离过近，只能看到部分门口，检查 Agent 是否记录了缺失内容，随后换了朝向或观察位置。每次调整都采集新的停稳后 RGB，以同一张最终画面核对四个门口。若改为“尽量看到”，可按实际可见数量报告部分满足。

三类场景均已有人工驾驶演示，过程和结果见 [11 月 22 日现场记录](../系统实机问题.md#11-月-22-日-agent-人工驾驶演示)。后续按上述条件复测，记录模型选择、定位估计的经过和停稳，以及实拍画面。

离线测试覆盖了工具调用、受阻反馈、撤销后停稳、路线更换和视觉复核。CPU 仿真还可在已接收路线的途中增加合成障碍，再检查替代路线的实际首段。自动实机接口目前只支持单点，撤销活动目标会退出使能。自动执行的异常恢复需另行验证。T2、T3 在局部阶段交接后的 Agent 恢复动作仍列为后续开发和验证。

## 实验安排

基本对照覆盖每类异常的正常执行、短时异常自行消失和持续异常。持续异常既有可行的恢复方案，也有无安全候选或证据不足的对照。视觉场景分别布置固定物体遮挡，以及无物体遮挡但初选位姿使目标处于视野外的情况。另检查定位失效、迟到反馈和相似行人出现时是否错误换点、启动运动、认错人或提前完成。比较现有局部策略及任务处理、采用同一交接条件的固定规则策略，以及使用统一执行 Prompt 的 Agent。规则基线可读相同的结构化硬约束和显式预案，使用相同的安全检查。例如终点受阻时在允许范围内选最近合规位姿，路径受阻时保留终点并选可用通路。

### 进阶实验：同一现场，只改变用户指令

每对指令使用相同起点、地图、障碍布置、目标或人物、异常触发前的观察及可行候选。先由评测者为两条指令分别列出可接受的动作和完成证据，可以接受多个位姿或路线。下表的预期动作仅供评测者判分。涉及运动后的观察时，按同一布置分别运行并记录各自实际看到的内容。

| 同一现场 | 指令 A 与预期动作 | 指令 B 与预期动作 |
| --- | --- | --- |
| 同一张桌子的所有可用桌边均无法贴靠，附近有朝向合适且不挡通道的停车位。 | “在这张桌边停一下，贴不上就面向这张桌子停在附近。”选择合规的普通停车位。 | “我要贴着这张桌子用餐，必须能靠到桌边。”停稳等待或报告贴桌条件无法满足。 |
| 门厅指定标记受阻，同一区域有空闲位姿。 | “停到门厅标记，附近也可以。”在满足要求的附近位置停稳。 | “只停在门厅标记，到不了就等。”保持原目标要求并等待。 |
| 通往接待台的主通道堵塞，侧廊可达。 | “去接待台，主通道堵了就走侧廊。”改走侧廊，保持接待台终点。 | “去接待台，只能走主通道。”等待或报告主通道受阻。 |
| 行人转弯后失去目标，指定等候点和一个观测位姿均可达。 | “跟着领队，跟丢就直接去大厅等候点。”结束局部跟随后去等候点。 | “跟着领队。”局部搜索结束后尝试一次观测位姿，以原参考确认领队。 |
| 到标记后展示牌被柱子挡住，原地转向仍不可见，侧移后可见。 | “到标记附近，看清展示牌，可以换个位置。”移到合规视角并用新 RGB 核实。 | “到标记后留在原位，看清展示牌。”保持位置，等待新观察或报告遮挡。 |

### 数据、指标与验证顺序

各策略共用可用观察、地图、执行接口、车体配置、异常判据和时间及动作预算。比较恢复策略时共用经复核的任务单。端到端实验从原指令开始，另记登记是否遗漏约束或预案。记录从持续异常成立到首次合规动作的用时、恢复成功率、额外路程和恢复尝试次数。成对实验报告两条指令均响应正确的对数占比。正常和短时异常分别报告误介入率，即无需恢复却取消、改动执行方案或询问用户的试验占比。另记等待、询问、任务未完成、违反指令、错认身份、错误完成和模型调用次数及耗时。按事先规定的停稳、等待或报告行为核对无法恢复的案例，安全退出与完成任务分别计数。人工复核可见性、人物身份、位姿及指令符合性，保留判定依据。

先用固定输入、带时间的事件记录或 bag 回放核对因果顺序、交接、权限和工具选择。回放只使用当时已有的输入，原驾驶轨迹的后续画面仅用于复核该轨迹，不能当作替代动作取得的新观察。再选择少量现场案例，在人工驾驶下按 Agent 建议执行并记录实际位姿、停稳和新视角，确认建议的适用性。自动闭环另用仿真及已明确授权的实机范围验证，从真实执行接口收集对应反馈，多点自动实机试验以接口接通为前提。分开汇总回放决策、人工驾驶和自动执行的结果。
