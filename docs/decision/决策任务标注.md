# T1、T2 决策任务标注

这个程序读取已有感知结果和 rosbag，用于标注行人的社会群组关系，以及跟随任务中的目标身份。它不在标注时运行三维检测或 VLM，服务、数据和缓存也与行人 XY 中心标注器分开。

统一入口为 `python -m decision.vlm.annotation`，代码位于 `decision/vlm/annotation/`。通常先在 Linux 准备工程，再本机打开，或由 Linux 提供数据、Windows 在本地绘图和编辑。

## 能力与边界

| 内容 | 当前支持 |
|---|---|
| T1 群组 | 同行、交谈、拍照、其他共同活动，以及活动未知、归属未知和确认未成组。 |
| T2 身份 | 描述、隐藏人工身份、轨迹片段关联、可见性、合理候选、感知覆盖和连续性证据。 |
| 使用方式 | Linux 本机，或 Linux HTTP 服务配合 Windows Qt 客户端。 |
| 可视化 | 三帧 RGB 与点云 BEV、朝向框、补偿自车运动的历史轨迹、实际模型输入审核和深色三维点云。 |
| 导出 | 已审核 T1 响应和 T2 固定事实，可显式附带不含答案的模型输入图。 |
| 尚未提供 | 排队和 T3 编辑页，以及依据真实模型历史审核 T2 完整五状态。模型调用使用独立任务入口。 |

T2 固定事实不是完整五状态金标准。`occluded`需要此前真实确认及保持依据，`lost`和 `not_found`也依赖该方法的实际确认历史，不能根据人工看过完整录像就自动填写。在线接入和端到端评测还需开发。

T1 导出保留活动未知、归属未知和角色等信息，响应仍用 `g/u`结构。[实机 VLM 紧凑群组响应](VLM部署与调用.md#实机t1群组输入)是另一种实验接口。用紧凑响应评分时，必须明确哪些标签可转换、哪些是未知或覆盖失败，不能直接把富信息导出当作答案。

本工具读取逐扫描 `people.jsonl`和原 bag，不把 `scene/scenes.jsonl`当作人物结果。新增局部几何、静态先验和 `perception_scene`由[环境场景适配](../../decision/vlm/environment_inputs.py)独立使用，暂不替换本工具的 REL 三帧输入或旧人工标签。runtime 保存的 `decision_inputs/`是无答案模型窗口，不是标注工程，见[VLM 手册](VLM部署与调用.md#直接运行时的三帧输入与响应接纳)。

## Linux准备与启动

### 选择环境和感知结果

HTTP 服务和本机界面都用项目开发 Conda 环境。依赖已安装时直接使用；新机器缺依赖时再安装，普通 Python 包优先中国镜像：

```bash
conda activate social-nav
python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
  -r decision/vlm/annotation/requirements-service.txt \
  -r decision/vlm/annotation/requirements-client.txt
```

新 bag 推荐通过[感知导航直接运行时](../感知导航运行手册.md#日常运行与回看)生成定位和三维检测跟踪结果。runtime 默认不加载 YOLO；需要二维记录时，显式启用对应图像支路。之后用 `prepare --results ...`导入已有结果，多次运行也可合并，不必重复推理。旧 ROS 联合准备入口保留作专项诊断。

`prepare`导入人物、位姿和 bag 时间索引。所有来源都已有二维记录时，还会导入并登记关联缓存，不运行模型或逐帧解码图像。查看某帧时才从原 bag 读取 RGB 和点云，Linux 保留 bag 句柄、有限缓存，并预读邻近帧。

bag 访问由独立系统 ROS 解释器子进程完成，HTTP 和 Qt 不导入 ROS 原生扩展。默认 ROS 位置为 `/opt/ros/noetic`；可用 `--ros-python`指定解释器，并将选择保存进工程。

准备必须提供已有 `people.jsonl`，不会运行三维检测、跟踪或 VLM。只有旧来源没有二维记录且显式加 `--with-rgb-associations`，或明确选择 `--recompute-rgb`时，才加载 YOLO。

检测权重和总输入帧数统一来自[感知推理配置](../../perception/detection_tracking/configs/inference.json)及[部署模型配置](../../perception/detection_tracking/configs/detector.yaml)，标注器不另存模型路径。改配置只影响后续感知，不会更新旧人物结果。需要新模型建议时，先按[运行手册](../感知导航运行手册.md)生成新感知结果，再导入新工程。

### 创建工程

从仓库根目录运行，目标工程必须尚不存在。以下示例合并两个固定安装后的旧联合回放结果；它们仍保留原检测来源，不因默认模型变化而更新：

```bash
python -B -m decision.vlm.annotation prepare \
  --results outputs/perception/wheelchair_20261020/environment_integration/localization1 \
            outputs/perception/wheelchair_20261020/environment_integration/localization2 \
  --root-group wheelchair_20261020 \
  --output data/annotations/vlm_decision/wheelchair_20261020
```

多个 `--results`合为一个工程。没有二维记录的旧来源可加 `--with-rgb-associations`运行一次 YOLO；`--rgb-output`选择新缓存目录，省略时用工程内 `rgb_association/`，推理设备由 `--image-device`选择。

有、无二维记录混合时，程序不会悄悄补跑。应拆开准备，或用 `--with-rgb-associations --recompute-rgb`明确重算。准备在 Linux 完成，只有实际推理才需要模型依赖。

### 原数据、时间和标定怎样选择

原 bag 默认从各结果目录的 `run.json`定位。在线结果或迁移后的路径，可以按 `--results`顺序用 `--bag`提供原文件；在线感知如果没有同步保留 bag，仅凭人物 JSONL 无法还原 RGB 和点云。

`--start`和 `--duration`限制准备片段，单位是相对各 bag 首帧点云的秒数。模型窗口需要前 1 秒历史，因此片段最前面的样本可能历史不足。

已有二维记录时，使用运行时封存的相机外参、RGB 和内参配对；显式提供的外参必须与原记录一致。没有二维记录时，先用运行时封存外参，否则用 `--calibration`或仓库当前外参。旧安装必须提供当时参数，不能把新矩阵套给旧 bag，既有工程也不会自动换标定。

图像时间同样保留来源。已有记录按实际配对 RGB 读取，不改用邻帧；缺原图时会报错。旧来源默认选扫描之前 100 ms 内的图像，可用 `--max-rgb-age`明确调整，但仍不取未来图，且只影响新工程。

导入保留实际检测历史帧数、扫描指纹、补偿变换，以及人物和定位各自的会话与重置代次。新三帧窗口不跨定位或跟踪重置；定位失效时不生成完整历史。只要局部历史连续，离开地图先验再返回本身不会切断它。原记录缺少模型身份时保持缺失，不拿当前权重路径补写。

### 工程保存了什么

原 bag、感知结果和旧人工中心标签只读。`observations.sqlite`保存来源、结果和时间索引，不保存全量图像或点云；`annotations.sqlite`保存人工工作，运行时另有 SQLite 附属文件。

旧感知记录保留在 `data/datasets/wheelchair_perception/wheelchair_20261016/`。已有工程导入人物和位姿后，不再依赖原输出目录持续存在；来源摘要和人工标签不需重建。但原 bag 仍须在 Linux 可访问，轻量工程不是复制了全部数据的离线包。

完成的旧全量缓存工程仍可直接打开，无需转换。中断的未完成工程不会自动覆盖，须先确认没有人工结果，再单独处理。首次打开子包可能要加载索引和启动 ROS 子进程，首次跳到未缓存位置也要读包；缓存命中后直接浏览。

### 打开或启动远程服务

本机打开：

```bash
python -B -m decision.vlm.annotation open \
  --project data/annotations/vlm_decision/wheelchair_20261020
```

远程服务默认只读。需要标注时显式加 `--write`，绑定 Linux 当前 Tailscale 地址，使用独立端口 8766：

```bash
python -B -m decision.vlm.annotation serve \
  --project data/annotations/vlm_decision/wheelchair_20261020 \
  --project-id wheelchair-vlm \
  --host "$(tailscale ip -4)" --port 8766 --write
```

服务不需要访问令牌，只允许访问启动时登记的工程，不接受客户端提交任意服务器路径。不要与检测标注器的 8765 端口混用。

### RGB框来源

二维框与三维轨迹的对应结果称为“RGB 关联”。带二维记录的旧 ROS 联合诊断，或导入这类记录的 `prepare`，会把默认关联来源记入工程。默认直接 runtime 不生成这份缓存，需要显式准备；对已有工程可运行 `prepare-rgb`，完成后登记来源。

Linux 的 `open`、`serve`和 `export`都读取工程登记来源，Windows 启动方式不变。来源仍待准备、缓存缺失或未完成、输入对应关系改变时会明确报错，不退回投影框。没有登记关联来源的工程仍保持原投影模式。

已有工程可单独准备或恢复二维阶段，不必重新定位或三维推理：

```bash
python -B -m decision.vlm.annotation prepare-rgb \
  --project data/annotations/vlm_decision/SESSION
# 默认恢复工程登记的目录；未登记时使用工程内rgb_association/。
# 已记录来源只导入数据，不用GPU；需要明确重算时加 --recompute --output 新目录。
# 没有记录的旧工程仍会推理，--device 选择可见GPU；恢复时保持原配置与设备。
```

程序先复用完整兼容缓存；有保存的二维记录时只做 CPU 导入。只有旧来源没有缓存或记录时才运行 YOLO。

也可以先按[感知运行手册](../archive/感知导航ROS诊断命令.md#rgb人物检测与三维关联)生成完整缓存，再一次登记到原工程。下面这一步只检查来源和覆盖范围，不运行 YOLO：

```bash
python -B -m decision.vlm.annotation prepare-rgb \
  --project data/annotations/vlm_decision/SESSION \
  --output outputs/perception/SESSION/rgb_association
```

`open`、`serve`和 `export`不提供临时来源覆盖参数。切换来源后，重启服务或本机窗口，客户端会按新身份重新读取快照和图片，不需要删除人工草稿或重做观察工程。YOLO 和 TensorRT 只安装在 Linux 项目环境，浏览与切帧不运行检测。

只有可靠匹配到已有三维轨迹的 YOLO 框，才进入 RGB、点击区域和模型图。未匹配的 YOLO 人物不显示，也不生成参考或 PID。没有 RGB 匹配的三维目标，仍按原状态显示在 BEV、三维图和列表中，列表注明“无 RGB 匹配”。

启用关联后，处理失败不会退回投影框。“缓存缺失”“来源不符”和“已处理但无匹配”分别报告。runtime 没处理的观察保留 `not_processed`和空 RGB 框，不补造或自动推理，正常三维目标仍保留。人工补框规则不变。

新框会改变模型图、像素高度和输入摘要。事件、身份与标签仍保留，但旧已标样本必须重新进入输入审核，正式导出会拒绝过期输入。导出使用与审核相同的登记来源，并记录关联身份；准备阶段只更新来源元信息，不改写原始观察行或人工标签。

## Windows客户端

先在 Linux 生成便携包，再传到 Windows 解压。输出文件必须尚不存在：

```bash
python -B -m decision.vlm.annotation package-client \
  --output outputs/decision/annotation_client/client.zip
```

已有 PyQt5、NumPy、Pillow 和 HTTPX 环境时直接运行。新环境可按下面创建：

```powershell
conda create -n social-nav-vlm-annotator python=3.11 pip
conda activate social-nav-vlm-annotator
python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r decision/vlm/annotation/requirements-client.txt
```

在解压目录运行，将 `LINUX_TAILSCALE_IP`替换为 Linux 当前地址：

```powershell
python -B -m decision.vlm.annotation open --server http://LINUX_TAILSCALE_IP:8766 --project-id wheelchair-vlm
```

`--read-only`用于只读浏览，`--cache-dir`可指定客户端缓存。Windows 不需要 ROS、Torch 或 CUDA，默认缓存位于 `%LOCALAPPDATA%/SocialNav/vlm_annotation/`，与检测标注器分开。

## 事件与样本

### 先确定标注范围，再建立样本

事件是一段原始观察的时间范围，只引用已有数据，不切割或复制 bag。所有创建和编辑都在时间条上方的页内面板完成，不再使用事件弹窗。

| 操作 | 方法 |
|---|---|
| 直接选片段 | 沿时间条左右拖动，松开后查看终点。反向拖动也可选区，边界吸附到可用帧。 |
| 边看边定范围 | 用 `I`取当前帧为起点，浏览后用 `O`取终点，也可先点击“新建事件”。 |
| 覆盖整包 | 在“新建事件”右侧箭头选择“整包创建／选择”。已有整包事件时直接选中。 |
| 修改事件 | 点击“编辑事件”或双击事件条，再拖动两侧把手或输入秒数。 |
| 删除事件 | 选中后进入“编辑事件”，点击“删除事件…”，确认后删除该事件及所属标注。 |

橙色选区是临时草稿，按 `Enter`或点击创建、保存后才写入。`Esc`取消选区；切包或切换事件也会取消未保存选区，不修改旧事件。名称可留空自动生成，起止时间、名称和用途均可改。来源字段折叠在“来源…”中，优先沿用当前事件或同子包已有事件的信息。

默认可以浏览整包。事件外显示“仅浏览”，不能写标注；勾选“仅浏览当前事件”才限制 WASD 和时间条。创建选区时暂时放开限制，取消后恢复。选择事件只改变标注归属，点击事件条还可以跳到对应时刻；下拉框中的“整包浏览（未选事件）”用于退出事件选择。

修改范围不能排除已有标注、辅助人物或 T2 描述参考帧。失败时保留旧事件和临时选区，不自动删除内容。用途可以设为开发、验证或留出；相同采集来源和重复地点不能跨划分，没有独立留出数据时只能作开发集。

删除确认会显示范围和 T1、T2 样本数，默认取消。确认后会删除事件所属样本、人物关联及辅助标注，不能用 `Ctrl+Z`撤销；原 bag、感知结果和其他事件保留。界面返回整包浏览，若删除期间已选择其他事件，则保留新选择。既有导出不会随之更新，需要另行导出。

远程断网时，删除只在本机暂存，重连同步成功后才算服务器已删除。修订冲突会保留待处理操作，不强行覆盖。

### 样本状态与审核

普通浏览、选区和创建事件都不会生成样本。点击“加入样本”、实际编辑标签，或明确执行“区间取样”时，才建立待标样本。取样默认间隔为 2 秒，改间隔不会移动已有样本。批量建立待标记录不解码全部图像，实际编辑或审核时才检查该样本的输入。

时间条上方是事件条。重叠时优先选中较短事件，也可以在下拉框明确选择。下方分为 T1、T2 两条轨道：黄三角表示待标，灰方块表示跳过，绿圆点表示已标。普通点击只浏览，Shift 点击可建立单点临时选区。

日常浏览使用轻量预览，不生成完整无损模型输入。上下文编辑先保存为待标草稿；切换“输入审核”后，程序读取实际模型窗口并记录审核所对应的输入，之后才能标为已标。

标为已标要求完整历史和 RGB。首次编辑、待标和跳过不必先进入审核。旧已标样本仅浏览时保持原状态，不会因预览尚未验证而提示输入改变；实际修改后才回到待标。绿色已标只表示审核状态，不表示远程同步已经完成。

## 模型图像与输入审核

### 浏览画面与模型实际看到的图

默认“三帧放大”横排显示三个时刻，每列上方是 RGB，下方是 BEV，右侧是可滚动的 T1、T2 编辑区和人物列表。上下文 RGB 使用轻量 JPEG 预览，构图、PID 和点击坐标与审核及导出图一致；各列 RGB 与 BEV 的分界可拖动。

双击图像或 BEV 会暂停播放，并按需读取原始、不含答案的组合图。输入审核使用实际无损 PNG，不能用 JPEG 预览证明模型输入已经核对。

“输入审核”固定当前决策时刻，只显示因果模型输入。三维点云和原始图编辑页不进入该模式，人工分组颜色和选中叠层关闭；仍可点击当前目标并在右侧列表确认。历史图标明实际时间偏移，缩放、换布局和点云操作不会改写输入图。

布局下拉框还提供“三维＋三帧同屏”和“三维大图”。三维图使用深色背景及明亮高度色带，原始 RGB、BEV 放在上下文标签页；“补 RGB 人物”自动进入当前 RGB 大图。同屏布局中的三帧卡片把 RGB 与 BEV 左右排列。

上下文点云、参考目标和当前分组色由客户端绘制，界面注明“非模型图”。这些浏览裁剪、抽样和编辑叠层不进入模型输入。服务端另从原 bag 读取完整模型扫描，并记录它对应的源观察。

三维预览不合成检测的历史扫描，也不加入 VLM 协议。它使用 Qt 和 NumPy 本地绘图，不新增 OpenGL、ROS 或 CUDA 客户端依赖；旋转、缩放不请求服务器。轻量工程按需提供有限大小的全向扫描，旧全量缓存工程沿用已有点云范围。

### 模型图怎样绘制

模型组合图采用紧凑 RGB 加 BEV 布局，使用统一顶部短标题，去掉 BEV 网格，保留尺度条。PID 标签有对比底色，人物与自车当前位置都用半径 7 像素的等大实心圆点，不画白色描边，以颜色和朝向箭头区分。具体布局由 `decision/vlm/scene_inputs.py`维护，本机样例由环境记录定位。

人物和自车历史使用同宽连续实线，不画采样点或分段端点。线条采用抗锯齿接合，并绘制在点云背景上层。它们表示跟踪估计历史，可能包含预测位置；观测与预测标记仍保留在原数据中。状态切换不会人为打断线条，真实缺口仍会断开。

**当前模型图使用全高度单帧扫描作为背景。** 三个观察分别读取各自时刻的完整原始扫描，检查与感知输入是否对应。只排除非有限 XYZ 和显示 XY 范围外的点，不去地面、不筛高度、不删行人、不抽样，也不跨帧融合。

背景采用较浅的高度颜色，顶部 `LiDAR Z[m]`色条表示雷达坐标系 Z，不是离地高度。色标范围之外的点仍保留，使用端点颜色。窗口保存扫描时间、坐标系、原感知指纹和扫描资产摘要，审核与正式导出共用 `Store.model_image`。

旧物化工程没有完整扫描记录时，必须从原 bag 重新准备，不能静默退回无点云图。已有按需读 bag 工程不需重新 `prepare`。

**模型 BEV 使用固定感知平面范围。** Linux 从当前公共检测配置所指向的 YAML 读取 `DATA_CONFIG.POINT_CLOUD_RANGE`，取 XY 边界作为绘图范围，并记录配置摘要；这不会改变旧检测的来源。

目标和自车历史不会扩大这个范围，超出部分按线段裁掉。当前有效人物的 PID 和数值几何仍保留，不因画面外没有画点就删除身份。XY 用相同米制比例；范围不等宽时留边，不拉伸。上下文视图仍可缩放查看参考目标。

渲染策略或显示范围改变后，实际模型输入也会变化。原始观察、标签和旧冻结图保持原样，旧已标样本须重新审核，程序不自动改写原审核记录。按需读 bag 工程不必重做准备，但更新后要重启 Linux 界面或服务，并同步 Windows 客户端，让缓存按新输入身份取图。

### BEV轨迹

每张 BEV 只使用截止它自身时刻、最多过去 3 秒的行人和自车轨迹。因此，三帧最早可以引用决策时刻之前 4 秒的几何历史。轨迹来自已有感知和位姿记录，界面只另读三个观察时刻的扫描，不累积历史点云。

上下文 BEV 使用深蓝灰背景和弱化网格，配色如下：

| 元素 | 上下文显示 |
|---|---|
| 扫描点云 | 固定高度色带，从低处蓝色经过青、绿、黄到高处红色，并标明范围。 |
| 目标框 | 当前有效 PID 用蓝青色实框；仅历史存在的已确认轨迹用橙色虚框和 `R`编号。 |
| 观测和预测轨迹 | 分别用黄色实线和紫色虚线。 |
| 自车 | 薄荷绿原点、朝向箭头和历史轨迹。 |
| 相机水平视野 | 浅蓝虚线边界及淡色扇区，仅作示意。 |
| 选中目标 | 粉色框、标签及半透明填充。 |
| 已标群组 | 同组使用相同色相，并提高深色背景上的亮度。 |

每幅图使用该时刻有效且连续的局部位姿，把历史世界位置转换到这幅图的雷达坐标系。不能把传感器坐标差当作人物运动，也不读取该帧之后的状态补历史。

图中的“自车”实际是雷达原点及其历史，箭头表示 X 轴，不代表已确认车体外参或轮廓。模型 BEV 中，自车历史是灰色、行人是蓝色，都用实线且不画空心或实心历史采样点；观测与预测状态仍在轨迹记录中。

正常人物是定位有效时，已确认且当前有观测的三维轨迹，不要求相机投影或 YOLO 匹配。相机视野外的人同样有正常 PID，可以在列表、BEV 和三维图中标注。没有 RGB 框时按[来源规则](#rgb框来源)解释原因，不补造框。

未确认轨迹、预测轨迹、没有稳定身份的原始检测，以及人工 RGB 补框仍可作为参考人物，它们是否位于相机视野内不是分类依据。上下文各时刻的框按以下规则显示：

- 当前帧 BEV 只显示已确认且有观测的目标。
- 历史帧中，如果目标有当前有效 PID，就显示同一 PID 的蓝青色实框，即使该轨迹当时未确认或处于预测状态。
- 只在历史帧存在、且当时已经确认的轨迹，用橙色虚框作为参考，保留其观测或预测状态。三帧窗口内使用一致的 `R`编号，不分配当前模型 PID。
- 其他未确认历史轨迹和无稳定身份检测不在上下文 BEV 显示，缺失位置不补框。RGB、三维图和人物列表仍可显示参考人物。

框的线型区分当前目标和历史参考，轨迹线型区分观测和预测，原始状态与模型输入不会因此改变。选中颜色和群组颜色仍用于高亮。没有三维位置的人工 RGB 补框只留在 RGB 和列表中，不生成 BEV 框或轨迹。

上下文框按真实长宽和朝向绘制，三帧采用共同米制范围，范围由显示目标与轨迹确定。点大小同时影响上下文 BEV 和三维预览，BEV 使用更细的点径，设为 `1`时显示最细点。

相机视野示意由工程封存外参和该时刻因果配对的 CameraInfo 计算。程序考虑畸变，把主点行两端射线投影到雷达 XY 平面，不假定相机与雷达重合。它只解释前视 RGB 大致覆盖哪里，不筛选人物，也不表示垂直视野、遮挡或最远可见距离。缺 RGB、有效内参或旧缓存相机资料时，明确标为不可用，不套固定角度。

上下文点云色带也是雷达 Z，不是离地高度。所有帧用固定映射，同一像素按最高点着色，超范围用端点颜色，不按每帧重新缩放。

上下文 ID 使用深色底、浅色字和彩色边框；模型 BEV 仍用深色字和白底。标签在框、轨迹和点云之后绘制，并避让图例与其他标签；移动后的标签用引线指向目标。

模型 BEV 使用完整单帧扫描背景，只绘制当前有效全向 PID 及其历史，不加入参考目标。前视 RGB 只绘制所选来源的有效框。视野外或没有可靠图像框的人物仍提供米制位置和距离，框与像素高度为 `null`。无框不能证明视野外或遮挡，历史轨迹也不能证明当前衣着、视线或拍照动作；证据不足时标未知。

轨迹必须来自稳定、已确认的源轨迹及有效定位。临时检测和未确认轨迹不推断历史；跟踪或定位重置、失效、身份变化、位姿缺失或过期，以及较长观测空隙都会截断轨迹，不跨缺口外推，不补零位姿。三帧几何字段 `v/dt/ts/e/o/d`及响应 Schema 的语义保持不变，来源和渲染身份随输入与导出保存。

上下文预览点云及视野示意不会直接写入模型图。改变有效人物范围，会改变模型 PID、几何字段及输入摘要，需要重审旧已标样本，但不删除原标签。旧缓存有明确确认和观测状态时可生成派生输入并保留源指纹；缺必要字段时不猜状态，需要完整资料时从同源感知建立新工程，不覆盖旧工程。

## T1群组

1. 按住 `Ctrl`点选或在列表多选人物，选择活动，再点“应用群组”。拍照角色明确时，指定摄影者和主要被摄者。
2. 对其余有效 PID，分别标为“确认未成组”或“归属未知”。成员明确、活动不清楚时用组内“活动未知”，不要与归属未知混用。
3. 核对实际输入后标为已标。程序不会自动确认剩余人物，也不会把未处理人物自动改为未知。

列表上方常驻显示当前帧群组和成员，人物行显示 `G1 · 同行`等分类。上下文当前 RGB 框、BEV 框和列表文字使用同组颜色；点击“当前帧群组”可以选中整组。

`G1/G2`只是本帧显示编号，不表示跨帧群组身份。含漏检或无 PID 人物的参考组以 `参考R1`单列。保存、切帧返回、撤销和重做都会刷新显示，不自动把群组传播到下一帧。

同一人不能属于两个正式群组。多活动压缩为主标签时按“拍照＞交谈＞同行＞其他”处理，但距离近、同向、站在一起或拿手机都不足以自动确定关系。排队片段可以跳过并备注“范围外”。

“复制上一已标样本”和“应用到指定区间”只生成待标草稿。人物匹配依据轨迹或已核对关联，不照抄 PID 数字，覆盖区间需要确认。

漏检人物可在上下文中用“补 RGB 人物”画辅助框。列表将这类人物及其他参考人物标为“参考／无模型 PID”，用于身份和覆盖说明。含辅助人物的群组作为覆盖失败参考导出，`semantic_eligible=false`且 `response=null`，不编造 PID 或完整 3D 框，但仍保留供端到端诊断。

## T2身份

T2 区分实际人物和模型窗口内的编号。实际人物由隐藏人工 ID 表示；模型 PID 来自原始因果轨迹，人工事后关联不会修复原输入，也不会由辅助 RGB 框补出几何。

1. 新建实际人物，再从三维图、RGB、BEV 或列表选择轨迹，用“关联／拆分片段”指定身份和时间范围。默认只关联当前帧，扩区间前先人工检查；重叠旧关联会在边界拆分。
2. 建立目标任务，填写初始可见外观描述、目标人物和描述参考时刻。一个事件可有多个目标任务，“另建一个目标任务”会保留原任务。
3. 按观察点填写可见性、合理候选、真实对应、覆盖和连续性证据，按需填写事件标记和备注。T2 不要求先完成 T1。
4. 切换输入审核，判断该窗口能否唯一匹配、是否存在歧义，再标为已标。真实目标可以用完整上下文核实，但“当前是否能匹配”的证据仍以模型当前可见输入为准。

目标始终不在场时选择对应选项，并在独立“描述来源（隐藏）”栏记录合法来源，不把“不在场”等答案写进模型描述。描述不能包含 PID、隐藏真值或未来才出现的细节。

修改人物关联、描述或参考时刻，会使受影响已标内容重新待标。目标漏检时仍可记录真实辅助人物和 `coverage=missed`；目标可见、完全遮挡、视野外和无法判断分别保存。

## 快捷键与保存

| 按键 | 操作 |
|---|---|
| `A / D` | 上一帧或下一原始帧，只浏览。 |
| `W / S` | 按采样间隔前后浏览，步长内优先停靠已有任务样本，不自动创建标签。 |
| `I / O` | 取当前帧为事件选区起点或终点。 |
| `Enter` | 创建或保存页内事件选区。 |
| `1 / 2 / 3` | 标为待标、跳过或已标，不跳帧。 |
| `Q` | 应用群组或设置合理候选。 |
| `R` | 清除 T1 选中人物的分类。 |
| `空格` | 上下文播放或暂停，输入审核不播放未来帧。 |
| `Ctrl+Z / Ctrl+Y` | 撤销或重做标签编辑。 |
| `Esc / F1` | 先取消事件临时选区，否则取消补框与选择；F1 打开帮助。 |

没有事件或样本时，W、S 也能按间隔浏览子包。只有勾选“仅浏览当前事件”，才限制到该范围。

人物列表、标注列表、按钮和数值框上的 WASD 统一用于场景导航，I、O 用于事件取点，不修改控件值；数值可直接输入或用方向键调节。名称等文字框和可编辑下拉框仍保留正常打字，按 `Esc`退出编辑后再导航。普通下拉框展开时，WASD 会先收起它再导航，不改变选项；弹出对话框保留自身按键行为。事件编辑中的 Enter 提交，Esc 取消。

三维点云左拖旋转、右拖平移、滚轮缩放、双击复位。点击人物框与列表联动，`Ctrl`多选，工具栏可调点大小或切俯视。切帧保留视角，切包复位，点大小不影响模型输入。

### 读取与播放

切帧和播放共用观察缓存。停留时，后台准备前后邻近帧及 W、S 实际跳转目标；最近访问帧优先留在内存，预读也为回看保留空间。远程内存画面被回收后，先尝试本地磁盘图片缓存。图片按容量回收，但人工草稿和同步队列保留。

同一窗口内重连时，只要工程、资产和渲染身份不变，就保留内存缓存及当前位置；身份变化才重新取数。关程序后内存释放，磁盘缓存仍可用。

服务合并传输元数据、三帧预览和扫描，同批共享资产只发一次。图像解码和点云底图在后台准备，隐藏视图不重复构建扫描，标签避让按图合并计算。首次打开或跳到未缓存位置仍须取数，不需要重做 `prepare`。失败时界面显示“读取失败”，底部提示具体原因。

Linux 本机模式会用当前 Python 环境自动启动数据工作进程，避免读包和预览计算争用界面解释器，关窗口时一并退出，不需要额外环境或手动服务。远程模式由 Linux 计算，Windows 负责缓存、绘图和交互。

空格播放按原始观察时间顺序显示，开始前短暂缓冲。“连续可播 x/y 帧”表示当前准备程度，不是缓存总量或上限。跟不上时显示“播放缓冲”，不把旧图当新帧，也不跳过原始帧。手动跳转会暂停播放，预读和播放不改变标注状态。流畅程度仍受客户端 CPU 和网络吞吐限制。

当前帧 RGB 框、上下文 BEV 框或 ID 都可选人，`Ctrl`增选或取消，与列表和三维联动。输入审核 BEV 可以点击目标点。历史两帧用于观察，BEV 均可滚轮缩放、拖动平移，“复位视图”恢复范围。RGB 框重叠时优先选较小框，可用 BEV 或列表选择被挡住的人。

### 保存与同步

日常编辑自动保存。远程界面分别显示本机暂存、待同步、服务器已保存和冲突。服务一次只允许一个写入会话，第二个客户端自动只读。断网时可继续浏览已缓存资产，未缓存帧明确报错，不拿旧帧替代。

写入结果不确定时，重连先查询原操作回执，不盲目重复写入。修订冲突会保留草稿并停止覆盖。点击“处理同步冲突”并确认后，当前工作和未同步操作会移入同一缓存内的存档，再读取服务器结果。存档及未同步操作不会随图片缓存淘汰，不要删除整个缓存排查连接问题。

“导出本机草稿”可保存当前工作及待同步、冲突内容。无 GUI 时也可导出：

```powershell
python -B -m decision.vlm.annotation export-drafts --cache-dir YOUR_CACHE_DIR --output drafts.json
```

客户端升级后重启界面，Windows 替换当前代码包。Linux 服务需要支持 `views`合并读取、`context-frames`和 `delete-event`接口，缺接口时更新并重启。原工程不需重新准备，预览缓存有独立身份，不改写模型输入指纹、标签或导出 PNG；客户端草稿和缓存继续保留。

## 导出与后续使用

在 Linux 导出服务器已保存的已标样本，目标必须为新目录：

```bash
python -B -m decision.vlm.annotation export \
  --project data/annotations/vlm_decision/wheelchair_20261020 \
  --output outputs/decision/annotations/wheelchair_20261020
```

默认只生成 `manifest.json`、`t1.jsonl`和 `t2.jsonl`，不复制 bag 或全部截图。显式加 `--include-inputs`才附模型图像；图像和几何不含人工群组颜色、真实人物身份或目标答案。

清单记录实际观察来源、感知结果、标定摘要和已有模型身份，用来区分检测模型与安装条件。旧工程缺少的字段保持缺失，不反向补写当前配置。

未设置来源划分、审核后输入改变，或已标内容违反任务约束时，正式导出会拒绝。导出只读取所选样本，并在读取时检查原始扫描和时间配对；保存一条样本不会反复解码其他未修改样本。

待标、跳过和客户端未同步草稿都不能当作金标准。T2 固定事实与 T1 响应分别使用；合法 JSON、Qt 可运行或 Linux 回环 HTTP 测试，都不能代替真实 Windows 多机验收或完整决策能力成绩。

规则、事务与远程恢复检查见 `tests.test_vlm_annotation`，Qt 异步交互与导航见 `tests.test_vlm_annotation_gui`，运动补偿、因果性和轨迹截断见 `tests.test_vlm_trajectories`。按改动范围运行，不必每次扫描全 bag 或调用 VLM。
