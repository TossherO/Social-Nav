# T1／T2决策任务标注

独立入口为`python -m decision.vlm.annotation`，代码在`decision/vlm/annotation/`。该工具读取已有感知结果和rosbag，标注社会群组及目标身份，服务、数据和缓存均与行人XY中心标注器独立。

## 能力与边界

| 内容 | 当前支持 |
|---|---|
| T1 | 同行、交谈、拍照、其他共同活动、活动未知、归属未知及确认未成组 |
| T2 | 描述、隐藏人物身份、片段关联、可见性、候选、感知覆盖与连续性证据 |
| 使用方式 | Linux本机；Linux HTTP供数＋Windows Qt本地绘制 |
| 可视化 | 同时显示可缩放RGB和米制BEV，历史图、人物列表和状态时间条 |
| 数据导出 | 已审核T1响应、T2固定事实；可显式附带中性模型输入图 |
| 暂缓 | 排队、T3、三维旋转视图、VLM调用与绑定真实历史的T2五状态审核 |

T2导出不是`REL_FOLLOW`五状态金标准。`o`需要真实先前确认和保持依据，`l/n`需要该方法的实际确认历史，不能按人工完整录像自动填写。完整推理接入和端到端评测仍需后续开发。

## Linux准备与启动

HTTP服务和本机客户端使用项目开发Conda环境。依赖已具备时直接使用；新机器按需安装缺失项，普通Python库优先中国镜像：

```bash
conda activate social-nav
python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
  -r decision/vlm/annotation/requirements-service.txt \
  -r decision/vlm/annotation/requirements-client.txt
```

`prepare`只导入已有检测／跟踪／位姿结果，读取bag索引和首帧头信息，建立轻量工程；不逐帧解码、重编码图像或复制点云。原始RGB、点云和匹配CameraInfo在查看对应帧时才读取，Linux保留bag句柄及有界内存缓存，并预读邻近帧。

bag访问在独立系统ROS解释器子进程中完成，HTTP与Qt不导入ROS原生扩展。默认ROS位置为`/opt/ros/noetic`，解释器可用准备命令的`--ros-python`指定并存入工程。准备命令不运行检测、跟踪或模型服务，必须提供已有`people.jsonl`。

从仓库根目录运行，目标工程必须尚不存在：

```bash
python -B -m decision.vlm.annotation prepare \
  --results data/datasets/wheelchair_perception/wheelchair_20261016/odometry/01-floor1 \
            data/datasets/wheelchair_perception/wheelchair_20261016/odometry/02-outdoors \
            data/datasets/wheelchair_perception/wheelchair_20261016/odometry/03-floor1 \
            data/datasets/wheelchair_perception/wheelchair_20261016/odometry/04-floor2 \
  --root-group wheelchair_20261016 \
  --output data/annotations/vlm_decision/wheelchair_20261016
```

- 原bag默认由各结果目录的`run.json`定位；迁移后可按`--results`顺序用`--bag`提供原文件。
- 已作为标注输入保留的旧感知记录使用上述数据目录。既有工程已导入人物与位姿，不依赖原输出目录继续存在，来源摘要及人工标签无需重建。
- `--start`／`--duration`限制准备范围，单位为相对各bag首帧点云的秒数，适合先试用短片段。历史窗口需要前1秒；准备片段最前面的样本可能历史不足。
- 相机外参默认读取仓库当前标定，可用`--calibration`显式指定；内参使用不晚于扫描的CameraInfo。RGB只选扫描前100ms以内的图，不取未来图补齐。
- 原bag、感知结果和旧人工中心标签只读。`observations.sqlite`只保存来源、结果和时间索引，不保存全量图像／点云；`annotations.sqlite`保存人工工作，另有SQLite运行时附属文件。完成的旧全量缓存工程仍可直接打开，无需转换或重做标签。中断的未完成工程不自动覆盖；确认没有人工结果后再单独处理。
- 首次打开某个bag可能需要加载索引和启动ROS子进程，首次跳到未缓存位置也需要读包；缓存命中后直接浏览。原bag仍须在Linux可达，不能将轻量工程当作已复制完整数据的离线包。

本机打开：

```bash
python -B -m decision.vlm.annotation open \
  --project data/annotations/vlm_decision/wheelchair_20261016
```

远程服务默认只读；需要标注时显式加`--write`。绑定当前Tailscale地址，使用独立端口8766：

```bash
python -B -m decision.vlm.annotation serve \
  --project data/annotations/vlm_decision/wheelchair_20261016 \
  --project-id wheelchair-vlm \
  --host "$(tailscale ip -4)" --port 8766 --write
```

服务无需访问令牌。它只允许访问启动时登记的工程，不接受客户端提交任意服务器路径。不要把旧检测标注的8765端口用于本程序。

## Windows客户端

在Linux生成便携客户端，输出文件须不存在，再传到Windows解压：

```bash
python -B -m decision.vlm.annotation package-client \
  --output outputs/decision/annotation_client/client.zip
```

在已具备PyQt5、NumPy、Pillow和HTTPX的Windows标注环境中，可直接运行。新环境参考：

```powershell
conda create -n social-nav-vlm-annotator python=3.11 pip
conda activate social-nav-vlm-annotator
python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r decision/vlm/annotation/requirements-client.txt
```

从解压目录运行，将`LINUX_TAILSCALE_IP`替换为Linux当前Tailscale地址：

```powershell
python -B -m decision.vlm.annotation open --server http://LINUX_TAILSCALE_IP:8766 --project-id wheelchair-vlm
```

可加`--read-only`只读浏览；`--cache-dir`显式选择客户端缓存。Windows不需要ROS、Torch或CUDA，默认缓存位于`%LOCALAPPDATA%/SocialNav/vlm_annotation/`，与旧标注器独立。

## 事件与样本

1. 选择子bag，点击“新建事件”，填写起止秒数。事件只引用原始观察，不切割或复制bag。
2. 在“事件／划分”中设置开发、验证或留出用途。相同原始采集和重复地点不得跨划分；没有独立留出数据时仅作为开发集使用。
3. 普通浏览不创建样本。“加入样本”、实际标签编辑或显式“区间取样”才创建待标。取样默认2秒，调整步长不移动已有样本；批量建立待标记录不解码所有图像，实际编辑／审核时才绑定对应输入。
4. 时间条分T1和T2两轨：黄三角为待标、灰方块为跳过、绿圆点为已标；点击时间条只浏览。

“上下文浏览”可查看完整事件，用于身份关联和找片段。“输入审核”固定当前时刻，下方三张图由Linux统一生成，使用与导出相同的中性RGB＋BEV渲染，避免两端字体差异改变审核输入。双击历史图可放大、缩放和平移。

标为已标须切换到输入审核，并具有完整历史和RGB；保存状态另行显示，绿色已标不代表已经同步。首次编辑、待标和跳过无需先进入审核模式。

## T1群组

1. `Ctrl`点选或在列表多选人物，选择活动，点击“应用群组”。拍照角色明确时勾选角色，并指定摄影者、主要被摄者。
2. 其余有效PID需要明确分类为“确认未成组”或“归属未知”。成员确定、活动不清用群组内“活动未知”，两者分别保存。
3. 核对输入后标为已标。不会自动确认剩余人物，也不把未处理人物自动改成未知。

一个人不能出现在两个正式群组中。拍照＞交谈＞同行＞其他用于同组多活动的主标签压缩；仅距离近、同向、站在一起或拿手机均不足以自动确定关系。排队片段可跳过并备注“范围外”。

“复制上一已标样本”和“应用到指定区间”只生成待标草稿，通过轨迹或已核对人物关联匹配，不按PID数字硬拷贝；区间覆盖需要确认。

列表中的“参考／无模型PID”可用于身份与覆盖说明。漏检可在上下文模式用“补RGB人物”画辅助框；含此类人物的群组保存为覆盖失败参考，导出`semantic_eligible=false`、`response=null`，不会编造PID或伪造完整3D框。此类样本仍保留在导出中供端到端诊断。

## T2身份

1. 新建物理人物，在RGB／BEV／列表选一条轨迹，使用“关联／拆分片段”指定身份与时间范围。默认只关联当前帧；扩展区间前人工检查，重叠旧关联会在边界拆分。
2. 建立目标任务，填写初始可见外观描述、物理目标和描述参考时刻。一个事件可有多个目标任务；“另建一个目标任务”保留原任务。目标始终不在场时选对应选项，在独立的“描述来源（隐藏）”栏记录合法来源，避免把不在场等答案写入模型描述。
3. 按观察点填写可见性、合理候选、真实对应、覆盖和连续性证据；事件标记和备注按需填写。T2无需先完成T1。
4. 切换输入审核，核对该窗口能否唯一匹配、是否有歧义，再标为已标。真实目标可由完整上下文核实；匹配证据仍以当前可见输入为准。

人物身份使用隐藏人工ID；模型PID由原始因果轨迹产生。人工事后关联不会修复P1输入；辅助RGB框不会自动补几何。修改人物关联、描述或参考时刻会使受影响已标内容重新待标。

目标漏检时仍可记录真实辅助人物和`coverage=missed`；目标可见、完全遮挡、视野外和无法判断分别记录。目标描述不能包含PID、隐藏真值或未来才出现的细节。

## 快捷键与保存

| 按键 | 操作 |
|---|---|
| `A / D` | 上一／下一原始帧，仅浏览 |
| `W / S` | 上一／下一已有任务样本，不自动创建 |
| `1 / 2 / 3` | 待标／跳过／已标，不跳帧 |
| `Q` | 应用群组／设置合理候选 |
| `R` | 清除T1选中人物的分类 |
| `空格` | 上下文播放／暂停；输入审核保持当前时刻 |
| `Ctrl+Z / Ctrl+Y` | 撤销／重做标签编辑 |
| `Esc / F1` | 取消补框与选择／帮助 |

输入框、下拉框及数值框获得焦点时保留正常编辑。RGB／BEV支持滚轮缩放、拖动平移；BEV点径调整只影响显示。

日常编辑自动保存。远程界面区分本机暂存、待同步、服务器已保存和冲突。服务一次只允许一个写入会话，第二个客户端自动只读；断网时已缓存资产可继续浏览，未缓存帧明确报错，不以旧帧冒充。

写入结果未知时，重连先查原操作回执，不盲目重复写入。修订冲突保留草稿并停止覆盖；“处理同步冲突”经确认将当前工作及未同步操作移入同一缓存内的存档，再读取服务器结果。存档和未同步操作不随图像缓存淘汰，切勿删除整个缓存来解决连接问题。

“导出本机草稿”可保存当前工作和待同步／冲突内容。无GUI时也可离线取出缓存草稿：

```powershell
python -B -m decision.vlm.annotation export-drafts --cache-dir YOUR_CACHE_DIR --output drafts.json
```

## 导出与后续使用

在Linux读取服务器已保存的已标样本，输出目录必须为新目录：

```bash
python -B -m decision.vlm.annotation export \
  --project data/annotations/vlm_decision/wheelchair_20261016 \
  --output outputs/decision/annotations/wheelchair_20261016
```

默认仅写`manifest.json`、`t1.jsonl`和`t2.jsonl`，不复制bag或全部截图。需要实际模型输入图时显式加`--include-inputs`；其图像和几何不含人工群组颜色、真实人物身份或目标答案。

来源划分未设置、输入绑定变化或已标内容违反任务约束时拒绝正式导出。导出只按需读取已选样本，原始扫描和时间配对在读取时核对；保存一个样本不会反复解码其他未修改样本。待标、跳过、客户端未同步草稿均不作为金标准。T2固定事实与T1响应分开；不能把合法JSON、Qt可用或Linux回环HTTP测试当成真实Windows多机验收或完整决策能力成绩。

相关专项：`tests.test_vlm_annotation`覆盖规则、事务和远程恢复，`tests.test_vlm_annotation_gui`覆盖Qt异步交互。按改动范围运行，无需每次重复扫描全bag或调用VLM。
