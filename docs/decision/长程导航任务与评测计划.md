# 导航任务与评测计划

本文维护 Agent 的任务范围、数据、操作和评测。当前先测试室内完备地图下的单段或多段导航，不接局部 T1、T2、T3。Agent 自身仍使用 VLM，直接选择导航位置和朝向。实现机制见[Agent 技术实现](Agent技术实现.md)，研究参考和后续开发见[技术计划](Agent技术开发计划.md)。

下文提及的旧实验报告和一楼输入示例未保留在当前工作区；相关描述保留当时的结果范围，不能代替查阅原始记录。

## 地图条件与首轮范围

| 地图条件 | 任务输入与约束 | 当前状态 |
|---|---|---|
| 完备地图 `complete` | 有整个场景的建图结果，并人工标注任务涉及的点、区域和对象。 | 当前开发与测试重点。 |
| 简单地图 `simple` | 有涂画简图或地图软件的 BEV 截图，只保证主要通道和障碍的大致关系，并有任务标注；可能不等比例。 | 保留接口，尚未实现坐标解释和执行。 |
| 无图 `none` | 没有任何地图先验，指令是地图无关的纯文本描述，执行依赖现场观察。 | 保留接口，尚未实现导航。 |

地图条件描述可用先验，不等同于底层的定位模式。当前不测试三种条件之间的切换，也不把简单图像素直接当成米制位置。选择未支持条件时明确返回能力缺失，不调用完备地图完成替代任务。

### 场地、标注与来源

首轮仍以一楼为开发场地，原有地点资料继续保留：

| 地点 | 登记身份 | 来源和使用范围 |
|---|---|---|
| 电梯口 | `elevator` | 来自一楼演示，只到电梯外，不包含自动乘梯。 |
| 大厅门口 | `lobby_entrance` | 对应 `2026-10-29-15-59-09.bag` 中进出的玻璃门内侧。 |
| 大厅正中央 | `lobby_center` | 大厅开放区的近似中央。 |
| 走廊等待点 | `corridor_wait` | 现有位置在走廊入口段，未确认为远端。 |
| 本次出发点 | `mission_start` | 从本次任务开始时的有效车体位置取得。 |

四个固定点的位置已有用户确认，坐标和来源由地图资产维护。原 R1、R2 区域草图继续禁用，不自动作为区域任务标注。新区域以二维多边形登记；需要“面向窗户”等条件时，还须登记对应对象的位置。真实点、区域和对象必须使用同一地图坐标系，格式见[空间输入](Agent技术实现.md#地图条件与空间输入)。

已有开发资料包含一楼定位地图、静态环境图、感知结果、10 月 29 日分段路线及 11 份派生观察。RGB 来自场景截止时刻或之前，实际资源路径需按所用机器核对。这些是开发输入，不是独立人工金标准；录制驾驶不能作为 Agent 动作的反馈。

沿用用户此前指定的自主范围：一般不进入房间内部，其余区域可通行和停车，走廊停车需保留通道。新室内任务若涉及房间，应另行明确可进入范围。离线测试继续使用已有车体与雷达关系，并保留假设和来源；真正运动前须核对[实车接入条件](../感知导航实机问题.md#导航配置与执行)。

## 任务设计

当前只组合点导航和区域导航。位置与朝向的选择必须来自模型，不能由工具产生终点候选或推荐朝向。

| 子任务 | 示例 | 完成判据 |
|---|---|---|
| 点目标，明确位姿 | “到电梯口，朝向为地图坐标中的 90°。” | 实际位置满足点误差，实际朝向满足用户指定值，已到达并停稳。 |
| 点目标，语义朝向 | “到电梯口，面向已标注的窗户。” | 点位置满足要求，VLM 自行计算并选择朝向；实际朝向满足面向对象条件。 |
| 点目标，无朝向要求 | “到大厅门口停下。” | VLM 根据布局和任务选择执行朝向，点资产中的旧朝向不自动成为用户约束。 |
| 区域目标，空间语义 | “在大厅停靠区内停下，面向窗户。” | VLM 直接选择区域中的位置和朝向；实际 `base_link` 参考点位于区域内，方向满足条件。 |
| 区域目标，视觉语义 | “到入口等候区，停在能看见玻璃门的位置。” | 几何到达、停稳后，当前 RGB 支持所要求的可见内容。看不清时仍未完成。 |
| 有序串联 | “先到电梯口面向窗户，再到大厅停靠区。” | 按顺序逐项通过检查，最后全部完成且停稳。 |

“点”可以是标注身份，也可以是用户明确给出的地图坐标。“区域”不指定工具生成的中心点，模型可以在范围内选择适合语义和布局的位置。导航对模型原始位姿做完整车体和运动可行性检查；检查失败后，模型依据返回原因决定是否重新选点，工具不修改它的答案。

首批测试分三步：先检查单点及朝向，再检查单区域及语义，最后组合成有序链。每一步都区分指令理解、位姿选择和实际完成，不能只凭 Schema 或规划成功判定整项任务通过。

## 运行与测试操作

命令均从项目根目录执行，按[本机记录](../../ENVIRONMENT.local.md)选择解释器，每次使用新输出目录。Agent 使用独立托管 API，无需启动局部 SGLang。凭证、预算与请求设置由[模型客户端](Agent技术实现.md#模型调用与响应)维护。

`run`、`shadow` 和 `evaluate` 共用 `AgentLoop.run()`。`--max-s` 限制仿真推进，`--duration` 限制影子运行墙钟时间。达到上限或输入结束时处理活动调用的取消，并保存 `exit_reason`。旧的完整计划入口和格式不再支持。

### 查看目录与状态

```bash
python -B -m decision.agent --help
python -B -m decision.agent catalog --map-condition complete
python -B -m decision.agent status --session /path/to/session.sqlite
```

这些命令不读取 API 凭证。`catalog` 默认查看真实一楼登记；资产缺失时可能只有无坐标模板。`status` 只读查看，不恢复运动。通过 `--catalog FILE` 选择自己的标注配置；`--map-condition` 可以显式声明三类先验，但目前只有 `complete` 支持目标工具。

### 合成反馈与交互

以下入口调用托管模型，使用[合成目录](../../decision/agent/configs/simulation.json)中的点、区域和窗户，不在真实一楼运动：

```bash
python -B -m decision.agent run --interactive --map-condition complete \
  --instruction '先到电梯口面向前方窗户，再到大厅停靠区内停下。' \
  --max-requests 24 --output outputs/decision/agent/my_indoor_simulation
```

模型通过原生协议每轮最多调用一项工具，请求上限不是站点数。通常需要登记要求、读取地图、提交目标、等待和检查完成。终端的 `assistant_text` 是模型说明，任务状态和本地完成检查才决定结果。纯文字回复进入等待用户；活动导航会先请求取消。仿真没有真实 RGB，因此需要视觉证据的任务不能在这里宣告成功。此命令是开发入口，本轮未用 API 执行完整自然语言导航链。

默认使用隐式输入缓存，并在完整工具结果仍保留时引用其中的重复元数据。`run` 和 `shadow` 都可显式指定 `--cache-mode implicit` 或 `--cache-mode explicit`；后者给稳定前缀添加缓存标记，需要服务支持，失败不会自动降级。已执行的缓存对照未证明显式策略更好，默认保持隐式。思考模式仍关闭。命中和创建数量从会话中的 `api_response.cache` 读取，不能把缺字段当成零。

| 交互命令 | 行为 |
|---|---|
| `pause / resume / cancel` | 暂停、恢复或取消。暂停与取消不等待模型。 |
| `answer 补充说明` | 回答澄清，保留原指令和已登记要求。 |
| `replace 新指令` | 先撤销旧调用并确认，再建立新任务修订。 |
| `continue` | 在显式等待用户继续时发出真实继续事件。当前首批任务不要求插入等待阶段。 |

非交互运行遇到澄清、暂停或用户等待时保存并退出，当前不自动续跑。恢复暂停后由模型决定下一步，不自动重发旧位姿。停止无法确认时保留未确认调用。

### 完全离线的反馈检查

```bash
python -B -m decision.agent evaluate \
  --output outputs/decision/agent/indoor_feedback_check
```

该入口检查五种场景：指定朝向、点与区域串联、目标被占据、缺少视觉证据，以及暂停恢复、替换、取消。工具决策来自明确标记的测试脚本，运动反馈来自共用规划、DWA、安全和差速积分，不调用 API。每个场景一个 SQLite，集中一份摘要；结果不计为 VLM 理解成绩。

`--actions FILE` 使用内部工具动作数组，程序明确将其包装成原生消息夹具，不读取凭证。这是离线测试格式，不是模型的回复正文协议。例如，只检查要求登记和地图查询：

```json
[
  {"tool":"record_task","arguments":{"goals":[{"goal_id":"stop1","kind":"point","target_id":"elevator","description":"到电梯口"}]}},
  {"tool":"query_map","arguments":{}},
  {"tool":"ask_user","arguments":{"question":"要求和空间输入已读取，本次不提交导航。"}}
]
```

```bash
python -B -m decision.agent run --instruction '到电梯口' \
  --actions /path/to/tool_actions.json \
  --output outputs/decision/agent/offline_tools
```

真实 `navigate` 调用必须填写本轮 `query_map` 返回的 `view_id`，不能在通用静态动作文件里预填伪摘要。需要连续导航检查时使用 `evaluate`；其中的地图身份由显式测试夹具传递，不用于修复真实模型响应。`--scripted-user-events` 仅用于合成演示，事件不能当作真实用户输入。

### 真实观察与runtime影子测试

保存观察模式只提交目标建议，录包驾驶不响应 Agent：

```bash
python -B -m decision.agent shadow \
  --observations data/datasets/wheelchair_agent/floor1/observations.sqlite \
  --sequences 1 4 --map-condition complete \
  --instruction '观察大厅门口的空间与玻璃门，缺少执行反馈时不要宣告导航成功。' \
  --max-requests 6 --output outputs/decision/agent/my_shadow
```

请求前会按有效观察准备当前图像；缺少 RGB 或局部栅格时明确保留缺失状态。完备地图放在对话前部，绘制全部固定标注；末尾包含当前 RGB、带实测轨迹的全局概览和局部图。模型仍可用 `observe_scene` 显式观察，用 `query_map` 指定局部范围。保存输入只在等待新观察或导航事件时推进，请求模型期间保持原观察，等待澄清时返回，不继续遍历。输入耗尽记录 `input_exhausted`，暂停的离线源时钟不用于评价在线延时。

模型可调用 `save_keyframe` 和 `read_keyframe` 管理重要节点，默认最多两张历史 RGB 同时参与输入，历史图不能证明当前任务完成。此前一楼示例包含消息、工具和图片；示例前置动作来自固定夹具，不是实际 API 生成的导航过程。

新数据若已有感知场景，只补过去 RGB，不重跑检测与定位。请求列表每项提供 `seq`、`scene`、`stamp_s` 和 `offset_s`：

```bash
/usr/bin/python3 -B -m decision.agent.workflows.prepare \
  --bag /path/to/source.bag --requests /path/to/requests.json \
  --output /tmp/agent_rgb.sqlite
python -B -m decision.agent.workflows.prepare --rgb-db /tmp/agent_rgb.sqlite \
  --output /path/to/new_observations.sqlite
```

第一步使用系统 ROS，第二步使用项目环境。新观察保留原场景来源，不修改原文件或使用未来图像。

连接运行中的 runtime 时，按[运行手册](../感知导航运行手册.md#日常运行与回看)启动，需要 RGB 时启用 `--agent-observations`：

```bash
python -B -m decision.agent shadow --runtime-socket /path/to/run/commands.sock \
  --instruction '去大厅门口，缺少信息时观察或询问。' \
  --interactive --map-condition complete --max-requests 16 --duration 60 \
  --output outputs/decision/agent/runtime_shadow
```

`--interactive` 不用于保存观察的步进模式。两端须使用匹配的状态协议，取消确认需对应处理回执；目标清除不能证明底盘已停车。Agent 没有底盘使能或解除安全保护工具。当前 runtime 的地图图像是登记静态图的裁剪，不冒充实时局部栅格。

```bash
python -B -m unittest tests.test_agent tests.test_agent_context tests.test_agent_conversation tests.test_agent_goals tests.test_agent_visual_context \

```

这些检查不调用 API。ROS 相关检查按本机记录加载环境；Unix socket 检查需要允许创建本机 socket。文档更新不重复整套回归。

会话数据库保留原始请求、响应、对话轮、工具事件、要求和完成依据。`conversation_exchange` 事件记录助手消息及对应工具结果；裁剪对话不删除原事件。`map_images` 表保存实际地图 PNG，可按 `view_id` 和 `role` 提取，不要重新渲染后声称它就是原输入。`--no-memory` 仅关闭附加证据记忆，仍保留正常对话、任务要求和执行证明，不代表全部论文消融已经实现。

## 开发验收与已有依据

原生对话迁移检查包括定向 CPU 检查、五个固定工具决策反馈场景，以及实际服务上的两轮“查询地图、读取结果和图像、选择位姿”。当时记录包含首次流解析错误和修复后的结果。API 选出的导航没有执行，这不是完整任务精度或速度对照。

后续输入缓存及重复元数据实验复用冻结场景，没有重跑导航或刷新原时间；减少输入和缓存命中比例的结果不等于任务精度提升。

固定高分辨率地图、当前三图及主动关键帧的检查区分了相同冻结请求与当前真实观察变化的缓存结果，并记录了重复登记任务的错误回复，不作为整项任务成绩。

系统提示、工具 Schema、机器人资料、目录引用、裁剪来源和澄清保留曾经过独立审查及优化。111 项回归通过，三次 API 检查记录了两次朝向来源标签错误及一次提示更新后的正确标签。检查只核对少量真实观察上的协议、身份、目标位置及来源标签，输出没有执行，不能作为导航成功或模型整体准确率。

此前的室内导航适配、单模型工具循环、组件检查和一楼影子检查属于历史工作，其中旧工具协议和性能不作为当前接口验收。

| 验证方式 | 结果的适用范围 |
|---|---|
| 单元与接口检查 | 参数、任务顺序、输入对应关系、异常和迟到结果处理；不证明真实运动或模型理解。 |
| 固定工具决策的反馈仿真 | 共用导航算法下的几何完成、等待、取消和拒绝；不算 VLM 任务成绩。 |
| 实际 API 图像交互 | 输入、模型选择、原始响应可追溯；少量开发样本不证明独立语义精度。 |
| bag 或 runtime 影子 | 真实输入和目标建议对应；没有 Agent 动作反馈，不计算闭环成功率。 |
| 实车闭环 | 实际到达、停车及任务语义共同满足；尚未接入 Agent 验收。 |

每个正式任务预先固定指令、标注、起点、允许范围和成功条件。分别评价模型有没有遗漏要求、选定位姿是否合理，以及真实运动和语义是否满足。区域参考点在范围内不代表车体安全，历史通过不代表当前可通行。

还需检查几何未知、语义不足、地图或定位变化、反馈迟到与重复、断连及 ACK 丢失。停止未确认时核对实际状态，不靠旧日志续跑。到达后的视觉判断必须使用模型真实读过的新观察，不能用未来视图或原驾驶冒充主动观察。

## 后续任务与论文评测

### 保留的扩展任务

原长程任务保留为后续项目，不是当前代码验收前置。包括多站点后等待继续并返回起点、视觉终点复核、行进中替换任务、持续受阻后的恢复，以及地图无关的“沿走廊到前方入口”等引导。

进一步再考虑相似入口、线索暂时不在视野、有图进入无图再返回、重访条件变化，以及人工辅助换层。无图任务仍应由 VLM 根据可靠空间输入选择位置，不恢复工具候选终点机制。特定人物跟随和就座后置，到达入口不等于完成这些独立阶段。

论文可保留四类长程研究任务：多阶段行程与视觉终点、相似入口与不完整视野、有图到无图再返回、重访与条件变化。原规模草案为 4 类×3 实例×3 重复×3 种 VLM 方法，共 108 次运行，仅作为论文阶段参考，按预算和实机场景重新确定。

开发先用已有 bag 的 4～6 个关键片段，方法稳定后再扩实机。开发与留出集按物理区域、路线和事件划分，相邻帧或相邻切包不增加独立样本。只有单区域时不声称泛化到陌生建筑。自然变化和人工故障分别报告，中断、服务延迟和重复反馈单列工程组；底层行人预测和安全不计为 Agent 新增社交推理。

### 基线与消融

| 方法 | 公平比较的设置 |
|---|---|
| 固定流程 | 共用地点标注、执行器、导航和必要视觉判断，比较共同任务的功能和代价。 |
| 基础 ReAct 式 VLM | 使用当前单模型循环及相同空间输入，`--no-memory` 关闭附加记忆，保留任务与必要历史。 |
| 图计划加视觉复核 | 使用普通图记忆及历史复核，共用位姿接口与执行层，作为较强对照。 |
| 拟议方法 | 增加选择性证据维护和任务相关主动观察，分别检验单项及组合收益。 |

这些是对参考方法的项目适配，不称为原论文完整复现。Habitat 和 VLN-CE 尚未部署，需要通用 VLN 结论时另行评估。

当前完整地图组先比较单图与全局加局部图、结构化坐标、必要 RGB 对朝向和区域位置选择的作用。先分开测指令解析、模型位姿选择与反馈检查，避免把拒绝非法调用当成语义能力提升。

研究机制稳定后，再固定观察策略比较无持久记忆、普通记忆、统一过期、全量清空、事件审查和选择性维护；固定记忆及几何比较不移动、固定视角、仅事件触发与任务相关观察。先做少量诊断，不要求本轮完成全部对照。

所有方法共用模型、输入权限、任务条件、导航配置、独立安全及调用、图像、移动预算。固定流程也可读取相同视觉证据，任何方法都不能独占答案或未来事件。服务别名变化时分批记录，不因个例失败换模型。

### 指标与结论边界

| 维度 | 记录内容 |
|---|---|
| 任务与语义 | 完整成功、有序子任务完成、遗漏或错误完成、点与区域选择、朝向及视觉条件正确性。 |
| 记忆与恢复 | 错误空间引用、旧语义误用、重新确认、恢复成功和耗时，以及无必要失效。 |
| 观察收益 | 实际消歧、无效或重复观察、额外距离和澄清次数；预测可见不算实际收益。 |
| 效率与干预 | 总耗时、路径长度、工具与模型调用、图像和 token 数、计划外接管；计划内等待和乘梯辅助另计。 |
| API | 首 token、完整返回、源观察年龄、用量及可获得的缓存或思考明细；估算费用与账单分开。 |
| 可复现性 | 标签与原输入、请求与返回模型、日期、设置、导航配置和硬件；异步阶段 P95 不相加。 |

先比较相同时间和预算下的成功率，再报告耗时和调用成本。SPL 需要可信且符合轮椅约束的最短路，多阶段等待另报路线效率。非法输出、超时、失败和接管进入预定统计分母，按独立任务或场景统计，不按帧扩大样本。

区分规划预算耗尽、几何未知、视觉误判、反馈失效和任务决策错误。若证据机制只减少接口错误，归为工程成果；若观察策略不优于强对照，应缩减论文主张，不反复调整留出集 Prompt，也不关闭安全做实车消融。

每次运行集中保留一个 `session.sqlite`、一份摘要和复现必需引用，包含原响应、用量、错误及未决预留。不逐帧产文件，不复制全套 bag、RGB、地图或权重。研究机制与后续接口只在[技术计划](Agent技术开发计划.md#后续开发)维护。
