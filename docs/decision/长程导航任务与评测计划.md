# 长程导航任务与评测计划

本文说明首轮场地、具体任务、运行方法和验收标准。Agent 当前怎样工作，见[技术实现](Agent技术实现.md)；研究参考和后续方法，见[技术开发计划](Agent技术开发计划.md)。

首轮优先完成单楼层实机闭环，不接局部 T1、T2、T3 任务。Agent 自身仍使用视觉模型。

## 场地与数据

首轮使用一楼地图。轮椅暂不进入房间内部，其余区域原则上允许通行和停车；在走廊停车时必须保留通道。开发继续使用已有车体尺寸和雷达相对位置，并保留这些参数的来源，不把补画区域或重新人工审核车体参数作为离线开发前置。

真正运动前，仍须满足[实车接入条件](../感知导航待办与数据采集.md#实车接入前)。

| 地点 | 登记身份 | 选取依据和范围 |
|---|---|---|
| 电梯口 | `elevator` | 来自一楼演示观察。目标只在电梯外，不包括自动乘梯。 |
| 大厅门口 | `lobby_entrance` | 对应 `2026-10-29-15-59-09.bag`中进出的玻璃门内侧。 |
| 大厅正中央 | `lobby_center` | 大厅开放区域的近似中央。 |
| 走廊等待点 | `corridor_wait` | 当前候选在走廊入口段，并非已经确认的走廊远端。 |
| 本次出发点 | `mission_start` | 从任务开始时有效的车体位置取得，不使用坐标原点。 |

四个固定候选的位置已有确认记录，坐标和来源只由地点资产维护。位置不合适的 R1、R2 区域草图继续禁用，其他未经确认的区域也不参与运行约束。地点登记不代表当前可达；停车朝向和通行性由导航检查及真实反馈判断，不作为本轮文档审核任务。

现有资料包括一楼定位图、静态环境图、感知结果和 10 月 29 日分段路线。Agent 开发观察集有 11 份场景，每份场景配有当时或之前的 RGB，入口见[本机记录](../../ENVIRONMENT.local.md#外层agent开发)。这些候选和片段来自开发过程，不能当作独立人工金标准或盲测数据。录制时能够驾驶通过，也不能证明 Agent 可以自主完成相同路线。

## 任务设计

| 用例 | 指令或操作 | 完成时需要核对什么 |
|---|---|---|
| 单目标接通 | “请到大厅门口。” | 地点解析正确，目标提交、查询和取消一致，轮椅实际到达并停稳。 |
| 多站点、等待和返回 | “先到电梯口，再到大厅门口，等我继续后到大厅正中央，最后回起点。” | 按顺序到达，等待前已停车，只在真实继续事件后出发，最终返回本次起点。 |
| 视觉终点 | “到大厅门口停下，确认位于通向室外的玻璃门内侧。” | 几何到达、停稳和新鲜语义支持都满足。缺少其中一项时不能报告完整成功。 |
| 用户交互 | 行进中暂停、恢复或取消；“先别去电梯口，改去大厅中央。”；回答澄清问题。 | 取消不等模型返回，先撤销旧目标。回答问题保留原要求，明确替换任务才允许改变要求。 |
| 受阻和缺信息 | 临时占道、持续受阻、目标足迹未知；“去那边的入口。” | 区分未知、规划预算耗尽与明确阻碍。存在歧义或缺能力时停止并求助。 |
| 有限无图引导 | “沿走廊到前方可见的大厅入口前。” | 不预登记终点，由视觉和当前几何生成有效候选，到达后再审查。 |

单目标是下一阶段的首个实机用例。当前单模型工具循环已完成固定工具决策的多站点反馈仿真，并检查等待、暂停、替换、取消和迟到结果；另有一次真实图像工具交互。完整自然语言多站点任务及视觉终点仍需实机闭环验证，不能用固定动作轨迹替代。

受阻用例目前可以检查拒绝和澄清，不能把自动选择备选路线写成已实现能力。有限无图任务要等局部目标和移动观察接通后再测试。首轮不要求走最远走廊；没有可靠备选路线时保留停止或求助，不用额外人工提示伪装自主恢复。

后续逐步增加相似入口、线索暂时不在视野、有图进入无图再返回，以及重访时条件变化。最终演示可以串联已知地点、未知门厅、相似入口、移动观察、停稳审查、等待和返回，但这仍是后续任务。

人工辅助换层、目标长期不可见的全局搜索、特定人物跟随和就座暂时后置。到达入口不等于已经完成跟随或就座。

## 运行与测试操作

以下命令均从项目根目录执行，按[本机记录](../../ENVIRONMENT.local.md)选择解释器。每次运行使用新输出目录。Agent 使用独立托管 API，不要求启动局部 SGLang 服务；需要凭证和费用计提的范围见[技术实现](Agent技术实现.md#输入模型与工具)。

当前命令围绕单模型工具循环组织。旧的 `plan`、`review`、`--plan`和 `--offline`已移除，不自动把旧计划转换成工具轨迹；历史输入和结果继续作为来源记录保留。

仿真、保存观察和实时影子入口共用 `AgentLoop.run()`。`--max-s` 仅限制测试侧仿真推进，`--duration` 是影子运行的墙钟预算；Agent 核心按任务、工具和用户事件运行。超限或输入结束时，会先处理活动调用的取消，运行摘要用 `exit_reason` 说明返回原因。

### 查看任务

```bash
python -B -m decision.agent --help
python -B -m decision.agent catalog
python -B -m decision.agent status --session /path/to/session.sqlite
```

这些命令不读取 API 凭证。`status`只展示已保存任务，不会恢复运动。请求和工具历史保存在该会话的 `session.sqlite`，不是只靠终端文字推断状态。

### 合成反馈测试与交互

以下命令调用托管模型，在合成目录中运行工具循环，不在真实一楼驱动车辆：

```bash
python -B -m decision.agent run --interactive \
  --instruction '先到电梯口，再到大厅门口，等我继续后到大厅正中央，最后回起点。' \
  --max-requests 32 --output outputs/decision/agent/my_simulation
```

模型每轮选一项工具，因此请求上限指工具决策轮数，不是导航站点数。导航到达和用户继续可以通过事件等待，不要求模型持续查询。当前未用托管模型完成上述整段自然语言实机任务，命令提供的是开发入口。

| 命令 | 作用 |
|---|---|
| `continue` | 在等待用户继续时发出真实继续事件。 |
| `pause / resume / cancel` | 暂停、恢复或取消。暂停和取消不等待模型返回。恢复后由模型根据当前记录决定下一项工具。 |
| `answer 补充说明` | 回答澄清，原指令和已有完成记录保留。 |
| `replace 新指令` | 明确更换任务。活动导航先撤销并等待确认，新指令随后生效。 |

非交互运行遇到用户等待、澄清或暂停时保存并退出，当前不支持自动从退出点续跑。达到运行上限或退出时，活动调用会请求取消；没有确认的停止仍保存为未确认。

### 完全离线的工具检查

集中运行四个共用参考规划、DWA、安全与差速积分场景：

```bash
python -B -m decision.agent evaluate \
  --output outputs/decision/agent/tool_feedback_check
```

场景包括多站点、等待继续与返回，暂停恢复及任务替换，目标被占据，以及缺少视觉证据。决策来自明确标记的工具测试脚本，运动反馈来自积分仿真，不调用 API。每个场景一个 SQLite，集中一份摘要；这验证工具与执行流程，不评价模型理解能力。

也可把要检查的动作写成 JSON 数组。例如，单目标的工具轨迹为：

```json
[
  {"tool":"navigate","arguments":{"place_id":"elevator"}},
  {"tool":"wait_for_event","arguments":{"event":"navigation"}},
  {"tool":"finish_task","arguments":{"status":"succeeded","evidence":"目标已到达并停稳。"}}
]
```

保存到自己的新文件后运行：

```bash
python -B -m decision.agent run \
  --instruction '检查已登记工具的反馈流程' \
  --actions /path/to/tool_actions.json \
  --output outputs/decision/agent/offline_tools
```

`--actions`不读取凭证，也不调用模型。它按顺序提供工具选择，不提供假的到达反馈；等待导航后，仍需仿真器真正到达才会继续。文件内容须是工具调用数组，不能传入旧计划。显式加 `--scripted-user-events`可在合成演示中生成并记录继续事件，不把它作为真实用户输入。

### 真实观察与runtime影子测试

#### 已有观察上的工具交互

```bash
python -B -m decision.agent shadow \
  --observations data/datasets/wheelchair_agent/floor1/observations.sqlite \
  --sequences 1 4 \
  --instruction '观察当前场景，检查是否能支持大厅玻璃门内侧的判断；证据不足时等待新观察或询问用户，不宣告真实导航成功。' \
  --max-requests 6 --output outputs/decision/agent/my_shadow
```

模型可以先调用 `observe_scene`，下一轮会获得那份图像。调用 `wait_for_event`等待新观察后，输入驱动才读取下一观察；等待导航事件时也可以推进输入，但不能取得执行成功。程序在等待 API 时暂停离线源时钟，等待用户澄清时返回而不继续遍历。输入耗尽记录 `input_exhausted`，这些结果不能用于在线观察年龄或闭环成功率。

`--actions FILE`同样适用于影子模式，可完全离线检查工具。即使源包录到了接近目标，也没有 Agent 执行反馈，不能报告到达或完成。

#### 准备新观察

已有感知场景时，只补齐过去 RGB，不重跑检测和定位。JSON 请求列表每项包含 `seq`、`scene`、`stamp_s`和 `offset_s`；`scene`是场景路径，`stamp_s`是观察截止时间。

```bash
/usr/bin/python3 -B -m decision.agent.workflows.prepare \
  --bag /path/to/source.bag --requests /path/to/requests.json \
  --output /tmp/agent_rgb.sqlite
python -B -m decision.agent.workflows.prepare --rgb-db /tmp/agent_rgb.sqlite \
  --output /path/to/new_observations.sqlite
```

第一步使用系统 ROS，第二步使用项目环境，生成新的观察数据库，不修改原场景或使用未来图像。

#### 连接 runtime

按[感知导航速查](../感知导航操作速查.md#日常运行与回看)启动 runtime，需要图像时启用 `--agent-observations`。再连接已有运行目录：

```bash
python -B -m decision.agent shadow --runtime-socket /path/to/run/commands.sock \
  --instruction '去大厅门口，必要时观察或询问，不把影子状态当作执行完成。' \
  --interactive --max-requests 16 --duration 60 \
  --output outputs/decision/agent/runtime_shadow
```

`--interactive`只用于 runtime 影子模式，保存观察的步进测试不启用交互。两端须使用匹配的 runtime 状态协议；旧服务缺取消处理回执时，仍保持取消未确认。Agent 不提供解除接管或安全保护的命令。

当前 `--no-memory`可以关闭附加证据记忆，用同一个循环和工具检查基础对照。原任务、用户补充、必要历史及执行证明仍保留；主动观察和复杂记忆机制尚未实现，不能据该选项宣称完成了全部论文消融。

## 开发验收与已有依据

| 验证方式 | 可以说明什么 | 不能说明什么 |
|---|---|---|
| 脚本化单元反馈 | 工具参数、状态转换、迟到响应和异常处理。 | 不能证明实际运动或模型理解正确。 |
| 固定工具决策的反馈仿真 | 共用规划、DWA、安全和积分后的导航、等待与取消。 | 决策不是模型产生，且无真实 RGB，不能称为 VLM 导航成绩。 |
| 真实图像工具交互 | 模型实际选择工具、收到图像和继续交互，原请求可追溯。 | 不能证明全任务成功、独立场景语义精度或实机到达。 |
| bag 或 runtime 影子 | 真实输入上的调用、数据对应关系和时效处理。 | 原驾驶不响应 Agent，不能计算闭环执行成功率。 |
| 实车闭环 | 真实动作、停车和任务所需语义共同满足完成条件。 | 缺反馈或未执行阶段不能记为成功。 |

当前重构结果集中见[单模型工具循环报告](../../outputs/decision/agent/react_tools/report.md)。此前的[组件检查](../../outputs/decision/agent/component_readiness/report.md)和[一楼影子检查](../../outputs/decision/agent/floor1_shadow/report.md)保留为旧框架与 runtime 接入的历史依据，不能把旧计划或审查成绩直接当成新循环成绩。

下一步按单目标、多站点与等待返回、到达后的视觉判断、有限无图与补观察逐步接实机。测试前固定指令、起点、成功区域和视觉条件，用真实反馈判定到达与停稳。工具成功只说明执行证据门槛通过，模型是否遗漏站点、跳过等待或误认场景，仍按完整指令评测。

每项任务都要检查：语义支持但几何未知、到达但视觉不足、地图或定位变化、反馈迟到与重复、断连或 ACK 丢失。停止未确认时保留调用并核对，不靠旧日志续跑，不将未来图或任意录包视图当作主动观察结果。

## 论文评测

### 任务族与规模

| 任务族 | 场景变化和参考 | 主要观察量 |
|---|---|---|
| 多阶段行程与视觉终点 | 改变指令和站点顺序，标明完成区域与语义条件。 | 阶段顺序、过早完成和完整成功。 |
| 相似入口与不完整视野 | 让线索暂时不可见，独立标明真正可辨认的视角。 | 观察是否消除歧义，以及移动和等待成本。 |
| 有图—无图—返图 | 记录真实地图关联，重置先在仿真或影子中注入。 | 空间信息失效后的引用与恢复，以及保留语义的作用。 |
| 重访与条件变化 | 设置受阻或线索矛盾，并保留不变场景作对照。 | 重复观察、误用旧事实和无必要失效。 |

改指令、重复反馈、服务延迟和中断单列为工程恢复组。自然变化与人工布置分别报告，不能通过大量人工故障放大方法优势。行人检测、预测和安全沿用底层能力，不计为 Agent 新增的社交推理。

开发先用已有 bag 的 4～6 个关键片段，方法稳定后再扩实机。早期正式实验草案为 4 类×3 实例×3 重复×3 种 VLM 方法，共 108 次运行，只是论文阶段的规模参考，不是当前执行要求。实际数量按路线、预算和设备条件重定。

开发集与留出集按物理区域、路线和事件划分。同一路线多帧或相邻切包不增加独立样本数；只有单区域时，不声称能够泛化到陌生建筑。

### 基线与消融

| 方法 | 使用相同接口时的设置 | 比较目的 |
|---|---|---|
| 固定流程 | 使用相同地点、等待和备选分支、执行器与导航，必要时也调用相同视觉审查。 | 比较共同任务的功能与代价。 |
| ReAct 式 VLM | 使用当前单模型循环和相同工具，以 `--no-memory`关闭附加证据记忆，仍保留任务及必要历史。 | 作为后续研究组件的基础对照。 |
| 图计划加视觉复核 | 使用普通图记忆、当前视图和历史复核，共用候选及执行层。 | 提供较强对照，而不只比较无记忆或无视觉系统。 |
| 拟议完整方法 | 在强对照上增加选择性证据维护和任务相关观察。 | 判断单项机制与组合机制的收益。 |

研究来源见[技术计划](Agent技术开发计划.md#研究参考)。这些是原方法在本项目接口上的适配，不称为原论文完整复现。Habitat 和 VLN-CE 尚未部署，若需通用 VLN 结论，再单独评估依赖和数据。

记忆消融固定观察策略，比较无持久记忆、普通记忆、统一过期或全量清空、事件审查及选择性维护。观察消融固定记忆、候选和几何，比较不移动、最近或固定视角、仅事件触发及任务条件覆盖。之后按需要检查延迟成本、固定周期和关键帧的作用，先用少量诊断筛选必要对照，不要求本轮全部开展。

所有方法共用[选定模型](Agent技术开发计划.md#模型与调用)、输入权限、任务条件、导航配置、独立安全和调用、图像、移动预算。固定流程也可以使用相同视觉审查，不能让某方法独占答案或未来事件。模型别名或服务变化时分批记录，不因个例失败换模型。

先比较同一结构化任务的执行，再分别评价指令解析、视觉判断和方法增量。纯文本只用于分析视觉输入的作用。

### 指标与结论边界

| 维度 | 记录内容 |
|---|---|
| 任务与语义 | 完整成功、有序阶段完成、错误完成、地点或候选正确性和取消处理。以真实反馈及独立参考为准。 |
| 记忆与恢复 | 错误空间引用、误用旧语义、重新确认次数、恢复成功与耗时，以及无必要失效。 |
| 观察收益 | 实际消歧、无效或重复观察、额外距离和澄清次数。预测可见不算实际收益。 |
| 效率与干预 | 总耗时、路径长度、工具和模型调用、图像数、token 数及计划外接管。计划内等待和乘梯辅助另计。 |
| API | 首 token、完整返回、源观察年龄、用量，以及可获得的缓存或思考明细。费用估算与账单分开，缺失字段不能记为零。 |
| 可复现性 | 源输入与标签的对应关系、请求和返回模型、日期、设置、导航配置与硬件条件。异步阶段的 P95 不相加。 |

先在相同总时间和预算下比较成功率，再报告耗时与调用代价。调用更少但完成也更少，不算无条件改进。SPL 需要可信且符合轮椅约束的参考最短路，多阶段等待任务另报路线效率。

非法输出、超时、失败和接管均纳入事先确定的统计分母，按独立任务或场景报告，不按帧扩大样本。规划预算耗尽、几何未知、视觉误判、反馈失效和计划错误分别归因。

证据机制如果只减少接口错误，应归为工程成果；观察策略如果不优于强对照，应缩减主张。模型持续认不出地标时报告适用范围，不反复调留出集 Prompt，也不关闭安全做实车消融。

每次运行集中保存一个 `session.sqlite`、一份摘要和复现必需引用。保留原始响应、用量、错误及未决预留，不逐帧产文件，也不复制整套 bag、RGB、地图和权重。研究机制与回看的待办只在[技术计划](Agent技术开发计划.md#后续开发)维护。
