# 感知导航实机问题

本页是感知导航当前实机问题的唯一清单。以轮椅端的新日志和实际响应推进，阶段结束后更新一次。操作命令见[运行手册](感知导航运行手册.md#rviz交互测试)，当前算法见[总览](感知导航总览.md)，耗时口径见[推理速度](感知导航推理速度.md)。旧bag的失败计数与服务器实验不作为现场待办，按需查阅[离线归档](archive/感知导航离线开发记录.md)。

## 已有基础

车体矩形轮廓、雷达到车体外参、倒车和原地旋转能力已经用户确认，后续沿用。轮椅端报告已完成受控前进、倒车、左右转向、归零与手柄接管；这些基本动作无需无故重测。当前主链为定位、检测跟踪、局部与静态地图、Hybrid A*、DWA和独立CPU安全，支持RViz选起点与车体目标。

11月7日轮椅端的进展来自已同步的代码与文档；补充压缩包不可读，服务器未独立复核其中原始日志。下面区分已经报告的现场异常和仍待完成的目标导航，不将资料缺失解释为功能失败。

## 当前问题与下一步

| 问题 | 已知情况 | 下一次实机要做什么 |
|---|---|---|
| IMU时间戳倒退或重复 | 轮椅端集中测量曾复现，阻断定位记录；缺可读故障输入，根因排查暂缓。 | 用本次短观察确认是否复现；若复现，保留原始纳秒时间、接收时间和发布者，检查驱动与时钟。不能用排序、去重或刷新时间掩盖异常。 |
| 带目标运行的计算长尾与输入过期 | 轮椅端旧代码曾出现超过控制周期的DWA认证长尾。服务器已增加共享预算、区间复用和有界GPU细分，现场效果待复测。 | 在实际CPU/GPU上运行当前版本，按实际候选计算统计长尾，区分地图生产、GPU等待、交付和控制。只在异常时保留对应冻结输入。 |
| 当前地图的局部高度形变 | 新采集地图的时间补偿减轻整体倾斜，却增加局部形变；尚未完成独立精度验收。 | 沿用现场选定地图，用新扫描检查地面及墙体对齐。只在形变影响定位或通行判定时追溯重力方向、空间外参与后端修正，不先整体重建。 |
| 实际目标导航与恢复行为 | 基本动作已有证据，完整自主到点、目标停车、旋转衔接和阻挡消失后的恢复尚未验收。 | 在现有现场条件下直接测试一段明确目标路线，记录实际速度、停车和恢复。参考生成、安全许可与真实到达分别判断。 |
| 车辆执行档案与现场配置的对应 | 仓库通用档案只确认几何，运动、协议和控制器字段仍有空项；不代表现场已有参数无效。 | 优先复用轮椅端已经验证的档案与参数，只补缺失或矛盾字段。确认当前选用档案与控制器一致，保证制动和失联停车以已有有效现场证据为准。 |

## 现场出现后再处理的问题

近处未知、人物经过后的背景恢复、普通命中残留，以及先验与当前地面不一致，都应对应本次实际受阻格检查。当前地面支持半径已经采用0.55米，其余规则由[地图配置](../perception/environment/configs/environment.yaml)维护；该半径依赖连续平整地面，不能证明没有地面回波的断面可通行。先检查实际导航图、地面支持、覆盖与命中，再决定是否放宽条件。

等待参考、目标修订、旋转锚点、倒车和限速引起的中断，应结合当前反馈与实际指令检查。旧bag不会响应减速建议，其长时间无候选不直接表示轮椅不能恢复，不据此要求提高常规速度上限。

人物分割已由用户检查所选动态片段并认为基本正确。没有新的靠墙误删、静止人物或漏检证据时，继续沿用，不扩大删除范围。VLM与Agent的持续任务接入由各自计划维护，不作为本轮人工目标导航的前置工作。

## 测试与记录方式

沿用已确认的安装、车辆能力、现有保护和现场操作方式。若本次输入、配置与基本动作条件正常，完成改动直接相关的最少检查后即可进入有目标测试，不要求重复整套服务器回放或基本动作验收。具体异常直接检查对应环节。

每个阶段保留实际配置、一份运行摘要和有用的失败片段。需要定位计算与规划问题时显式开启计时或规划记录；先查是否完整，再按实际输入复现。现场状态、命令、安全结果与真实运动要对应，不能用仿真、规划成功或软件停车请求代替执行反馈。

阶段结束只更新本页的结论和下一步。算法和命令没有变化时，不同步改写其他文档。服务器修复交接已单独发送给轮椅端，不作为第二份持续待办。
