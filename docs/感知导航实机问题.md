# 感知导航实机问题

本页集中维护当前轮椅导航配置、地图与实时性问题。运行步骤见[运行手册](感知导航运行手册.md)，性能统计口径见[推理速度](感知导航推理速度.md)。现场反馈、规划结果和实际执行分别判断，尚未完成完整自主目标导航验收。

文中 `outputs/` 下的现场记录不会随 Git 推送，其他机器需要单独迁移相应文件才能查看。

## 导航配置与执行

- 当前使用[本车执行档案](../configs/wheelchair_vehicle.yaml)和[试验运动配置](../navigation/planning/configs/motion_trial.yaml)。轮廓和雷达到车体外参由用户确认；前进、倒车、左右转向和人工接管已有本车受控动作记录。
- 档案中的运动、制动、响应和协议数值由用户选作试验假设。确认标志允许软件进入执行流程，但不代表已测得保证制动能力、固件超时或断发后停稳上界。当前角加速度为1.0 rad/s²，线性和角向制动预测均按0.75的公共系数计算；实际响应上界仍待核对。
- 最近导航中定位估计前进速度曾约0.110 m/s，超过档案`max_planar_speed_mps=0.10`，独立安全为此请求停车。定位估计不等同于独立速度真值；需结合轨迹与实际响应核对，而不是把目标速度直接当作物理上界。固件断发行为与串口进程自身失效后的停车仍未确认，保留[现场来源](../outputs/navigation/vehicle_profile_review_20261108/source_review.md)及[失联范围核查](../outputs/navigation/vehicle_profile_review_20261108/loss_boundary/report.md)。
- 当前转向上限0.20 rad/s。用户报告调整后能够转向；目标到达、停稳以及不同场景下的转向衔接仍需观察。不能仅凭软件检查或单次动作确认执行安全。

## 地图与定位

- 当前使用11月7日二楼补偿地图和0.20米静态先验，入口配置见[交互配置](../navigation/commissioning/interactive.yaml)。该地图尚未完成独立精度验收，存在局部高度形变；继续对照现场墙面和地面，影响定位或通行时再追查修正。
- 地图关联年龄上限为0.5秒，仍使用原始测量时间，安全授权也受静态支持所用关联的剩余时效限制。较长的时限会容许更旧的关联。最近一轮控制记录的关联年龄最大约0.437秒，未显示关联过期是主要停顿原因。
- 独立安全的响应范围覆盖未知区域时会停车。最近使能期间有122帧零速写入对应`response_envelope_unknown`；需检查同一时刻的局部观测、静态支持、车体姿态与响应范围，不能将未知直接当作空闲。
- 初始化选点须对应轮椅当前雷达位置和朝向。此前两次选点后出现地图匹配积压并退出；已保留[诊断依据](../outputs/navigation/localization_backlog_review_20261108/report.md)，需以现场特征及当前关联状态判断。

## 实时性与运动连续性

- 最近一次配置7.5 Hz环境图目标频率的现场运行，在约168.4秒有效定位期间发布1260张图，约7.48 Hz，地图任务无替换。检测与跟踪P95约116毫秒，源观察年龄P95约184毫秒；10 Hz环境图和更高负载尚未经过现场验证。各异步阶段的P95不能相加。
- 同次约158秒使能期间，有117次零速写入发生在安全授权到期后，通常每次约50毫秒；下一条授权往往很快到达。另有规划主动提出零速和未知范围停车，因此不能把所有卡顿归因于单个模块。优先检查定位、独立安全重新检查、授权有效期与串口写入的对应时序，不延长源数据时间或绕过停车检查。完整输入和日志保留在[本次会话](../outputs/navigation/live_execution/20261108_201643_680826811/run/summary.json)。
- 本车观察与执行入口使用18米局部窗口、7.5 Hz环境图目标频率和CPU 0—15性能核范围。同段离线回放以10 Hz为目标时实际约9.11 Hz，且未运行目标规划和显示，暂不提高入口频率；依据见[推理速度](感知导航推理速度.md)。新配置下的真实执行、授权到期次数和运动连续性仍需现场核对。
- 检测模型是本次实机记录中耗时最大的已计时阶段，跟踪本身耗时较小。同一bag的短段对照发现，本机4个性能核与4个能效核限制下检测耗时差别明显，FP16没有提速；各阶段和限制见[推理速度](感知导航推理速度.md#cpu核心调度和检测精度对照)。现场当时没有记录执行核心，不能确认该差异是实机慢速的原因。下次现场应同时采集核心、CPU频率、检测耗时、地图年龄和安全授权时序，再决定是否限制进程亲和性。
- 另一次无地图、无目标的实时传感器测试中，默认调度与性能核限制的速度接近，默认调度的检测采样几乎都在性能核。该测试未启用静态先验、RViz、目标规划和底盘输出，尚不能替代完整实机导航验证。数据见[推理速度](感知导航推理速度.md#轮椅端在线运行)。
- 带RViz的有图观察中，历史初值两次未建立地图关联并触发匹配队列保护；当前单帧扫描配准得到的候选随后通过实时关联。该候选尚未由现场特征独立核对，不能直接作为下次实车起点。观察期间RViz记录重复的`map→odom` TF时间戳并丢弃重复消息；显示层在扫描和导航显示路径均可能发布该变换，具体重复来源及其对性能的影响待核对。带两个历史目标的非执行耗时见[推理速度](感知导航推理速度.md#轮椅端在线运行)。
- 随后分别以12米和18米窗口、相同的性能核限制进行两目标非执行观察，两轮环境图均约7.5 Hz。18米环境图处理略慢，检测和源观察年龄接近；具体统计见[推理速度](感知导航推理速度.md#轮椅端在线运行)。连续运行的现场输入不同，且未运行真实执行安全检查或移动车辆，不能据此认定真实导航已经满足时效。12米观察的第一目标期间，影子安全在约1秒内7次因`predicted_people_collision`请求停车，使用了有效人物轨迹；这是模型预测，尚未核实现场人员或框的真值，不应据此绕过人员检查。两轮仍观察到RViz重复TF警告。
- 地图与检测进一步并行时须保留同次观察的人物时间和设备流依赖；安全检查继续独立运行。更高地图频率、减少模型输入或更换模型都需要分别验证，不能仅凭GPU利用率推断能满足实时要求。

## 其他现场前提

前视相机启动入口按本机配置重载并检查IMU采样；已观察到重启后恢复约200 Hz，长期稳定性仍需关注。驱动就绪后再启动定位。传感器断流、手柄接管、急停和串口独占均按当前程序与现场操作要求处理，不将传感器或通信异常视为地图空闲。
