# 感知导航实机问题

本页只列当前仍需现场核实或处理的问题。轮椅的矩形轮廓、雷达到车体外参、倒车和原地旋转能力已由用户确认；沿用这些前提。完整自主目标导航尚未验收。操作见[运行手册](感知导航运行手册.md)，历史现场观察见[归档](archive/感知导航现场历史.md)。

## 导航与执行

- 当前 `trial` 配置的前进、倒车和角速度上限为 0.80 m/s、0.20 m/s 和 0.40 rad/s。速度反馈门限与配置上限接近，实际响应和短时超调是否会触发拒绝，需要结合底盘反馈和定位估速核对。目标到达、转向衔接和实车停稳仍需验证。
- 已移除完整停车预测和执行响应范围。DWA 与独立安全对静态地图检查 1.5 秒预测，对人物硬检查当前时刻起 1.0 秒；超出人物硬时域的冲突保留为诊断。实际响应、障碍发现延迟和断发后停车尚未验证，不能据预测通过认定轮椅能够在障碍物或行人前停稳。
- 固件失联停车及串口进程自身失效后的停车行为仍未确认；保留现场急停、手柄接管和现有看门狗，按实际反馈核对。现场协议配置可通过档案检查，但软件检查不代表物理验收。

## 规划与控制待验证项

- 参考路径只优化空间几何，不按车辆速度计算行驶时间。已加强旧路径从当前位姿的同方向衔接；离线使用现场记录中的 69 对相邻路径及静态地图核对，通过扫掠的接续候选由 13 对增加到 30 对。该对照没有当时逐帧局部环境图，尚需现场核查路径切换和车辆响应；无法安全接回的情况仍会重新搜索。
- DWA 和独立安全的人物硬检查均使用当前时刻起 1.0 秒。现场记录人员位置、候选速度、冲突预测和实际接近情况，判断是否需要调整时域或人物处理；暂不把合成场景结果当作实机收益。
- 终点和换向点降速与 1.5 秒预测时域耦合。观察接近时是否过慢、越过目标或换向不顺，再决定是否单独调整降速规则；实际停稳仍须由现场反馈判断。
- 本车档案将前进和倒车的最低非零指令设为 0.10 m/s，角速度最低非零指令设为 0.20 rad/s。控制器已补充零角速度的加速与减速候选，减少最低角速度过滤造成的低速和意外零速；近目标及换向控制按名义运动模型提前请求零速。实车的加速连续性、停车和到达精度尚需核对；该模型不是制动保证，其他约束或安全检查不允许候选时仍可能停车。
- 11 月 10 日现场导航记录中，接近目标时朝向在容差附近反复变化，低速转向阶段的定位估速多次显示静止。还需结合参考段、定位变化和车辆实际响应区分转向超调与路径要求；历史串口反馈协议和设备测量时间未核实，不能据此直接确定响应延迟。
- DWA 候选数量有限，部分导航占据视图没有净空软评分。现场检查是否出现有可行空间却长期无候选、贴边或反复停车，并结合候选认证和安全拒绝记录，判断是否需要调整采样或净空评分。
- 地图中的门全开、现场半关时，参考工作图已加入实时局部占据，并在旧路线受阻时重新搜索。该修改通过合成障碍检查，尚需现场核对半开门的绕行、通行净空和规划耗时；临时占据没有跨查询记忆，遮挡或离开局部窗口后不能仅凭参考图判断门已打开。
- 独立安全依赖当前定位和环境地图，尚无独立的原始点云近场碰撞通道。结合新障碍进入视野、地图更新和安全授权的时序，判断是否有必要增加直接近场检查；16 线雷达近处缺少回波不能视为空闲。

## 地图与定位

- 本车[交互配置](../navigation/commissioning/interactive.yaml)使用 11 月 7 日二楼补偿定位地图和同源扫描融合、人工修正后的 0.10 米静态先验。人工空闲不等于传感器实测；编辑范围包括原先标为占据的格子，需结合现场核对。地图存在局部高度形变，人工修正后的地图尚未经过实机导航验证；定位精度和通行情况仍需结合现场核对。新生成或人工修正的地图不会自动替换该配置，启用前需确认定位地图、静态地图和关联区域互相对应。
- 二楼建图中曾发现行人造成的错误占据，新的静态生成与人工修正工具尚需结合实际场景核查效果；假定空闲和人工空闲不是自由射线实测，低矮障碍及被遮挡区域仍需留意。
- 地图关联区域覆盖二楼静态栅格的完整范围，其中包含未观测区域。全图定位精度尚未经过现场验证；关联仍须通过配准质量和有效期检查，区域本身不表示自由空间。历史观察中出现过起点足迹未知，仍需结合当前地图现场核查。
- 11 月 11 日 Agent 实机测试中，第一目标发出后轮椅短暂移动，随后地图关联失效，现场确认停稳。同样的匹配积压也在静止、无底盘观察会话中出现。追踪显示，匹配失效后固定子地图被反复同步重建，部分提取耗时约 300～400 毫秒，不能跟上约 10 Hz 的扫描。在线定位现只保留最多两个待匹配扫描，固定子地图不再因匹配失败而立即清空，仍按预测位置更新。过旧关联仍会失效并使导航停止；建图和 bag 回放保留原有队列行为。
- 后续静止观察中，匹配内点比例约 0.94、残差约 0.04 米，重力方向偏差却多次略超原 5° 门限，导致关联反复失效。本车交互入口将该限制设为 6°，其他匹配质量条件保持不变；随后的静止对照及一轮实机短程移动中关联保持有效。这是基于当前局部场景的操作配置，不表示整张地图的定位精度已经验证。
- 实时选点已支持依据选点附近静态地面和当前雷达地面观察估算高度初猜，缺少当前观察时使用同图历史高度差，地面依据不足时退回固定提示。该方法尚未实机验收；历史定位在相近位置曾出现高度不一致，仍须核对预览及实际地图关联，不能仅凭初猜判断定位正确。

## 时效与现场观察

- 实机授权和运动连续性仍需在当前版本复测。旧执行记录曾有授权过期后的短时零速；下一轮结合控制、安全、串口写入和底盘反馈判断当前原因，不能将旧响应范围导致的拒绝计入现算法。
- 显示层曾将同一时间的 `map→odom` 变换重复发布，已在发布出口按坐标系和原始时间去重；修复后需在新启动的会话中确认警告是否消失。IMU 曾出现采样异常，重启后观察到恢复，但长期稳定性仍需现场关注。
- Agent 已接入显式启用的实机单目标通道，多目标依次依赖定位估计的到达和取消后的停稳估计。本轮完成任务拆分和首目标提交，轮椅移动后在墙、门或障碍附近停住；控制器多次因轨迹涉及未知区域而没有可用速度。其中一帧的参考首段要求倒车，三个受检速度候选均因扫掠未知被拒绝。最后保存的全局参考路径约 54 米，明显长于起终点的直线距离。用户确认停稳后取消目标，两个子任务均未完成。代码现将持续无速度候选作为事件交给 Agent 判断，尚未完成实机验证；还需结合现场地图和规划记录核查未知区域来源、实际可通行空间，以及后续目标切换和停稳。
- 本轮人工取消后，Agent 曾尝试重新提交目标，但底盘已经退出使能，运行时拒绝了请求。代码已调整为使能失效时中止当前 Agent 执行，并将明确拒绝与回执丢失区分；该修正仍需以后续现场反馈验证。
- 后续 Agent 首目标提交后，模型仅以文字表示等待，程序将其解释为需要澄清并取消目标，轮椅短距离移动后停下。代码已改为目标被接受后直接等待导航事件；该修复已做合成反馈检查，仍需现场复核。
- 实机子任务到达后改为先清除运动目标并保持零速，确认新的定位停稳反馈后再检查子任务；人工取消仍会退出使能。合成反馈检查覆盖了子任务衔接和取消，连续多任务、实际停稳与任务结束后的退出使能仍需现场验证。
- 11 月 11 日使用不连接底盘的观察会话和原车手柄，完成了“停靠点 1 → 中转等候区”手动测试。两个子任务均记录了人工确认与定位停稳估计，不能作为自主导航验收。任务检查在最终通过前六次返回依据不足；观察更新频率和 0.5 秒位姿时效限制可能有关，需结合源时间进一步核对，避免模型重复检查。模型最终文字中的停靠点位姿与记录的定位不一致；复核以带时间和句柄的完成记录为准。

现场数据不会随 Git 推送。离线回放、软件自检和仿真仅能验证各自范围，不代表真实底盘运动或完整导航任务已验收。
