# 技术实现：检测训练

检测训练的目标是把源域学到的行人几何迁移到轮椅任务场景，并通过人工中心复核减少误检与漏检。源域有完整 3D 框，轮椅标签主要描述 XY 中心，因此不同来源不能使用同一套完整框监督。

实现只修改仓库内 `perception/detection_tracking/training/simpledet3d/` 副本，不修改外部 SimpleDet3d。本文先解释监督和评估，再说明数据准备、标注、增量训练和三阶段训练。部署见[检测与跟踪推理](技术实现-检测与跟踪推理.md)，新增数据需求见[共同清单](../感知导航待办与数据采集.md)。ROS 与标注启动命令放在[操作速查](../感知导航操作速查.md)，本页保留训练和数据生成命令。

## 监督语义与弱监督方法

迁移从 CODa-16line 模型开始，类别为 `Pedestrian`。CODa 完整框用于学习几何，目标域人工中心用于可靠的 XY 监督，伪框只在对应维度可信时提供低权重监督。背景监督另由“该帧是否完整复核”决定，不能从没有标注直接推断背景。

前两个阶段混合源域与目标域，并通过 EMA Teacher 在已有中心附近升级可靠几何。第三阶段冻结几何回归分支，适配实际室内或室外任务场景。历史三阶段保留原数据选择，新增标注通过[任务场景增量适配](#任务场景增量适配)继续训练。

### 标签来源与完整性

| 来源 | 可用监督 | 禁止推断 |
|---|---|---|
| CODa完整3D框 | 类别、背景、中心／尺寸／高度／yaw、ROI回归 | 源域成绩不代表目标域效果 |
| 历史人工BEV中心 | 高可信XY；只补原伪标签漏检 | 不能单独确定高度、尺寸、朝向，不能据“附近无人工点”否定伪框 |
| 原图像伪框／伪中心 | 类别与XY候选，通过过滤的框可低权重逐维监督几何 | 图像分数不是3D定位质量，未生成伪框不表示背景 |
| 历史人工补全帧 | 人工中心与同帧原伪标签并集具有近似中心穷举性，可启用有效范围背景 | 中心完整不等于完整3D框；不跨来源按距离合并相邻行人 |
| 新rosbag待标／已标帧 | 核验检测中心与人工BEV点；仅已标帧提供约定范围背景 | 未核验候选忽略，拒绝候选不重新并入，预测框不是几何真值 |
| 非穷举／无标签帧 | 已知正目标邻域及有锚点Teacher升级 | 未标注区域不直接作为负样本，单次Teacher不创造无锚点正目标 |

历史人工文件中的键 `k` 是主场景 pkl 的 `frames` 列表零基下标，读取顺序为 `annotation[k] → frames[k].frame_index → pointcloud`。不能按文件起始编号猜偏移。

这些人工点用于补原伪框漏检，两种来源互补，不能因距离近就自动匹配或跨类型去重。完整性取决于人工文件是否包含该帧键，与目标数量、`weak_centers` 是否为空分别判断。

`center_label_is_exhaustive` 表示中心是否完整，`is_target_domain` 表示数据域，两者独立。`bbox_3d=[x,y,z,dx,dy,dz,yaw]` 中，Z 是几何中心，垂直范围为 `z±dz/2`。参考尺寸 `ref_size` 不会自动成为可信回归真值。

### 人工复核中心协议

rosbag 工具先给出模型建议，人工接受的检测中心和补充 BEV 点才成为正标签。拒绝与未核验建议都不进入正标签，也不能再用历史互补规则把拒绝项合并回来。

默认导出待标和已标帧，也可只选已标。待标始终是部分标注，未核验区域不能作背景；只有人工明确标为已标的帧，才允许在约定范围内提供完整背景监督。

- 中心在原始雷达系、XY为米，绑定来源、话题、扫描序号、纳秒时间和点云指纹；不使用没有来源的地图位姿。
- 仅`complete`帧启用完整背景及ROI中心分类，零中心须人工确认无人；待标、跳过和未复核不作背景。当前不提供局部复核ROI的负监督掩码。
- 占位`gt_boxes`只为兼容接口，回归掩码为`[1,1,0,0,0,0,0,0]`；高度／尺寸／yaw及原预测框均不是真值。普通目标域ROI框回归关闭。
- 检测、拒绝与人工中心分开存储，晚返回候选不覆盖人工结论。显示降采样、Z筛选和分数滑块不改变训练点云或标签。
- 完整性只覆盖约定模型范围；不能经旋转、缩放或平移把未复核区域带入范围后当背景。增量配置只保留保持覆盖的镜像。

### 过滤与逐维监督

准备工具保存 `gt_boxes/gt_names/gt_cls_weights/gt_reg_weights/gt_box_reg_mask/gt_supervision_types` 与中心完整性。八维回归掩码依次对应 XY、Z、尺寸和 cos/sin yaw。数据增强同时变换点、中心、框、权重和掩码，padding 不作为真实目标。

伪框先检查有限值、正尺寸、范围和距离相关的点支持，再用双向时序等证据决定保留或降级。中心可信而几何不可信时，只保留 XY；中心也无法确认时忽略，剔除不能自动生成背景。来源内部去重不跨人工互补流。

当前过滤没有通过二维与三维投影一致性升级标签，前视图像之外也不能因缺图推断背景。阈值及逐维启用条件以准备工具和训练 YAML 为准。

| 计算分支 | 当前行为 |
|---|---|
| CODa Dense／ROI | 保持完整分类、几何与背景，维持源域能力 |
| 目标域Dense | 人工／伪中心按来源权重监督XY；只有已知可靠几何按掩码低权重回归，人工中心不监督Z／尺寸／yaw |
| 穷举中心背景 | 在有效检测范围计算目标域背景，背景权重与每目标类别权重独立；非穷举帧维持正邻域mask |
| 目标域ROI | 穷举中心帧按proposal中心与中心集合距离作分类，正／负间隔中间忽略；不启用普通IoU框回归，非穷举帧屏蔽目标域ROI |
| EMA Teacher | 在已有人工／伪中心附近升级可靠几何，保留`ALLOW_UNMATCHED=false`；恢复EMA状态，不凭单次预测扩张标签全集 |
| Stage 3 | 冻结Z／尺寸／yaw与ROI框回归，保留XY、分类及共享特征训练 |

训练实际组合源域完整检测损失、目标域中心与允许几何损失、完整性背景和中心 ROI 分类。损失权重由配置维护，本文不再设置一套数值。双教师、双视图、持久化质量记忆和轨迹传播仍是候选研究，不作为已经实现的训练路径。

训练默认单帧，强度使用 `intensity/255`，第五维 `time_lag=0`。多帧必须显式启用，并具有可靠位姿或明确静止依据，用 `inv(T_current) @ T_history` 补偿自车运动。它不补偿行人运动，因此可能出现拖影，运动方向也不等于人体 yaw。

源域与目标域的增强遵循相同约定，目标域不会用噪声伪框建立普通 GT 采样库。

### 评估与模型选择

- 完整框CODa可以报告3D／BEV AP；目标域中心与伪标签不能提供可信3D框AP或Z／尺寸／朝向误差。
- 穷举中心验证帧使用一对一中心距离匹配，报告中心Precision／Recall／F1、FP/frame、中心误差及有效范围覆盖；非穷举帧未匹配预测是待复核，不能计假阳性。
- 单独`CenterHit`是召回式指标，须同时看预测数；最佳目标域checkpoint按配置中的中心F1等指标选择，阈值只从独立验证选择。
- 固定输入、范围和坐标比例看少量BEV／点云样本，区分人工中心、弱框与预测；时序稳定或框内点数不是几何真值。
- 训练／验证按场景和原始采集／重复地点隔离，不随机拆相邻帧；验证观察不进入Teacher更新。指标、最终NMS与proposal NMS用途分开，不用提高阈值替代误差评价。

### 按距离分层与综合评分

距离分层用于区分近处与远处错误对任务的影响，原全范围 Precision、Recall、F1 和 FP/frame 继续报告。距离是当前雷达坐标中的水平半径 `r = sqrt(x²+y²)`，单位米，不是到车体外壳的净距离。只统计原检测矩形内的目标，范围外不补成背景。

分档下界、权重与开关由[增量配置](../../perception/detection_tracking/training/simpledet3d/configs/voxelrcnn_ros_centers_finetune.yaml)的 `DATA_CONFIG.WEAK_SUPERVISION.DISTANCE_EVAL` 维护。区间左闭右开，最后一档延伸到检测范围边界。权重表达近处更重要的任务偏好，不是根据本轮成绩拟合，也不代表制动距离或安全认证。

每帧先做全范围一对一 XY 匹配，再分档。命中和漏检按真值中心距离归属，未匹配预测按预测中心距离归属，避免跨档的正确匹配被拆成漏检与误检。匹配半径仍取 `CENTER_HIT_THRESHOLDS` 第一项，不额外放宽远处条件。

| 输出 | 使用边界 |
|---|---|
| `Distance/<区间>/LabeledCenterCount`、`CenterHit@…` | 全部已知正中心，包括部分标注；只说明已知目标命中率 |
| `Distance/<区间>/ExhaustiveCenterCount`、`CenterRecall@…`、命中／漏检数 | 仅完整复核帧，空档Recall未定义 |
| `Distance/<区间>/CenterFalsePositiveCount@…`、`CenterFalsePositivesPerFrame` | 仅完整复核帧；分母为全部完整帧数，各档FP/frame可相加 |
| `Distance/<区间>/EmptyFalsePositivesPerFrame` | 仅整帧人工确认无人样本，分母为该组无人帧总数 |
| `DistanceWeightedPrecision/Recall/F1@…`、`DistanceWeightedFalsePositivesPerFrame` | 仅完整复核帧，按配置距离权重累计 |

综合分数采用距离加权F1：

```text
TPw = Σ已匹配目标 w(真值距离)
FNw = Σ漏检目标   w(真值距离)
FPw = Σ未匹配预测 w(预测距离)
距离加权F1 = 2TPw / (2TPw + FNw + FPw)
```

同时报告加权 Recall=`TPw/(TPw+FNw)` 和 Precision=`TPw/(TPw+FPw)`。权重全部相同时，加权 F1 退化为普通 F1。没有完整正目标时，Recall 与 F1 未定义，JSON 输出 `null`，无人帧仍提供误检统计。部分标注不贡献负样本、误检或综合分数。

候选比较先看最近距离档的召回和样本量，再看全范围误检、无人帧误检及距离加权F1；不让一个综合分数掩盖近处漏检。独立任务开发集具备完整标签后，可将`DATA_CONFIG.WEAK_SUPERVISION.BEST_METRIC`设置为相应半径的`DistanceWeightedF1@…`用于选模；当前历史弱验证的既有选择规则及已保存`best_model.pth`不自动改变。增补评估配置后，已有训练输入快照仍保留原值，新实验采用新的输出目录。

中心距离匹配可参考[nuScenes官方评估说明](https://github.com/nutonomy/nuscenes-devkit/blob/master/python-sdk/nuscenes/eval/detection/README.md)，按距离体现任务相关性的思路可参考[CVPR行人检测相关性评估研究](https://openaccess.thecvf.com/content/CVPR2021W/SAIAD/html/Lyssenko_From_Evaluation_to_Verification_Towards_Task-Oriented_Relevance_Metrics_for_Pedestrian_CVPRW_2021_paper.html)。本项目分档、权重及综合分数是当前中心标注任务的评估约定，不作为这些论文的原版指标。

### 历史标签统计与基线

以下保留原弱监督记录中的冻结统计，不能当作新rosbag标签数量或当前部署成绩：40个室内人工场景共有9,705个补全帧、21,984个人工中心；17,145个原伪标签中心经来源内部去重保留17,126个，合计39,110个目标。原划分为训练8,486帧／34,049目标、验证1,219帧／5,061目标，分别有穷举／非穷举info。

原A0重构前Stage 3，在有效范围4,918个并集中心及8,519个预测上，以`score>=0.3`、最终`NMS=0.2`和当前帧点支持过滤作0.5米匹配：Precision 55.86%、Recall 96.77%、F1 70.83%、FP/frame 3.08。它说明只看人工召回会漏掉误检，不作为新训练已改善的证据。原pkl中约5.8万个正尺寸伪框、4.1万个无有效尺寸伪中心及约4.1万伪标注帧／7.9万原始帧也按历史来源解释，缺失帧不作空GT背景。

## CUDA 13.0 开发环境

新建环境使用根目录 [requirements-cu130.txt](../../requirements-cu130.txt)，其中固定 Linux x86_64 / Python 3.12 的检测、渲染和 VLM 客户端组合。远程 SGLang profile 与 ROS 系统运行时另行维护。

PyTorch 从官方 cu130 源安装，其余 Python 包优先使用中国镜像。以下用于新的隔离环境，已有环境不需要重复安装：

```bash
conda create --prefix /path/to/new_env --override-channels \
    --channel https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main \
    python=3.12 pip setuptools wheel -y
conda activate /path/to/new_env
conda env config vars set CUDA_HOME=/usr/local/cuda-13.0 PYTHONNOUSERSITE=1
conda deactivate
conda activate /path/to/new_env

# 从 Social-Nav 根目录执行。
python -m pip install \
    'https://download.pytorch.org/whl/cu130/torch-2.13.0%2Bcu130-cp312-cp312-manylinux_2_28_x86_64.whl' \
    --index-url https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple
python -m pip install -r requirements-cu130.txt \
    --index-url https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple
PATH="$CUDA_HOME/bin:$PATH" FORCE_CUDA=1 MAX_JOBS=4 \
    python -m pip install --no-build-isolation --no-binary=torch-scatter \
    torch-scatter==2.1.2 \
    --index-url https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple
```

PyTorch 扩展使用 C++20，应分别确认 GCC/G++，按环境选择 `CC/CXX/NVCC_CCBIN`。Toolkit 与 PyTorch CUDA 大版本需匹配。PyTorch 自带 CUDA/cuDNN 运行库，不覆盖系统 cuDNN，也不把旧 CUDA 库永久放到当前环境的库搜索路径前面。

当前依赖清单采用 CUDA 12.6 预编译 spconv/cumm 配合 cu130 PyTorch；spconv 不绑定 PyTorch 二进制 ABI，但这仍是混合 CUDA 大版本的组合。换机器后需针对目标 GPU 核验稀疏卷积前后向，不能仅依据安装成功判断兼容。

在副本编译四个扩展：

```bash
cd perception/detection_tracking/training/simpledet3d
PATH="$CUDA_HOME/bin:$PATH" MAX_JOBS=4 \
    python setup.py build_ext --inplace --force
python -m pip check
```

应生成 `iou3d_nms`、`roiaware_pool3d`、`pointnet2_stack` 和 `pointnet2_batch`。GPU 不可见时先检查驱动/容器/调度；确需无 GPU 编译时显式设置目标 `TORCH_CUDA_ARCH_LIST`。新 Python、Torch ABI 或 GPU 架构需要重新编译，不复用旧 Python 的扩展。项目从源码运行，不要求 `pip install -e .`。

仅在新环境或二进制变动时，按实际需要检查扩展导入及少量算子，不重复已有有效结果。旧 CUDA 12/Python 3.10 二进制不能与本组合混用。真实权重、训练和 ROS 的验收范围见本机记录。

## 数据准备

统一链接方法见 [开发指南](../开发指南.md#数据入口与迁移)。副本 `data` 指向项目 `data/datasets`；`DATA_PATH` 定位 info/数据库，`RAW_DATA_PATH` 定位原始点云。共享原始数据与现有 info 默认只读；通用预处理使用新的`output/data_preparation/`子目录，实机增量检测数据统一使用`data/datasets/wheelchair_det_extra/<名称>/`。

### CODa 与降采样

已有 16 线数据适用时直接复用。需要新生成时：

```bash
python tools/downsample_coda_lidar.py \
    --data_root data/coda_raw --workers 4
python tools/generate_coda_info.py \
    --data_root data/coda_raw \
    --output_dir output/data_preparation/coda_new
```

降采样把 OS1-128 点云还原为 `(128,1024,4)`，在完整垂直视场均匀保留16通道。默认写到本地 `output/data_preparation/coda_raw/3d_comp_downsample/os1`，不补写共享原始根目录。支持 `--seq_ids`、`--limit`；只有明确重生成时使用 `--overwrite`。

生成降采样 info 的例子：

```bash
python tools/generate_coda_info.py \
    --data_root data/coda_raw --pc_dir 3d_comp_downsample/os1 \
    --filter_class Pedestrian \
    --output_dir output/data_preparation/coda_downsample_new
```

该例读取原始根下**已有**的降采样子目录。若点云是本地新生成的，应另准备含标定、位姿、metadata 和点云子目录的本地数据根，再指定 `--data_root`；仅运行降采样工具不会补齐共享数据。显式相对 `--output_dir` 的解析依工具而异，外部输出优先使用新的绝对路径。

CODa 生成器输出 train/val/test info，并报告缺点云/标注、空框、类过滤和非法框。新路径相对于原始根；历史 sweep 来自目标帧之前的原始帧，受断点和时间差限制，可以跨 metadata 标注划分。需要时用 `--sweep_frame_len/--max_sweep_time_lag` 调整索引，具体参数见工具 `--help`。

只有启用 `gt_sampling` 才需要 GT 数据库：

```bash
python tools/generate_gt_database.py \
    --cfg_file configs/voxelrcnn_coda.yaml --split train
```

### Wheelchair 基础与弱监督 info

```bash
python tools/generate_wheelchair_info.py \
    --data_root data/wheelchair_raw \
    --output_dir output/data_preparation/wheelchair_new

python tools/prepare_wheelchair_weak_data.py \
    --data-root data/wheelchair_raw \
```

基础 info 默认包含五类场景，不含 old1/old2；无 GT，只用于读取/推理。缺位姿保留 `has_pose=false`，不能将预处理中的单位变换当作在线有效定位。

人工标注键必须通过 `scene.frames[k].frame_index` 映射原始帧，不能用 `k+1`。原伪框为 `[x,y,z,dx,dy,dz,yaw]`，z 是几何中心。人工中心和原伪标签互补保留，不按两类之间的中心距离去重。监督语义统一见本文[弱监督方法](#监督语义与弱监督方法)。

弱生成器输出全量、室内、过渡及中心完整性分层 info，并记录实际参数。阶段2/3与验证使用的关键分层为：

```text
wheelchair_weak_infos_train_indoor_exhaustive.pkl
wheelchair_weak_infos_train_indoor_non_exhaustive.pkl
wheelchair_weak_infos_val_indoor_exhaustive.pkl
```

仅人工补全帧的人工中心与伪标签中心并集近似穷举；不因此把 size/yaw 提升为完整3D真值。未知区域不自动当作背景。新机器只在来源可信、数据或处理版本变化时追加代表样本核对，不加载来源不明的 pickle。

## rosbag人工中心复核与增量训练

标注分成“先计算建议”和“人工复核”两个阶段。`predict` 按原时间顺序处理约 10Hz 全部扫描，把候选存入 `annotations.sqlite`，结束后释放 GPU。`open` 只读取这些建议，不运行模型。同模型继续计算会复用候选并保留人工编辑，换模型则要新建工程。

多个子包共享数据库，但进度各自保存。`--start/--duration` 相对每包首帧点云的记录时间计算。

可显式指定点云／RGB话题、初始子包及采样步长。导入`--detections`须有相邻`settings.json`或`manifest.json`的模型、单帧／范围来源，并逐扫描匹配指纹；不能把跟踪预测当标签。只有来源不符或候选缺失时才重新预计算，不在切帧时隐式推理。

完整流程是先计算检测建议，再逐子包核验或补充 XY 中心，然后导出点云、当前 RGB 和核验标签，最后独立启动微调。预计算可以按冻结工程配置使用单帧或多帧，人工标签仍只描述当前帧。

标注不需要 ROS master、RViz、地图、IMU 或相机外参，RGB 只是辅助。工具不标完整 3D 框、轨迹，也不自动传播跨帧标签。

标注范围为模型的XY矩形边界，包含原点及车体周边，不按未知车体形状设禁选区。检测／训练的近场点云过滤独立维护，使用近场标签训练前需确认预处理适用；工具不自动改写已有人工结果。

入口与命令统一见[感知导航操作速查](../感知导航操作速查.md#bag-行人中心标注)。实现位于 `perception/detection_tracking/annotation/`：本机模式用系统 Python 读取 bag 并运行Qt；远程模式用 Windows Qt 绘制、Linux HTTP服务供数，ROS读取保留在系统解释器子进程。独立检测环境只在预计算命令中运行模型，标注窗口使用缓存或手工输入。

### 标注操作

“标注帧”是人工纳入后续训练或验证考虑的帧。初始所有扫描都是非标注帧，计算建议、打开窗口、切包、筛选和普通浏览都不会改变状态。每个子 bag 独立保存进度、采样步长和断点，共用同一个 SQLite 文件。

| 帧的类别／状态 | 成为该状态的操作 | 用于训练导出 |
|---|---|---|
| 非标注帧 | 初始状态，未加入标注计划 | 否 |
| 标注帧：待标 | 确认／拒绝候选，或添加／调整人工中心；无人工处理后退回普通帧 | 默认导出；仅正中心监督 |
| 标注帧：跳过 | 点击“标记为跳过”或按2，无需先作修改 | 否 |
| 标注帧：已标 | 点击“标记为已标”或按3，直接认定当前整帧标注 | 是 |
| 标注帧：已标（无人） | 点击“标记无人／空标注”或按4，明确认定检测范围内无人 | 是；完整背景监督，中心为空 |

#### 准备与修改

先预计算，再打开窗口选择子包。新工程使用当前[推理模型](技术实现-检测与跟踪推理.md#配置和指定模型)，已有工程继续使用冻结的配置、候选和人工结果，不能直接换模型。

多帧预计算通过 `predict --pose-results` 指定已有定位，有图优先、无图次之，只使用连续局部位姿，不拼接地图修正。实际输入数记录在 `input_context` 中。断点恢复会恢复历史上下文，复用帧不额外执行网络，也不需要 ROS master。

选中候选后按 `Q` 接受、`R` 拒绝，按 `E` 在 BEV 添加漏检中心。已接受中心可以拖动或输入 XY 后移动，原建议框留在参考位置。按 `C` 恢复选中候选为未核验，用 `R` 删除人工点。最后一项人工处理移除后，帧退回普通状态；撤销和重做同样保存。

原始帧、采样步长和时间跳转都只浏览，备注、筛选与视图操作也不建立标注帧。

#### 标记整帧与无人帧

按 `2` 标记跳过，按 `3` 标记已标，均立即保存、不弹确认，也不自动跳帧。按 `1` 取消完成或跳过状态，有人工处理则回待标，否则回普通。

标记已标会接受显示阈值内剩余候选。如果还有低于阈值的隐藏未决项，必须先处理，否则不能确认。显示筛选不缩小监督范围，零中心标为已标也表示人工认定范围内无人。备注独立保存，不改变状态，旧工程已有标记继续保留。

按 `4` 或点击“标记无人／空标注”，会拒绝检测范围内全部建议，包括隐藏低分项，并清除已接受中心和人工点，保存为已标无人。该操作立即保存、不跳帧，可以用 `Ctrl+Z` 撤销，之后编辑中心或候选会回到待标。

无人帧在数据库中仍是 `complete`，只是中心为空，继续按原同步、时间条和导出流程使用。必须先读取有效扫描并检查完整检测范围，不能只因前视 RGB 中无人就确认。

| 视图／图元 | 含义与操作 |
|---|---|
| BEV | 可编辑XY，滚轮缩放、工具栏平移；黄框待复核、绿十字为人工中心、红框为已拒绝、灰色虚线框为接受后的模型参考 |
| 三维点云 | 高度使用跨帧一致的明亮色带；左键旋转、中键或`Shift`拖动平移、滚轮／右键缩放，白色突出当前选择 |
| RGB | 同时显示配对原图，悬停查看时间差，不依赖外参投影 |
| 布局与点大小 | 拖动分隔条调整视图，侧栏调节BEV与三维点径；显示设置保存，不改变点数、坐标或标签 |

三维网格间隔 1 米，位于检测范围 Z 下界，人工十字只表达 XY，不是地面或高度标注。“显示已拒绝”仍受显示阈值限制，“确认可见候选”只处理可见待复核项，隐藏项不变，帧保持待标。

#### 快捷键

输入框、数值框与下拉框获得焦点时保留原编辑行为；`F1`显示帮助。

| 快捷键 | 操作 |
|---|---|
| `1`／`2`／`3` | 回到待标或普通／显式跳过／显式已标，不跳帧 |
| `4` | 标记无人／空标注：拒绝全部范围内候选，清空中心，保存为已标；可撤销 |
| `W`／`S` | 优先跳到步长内的已有标注帧，否则按步长浏览 |
| `A`／`D` | 上一／下一原始帧，只浏览 |
| `↑`／`↓` | 选择上一／下一候选或人工中心 |
| `Q`／`R` | 接受选中候选／拒绝候选或删除人工中心 |
| `C` | 将选中候选恢复未核验，撤销该候选的人工决定 |
| `E`／`Esc` | 开始补点／取消补点、拖动与选择 |
| `B` | 立即接受可见待复核候选，保留隐藏项，帧变为待标 |
| `Ctrl+Z`／`Ctrl+Y` | 撤销／重做内容及状态 |
| `PgUp`／`PgDown` | 上一／下一子包 |
| `T`／`V`／`F` | 点云俯视／斜视／复位视图 |
| `H`／`L` | 显示已拒绝候选／切换选中目标局部点云 |

#### 跳帧与时间条

- `W/S`查找一个采样步长以内最近的已有标注帧，包含三种状态，抵达时保留状态；找不到则落到步长位置附近的实际扫描。所有跳转都不改变帧状态。
- 例如步长1秒，从9.5秒向前会复用已有10秒标注，再从10秒向前浏览约11秒的扫描，只有人工核验或补点才将其纳入待标。导航止于包边界，不跨包、不插值。
- 步长初次为1秒，按子包保存，显式`--sample-interval`优先；修改只影响后续导航，不重排已有标注。数据库状态`unreviewed / draft / skipped / complete`分别对应非标注／待标／跳过／已标。
- 时间条以各包首帧点云记录时间为零点：**黄＝待标、灰＝跳过、绿＝已标有人、紫＝已标无人**，白线为当前帧。两种已标共用已标行，顶端图例区分颜色；当前帧状态色条与按钮高亮使用相同颜色，悬停可见无人状态。点刻度回看，空白点击／拖动只浏览；`--start/--duration`之外变暗且不可跳入。颜色根据已标状态及中心是否为空推导，旧标注、撤销／重做和远程同步后均自动更新，不增加保存状态。

#### 保存、重置与划分

界面自动保存，不需要逐帧另存。切帧、切包或退出前先等本机写盘，失败时保留修改，可重试，或明确放弃后重新读取。本机尚未保存的工作稿仍在内存，远程模式另外使用持久暂存队列。

备注失焦、翻帧或关窗时提交，数值XY须点移动按钮才应用。修改已标／跳过帧会回到待标；撤销／重做恢复内容和状态。不能判断的帧保留待标或跳过，不作为无人背景导出；后导入候选只作参考，不重建人工结论。

折叠的“分组与序列管理”包含两类操作：

| 操作 | 范围与要求 |
|---|---|
| 清空当前序列所有标记 | **须确认、不可撤销**；清除当前子包全部状态、人工中心、候选决定和备注，含浏览范围外扫描，恢复非标注与原建议。保留检测、绑定、设置及其他子包；远程还须满足同步条件 |
| 设置训练划分 | 按子包填写采集组、地点组及train／val／holdout；同原包切片共用采集组，同地点共用地点组，导出拒绝任一组跨划分，不随机拆相邻帧。已有调试数据不改称盲测 |

### 远程标注与同步

远程模式把界面放在 Windows，数据和正式标签留在 Linux。两端使用同一套标注规则，Windows 通过 Tailscale 以服务地址与工程 ID 直连，不需要访问令牌，但仍遵守工程只读设置和单写入会话。

Windows 负责绘制三视图并保存个人缓存，不下载整套 bag。安装与启动见[远程服务命令](../感知导航操作速查.md#远程服务linux)，设备记录见[本机记录](../../ENVIRONMENT.local.md)。

Linux HTTP复用项目开发／检测Conda环境，系统ROS子进程读取bag；Windows只安装客户端依赖。该接口只提供已有数据与标注读写，不运行检测或训练。不同设备的图形性能、网络延迟和故障恢复验证按实际使用范围记录，不由功能可用推断统一性能保证。

#### 连接与权限

服务端 JSON 登记允许访问的工程、稳定 `server_id` 和实际 `ros_python`。工程必须已有索引与扫描对应关系，客户端不能提交任意文件路径。示例的 `read_only=true` 用于浏览，正式标注需要改为 `false` 后重启，客户端不加 `--read-only`。

服务只监听回环或当前 Tailscale 地址，默认使用已激活项目环境，也可通过 `SOCIAL_NAV_ANNOTATION_SERVICE_PYTHON` 指定。Windows 只装客户端依赖，不复制服务器环境。

#### 浏览与本机暂存

首次打开需要联网。点云保留完整 XYZI 与原输入来源，RGB 默认是原分辨率 JPEG 预览，需要无损细节时可选 PNG。切帧刷新服务器状态，旋转、缩放和点大小调整复用本机资产，不持续传输 bag。

缓存有容量限制。断网后，已缓存帧可以继续浏览并暂存编辑；未缓存扫描会明确失败，不显示旧帧来代替。

| 侧栏提示 | 含义与后续操作 |
|---|---|
| 正在本机暂存 | 修改尚未写入客户端SQLite；切帧／退出先等待落盘 |
| 已在本机暂存／待同步 | 修改可随同一缓存重开恢复，尚未进入服务器标签和训练导出 |
| 服务器已保存 | 对应操作回执已确认；后续编辑继续单独同步 |
| 同步冲突 | 保留本机草稿，停止继续编辑；不会覆盖服务器当前结果 |
| 只读浏览 | 工程配置为只读、显式只读打开或其他设备正在写入；不提交新标注 |

#### 同步与冲突

“同步／重连”恢复连接，查询原操作回执并更新索引。网络失败时保留原操作 ID，服务器对同一个 ID 不重复写入；结果未知时先查回执，不能换 ID 盲目重发。

“处理同步冲突”需要确认。它将冲突子包中全部未同步编辑移到本机冲突存档，再读取服务器结果，不自动合并或覆盖。存档和待同步操作都可以显式导出。

同一工程只有一个写入会话，客户端定期续期，第二台只能只读。换设备前应等待“服务器已保存”，再关闭原客户端。本机直接打开工程时，也会拒绝在有效远程写入会话期间修改。

退出时仍有未同步编辑，会询问是否保留暂存。恢复时沿用同一服务地址、工程 ID 和缓存目录。不可达、权限不足或冲突都不会显示为已同步。

清空序列需要联网，并先同步完已有队列，仍通过原确认框执行。结果未知时暂停编辑，等回执和界面刷新。清空使来源代次递增，旧离线编辑不能把已清空标签写回来。

Linux 导出只读取服务器已经保存的待标与已标，Windows 未同步修改不会进入数据集。

资产、设置、待同步编辑和冲突存档都在 `cache.sqlite` 中，旁边锁文件阻止两个窗口共用缓存。SQLite 的 WAL/SHM 附属文件不能手工删除。

LRU 只淘汰资产，即使待同步帧的点云或图像被淘汰，人工编辑和输入摘要仍保留，再次查看需要联网。未同步编辑与冲突存档不随资产清理，不能用删除整个缓存来处理连接问题。默认位置见开发指南，草稿导出命令见操作速查。

实现均在`perception/detection_tracking/annotation/`。HTTP请求绑定服务／工程身份、扫描指纹、期望修订及来源代次；服务器在同一SQLite事务内核对状态、写标签并记录回执。迟到读取或回执不能覆盖新草稿，客户端不直接挂载服务器SQLite。

### 导出与微调

导出默认取待标和已标帧，`--complete-only` 只取已标，普通和跳过帧不作为当前标注样本。正标签只有接受的检测中心与人工 BEV 点，预测框不是几何真值，未决候选也不会自动变成正标签或背景。

即使所有候选都处理过，待标仍按部分中心监督。零中心待标没有负样本意义，只有明确已标的无人帧提供完整背景。

数据集仅包含以下三类内容，不复制bag、模型、数据库、IMU或历史图像：

```text
points/<来源ID>/<原始扫描序号>.bin   # 原始float32小端XYZI，每个实际扫描只存一份
images/<来源ID>/<标注当前帧序号>.png  # 当前帧配对RGB，无损PNG
annotations.json                    # XY标签、当前／历史引用、可选位姿与变换、时间、来源摘要和分组
```

`--history-frames N` 是不含当前帧的历史扫描数，默认 0。导出沿原始点云序列向前取最近 N 帧，`--history-stride K` 控制原始扫描间隔，不是取前 N 个标注帧。普通和跳过帧也可能成为历史资产。

重复历史按来源和扫描去重。不足时保存实际存在数量并统计，不复制填充、不跨子包、不取未来。`--sequence` 与 `--start/--duration` 限制当前标注帧，所需历史仍可早于范围起点。`--dry-run` 只规划样本和去重后的点云数量，不读取 bag。

历史点云文件始终保存各帧原始雷达坐标。需要运动补偿时，加`--pose-results <已有结果根目录>`关联定位：按子包优先使用`localization/<包名>`，其次`odometry/<包名>`，也可直接指定单次结果目录。结果须成功完成并绑定同一bag，关联会核对已有bag指纹、记录运行及状态文件摘要；静止假设结果不能代替实测位姿。

位姿按雷达消息头匹配最近过去状态，默认最大时差 20ms，可用 `--max-pose-age` 调整。变换来自同一运行的连续局部雷达位姿：`T_当前←历史 = inverse(T_局部←当前) × T_局部←历史`。可用地图位姿另存为来源，不直接把地图修正用于相邻扫描补偿。

训练加载历史时才应用变换并填第五维时差。点云文件始终保留各帧原始雷达坐标，避免重复补偿。

跨子包、定位会话／生命周期或失效状态不生成变换；初始化无位姿时仍保留当前单帧，有部分有效历史时只加载有效历史，缺失原因写入元数据。不用原始ROS里程计、未来位姿或单位矩阵补位。历史定位仍受当时的标定和算法精度限制，不作为真值；这里只补偿扫描间自车运动，不消除扫描内部畸变或行人自身运动。

训练仍默认`MAX_SWEEPS=1`。关联位姿后可显式设置`MAX_SWEEPS=历史帧数+1`，并按历史步长配置`MAX_SWEEP_TIME_LAG`；未关联位姿的旧导出在请求多帧时仍明确报错。实际可加载历史数可能因包边界、位姿失效或时间窗而减少。

RGB 沿用标注器的因果配对，图像不晚于点云，默认最多早 100ms。切包等情况可以用秒制 `--max-image-age` 调整，实际窗口与时差写入元数据，不取未来图像。

默认缺图会使整次导出失败，不发布半成品。显式 `--allow-missing-images` 才保留缺图样本，记录 `image=null` 与缺失数量。省略 `--out` 时写入 `data/datasets/wheelchair_det_extra/<工程名>/`，也可显式指定新目录。原 bag 和标签只读，未划分的数据可以先导出保存。

`CodaDataset`直接读取`annotations.json`，按来源的`train / val / holdout`筛选；训练要求有效采集／地点分组，阻止已知分组跨划分。可用`data/datasets/wheelchair_ros_centers`别名，也可由下述准备工具直接绑定导出目录，无需复制点云。新JSON不依赖pickle；历史可信pkl输入继续支持。

[voxelrcnn_ros_centers_finetune.yaml](../../perception/detection_tracking/training/simpledet3d/configs/voxelrcnn_ros_centers_finetune.yaml)沿用原Stage3冻结策略：关闭EMA，仅冻结Z／尺寸／yaw与ROI框回归分支，VFE、3D骨干、2D共享特征、XY及分类参与训练。冻结名单直接继承Stage3配置。仅复核当前范围时关闭随机旋转、缩放及平移，保留保持范围覆盖的Y镜像，避免未复核行人经增强进入训练范围成为假背景。

`tools/task_scene.py prepare`显式将指定导出的采集组用于训练，生成绑定文件摘要、路径和`ROS_GROUP_ASSIGNMENTS`的输入YAML，按`data/datasets/wheelchair_det_extra/<名称>.yaml`保存；不会修改人工SQLite或原`annotations.json`，也不会重新解释已有验证划分。支持重复`--annotations`加入更多导出，`--complete-only`仅用已标帧。地点组应保守覆盖已知重复路线，同一采集及地点不跨训练／验证。

准备、CPU检查、训练与对比命令集中在[操作速查](../感知导航操作速查.md#任务场景检测微调)。新实验默认从对应输入帧数的历史Stage 3最佳权重初始化，直接开始第三阶段，可用`--pretrained_model`显式覆盖；选择规则见[模型资产](#模型资产与输入帧数)。`--ckpt`恢复完整状态时要求同一份输入记录及相同冻结策略。新增标签或更改采样／时序设置后重新准备输入并使用新实验目录；更改冻结策略也使用新实验目录及预训练初始化，以匹配可训练参数和优化器状态。

### 任务场景增量适配

增量训练直接继续第三阶段，不重跑前两阶段，适配的是部署任务分布，不固定为室内。`TaskSceneDataset` 合并新 JSON 和历史目标域，`CyclicCoverageSampler` 管理每轮曝光及跨轮回放，仍使用 `tools/train.py` 与 `tools/test.py`。资源与结果入口见[本机记录](../../ENVIRONMENT.local.md#原始与派生数据)，能运行不代表误检已改善。

[train_wheelchair_task_scene.sh](../../perception/detection_tracking/training/simpledet3d/train_wheelchair_task_scene.sh)提供与三阶段脚本一致的环境变量入口：`TRAIN_CFG`选择已准备的输入YAML，`MAX_SWEEPS`选择帧数，`RUN_TAG`区分实验。`BATCH_SIZE`、`EPOCHS`和`EPOCH_SAMPLES`未设置时沿用YAML，不在脚本另设一套训练预算；`PRETRAINED_MODEL`／`CKPT`分别覆盖初始化／完整恢复。默认两卡并固定随机种子，完整参数见脚本帮助，命令见[操作速查](../感知导航操作速查.md#任务场景检测微调)。

脚本只启动训练；导出、准备新配置及对比模型继续使用各自入口。`DRY_RUN=1`复用`tools/train.py --dry_run`解析最终配置及权重选择，不读取训练样本、创建输出目录或初始化CUDA，不能代替数据完整性或训练可运行性检查。

#### 数据与采样

采样权重描述每帧在一轮中的目标曝光率，不固定数据集、场景或正负帧总占比，也不乘到损失上。本次第三阶段不加入 CODa，Stage 1、2 和历史记录保持原职责。

| 样本来源 | 每帧目标曝光权重 | 监督边界 |
|---|---:|---|
| 新增任务标注 | 1.0 | 待标只提供已核验正中心，已标提供约定范围背景；明确无人帧与有人帧权重相同 |
| 历史Wheelchair高频穷举中心 | 0.2 | 保留既有完整性及弱监督掩码；历史3D伪框不升级为完整框真值 |

`TASK_SCENE.SAMPLER=cyclic_coverage` 使权重 1 的有效新增帧每轮出现一次，旧帧按分数权重分配回放数量。旧样本池先打乱，下一轮继续读取尚未覆盖部分，而不是从头重新抽签。

一轮跨越池尾时，先取完余项，再从重新打乱的下一循环补齐，同时把本轮已选项移到后面，保持轮内不重复。各池索引最后统一打乱，再分给 DDP 各 rank。

默认预算下，新帧每轮 1 次，旧帧约 0.2 次，整数取整与 DDP 对齐会产生小偏差。新数据占比约为 `N_new / (N_new + 0.2*N_old)`，随样本量变化，不能解释为每次抽签概率恒为 1:5，也不只是把多项式采样改成不放回。

0.2 是任务回放选择，不是从 10Hz 与 1Hz 严格推导。旧帧不按 1 秒桶删除，也不另做场景均衡。来源和地点分组仍用于隔离训练与验证。

#### 无人帧与误检

只有人工确认完整检测范围无人、标记 `complete` 且中心为空的帧，才提供 Dense 背景与 ROI 负分类。现有 `ALLOW_EMPTY_GT`、完整性 mask 和零 GT 分支支持它。

未知、未核验和零中心待标不能替代无人标签，零中心待标本轮也不占采样预算。前视 RGB 只是辅助，还要检查其视野之外的点云。

- 优先补充会诱发高置信误检的椅子、轮椅、展示设施、立柱、设备等无人场景，兼顾室内外、距离与视角；采样不同背景，少重复同一个静止位置。
- 无人帧与同来源有人帧使用相同权重，不另设负样本配额；通过增加不同场景的有效无人标注补充背景。有人帧中的已复核背景同样参与抑制误检。
- 待标帧中删除候选目前不会形成专门的局部负监督。优先完整复核这些帧并手动标为已标；未完整复核时仍只使用其已核验正中心。局部拒绝区域mask留待确有需求时实现，不自动扩大为全帧背景。
- 首轮沿用既有Focal Loss和背景权重，先改变数据组成，不叠加新的负样本损失或同时调多组阈值。聚焦困难背景、控制简单负样本数量的依据见[Focal Loss原论文](https://openaccess.thecvf.com/content_iccv_2017/html/Lin_Focal_Loss_for_ICCV_2017_paper.html)；上述帧比例仍须由本项目验证。

#### 训练预算与恢复

默认单帧、两卡、FP32，从相同帧数的历史 Stage 3 最佳权重开始。冻结模块保持 eval，但共享特征仍在变化，因此冻结回归头不表示几何数值完全不变。学习率、轮数与冻结名单以增量 YAML 和 Stage 3 基配置为准。

多帧实验通过 `--max_sweeps` 显式选择，测试必须使用相同输入。缺位姿时的降级见[导出与微调](#导出与微调)。

先过滤无监督草稿，再计算轮长。`EPOCH_SAMPLES=null` 时，轮长为 `ceil(sum(N_i*w_i))`，并向上对齐到卡数倍数。权重 1 的样本全部保留，剩余名额按各分数权重池的样本数与权重分配，轮间配额固定，使训练步数与学习率调度稳定。

`--epoch_samples` 只改变分数权重池回放量，不重复新增帧。预算不能少于权重 1 的样本数，DDP 对齐后不能超过全部唯一帧数，无法同时满足则报错。循环模式只支持 `0<WEIGHT<=1`。

固定种子、数据顺序、轮次、配额和卡数即可重建相同分片，不需要保存额外循环池。训练先 `set_epoch` 再创建 DataLoader 迭代器，恢复首轮预取也使用正确索引。

`training_data.json` 记录策略、池规模、配额、实际曝光率、输入摘要和数据配置。更换输入或策略后，用新实验目录及 `--pretrained_model` 初始化，不续用旧优化器。历史有放回的 `weighted_replacement` 只用于复现，不重写已有记录。

#### 划分与模型对比

同一原始长包和重复地点不能跨训练与验证，切成子包也不成为独立采集。缺独立新场景验证组时，旧验证只检查遗忘，新样本回代只作开发诊断。

后续独立采集应完整复核，并按室内、室外、有人和无人分组。无人集报告 FP/frame 与出现误检的帧比例，不报告未定义召回率。

`tools/task_scene.py compare`在相同未加权样本、检测范围及后处理配置上比较部署基线与一个候选，保存一份JSON：总体及按数据源／已知采集组／地点／序列的中心Precision、Recall、F1、漏检、FP/frame，以及无人帧和上述距离分层／加权指标。默认沿用`score=0.3`、最终`NMS=0.2`；`--score-threshold`同时覆盖检测输出和中心评估计分阈值。没有定义的指标写`null`，不用零伪造无人集召回。`--diagnostic-training`明确标记训练集回代，`--limit-per-dataset`明确限制诊断预算；两者以及历史弱验证均不作独立效果验收，`--max-recall-drop`仍约束全范围Recall，不替代近距离检查。

`TASK_SCENE.TRAIN_DATASETS`配置每个来源的逐帧`WEIGHT`与数据覆盖项，`VALIDATION_DATASETS`独立配置验证来源；各`CONFIG`覆盖基础`DATA_CONFIG`，可指定不同数据根、info列表、划分及组归属。新增独立标注后，将其配置为验证来源、设置`ROS_COMPLETE_ONLY=true`及`VALIDATION_ROLE=task_development`；留出测试可使用`DATA_SPLIT.test=holdout`。新场景验证应完整复核，部分标注仅提供已核验中心召回，不计未知背景为误检。验收前明确`--max-recall-drop`，只有完整的任务开发集对比才判断约定的误检／召回取舍；工具不会替换部署权重或自动启停训练。

## 模型资产与输入帧数

用户提供的历史模型统一保存在`models/wheelchair_detector/{1,2,3,4}frame/`。每组包含：

| 相对路径 | 用途 |
|---|---|
| `checkpoints/coda_initialization.pth` | 对应输入帧数的CODa-16line权重，用于Stage 1初始化 |
| `checkpoints/stage1_final.pth` | Stage 1最终权重，用于Stage 2初始化 |
| `checkpoints/stage2_best.pth` | Stage 2最佳权重，主权重为被评价的EMA，用于Stage 3初始化 |
| `checkpoints/detector_best.pth` | Stage 3最佳权重，用于推理或任务场景增量训练初始化 |
| `training/portable_configs/`、`training/history.json` | 原包展开配置及历史训练来源，保持原始内容 |

2／3／4帧组另含原包`inference/detector_<帧数>frame.yaml`及`manifest.json`；原包清单用于追溯来源，不表示目录中已解压清单内的全部文件。完整源码、日志及其余资料留在原ZIP中，资产来源见模型根目录`SOURCE.md`。后续训练产物继续放在检测副本`output/<配置名>/<实验名>/`，不覆盖这些历史权重。

`MAX_SWEEPS=N`表示**当前帧加最多N−1个历史帧**，不是N个历史帧。多帧输入须匹配权重、配置、位姿补偿和时间差通道；训练／测试入口的`--max_sweeps`须保持一致。训练配方仍默认单帧；后续推理测试与新工程候选生成默认使用3帧任务场景候选，在线／ROS也通过同一适配器读取可靠历史，详见[推理配置](技术实现-检测与跟踪推理.md#配置和指定模型)。

当前部署候选另存为 `3frame/task_scene/detector.pth`，保留第 2 轮全部模型张量与来源，没有优化器状态，不能用于完整恢复。它不覆盖原 Stage 3 或训练自动选择的 `best_model.pth`。

候选用于开发测试和生成待复核建议，预测不是人工真值。旧工程与导出继续对应原模型，路径和输入由推理配置维护，来源见模型根目录 `SOURCE.md`。

初始化按最终输入帧数自动选择：

| 入口 | 默认初始化 |
|---|---|
| 三阶段脚本Stage 1 | `Nframe/checkpoints/coda_initialization.pth`；`MAX_SWEEPS`决定N，`CODA_CKPT`可覆盖 |
| `tools/train.py`任务场景增量训练（含微调脚本） | `Nframe/checkpoints/detector_best.pth`；CLI `--max_sweeps`优先于YAML，`--pretrained_model`可覆盖 |
| 其他独立训练配方 | 保持显式初始化／从头训练，不自动套用Wheelchair权重 |

路径均位于上述模型根目录。0按单帧处理；缺少对应权重直接报错，不回退到其他帧数。自动增量初始化要求VoxelRCNN／Pedestrian及各任务数据来源具有一致的输入帧数；如有逐来源时序覆盖，需自行明确初始化权重。实际选择写入训练日志。

权重选择按以下优先级：显式 `--ckpt`、当前实验目录的 epoch 断点、显式初始化、按帧数默认初始化。完整恢复不会读取初始化权重，也不要求它仍在原位置。

自动恢复按新到旧尝试，全部失败就终止，不转为新训练。修改帧数或输入后要换实验名，不能继续旧优化器状态。

历史展开配置用于追溯实验，不替代当前环境的训练策略。2／3帧的三阶段训练预算为10/10/5轮，4帧为10/12/5轮；4帧原包未附独立CODa训练YAML，其实际配置可查`training/history.json`。复用当前两卡脚本做多帧实验时，只需设置`MAX_SWEEPS`；如需沿用4帧历史轮数，另设`STAGE2_EPOCHS=12`，不会因选择4帧自动改变训练预算。

## 单帧、两卡三阶段训练

仓库内当前训练配方和一键脚本默认单帧 `MAX_SWEEPS=1`，CODa/Wheelchair 一致，保留第五维 `time_lag=0`。已有历史 sweep 索引可复用，加载时忽略历史帧。

默认使用 GPU 0、1，FP32，每卡 batch 8、每进程2个 worker。轮数、验证间隔和阶段衔接以 [train_wheelchair_3stage.sh](../../perception/detection_tracking/training/simpledet3d/train_wheelchair_3stage.sh)为准，手册不另维护完整默认值表。

```bash
# 副本根目录：打印命令与路径检查，不启动训练。
DRY_RUN=1 RUN_TAG=wheelchair_two_gpu_new ./train_wheelchair_3stage.sh

# 确定训练资源后正式执行，使用新的实验名。
RUN_TAG=wheelchair_two_gpu_new ./train_wheelchair_3stage.sh
```

初始化自动选择对应帧数的CODa权重；例如仅检查3帧训练入口：

```bash
MAX_SWEEPS=3 DRY_RUN=1 RUN_TAG=wheelchair_3frame_new ./train_wheelchair_3stage.sh
```

需要手动覆盖资源时：

```bash
CUDA_VISIBLE_DEVICES=2,3 NPROC_PER_NODE=2 BATCH_SIZE=8 WORKERS=2 \
CODA_CKPT=/path/to/coda_single_frame_checkpoint.pth \
RUN_TAG=wheelchair_other_gpus_new ./train_wheelchair_3stage.sh
```

`BATCH_SIZE` 为每卡 batch，全局 batch 等于每卡值乘进程数。精度、轮数、输入帧数和验证间隔可通过脚本同名环境变量覆盖。脚本默认实验名按输入帧数区分，单帧保留原名；独立新实验仍应显式指定新`RUN_TAG`，不能从旧单帧/多帧结果混合恢复。手动覆盖的权重由调用者确保与输入匹配。

三个阶段的监督职责：

| 阶段 | 数据与行为 |
|---|---|
| Stage 1 | CODa 完整框＋Wheelchair 全量目标域，完成混合适配 |
| Stage 2 | CODa、室内穷举中心帧、室内非穷举帧分层采样；EMA 仅升级已有中心附近的可靠几何，穷举帧启用中心/背景与 ROI 中心分类 |
| Stage 3：任务场景适配 | 历史配置保留室内穷举集；新增标注采用[任务场景增量适配](#任务场景增量适配)，沿用原几何分支冻结策略，VFE、3D骨干、2D特征、XY及分类参与训练 |

损失和采样依据见[监督方法](#监督语义与弱监督方法)。配置中的`ALLOW_UNMATCHED=false`保留；无标签帧不作负样本，也不凭一次Teacher输出新增无锚点正目标。

三个阶段使用相同实验名、不同配置目录。Stage 2 接收 Stage 1 最终 checkpoint，Stage 3 优先接收 Stage 2 的最佳模型，缺失时使用最终 checkpoint。相同 `RUN_TAG` 会跳过已完成阶段并恢复未完成阶段；新实验必须更换名字。

阶段2普通 checkpoint 保存 Student 和 EMA；恢复两者时使用 `--ckpt`。弱验证默认评价 EMA，因此其 `best_model.pth` 主权重也是被评价的 EMA，可用于下一阶段 `--pretrained_model`。权重受限加载并先映射 CPU，再转到当前 rank；来源不明的 pickle 不在兼容范围内。

## 独立训练、恢复与评估

```bash
# 单卡完整监督训练。
python tools/train.py --cfg_file configs/voxelrcnn_coda_16line.yaml \
    --extra_tag coda_single_frame_new

# 单独调试某阶段；以下初始化路径需使用实际已完成的上一阶段结果。
CUDA_VISIBLE_DEVICES=0,1 torchrun --standalone --nproc_per_node=2 tools/train.py \
    --cfg_file configs/voxelrcnn_wheelchair_weak_stage2.yaml \
    --pretrained_model /path/to/stage1_final.pth \
    --extra_tag stage2_indoor_new --eval_interval 1

# 完整恢复与仅加载初始化权重的含义不同。
python tools/train.py --cfg_file configs/voxelrcnn_wheelchair_weak_stage2.yaml \
    --ckpt /path/to/stage2_epoch.pth --extra_tag resumed_stage2

python tools/test.py --cfg_file configs/voxelrcnn_coda_16line.yaml \
    --ckpt /path/to/coda_checkpoint.pth
```

DDP 日志、TensorBoard、保存与验证由 rank 0 执行，其他 rank 配合同步。每个实验输出到 `output/<配置名>/<extra_tag>/`。已有目录可能触发自动恢复，不用其作为新实验输出。

`--eval_interval` 控制训练中验证；`--ckpt_save_interval/--max_ckpt_save_num` 控制保留数量。普通 epoch checkpoint 保存最佳指标元数据，恢复时结合历史最佳模型取较优者；缺最佳指标元数据的旧 checkpoint 从恢复后的验证重新跟踪。恢复 EMA、优化器、GradScaler 要使用完整训练 checkpoint，部署最终权重没有优化器状态。

`--precision` 优先于 YAML，可用 fp32/fp16/bf16；`--use_amp` 仅是 fp16 兼容别名，不与不同精度同时使用。混合精度保留 FP32 主权重，不调用 `model.half()`；当前稀疏实现的 bf16 路径可能仍采用 fp16，不能把 autocast 通过当原生 BF16 稀疏运算验证。

完整监督CODa可以报告AP3D/APBEV；Wheelchair仅按[中心评估边界](#评估与模型选择)评价，不用中心指标代替3D AP。

显存管理先选择 CUDA 设备，再初始化 NCCL。Teacher 注入伪标签后释放特征与 head 缓存，`DynamicVoxelVFE` 实际执行训练和测试体素上限；超限时用确定性坐标哈希选择，Teacher 与 Student 对同输入保持一致，未超限则沿用原数值路径。

显存不足时先区分每卡点数、体素负载和缓存，按需开启 `LOG_GPU_MEMORY=1` 或 `--log_gpu_memory`，排查后关闭，不在每个 iteration 清缓存。

## 实现与源码导航

训练入口直接构建模型，不采用注册器；数据流为：

```text
可信 info + 原始点云
  → CodaDataset / 历史帧选择与位姿变换
  → 特征编码、增强与数据处理
  → collate_batch / load_data_to_gpu
  → VFE → 稀疏 3D backbone → BEV 2D backbone
  → CenterHead →（VoxelRCNN 的 ROI pooling/head）
  → 完整/弱监督损失或后处理与评估
```

info框为`[x,y,z,dx,dy,dz,yaw]`，点为`[x,y,z,intensity,time_lag]`；sweep只取过去并变换到当前LiDAR系，GT及弱监督权重／掩码同步变换，字段与背景语义见[监督方法](#监督语义与弱监督方法)。

以下路径都相对于检测副本：

| 源码 | 修改时关注的内容 |
|---|---|
| `tools/train.py`、`tools/test.py` | 参数覆盖、DDP、权重与恢复、训练/评估入口 |
| `simple_det3d/utils/config.py` | YAML 递归继承与命令行覆盖 |
| `simple_det3d/datasets/coda_dataset.py` | 数据加载、路径重定位、单帧/sweep 与批处理 |
| `simple_det3d/datasets/data_augmentor.py`、`data_processor.py` | GT采样、增强、特征编码与体素参数 |
| `simple_det3d/datasets/mixed_domain_dataset.py`、`weak_label_utils.py` | 域与完整性分层采样、弱监督字段和权重 |
| `simple_det3d/models/vfe.py`、`backbones_3d.py`、`backbones_2d.py` | Mean/Dynamic VFE、体素限流和特征 |
| `simple_det3d/models/center_head.py`、`voxel_rcnn_head.py` | Dense/ROI 预测、目标分配、弱掩码与中心分类 |
| `simple_det3d/models/voxel_rcnn.py` | VoxelRCNN、目标域分支与冻结策略 |
| `simple_det3d/train/train_utils.py`、`ema_utils.py` | 优化、EMA伪标签升级、验证和 checkpoint |
| `simple_det3d/ops/` | 四个自定义 CUDA 扩展及 Python 封装 |
| `tools/prepare_wheelchair_weak_data.py` | 标注映射、过滤、完整性分层与 info 生成 |

CenterPoint 使用 MeanVFE 和 Dense Head；VoxelRCNN 使用 DynamicVoxelVFE，增加 ROI pooling 与分类/回归。动态体素数量上限必须实际生效，Teacher/Student 对同一输入采用一致的确定性限流；部署加载严格检查checkpoint参数匹配。

新增模型需实现训练/推理 forward 及初始化/完整恢复接口，在 `models/__init__.py` 显式添加构建分支；新增数据优先复用 info 格式，确有差异再增加 Dataset。函数签名、完整默认值和各模型结构以源码、YAML 及工具 `--help` 为准。

相关CPU测试位于副本`tests/`；只选择本次修改涉及的数据、损失、时序或恢复测试。根级行人检测跟踪及ROS输入／消息接口测试入口为`python -m unittest tests.test_detection_tracking`，不是训练精度验收。

## 方法依据

以下保留原设计参考，不把论文结果当成本项目成绩，也不表示其完整算法均已实现：

- [ST3D](https://openaccess.thecvf.com/content/CVPR2021/html/Yang_ST3D_Self-Training_for_Unsupervised_Domain_Adaptation_on_3D_Object_Detection_CVPR_2021_paper.html)：质量感知伪标签记忆和课程增强。

- [HSSDA](https://openaccess.thecvf.com/content/CVPR2023/html/Liu_Hierarchical_Supervision_and_Shuffle_Data_Augmentation_for_3D_Semi-Supervised_Object_CVPR_2023_paper.html)、[NoiseDet](https://openaccess.thecvf.com/content/ICCV2023/html/Chen_Learning_From_Noisy_Data_for_Semi-Supervised_3D_Object_Detection_ICCV_2023_paper.html)：分级／噪声监督。
- [WS3D](https://www.ecva.net/papers/eccv_2020/papers_ECCV/html/1956_ECCV_2020_paper.php)、[Back to Reality](https://openaccess.thecvf.com/content/CVPR2022/papers/Xu_Back_to_Reality_Weakly-Supervised_3D_Object_Detection_With_Shape-Guided_Label_CVPR_2022_paper.pdf)：中心点击与形状先验；本项目用源域完整框学习几何，对目标域采取更保守掩码。
- [DetMatch](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136700366.pdf)：2D／3D一致性候选，当前过滤不据此自动升级几何。
