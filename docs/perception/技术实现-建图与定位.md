# 技术实现：建图与定位

建图与定位为下游提供自车位姿。主方案中，FAST-LIO 用雷达与 IMU 连续估计局部运动，ROLL 在后台进行地图匹配或位姿图修正。系统将连续局部位置与地图修正分开保存，避免地图跳变影响人物速度和局部导航。

本文解释三种任务、地图关联、起点、标定和 GPU 实现。离线纯建图使用`build_map.sh`，联合感知导航使用直接运行时，旧 ROS 诊断与 PIN 实验单独说明。命令见[运行手册](../系统运行手册.md)，人物推理见[检测与跟踪](技术实现-检测与跟踪推理.md)，导航和决策需要的几何见[环境表示](技术实现-环境地图与场景表示.md)。

## 任务、配置与输入

| 任务 | `--mode`／默认后端 | 地图策略 |
|---|---|---|
| 建图 | `mapping`／ROLL＋FAST-LIO | 积累关键帧，后台按序检查回环，保存完整地图 |
| 有图定位 | `localization`／ROLL＋FAST-LIO | 指定完整先验和初值，关闭回环、更新及保存输入地图 |
| 无图定位 | `odometry`／FAST-LIO | 新建连续局部系、内部滚动匹配地图，不启动ROLL或输出全局先验 |

三种模式都支持 bag 和 live。无图定位没有预建先验，但仍维护内部局部匹配地图，不保证长期绝对位置。PIN 是另行选择的建图和固定地图实验后端，见文末专节。

独立离线建图实现位于`perception.mapping_localization.build_map`，复用`LocalizationSession`和现有传感器解码，不运行检测、环境地图更新或导航。前台按源顺序处理选定区间，以4帧提交窗口等待ROLL，默认封存去畸变扫描及射线原点。地图、连续局部位姿、扫描日志和来源指纹沿用现有格式，后续静态环境导出继续使用最终关键帧修正。扫描数量不符或运行失败时，不把部分输入报告为完整建图。

| 配置入口 | 职责 |
|---|---|
| [fast_lio.yaml](../../perception/mapping_localization/configs/fast_lio.yaml) | 输入、初始化及FAST-LIO基础参数 |
| [roll.yaml](../../perception/mapping_localization/configs/roll.yaml) | ROLL线程、关键帧／地图匹配与回环 |
| [mapping.yaml](../../perception/mapping_localization/configs/mapping.yaml)／[localization.yaml](../../perception/mapping_localization/configs/localization.yaml)／[odometry.yaml](../../perception/mapping_localization/configs/odometry.yaml) | 各模式地图、显示及资源策略 |
| [lidar_imu.yaml](../../perception/sensors/calibration/lidar_imu.yaml) | 当前安装／会话的空间与时差，可按次显式覆盖 |
| [pin_slam.yaml](../../perception/mapping_localization/configs/pin_slam.yaml) | PIN算法、查询及地图精修 |

FAST-LIO 根据静止或运动情况自适应初始化，只有输入与对齐条件通过后才输出有效状态。`initialization` 维护这些条件。人工起点对应首个扫描，初始化期间的运动通过参考位姿传播，不能把初始化结束位置误当首帧位置。ROLL 提交回环前核对地图快照，固定地图定位不修改输入地图。

直接运行时读取 bag 不需要 ROS master，在线输入则连接已有 master 和传感器。有图定位必须提供明确的地图初值，或从来源运行中继承初值。下面的隔离 master、模拟时钟和墙钟时长规则专指 `run_ros_diagnostic.sh` 的 ROS 诊断入口：

| 输入模式 | 调度与时间 |
|---|---|
| bag | 诊断入口自建隔离 master 与模拟时钟，扫描绑定结束时刻；`--start/--duration` 按记录时间选片段，`--rate` 控制回放。 |
| live | 连接已有master和话题；真实设备`use_sim_time=false`，外部bag模拟在线需显式`true`及`/clock`；`--duration`为墙钟秒，不接受bag偏移／速率 |

原始逐点绝对时间继续保留。检测与其显示使用原始扫描，配准和环境使用前端去畸变结果。缺少位姿时不填单位矩阵，也不借原始里程计替代。用同包先建图再定位时，应说明同源关系，不能作为独立精度评测。

## 局部定位与先验关联

公共定位上下文同时管理“局部位置是否有效”和“是否仍能关联到先验地图”。直接运行时默认使用它，并允许局部位置有效而地图关联缺失。ROS 诊断在显式 `--environment` 后启用相同语义：内部前端与地图消息由唯一 `localization_context` 汇合，再发布公共状态、地图关联和 TF。

| 状态 | 含义 |
|---|---|
| `LOCAL_INVALID` | 局部前端无效；不提供可融合世界位姿 |
| `LOCAL_ONLY` | 局部有效，无当前有效先验关联 |
| `ASSOCIATING` | 局部有效，地图候选仍在连续确认 |
| `PRIOR_ASSOCIATED` | 局部有效，当前先验关联有效 |

建图和无图定位的健康由局部配准决定。ROS 固定地图定位默认要求有效地图关联，需要 `--allow-local-only` 才保留离图后的有效局部输出；直接运行时已允许该行为。

`session_id/generation` 标识连续局部坐标的生命周期，`association_generation` 标识一次新接受的地图关联，`map_revision` 标识后端地图修正。这三种变化影响不同数据，不能互相替代。

每份地图匹配必须对应实际配准测量，以及完全相同观察的前端位姿。未来、跨生命周期、失配或过期结果不会使用。最近修正可以在有限年龄内传播，但原测量时间不变；失效后需要新的连续匹配才能恢复。

直接运行时在异步匹配完成后，立即用最后一份真实前端观察重新检查关联，不等待下一帧到来。检查与前端更新由同一把锁串行执行，沿用连续确认、可信覆盖、位姿对应和时效规则；达到要求的连续匹配数量后，停止遍历更早的确认历史。重新检查不增加观察、不推进时间，也不修改先前返回的记录。

重新检查产生的关联通过有界私有通道送到感知主进程。提交地图任务前，只能选择观察时间、局部坐标生命周期和地图资产均对应本次扫描的结果，原匹配时间不得晚于扫描。较新的失败结果同样会撤销本次关联；通道繁忙或没有对应更新时继续使用扫描包原关联，并接受其原有时效限制。场景一旦封存，后续关联不会回填其中，派生地图与独立安全检查使用实际封存的证据。

只有有效关联才产生地图位姿和新的 `map→odom`。地图修正发生跳变时，连续局部位姿和由它估计的速度保持独立。

### 手动地图可信区域与混合定位

使用`pick_coverage.sh --localization-map MAP --out COVERAGE.yaml`在二维地图上划定适合定位的区域；目标文件已存在时会加载其中的原有区域。窗口显示点云和建图关键帧轨迹，支持工具栏缩放／平移；左键逐点绘制，Enter闭合，Backspace撤销顶点。

底部“区域”列表区分原有和新绘制的多边形，选中项以橙色边界突出，也可以在区域内部右键选中。点击“删除选中区域”或按 Delete 可以删除选中项，包括从文件加载的原有区域。“清空全部区域”经确认后可以全部重画。

点击“保存区域”或按 Ctrl+S 才会写入文件，至少需要保留一个闭合区域；关闭窗口不会自动保存。多个多边形取并集，覆盖 YAML 保存地图资产指纹和坐标帧，重建地图后须重新选择。

区域只表达定位可信范围，不声明地面、空闲或可达，也不裁剪原始地图点云。

直接运行时通过 `--coverage COVERAGE.yaml` 选择可信区域。ROS 诊断对应组合为 `--environment --allow-local-only --association-coverage COVERAGE.yaml`。同一份区域同时约束 ROLL 匹配和公共地图关联：

| 情况 | 后端与公共输出 |
|---|---|
| 区域内，配准可信 | 接受地图修正；局部坐标继续由FAST-LIO维护 |
| 离开区域 | 以最后可信修正传播当前局部位姿判断边界，停止扫描到先验地图的匹配及修正，公共关联撤销，维持`LOCAL_ONLY` |
| 返回区域 | 进入边界内侧缓冲后重新匹配；检查残差、内点率、修正幅度、重力方向及连续候选一致性，通过确认后恢复关联 |
| 返图匹配不可信 | 保留连续局部定位，拒绝更新地图修正；可重新人工选点 |

只有配置区域时，才启用 [roll.yaml](../../perception/mapping_localization/configs/roll.yaml) 中的 `coverageGate`。启动时固定区域内容，公共层继续检查测量时间、来源和连续确认。详细记录保存拒绝原因与匹配前预测位置，缺失配准质量不会补值。未配置区域时，保持原匹配行为。

返回地图后，连续局部推算必须仍落在正确配准邻域，匹配才有机会恢复。这套机制没有解决长距离漂移、跨楼层或任意位置全局重定位。有效状态仍需结合轨迹与点云对齐查看，独立验收见[采集与验收清单](../系统实机问题.md)。

消息与TF发布权见[接口约定](../接口约定.md#可选环境状态与地图关联)，连续几何与场景消费见[环境文档](技术实现-环境地图与场景表示.md)。

## 起点与重新定位

### 独立标注bag起点

[pick_start.sh](../../perception/scripts/pick_start.sh) 是独立选点工具，不运行定位或检测。它只读地图、首帧雷达和此前 500 毫秒内最近 RGB，并创建临时 master。点云与图像可同时参考，左键旋转，中键或 Shift＋左键平移，滚轮或右键缩放，也可切到俯视或全览。

在地图中使用 RViz `2D Pose Estimate` 选择位置和朝向，工具按初值叠加青色扫描。控制窗口的 XYZ 使用米，RPY 使用度；Z 初值取最近 XY 关键帧的高度，多楼层或倾斜处仍需人工确认。保存会写入新的 `BAG.initial_pose.json`，直接关闭窗口则取消。`--start` 可指定偏移后的首帧。

起点文件保存六维雷达地图位姿、扫描时间，以及 bag 与地图指纹。它是人工初值，不是有效定位。`--pose-file` 只用于 ROLL 的 bag 定位，运行起始偏移必须与选点一致，也不能同时提供其他初值。

### 定位运行中的选点与重新定位

本节是旧 ROS 诊断入口的交互方式。直接运行时使用明确的 `--pose`、`--pose-file` 或来源运行中的初值，不会因开启显示而自动进入 RViz 等待。

| 输入 | 行为 |
|---|---|
| `--initialization rviz` | 地图加载后等待2D Pose Estimate，接受后才启动前端／输入；只加`--rviz`且无起点也默认此方式 |
| `--initialization map-start` | 仅确知与建图起点相同时使用；不开RViz且无初值时默认使用已知地图起点 |
| `--pose roll pitch yaw x y z` | 六维已知初值，弧度／米 |
| `--pose-file FILE` | 使用绑定的bag首帧起点文件 |

ROS 选点等待不计入任务 `--duration`，取消窗口或 Ctrl+C 会终止。接收初值不等于配准通过，健康以 `/localization/state` 为准。ROLL 运行中重新选点会清理旧扫描和显示，并增加重初始化代次；失败时不发布有效地图位姿。

公共环境上下文把连续局部身份与地图关联分开管理。仅地图重新关联时，不按后端代次清空局部人物轨迹。

## 传感器与标定

### 传感器接入

驱动来自用户提供的轮椅归档，包括 RoboSense SDK 1.5.0、rs_driver 1.5.6、realsense-ros 2.3.2 和独立底盘反馈节点。许可证留在源码目录，原始来源见 `data/datasets/wheelchair_live/README.md`。设备序列号由本机配置或显式参数提供，不写死在公共代码中。

| 内容 | 配置与约定 |
|---|---|
| 雷达 | RSHELIOS_16P；[rslidar.yaml](../../perception/sensors/ros/wheelchair_sensors/config/rslidar.yaml)选择型号／端口；`/rslidar_points`，`rslidar`系，保留`ring/timestamp` |
| 相机／IMU | D435i；[camera.launch](../../perception/sensors/ros/wheelchair_sensors/launch/camera.launch)维护开关、尺寸及帧率；默认`/camera/color/image_raw`与`/camera/imu` |
| 设备绑定 | 忽略的`configs/perception.local.json`中`sensors.serial_front/serial_rear`或显式参数；后视按需启用 |
| 驱动边界 | V4L2／IIO，不构建CUDA／Python SDK，不自动修改内核、固件、udev或重置设备 |
| 底盘反馈 | `wheelchair_sensors/odometry.launch`默认`allow_serial_read=false`，不发送控制命令；原始编码器里程计不作为可靠定位 |

驱动启动需要已有 master 和现场设备权限，不会启动底盘运动。FAST-LIO 与 ROLL 正常流程需要 D435i 的真实 IMU，只启用 `--lidar-only` 不足以运行。约 2000Hz 的 IMU 消息按原频率保留，并使用实际时间差积分，不默认降采样。

### 标定与数据边界

| 标定 | 唯一参数源 | 使用范围 |
|---|---|---|
| 相机—雷达 | [front_camera_lidar.yaml](../../perception/sensors/calibration/front_camera_lidar.yaml) | 整台D435i重新固定后的安装；用于二维—三维关联、离线投影与雷达—IMU空间先验，驱动不加载 |
| 雷达—IMU | [lidar_imu.yaml](../../perception/sensors/calibration/lidar_imu.yaml) | 当前安装的带先验空间标定和指定会话固定时差；默认由FAST-LIO／ROLL入口加载 |

定位和环境几何不需要相机图像或 YOLO。显式启用 VLM 图像辅助或 ROS 图像诊断时，才使用配对图像的 CameraInfo 与原像素；ROS 可以另发叠框图供 RViz 查看，见[图像框与三维身份](技术实现-检测与跟踪推理.md#rgb人物框与三维身份)。当前位姿描述雷达位置，雷达到车体的外参属于导航接入。

整台 D435i 移动时，相机到雷达、雷达到 IMU 的空间关系都会改变。相机松动期间，一个固定外参可能无法解释整包数据。使用历史 bag 前，应核对安装状态与设备时钟会话，不能统一套用当前参数。启动器无法自动验证这些物理条件，参数来源和适用范围由 YAML 记录。

### 相机—雷达无靶标标定

相机标定使用独立 [direct_visual_lidar_calibration](https://github.com/koide3/direct_visual_lidar_calibration) 工具的 NID 优化。当前参数来自固定安装后的多包联合求解，并用留出数据查看投影。验证依据是 NID 和视觉复核，没有人工对应点或独立几何真值；具体数据与结果由参数文件引用。

矩阵按列向量把 `rslidar` 点转换到 `camera_color_optical_frame`，平移单位为米，反向变换使用刚体逆。重新采集时保持刚性安装，选择近、中、远结构清晰的静态观察，保存 RGB、CameraInfo、原始点云和逐点时间，运动片段先做补偿。工具位置见本机记录，本文不复制矩阵数值。

### 雷达—IMU标定与同步实施策略

雷达与 IMU 标定先用同台相机内部 TF 和当前相机到雷达外参构造空间先验，再用 LI-Init 的独立纯雷达轨迹求解。多个包共享旋转，各设备会话分别估计固定时差。平移和绕主要转轴等弱约束分量保留先验，因此输出完整矩阵不代表已经独立标定了六自由度。

```text
p_IMU = R_IL × p_LiDAR + t_IL
t_imu_used = t_imu_header + common.imu_time_offset
```

`mapping.extrinsic_R/T` 表达上述变换。平移单位为米，加速度为 m/s²，角速度为 rad/s。正常运行关闭在线外参估计和启发式自同步；求解时的滤波只用于提取拟合特征，不修改原消息。bag 记录时间与消息头时间的差，也不能直接解释为传感器物理时差。

| 步骤 | 实现及边界 |
|---|---|
| 构造先验 | [lidar_imu.py](../../perception/sensors/calibration/lidar_imu.py)的`compose`；跨包内部TF复用要求同设备，外部安装变化后须使用新相机—雷达关系 |
| 独立参考 | [replay_lidar.py](../../perception/sensors/calibration/replay_lidar.py)及[LI-Init补丁](../../perception/sensors/calibration/li_init.patch)，强制纯雷达，不用待求IMU关系自证 |
| 提取及拟合 | `extract`、单包`fit`或多包`fit-joint`；显式训练／留出、可观测方向、先验保留及候选YAML |
| 验证及采用 | 在独立留出上比较候选和原参数，再作完整回放；留出未改善时保留候选及结果，不自动覆盖默认参数。可用`--lidar-imu-calibration FILE`显式测试候选 |

多包输入由 `sources.json` 划分 `train/validation`。每行保存 `id/bag/poses/range_s/clock_group`，顶层 `deployment_clock_group` 指定部署时输出哪组时差。

同一持续运行的设备消息流可以共用会话组，只重启 `rosbag record` 不会自动形成新设备会话。驱动是否重启无法确认时，应分组处理。验证数据的时差组必须已在训练中出现，不能借验证包重新拟合。每包陀螺偏置只作为求解辅助量，运行初始化仍会重新估计。

正常运行默认采用零偏移，保留历史空间外参，直接按传感器消息时间戳组装雷达与IMU。启动不再执行运动时差估计，也不要求已验证的时钟会话作为统一前置条件。FAST-LIO自身的重力与偏置初始化继续执行；原始时间倒退、输入缺失和定位无效仍按原规则处理。

默认选择参考过同输入的零偏移对照：二层恢复包前250秒的CPU前端比较中，零偏移与历史固定补偿的状态连续性及局部几何差异较小。这是工程简化依据，不能证明真实偏移为零，也没有验证跨设备重启、所有运动条件或独立轨迹精度。

有证据需要补偿时，仍可通过`--lidar-imu-calibration FILE`选择固定偏移；离线`fit`和`fit-joint`标定工具保留。非零补偿的未知会话会提示适用范围尚未确认，明确不符的会话则拒绝使用。输入会话来自显式参数、与bag指纹对应的记录，或同一bag的来源运行，不能从标定声明反推。组名相符不证明偏移准确。

生效偏移及来源保存在`run.json`与`summary.json`的`imu_time_calibration`中。`offset_policy`区分原时间戳和非零固定补偿，`validation_performed=false`明确本次没有重新校准。`--source-run`继续复用原运行的几何和偏移；如需应用当前默认，应显式覆盖标定配置。覆盖时不会继承旧标定的会话和验证声明，原始消息与冻结结果不改写。操作见[会话选择与记录](../系统运行手册.md#选择传感器时钟会话)。

记录中的`clock_group_match`为`true`、`false`或`null`，分别表示声明相符、不符或信息不足。默认零偏移不声明某一校准会话，缺少会话记录不会阻止运行。设备会话与定位的`session_id/generation`含义不同，运行中时差漂移监测尚未实现。

跨会话比较时，同时保留两种结果：直接使用原参数，以及固定空间外参、只用训练包重估会话时差。后一种由 `solve_rotation(..., refine_rotation=False)` 支持。

所有方案使用相同留出范围和训练偏置处理，先分包报告再汇总，避免把时差变化误算为外参改善。旧矩阵保持冻结，验证包不参与时差或偏置拟合，留出未改善的候选不自动替换默认参数。

## 运行状态与计时

定位与环境地图分别使用自己的 GPU 算法。定位默认把近邻和去畸变交给 GPU，保留 CPU 原拟合；连续前端逐扫描输出，ROLL 在后台匹配。建图可以离线完成，在线定位则需要及时为跟踪、控制和安全提供状态。

当前加速保持点数、迭代、标定、残差和健康门限不变：

- ikd-Tree复用近邻及距离缓冲，按原顺序取回近邻；递归搜索和堆顶读取使用常量引用，减少点结构复制。
- 公共上下文冻结收到的匹配，只有与同会话原始位姿核对后才缓存绑定结果；后续仍检查观察、时效、健康和生命周期，不反复对最多64条历史记录重做矩阵核验。
- `matching_threads`控制前端逐点匹配，默认1。可在目标设备显式比较2／4；小点集及共享信息筛选队列保持串行，残差归约保持原顺序。并行思路参考[FAST-LIO官方匹配实现](https://github.com/hku-mars/FAST_LIO/blob/main/src/laserMapping.cpp)，本项目不按CPU核数自动加线程。

最近轮椅端计时与验证范围见[推理速度](../推理速度记录.md)。历史固定输入的数值一致性只适用于原对照，不能据此保证并发长回放逐位复现，也不能代替检测、地图、控制和安全同时运行的完整负载成绩。

<a id="可选cuda匹配"></a>

### CUDA匹配与去畸变（默认）

`native/cuda_matcher.cu` 实现 GPU 点图索引、去畸变和可选观测矩阵归约。FAST-LIO 索引跟随 CPU ikd-Tree 的实际增删，ROLL 另存子图索引，仅在子图版本变化时重传。索引栅格不改变点数、采样率或匹配距离；等距、距离边界或邻点不足时，交回原搜索处理。

IMU 状态与协方差传播、插图策略、小矩阵更新和 GTSAM 仍在 CPU。这样可以保留已验证的数值流程，不把“使用 GPU”解释为整套定位均在设备上完成。

| 参数 | 行为 |
|---|---|
| `matching_backend: cpu / cuda` | 默认`cuda`；直接入口`--lio-backend`显式覆盖，实际后端保存在新运行中 |
| `matching_cuda_device` | 当前`CUDA_VISIBLE_DEVICES`内的设备编号；统一入口由`--gpu`选择物理设备 |
| `matching_cuda_plane_fit: false` | CUDA后端默认复用CPU的Eigen QR平面拟合与残差筛选，保持原数值路径 |
| `matching_cuda_plane_fit: true` | 实验性GPU最小二乘及残差计算；病态或阈值附近回CPU QR，仍有浮点数值差异，不作为默认策略 |
| `deskew_backend: cpu / cuda` | 默认`cuda`；直接入口`--deskew-backend`覆盖；沿用原IMU轨迹、严格时间区间及首点处理，当前仍下载点云给CPU降采样与后台消费 |
| `linearization_backend: cpu / cuda` | CUDA匹配下可选GPU雅可比及FP64的12×12矩阵／12维向量归约，CPU完成23维更新；存在归约顺序差异，保留实验项 |
| `filter_compact_solve` | CPU先计算小维度的`Hᵀr`，减少中间矩阵；默认关闭，不与GPU收益混算 |
| `roll.matchingBackend: cpu / cuda` | 默认`cuda`；直接入口`--roll-backend`覆盖；仅加速平面近邻，仍用原CPU拟合、退化和质量门控；纯无图模式不构造ROLL |
| `roll.matchingCudaCellSize / matchingCudaThreads` | GPU索引格长与CPU拟合线程；选用0.5米／1线程，区别于实际地图采样；CPU后端仍使用`matchingThreads` |
| `roll.matchingCudaCorners / matchingCudaPlaneFit` | 边缘近邻GPU化／GPU加权平面拟合；均默认关闭，后者为实验项 |

后端默认值由本模块 YAML 统一维护。复用 `--source-run` 时，几何、标定和其余算法参数继承原记录，三处执行后端采用当前默认或显式覆盖，原文件不改写。实验性数学参数继续按源记录继承。

CPU 定位对照需要显式选择三处 `cpu`；如果来源还启用了 GPU 观测归约，另加 `--linearization-backend cpu`。这不会把检测、环境和导航一起改成 CPU，命令见操作速查。

CUDA使用独立流，各线程显式绑定可见设备；CPU消费前同步，子图只读快照沿用原生命周期。邻点仍下载供QR及插图使用；GPU观测归约不代表整条链只返回小矩阵。去畸变与三维检测分别使用补偿／原始点云，不因共用设备而改变模型输入。

位姿结果 ABI 保持不变，`sn_lio_stages` 和 `sn_roll_stages` 单独返回阶段计时，Python 放在 `stages` 中。前端记录 IMU 准备与传播、去畸变、降采样、雅可比及滤波求解；ROLL 记录特征、子图、降采样、匹配、线面约束、线性求解和位姿图。

输入进程记录每次后台 `roll_processing`，不只记录前台最后使用的那份结果。`processing_ms` 包含同步与地图维护，CUDA 事件另行命名，复制按消费者累计。各阶段有嵌套和并行关系，分位数不能相加。

原生构建可用`SOCIAL_NAV_BUILD_LIO_CUDA=OFF`保留纯CPU数值库。未编译CUDA、设备不可用或启用不受支持的`info_filtering`时明确报错，不静默回退；旧ROS诊断在launch中明确覆盖为CPU，GPU入口统一为直接运行时。完整负载耗时与共享GPU的计时限制见[推理速度](../推理速度记录.md)。

| 位置 | 解释 |
|---|---|
| `/localization/state` | 实际观察的健康，不能由发布频率推断精度 |
| `/roll/status` | 收到、处理、丢弃和待处理队列；初始化未送入ROLL的扫描不是ROLL丢帧 |
| 回放收尾 | 按实际忙闲及处理进度等待；持续有进展继续等待，停滞或队列溢出明确失败，不伪造完整处理 |
| `timings.csv` | 详情模式按观察时间合并前端与ROLL阶段耗时，缺项留空 |
| `registration.csv`／`loop_check` | 配准初值、残差、步长、最弱方向及回环各环节诊断；角度弧度、位置米 |
| `raw_to_state_ms` | 本机收到原扫描至收到同时间戳状态的单调墙钟耗时，不含采集／上行，缺匹配为空 |
| `observation_age_ms` | 当前ROS时钟减扫描结束；模拟时钟暂停后不能表示继续收尾的墙钟等待 |

## 结果与地图资产

本节的“地图”指**三维定位地图**，ROLL使用特征关键帧与位姿，PIN使用完整神经地图包。静态环境地图、实时局部环境地图和派生视图的关系统一见[对象分类](技术实现-环境地图与场景表示.md#地图与非地图对象)。

| 产物 | 内容 |
|---|---|
| `run.json` | 来源、bag 与地图指纹、初值和实际参数；诊断入口另保留清理及保留清单。 |
| `summary.json` | 直接运行时的计数、阶段耗时与退出情况。 |
| `localization.jsonl` | 采集时间下的连续位姿、健康、来源、会话和地图修正 |
| `people.jsonl` | 启用检测时的传感器框、世界轨迹、位姿／RGB来源与耗时 |
| `map/` | 建图成功时的完整三维定位地图，另两种任务不生成 |
| `environment/` | 可选实时局部地图快照及扫描证据；静态环境地图另行导出 |
| `scene/`、`scenes/`、`final_scene/` | 分别用于 ROS 场景、直接运行时限频归档和末帧保存；先验裁剪视图仍属于对应观察。 |
| `--keep-details` | ROS 诊断的详细轨迹、配准和计时。只在需要排错时开启，失败保留实际诊断。 |

地图先保存到暂存目录，再原子重命名，已有目标不会被覆盖。`COMPLETE` 只说明 I/O 完成，不证明定位质量。ROLL 保存关键帧、位姿和显示点云，`GlobalMap` 不是占据地图。大 bag 或点云可使用大小与边缘 SHA256 识别，这不等于完整文件摘要，也不能重写摘要来掩盖变化。

历史楼层地图经`import_map.sh`读取全部关键帧／位姿，拒绝缺失、非有限或空表面帧，保存来源和完成标记；用相对目录链接引用原地图，不复制逐云。地图、原bag与人工起点成套迁移，源地图保持可达只读。环境与导航图另由派生导出，不向定位地图写回。

## 可视化与回看

跨楼层bag可用`--start/--duration`划分各层窗口，为每层分别选择地图与绑定起点。电梯过渡段不强行并入平面地图，层间变换未知时保持独立坐标；这仍是离线分段，不代表已实现在线楼层识别／地图切换。小区域地图未覆盖的房间也应排除在可信区域外，局部定位与环境表示继续运行。

直接运行时使用 `--display` 发布可选显示话题，不自行启动 RViz；`--record-views` 保存限频场景，默认 `final_scene/` 只保存末帧几何与人物，见[运行手册](../系统运行手册.md#日常运行与回看)。

ROS 诊断需要另存处理后扫描、占据栅格和 TF 时，可用 `--environment --record-display`，再用 `python -m perception.visualization.playback --result RUN` 独立回放，无需重算 SLAM。显示包不能替代原 bag 或完整静态融合证据。

### RViz 查看建图、定位与局部里程计

以下窗口行为指 ROS 诊断的 `--rviz`。建图与有图定位使用 `roll.rviz` 和 `map`，无图定位使用 `odometry.rviz` 和连续 `odom`，启用环境后按连续局部坐标组织。人物颜色与雷达原生视图见[检测显示](技术实现-检测与跟踪推理.md#检测跟踪的rviz显示)。

青色`Current scan (observation-bound)`使用`/perception/visualization/scan`：仅定位时取同观测有效位姿，联合检测时取该检测结果位姿，扫描与框共用观察。它是原始点云刚体显示，不重新去畸变；缺同刻扫描／可靠定位或超时清空，模拟时钟暂停也按墙钟清空，不依赖旧TF。

`Recent scans`为可选累积诊断，没有逐帧绑定语义。扫描与图元经两个ROS话题刷新，严格核对用结果回看`--points`。历史ROLL轨迹不随回环整体重画，优化关键帧轨迹可订阅`/roll/mapping/path`。

| 任务结束 | 窗口行为 |
|---|---|
| 建图＋RViz | 先保存并退出算法，随后用独立master显示最终地图及优化关键帧稀疏轨迹，关闭窗口／Ctrl+C退出 |
| 有图／无图＋RViz | 正常结束时关闭本次窗口 |

最终视图不新增全局优化，也不将未回溯修正的逐帧轨迹拼到最终地图。在线建图第一次Ctrl+C保存并进入结果视图，退出查看不会撤销已保存结果。

### 已有结果查看与播放

[view.sh](../../perception/scripts/view.sh)只读已有产物，不运行SLAM、检测、传感器或底盘，不创建新结果目录。需系统ROS、RViz、NumPy、PyYAML和PyQt5；关闭窗口清理自有进程。

| 选项／操作 | 行为 |
|---|---|
| 全览／播放／跳转 | 空格暂停，倍速、滑条和秒数跳转；时间条绿有效、红无效／降级、灰无健康记录，空白无观察 |
| `--frame odom` | 连续局部位姿，不叠先验；默认自动选择map或odom |
| `--frame lidar` | 原生雷达扫描／检测，支持初始化或失效时刻，不要求世界定位 |
| `--points` | 同扫描原始点云，世界视图取该次位姿刚体放置，缺失不借邻帧；未重新去畸变 |
| `--bag/--map` | 迁移后明确重定位同一输入，绑定仍须匹配 |
| 显示预算 | `--max-points/--max-trace-points`只影响显示 |

同目录`people.jsonl`自动合并观测时间线，保留检测独有时刻；只显示与当前扫描同刻的结果。历史线只取过去确认观察，定位失效、会话／代次变化处断开，地图轨迹另在修正处断开。静态回看不按墙钟清空，不插值补位姿。

查看器只在隔离master发布`/result_view/`显示参考，不发布在线定位／车体TF或接受选点。PCD支持项目ASCII／binary，暂不支持`binary_compressed`。旧产物仅有汇总时无法恢复完整定位轨迹，不能用建图关键帧代替；未保存的逐时刻地图和回环几何不能忠实重现。

## 运行环境与构建

直接运行时由系统 Python 读取 bag 或传感器，通过不链接 ROS 的 C ABI 加载 FAST-LIO 和 ROLL。连续前端与后台地图匹配分别调度，`LocalizationContext` 核对原观察后管理公共状态。GPU 主进程使用检测环境，不跨 Python ABI 导入 PCL 或 GTSAM。

构建入口见[运行时](../系统总览.md)，机器依赖见[本机记录](../../ENVIRONMENT.local.md)。下表列出 ROS 诊断工作区的构建范围，ROS、RViz 与 PIN 的依赖不作为默认内部通信方式。

| 构建范围 | 依赖／用途 |
|---|---|
| `sensors` | ROS 1、PCL、libusb／libpcap、ddynamic-reconfigure；底盘接收另需python3-serial |
| `mapping` | ROS 1、PCL／pcl_ros／pcl_conversions、系统C++工具链、项目固定GTSAM与Ceres |
| `environment` | 上述定位组件、OctoMap开发库及已有NumPy／OpenCV／PyYAML |
| `interfaces` | 定位及检测消息；显示使用系统ROS，模型使用兼容检测环境 |

固定的 librealsense、GTSAM 和 Ceres 恢复资源位于 `data/cache/perception/`，私有依赖和 ROS 工作区的 build/devel 位于 `outputs/perception/`。直接运行时的库放在 `outputs/runtime/build/`。只有缺少产物或相关源码变化时才构建，不同时构建同一工作区，也不跨解释器 ABI 加载 ROS 原生扩展。

## PIN-SLAM实验后端

### PIN-SLAM 环境与完整回放

PIN 使用独立兼容的 PyTorch 与 CUDA 环境，普通包优先中国镜像，通过 `--backend-python` 显式选择，不把依赖装入检测环境。它只使用雷达，没有 IMU 重力约束或确认后的车体约束，输出不能直接当作水平导航地图。

PIN 通过 `run_ros_diagnostic.sh` 运行。`--step-replay` 每次等到对应扫描的结果再继续，忽略回放速率，不支持 `--start`，也不能用于证明在线实时性。它只回放原始扫描，可以联合三维检测，默认不启动图像支路；需要 RGB 关联时改用普通回放。

PIN 不接受该入口的 `--rviz`、ROLL 起点 JSON 或交互选点，其他起点需明确六维 `--pose`。XYZI 与原扫描区间时间保留，不能根据过滤后的时间范围重新归一化。

### PIN 地图恢复与运行边界

完整地图包含 `map.pt/manifest.json/COMPLETE`，保存神经点位置与方向、特征、解码器、观测时间、置信和参数。加载限于张量与基本类型，恢复回环后的 `after_pgo` 状态并重建索引，不加载未知 pickle。PLY 或 mesh 不能替代完整包，ROLL 与 PIN 地图也不兼容。

固定地图定位不会创建建图优化器、扩展地图或保存输入，只允许实现支持的设备、采样、批量、迭代和短预测覆盖，模型与查询参数保持固定。已知起点仍须经过首帧真实配准，失败或有界运动预测不能当有效位姿。时间回退后保持无效，需要重启会话。

建图结束时，用定位恢复时的全局查询方式精修几何特征。样本只来自同源已观测表面及有限近表面邻域，解码器、点位置、方向、置信和时间保持固定，不使用验证行程或 ROLL 位姿来证明地图正确。

PIN独占本次公共定位／TF，不能与ROLL同跑；`/pin_slam/map`、`/pin_slam/status`、`/pin_slam/save_map`分别用于显示、诊断和仅建图保存。对比查看不启动模型，单独CPU读PIN节点位置需指定后端解释器。来源与补丁见[ROLL＋FAST-LIO](../../perception/mapping_localization/backends/roll_fast_lio/SOURCE.md)及[PIN-SLAM](../../perception/mapping_localization/backends/pin_slam/SOURCE.md)。现场恢复等实验范围统一见[待办](../系统实机问题.md)。
