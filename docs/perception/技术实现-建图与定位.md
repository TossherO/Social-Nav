# 技术实现：建图与定位

本文维护传感器／标定、SLAM任务、定位状态、地图资产与定位可视化。启动命令集中于[感知操作速查](感知操作速查.md)，模型及人物显示见[检测与跟踪推理](技术实现-检测与跟踪推理.md)，局部几何和统一场景见[环境地图与场景表示](技术实现-环境地图与场景表示.md)。

## 运行环境与构建

系统ROS负责bag、调度、C++后端和RViz，检测与PIN分别由显式解释器运行。环境选择见[开发指南](../开发指南.md#选择运行环境)，具体本机路径和已执行检查见[环境记录](../../ENVIRONMENT.local.md)。

| 构建范围 | 依赖／用途 |
|---|---|
| `sensors` | ROS 1、PCL、libusb／libpcap、ddynamic-reconfigure；底盘接收另需python3-serial |
| `mapping` | ROS 1、PCL／pcl_ros／pcl_conversions、系统C++工具链、项目固定GTSAM与Ceres |
| `environment` | 上述定位组件、OctoMap开发库及已有NumPy／OpenCV／PyYAML |
| `interfaces` | 定位及检测消息；显示使用系统ROS，模型使用兼容检测环境 |

固定的librealsense、GTSAM、Ceres等恢复资源放在`data/cache/perception/`，私有依赖、源码工作区及build/devel放在`outputs/perception/`。只在缺产物或相关源码变更时构建，不同时构建同一工作区。ROS原生Python扩展不能跨解释器ABI导入。

## 传感器与标定

### 传感器接入

驱动来自用户轮椅归档：RoboSense SDK 1.5.0／rs_driver 1.5.6、realsense-ros 2.3.2及独立底盘反馈节点。许可证留在源码目录，原始来源见`data/datasets/wheelchair_live/README.md`；公共代码不固化设备标识。

| 内容 | 配置与约定 |
|---|---|
| 雷达 | RSHELIOS_16P；[rslidar.yaml](../../perception/sensors/ros/wheelchair_sensors/config/rslidar.yaml)选择型号／端口；`/rslidar_points`，`rslidar`系，保留`ring/timestamp` |
| 相机／IMU | D435i；[camera.launch](../../perception/sensors/ros/wheelchair_sensors/launch/camera.launch)维护开关、尺寸及帧率；默认`/camera/color/image_raw`与`/camera/imu` |
| 设备绑定 | 忽略的`configs/perception.local.json`中`sensors.serial_front/serial_rear`或显式参数；后视按需启用 |
| 驱动边界 | V4L2／IIO，不构建CUDA／Python SDK，不自动修改内核、固件、udev或重置设备 |
| 底盘反馈 | `wheelchair_sensors/odometry.launch`默认`allow_serial_read=false`，不发送控制命令；原始编码器里程计不作为可靠定位 |

启动驱动需已有master和现场权限；入口不启动底盘运动。FAST-LIO／ROLL需要真实IMU，当前IMU来自D435i，只有`--lidar-only`不满足正常链路。IMU保留约2000Hz真实消息，按实际时间差积分，不因频率正常而添加排查或默认降采样。

### 标定与数据边界

| 标定 | 唯一参数源 | 使用范围 |
|---|---|---|
| 相机—雷达 | [front_camera_lidar.yaml](../../perception/sensors/calibration/front_camera_lidar.yaml) | 整台D435i重新固定后的安装；用于离线投影与雷达—IMU空间先验，驱动不加载 |
| 雷达—IMU | [lidar_imu.yaml](../../perception/sensors/calibration/lidar_imu.yaml) | 当前安装的带先验空间标定和指定会话固定时差；默认由FAST-LIO／ROLL入口加载 |

相机内参取对应图像CameraInfo。在线RGB是时间配对原图，离线投影不表示在线框叠加已接通。当前自车输出为雷达位姿，雷达—车体外参属于导航接入。

整台D435i移动会同时改变相机—雷达和雷达—IMU空间关系；松动期间不保证一个固定外参适用于整包。历史数据须匹配安装和时钟会话，不能统一套用当前默认值。启动器不会自动核验这些物理条件，当前参数的来源与适用范围由YAML维护。

### 相机—雷达无靶标标定

采用独立[direct_visual_lidar_calibration](https://github.com/koide3/direct_visual_lidar_calibration)的NID优化，当前默认来自固定后多包联合求解与独立留出投影复核。验证限于NID和视觉复核，没有人工对应点或几何真值；实际输入与成绩由参数源记录指向。

矩阵按列向量将`rslidar`转换到`camera_color_optical_frame`，长度单位米，反向矩阵为刚体逆。需要重标定时保持刚性安装，使用近中远结构清晰的静态观察，保留RGB、CameraInfo、原始点云及逐点时间；运动片段先补偿。独立工具位置见本机记录，本文不另维护第二份矩阵。

### 雷达—IMU标定与同步实施策略

利用同台相机内部TF与当前相机—雷达外参构造空间先验，以独立LI-Init纯雷达参考联合求解多包共享旋转和分会话固定时差。平移及绕主要转轴等弱约束分量保留先验；完整矩阵不表示独立六自由度标定。

```text
p_IMU = R_IL × p_LiDAR + t_IL
t_imu_used = t_imu_header + common.imu_time_offset
```

`mapping.extrinsic_R/T`表达上述变换，平移为米，加速度m/s²、角速度rad/s。正常运行关闭在线外参估计和启发式自同步；拟合滤波只用于求解特征，不改写原消息。bag记录时间与消息头的差不能直接作为物理时差。

| 步骤 | 实现及边界 |
|---|---|
| 构造先验 | [lidar_imu.py](../../perception/sensors/calibration/lidar_imu.py)的`compose`；跨包内部TF复用要求同设备，外部安装变化后须使用新相机—雷达关系 |
| 独立参考 | [replay_lidar.py](../../perception/sensors/calibration/replay_lidar.py)及[LI-Init补丁](../../perception/sensors/calibration/li_init.patch)，强制纯雷达，不用待求IMU关系自证 |
| 提取及拟合 | `extract`、单包`fit`或多包`fit-joint`；显式训练／留出、可观测方向、先验保留及候选YAML |
| 验证及采用 | 在独立留出上比较候选和原参数，再作完整回放；留出未改善时保留候选及结果，不自动覆盖默认参数。可用`--lidar-imu-calibration FILE`显式测试候选 |

多包`sources.json`含`train/validation`，各行保留`id/bag/poses/range_s/clock_group`，顶层`deployment_clock_group`选择输出时差。同一持续运行的设备消息流可以共用会话组，包括只重新执行`rosbag record`的独立录包；驱动是否重启未确认时分组。留出时差组必须已在训练中出现，不能借验证数据拟合。每包陀螺偏置仅为求解辅助变量，运行时初始化另估计。启动器只加载一组固定时差，跨重启复核，不按bag自动切换；同一会话也不保证固定时差模型始终足够准确。

跨采集会话比较外参时，同时保留原参数直接迁移和固定空间外参、仅用训练包重新估计会话时差两种结果；后者由`solve_rotation(..., refine_rotation=False)`支持。所有方案使用相同留出范围与训练偏置处理，分包报告再汇总，避免把时差变化混为外参改善。旧矩阵保持冻结，验证包不参与时差或偏置拟合，留出未改善的联合候选不自动采用。

## 任务、配置与输入

| 任务 | `--mode`／默认后端 | 地图策略 |
|---|---|---|
| 建图 | `mapping`／ROLL＋FAST-LIO | 积累关键帧，后台按序检查回环，保存完整地图 |
| 有图定位 | `localization`／ROLL＋FAST-LIO | 指定完整先验和初值，关闭回环、更新及保存输入地图 |
| 无图定位 | `odometry`／FAST-LIO | 新建连续局部系、内部滚动匹配地图，不启动ROLL或输出全局先验 |

三种模式都支持bag与live。无图意味着没有先验，不意味着没有内部局部地图；长期绝对位置不保证。PIN作为建图／有图定位实验后端另见专节。

| 配置入口 | 职责 |
|---|---|
| [fast_lio.yaml](../../perception/mapping_localization/configs/fast_lio.yaml) | 输入、初始化及FAST-LIO基础参数 |
| [roll.yaml](../../perception/mapping_localization/configs/roll.yaml) | ROLL线程、关键帧／地图匹配与回环 |
| [mapping.yaml](../../perception/mapping_localization/configs/mapping.yaml)／[localization.yaml](../../perception/mapping_localization/configs/localization.yaml)／[odometry.yaml](../../perception/mapping_localization/configs/odometry.yaml) | 各模式地图、显示及资源策略 |
| [lidar_imu.yaml](../../perception/sensors/calibration/lidar_imu.yaml) | 当前安装／会话的空间与时差，可按次显式覆盖 |
| [pin_slam.yaml](../../perception/mapping_localization/configs/pin_slam.yaml) | PIN算法、查询及地图精修 |

FAST-LIO支持静止／运动自适应初始化，参数由`initialization`维护；满足输入及对齐条件后才有效。人工起点绑定首个扫描，初始化期间运动通过参考位姿传播。ROLL回环提交前核对地图快照，固定地图定位保持输入只读。

| 输入模式 | 调度与时间 |
|---|---|
| bag | 统一入口自建隔离master与模拟时钟，扫描绑定结束时刻；`--start/--duration`按记录时间选片段，`--rate`控制回放 |
| live | 连接已有master和话题；真实设备`use_sim_time=false`，外部bag模拟在线需显式`true`及`/clock`；`--duration`为墙钟秒，不接受bag偏移／速率 |

原始逐点绝对时间保留。检测及其显示用原始扫描，配准和环境分支使用前端去畸变观察。缺定位不补单位矩阵、不借原始里程计；同包先建图再定位须披露同源关系，不能当独立精度评测。

## 起点与重新定位

### 独立标注bag起点

[pick_start.sh](../../perception/scripts/pick_start.sh)只读地图、首帧雷达及此前500毫秒内最近RGB，自建临时master，不运行定位或检测。独立窗口可同时参考首帧点云与图像；左键旋转、中键或Shift＋左键平移、滚轮／右键缩放，有俯视／全览。

地图中用RViz `2D Pose Estimate`选位置和朝向，青色扫描按初值叠加；控制窗口XYZ用米、RPY用度，Z初取最近XY关键帧高度，多楼层／倾斜须人工确认。保存写新`BAG.initial_pose.json`，关闭窗口取消；`--start`可以选择偏移后的首帧。

起点文件绑定六维雷达地图位姿、扫描时间和bag／地图指纹，只是人工种子。`--pose-file`仅适用于ROLL bag定位，起始偏移必须一致，不能与其他初值方式混用。

### 定位运行中的选点与重新定位

| 输入 | 行为 |
|---|---|
| `--initialization rviz` | 地图加载后等待2D Pose Estimate，接受后才启动前端／输入；只加`--rviz`且无起点也默认此方式 |
| `--initialization map-start` | 仅确知与建图起点相同时使用；不开RViz且无初值时默认使用已知地图起点 |
| `--pose roll pitch yaw x y z` | 六维已知初值，弧度／米 |
| `--pose-file FILE` | 使用绑定的bag首帧起点文件 |

选点等待不计入任务`--duration`，取消窗口或Ctrl+C终止。高度取附近地图关键帧；初值接收不等于有效配准，实际以`/localization/state`健康为准。默认ROLL任务在运行中重新选点会清理旧扫描／显示并增加重初始化代次，失败不发布有效地图位姿。启用环境适配后的连续局部身份与地图关联分开维护，不能据后端重新关联代次清空局部人物。

## 局部定位与先验关联

默认定位任务沿用既有状态契约。显式`--environment`后，内部`/localization/frontend_state`与`/localization/map_state`由唯一`localization_context`汇合，再发布公共定位、关联及TF。

| 状态 | 含义 |
|---|---|
| `LOCAL_INVALID` | 局部前端无效；不提供可融合世界位姿 |
| `LOCAL_ONLY` | 局部有效，无当前有效先验关联 |
| `ASSOCIATING` | 局部有效，地图候选仍在连续确认 |
| `PRIOR_ASSOCIATED` | 局部有效，当前先验关联有效 |

建图和无图健康由局部配准决定；固定地图定位默认仍要求有效关联，只有显式`--allow-local-only`才保留地图关联缺失时的局部输出。局部`session_id/generation`表达连续坐标生命周期，`association_generation`独立表达重新接受关联，后端`map_revision`表达修正，三者不能混用。

关联绑定实际配准测量及与之完全一致的前端位姿，不接受未来、跨生命周期、失配或过期结果。有限年龄内可传播最近修正，但保留原测量时间；失效后须新的连续匹配才恢复。只有有效关联产生地图位姿及新`map→odom`，局部位姿与速度不受地图修正跳变污染。

### 手动地图可信区域与混合定位

使用`pick_coverage.sh --map MAP --out COVERAGE.yaml`在二维地图上划定适合定位的区域；目标文件已存在时会加载其中的原有区域。窗口显示点云和建图关键帧轨迹，支持工具栏缩放／平移；左键逐点绘制，Enter闭合，Backspace撤销顶点。

底部“区域”列表区分原有／新绘制多边形，选中项以橙色边界突出，也可右键区域内部选中。点击“删除选中区域”或按Delete删除，包括从文件加载的原有区域；“清空全部区域”确认后可全部重画。点击“保存区域”或Ctrl+S才写入文件，至少保留一个闭合区域；关闭窗口不自动保存。多个多边形取并集，覆盖YAML绑定地图资产指纹和坐标帧；重建地图后须重新选择。区域只表达定位可信范围，不声明地面、空闲或可达，原始地图点云不裁剪。

定位显式组合`--environment --allow-local-only --association-coverage COVERAGE.yaml`后，同一份区域同时用于ROLL后端和公共关联：

| 情况 | 后端与公共输出 |
|---|---|
| 区域内，配准可信 | 接受地图修正；局部坐标继续由FAST-LIO维护 |
| 离开区域 | 以最后可信修正传播当前局部位姿判断边界，停止扫描到先验地图的匹配及修正，公共关联撤销，维持`LOCAL_ONLY` |
| 返回区域 | 进入边界内侧缓冲后重新匹配；检查残差、内点率、修正幅度、重力方向及连续候选一致性，通过确认后恢复关联 |
| 返图匹配不可信 | 保留连续局部定位，拒绝更新地图修正；可重新人工选点 |

门控参数由[roll.yaml](../../perception/mapping_localization/configs/roll.yaml)的`coverageGate`维护，仅在配置区域时启用。公共层仍检查测量时间、来源和连续确认；启动时冻结区域内容，详细计时记录门控原因和匹配前的预测位置，缺失配准质量保持缺失。未配置区域时保持原匹配行为。

返图依赖连续局部推算仍落在正确配准邻域；长距离漂移、跨楼层和任意位置全局重定位未由该机制解决。状态有效不能替代轨迹和点云对齐检查；泛化与现场验收见[采集与验收清单](待办与数据采集.md)。

消息与TF发布权见[接口约定](../接口约定.md#可选环境状态与地图关联)，连续几何与场景消费见[环境文档](技术实现-环境地图与场景表示.md)。

## 可视化与回看

### RViz 查看建图、定位与局部里程计

默认任务加`--rviz`打开连接本次master的窗口。建图／有图视图为`roll.rviz`、地图坐标`map`；无图为`odometry.rviz`、连续`odom`；启用环境运行时视图以连续局部坐标组织。检测图元颜色及原生检测视图见[检测显示](技术实现-检测与跟踪推理.md#检测跟踪的rviz显示)。

青色`Current scan (observation-bound)`使用`/perception/visualization/scan`：仅定位时取同观测有效位姿，联合检测时取该检测结果位姿，扫描与框共用观察。它是原始点云刚体显示，不重新去畸变；缺同刻扫描／可靠定位或超时清空，模拟时钟暂停也按墙钟清空，不依赖旧TF。

`Recent scans`为可选累积诊断，没有逐帧绑定语义。扫描与图元经两个ROS话题刷新，严格核对用结果回看`--points`。历史ROLL轨迹不随回环整体重画，优化关键帧轨迹可订阅`/roll/mapping/path`。

| 任务结束 | 窗口行为 |
|---|---|
| 建图＋RViz | 先保存并退出算法，随后用独立master显示最终地图及优化关键帧稀疏轨迹，关闭窗口／Ctrl+C退出 |
| 有图／无图＋RViz | 正常结束时关闭本次窗口 |

最终视图不新增全局优化，也不将未回溯修正的逐帧轨迹拼到最终地图。在线建图第一次Ctrl+C保存并进入结果视图，退出查看不会撤销已保存结果。

### 已有结果查看与播放

[view.sh](../../perception/scripts/view.sh)只读已有产物，不运行SLAM、检测、传感器或底盘，不创建新结果目录。需系统ROS、RViz、NumPy、PyYAML和PyQt5；关闭窗口清理自有进程。

| 选项／操作 | 行为 |
|---|---|
| 全览／播放／跳转 | 空格暂停，倍速、滑条和秒数跳转；时间条绿有效、红无效／降级、灰无健康记录，空白无观察 |
| `--frame odom` | 连续局部位姿，不叠先验；默认自动选择map或odom |
| `--frame lidar` | 原生雷达扫描／检测，支持初始化或失效时刻，不要求世界定位 |
| `--points` | 同扫描原始点云，世界视图取该次位姿刚体放置，缺失不借邻帧；未重新去畸变 |
| `--bag/--map` | 迁移后明确重定位同一输入，绑定仍须匹配 |
| 显示预算 | `--max-points/--max-trace-points`只影响显示 |

同目录`people.jsonl`自动合并观测时间线，保留检测独有时刻；只显示与当前扫描同刻的结果。历史线只取过去确认观察，定位失效、会话／代次变化处断开，地图轨迹另在修正处断开。静态回看不按墙钟清空，不插值补位姿。

查看器只在隔离master发布`/result_view/`显示参考，不发布在线定位／车体TF或接受选点。PCD支持项目ASCII／binary，暂不支持`binary_compressed`。旧产物仅有汇总时无法恢复完整定位轨迹，不能用建图关键帧代替；未保存的逐时刻地图和回环几何不能忠实重现。

| `run.json` | 来源、bag／地图绑定、初值、实际参数、计数、清理及保留清单 |

地图经暂存与原子重命名保存，拒绝覆盖；`COMPLETE`只代表I/O完成。ROLL地图含关键帧、位姿及显示点云，`GlobalMap`不是占据地图。包／大点云可用大小和边缘SHA256绑定，非完整文件摘要，不重写摘要掩盖变化。

历史楼层地图经`import_map.sh`读取全部关键帧／位姿，拒绝缺失、非有限或空表面帧，保存来源和完成标记；用相对目录链接引用原地图，不复制逐云。地图、原bag与人工起点成套迁移，源地图保持可达只读。环境与导航图另由派生导出，不向定位地图写回。

## PIN-SLAM实验后端

### PIN-SLAM 环境与完整回放

PIN使用独立兼容PyTorch／CUDA环境，普通包优先中国镜像；由`--backend-python`显式选择，不把依赖装入检测环境。算法仅用LiDAR，无IMU重力或确认后的车体约束；PIN地图不能直接视为水平导航地图。

`--step-replay`逐扫描等待绑定结果，忽略速率，不证明在线实时性；不支持`--start`。PIN不接受默认入口的`--rviz`或ROLL起点JSON／交互选点，其他起点须已知六维`--pose`。输入点保留XYZI和原扫描区间时间，不能用过滤后的范围重新归一化。

### PIN 地图恢复与运行边界

完整包为`map.pt/manifest.json/COMPLETE`，包括神经点、特征、解码器、时间／置信及参数。受限加载张量和基本类型，恢复回环后`after_pgo`状态并重建索引，不加载未知pickle；PLY／mesh不能替代完整包，ROLL／PIN互不兼容。

定位固定模型和查询参数，只允许实现支持的设备、采样、批量、迭代和短预测覆盖；不创建建图优化器、扩展地图或保存输入。建图精修只使用同源已观测表面，固定解码器／位置／方向／置信／时间，不使用验证行程或ROLL位姿自证。时间回退保持无效，需重启会话。

PIN独占本次公共定位／TF，不能与ROLL同跑；`/pin_slam/map`、`/pin_slam/status`、`/pin_slam/save_map`分别用于显示、诊断和仅建图保存。对比查看不启动模型，单独CPU读PIN节点位置需指定后端解释器。来源与补丁见[ROLL＋FAST-LIO](../../perception/mapping_localization/backends/roll_fast_lio/SOURCE.md)及[PIN-SLAM](../../perception/mapping_localization/backends/pin_slam/SOURCE.md)。现场恢复等实验范围统一见[待办](待办与数据采集.md)。
