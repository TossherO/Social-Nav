# 开发指南

本文维护公共目录、环境边界、配置来源和资源迁移方法。模块命令分别见 [感知ROS速查](perception/ROS命令速查.md)、[检测与跟踪](perception/检测与跟踪.md)、[检测训练](perception/检测训练.md)与 [VLM 部署与调用](decision/VLM部署与调用.md)。研究设计及未完成事项见 [系统方案](系统方案.md)。

## 目录与配置

```text
perception/
  sensors/                      驱动、设备启动、标定参数与离线约束标定工具
  mapping_localization/         建图定位后端、联合任务调度、地图处理与健康绑定消息
  detection_tracking/
    training/simpledet3d/       仓库内检测训练副本
    annotation/                本机／远程候选复核、人工XY中心与训练导出
    inference/                 在线/离线共用的检测与跟踪核心
    ros/                       ROS 1 节点、消息与 launch
    configs/                   部署模型和推理策略
  scripts/                     感知统一命令入口、系统ROS构建与终端环境
  visualization/               共用实时显示、结果回看及RViz配置；不执行算法
decision/
  vlm/                         输入、审核、远程调用、打包和部署工具
    annotation/                独立T1／T2事件、关系与身份标注；本机／HTTP客户端
  agent/                       外层任务决策预留位置
navigation/
  planning/ control/ safety/   规划、控制及独立安全监督预留位置
interfaces/contracts.py        跨模块类型草案
configs/                       系统登记与忽略的本机覆盖
scripts/                       项目公共资源与系统检查工具
tests/                         根级离线测试
docs/                          当前手册与 archive 历史资料
data/datasets/                 统一数据软链接
models/                        忽略的模型资源
outputs/                       忽略的运行结果与构建产物
```

VLM 从 `decision.vlm` 导入和执行，例如 `python -m decision.vlm.benchmark_vlm`；旧 `scripts.*` VLM 包装已移除。

Linux感知入口集中在`perception/scripts/`：`run.sh`运行定位及可选检测，`view.sh`回看结果，`start_sensors.sh`启动驱动，`pick_start.sh`／`import_map.sh`处理地图，`annotate_people.sh`提供预计算、本机标注与导出，`serve_annotations.sh`提供远程标注HTTP服务。Windows客户端直接使用Python模块入口。Python实现归属对应模块，共用显示归属`visualization/`，catkin包保留消息、launch与必要节点启动器。

| [感知显示 configs](../perception/visualization/configs) | 实时建图／定位／检测及结果回看的RViz视图 |

CLI 覆盖规则由对应手册说明。不要把训练参数写入 VLM 配置，也不要在一处改了参数后手动同步多张文档表。项目文件不添加发布编号；第三方版本、API 路径、数据提交及运行时生命周期编号保留。

## 选择运行环境

先查 [本机环境记录](../ENVIRONMENT.local.md)，按任务选择解释器；该文件被 Git 忽略，新设备需要按实际情况创建。

- 检测、数据渲染和 VLM 客户端可使用 [requirements-cu130.txt](../requirements-cu130.txt)对应的开发环境。CUDA 13 安装与扩展编译见 [检测训练](perception/检测训练.md#cuda-130-开发环境)。
- 独立VLM远程客户端只需要 `httpx` 与 `jsonschema`，无需为了测速升级开发环境的 GPU 库。
- 远程标注客户端使用独立Python 3.11 x64 Conda与`annotation/requirements-client.txt`中的Qt／数组／HTTP依赖；Linux HTTP服务复用项目Python 3.12开发／检测Conda环境，按`requirements-service.txt`补齐依赖，系统ROS子进程负责bag，不跨Python ABI加载其原生扩展。安装与启动见[ROS速查](perception/ROS命令速查.md#远程服务linux)，数据与同步边界见[检测训练](perception/检测训练.md#远程标注与同步)。
- 独立[T1／T2决策标注](decision/决策任务标注.md)在`decision/vlm/annotation/`维护自己的依赖、HTTP协议与缓存，不调用检测标注器。准备阶段只导入已有结果和bag头信息，日常通过系统ROS子进程按需读帧，使用持久句柄和有界缓存；本机Qt可使用项目环境，Windows仅安装该工具客户端依赖。
- ROS 1 Noetic的原生工具、bag和C++构建使用系统环境；检测节点在其Python环境中导入生成的纯Python消息接口。不要在其他Python ABI下加载系统rosbag原生扩展。操作命令集中见[感知ROS命令速查](perception/ROS命令速查.md)。
- 自有SGLang服务器使用独立原生Conda环境、源码构建和cu129依赖约束，见VLM手册；该服务的构建及运行依赖留在服务端，开发机通过客户端访问。
- VLM推理及离线决策调试优先使用远程SGLang客户端；仅远程不可用或其所需GPU被其他任务占用时考虑本地Transformers＋XGrammar。后端选择与调用见[VLM手册](decision/VLM部署与调用.md)。本地备用环境依赖见`decision/vlm/requirements-local.txt`，模型路径与GPU由`configs/vlm_local.local.json`提供，本地入口不读取远程API配置。

查看手册不自动授权安装、编译、训练或启动服务。已有环境适用时复用；环境变更后只更新本机记录，不写入密钥或认证代理信息。

## 数据入口与迁移

所有默认数据入口使用`data/datasets/`。仅准备本次任务需要的资源；JRDB原始数据不作为CODa/Wheelchair和实机bag迁移的前提。VLM客户端可使用已有冻结JRDB输入，重新生成输入或审核源标签时再准备原始资源。

| 别名 | 用途与目标层级 |
|---|---|
| `coda_raw` | CODa 原始根目录，含点云、标注、标定、位姿和 metadata |
| `coda`、`coda_downsample` | 原始点云版、降采样版的预处理 info |
| `wheelchair_raw` | 直接含 indoor1/indoor2 等类别的 Wheelchair 原始根目录 |
| `wheelchair` | 基础点云/位姿 info；无 GT 的 info 仅供读取与推理 |
| `wheelchair_weak` | 检测弱监督 info |
| `wheelchair_ros_centers` | 人工完整复核的实机单帧中心训练导出；按任务建立，不自动替换旧弱标签 |
| `wheelchair_annotations` | 伪标签及人工 BEV 中心 |
| `wheelchair_live` | 实机来源 bag，保持原始话题与字节 |
| `wheelchair_calibration` | 相机—雷达与雷达—IMU专用原始bag；按传感器组合分目录，求解／验证划分随结果保存 |
| `jrdb`、`jrdb_t1_dev` | JRDB 源数据与冻结开发输入，使用相应流程时准备 |
| `socialnav_sub` | 已下载的社会理解诊断样例 |

检测副本的 `data` 是指向 `../../../../data/datasets` 的相对链接。原始地图位于 `data/maps/wheelchair/`；固定依赖下载位于 `data/cache/perception/`。具体物理目标只记录在本机记录，不硬编码到公共配置。

rosbag 人工工程放在 `data/annotations/rosbag_people/<工程名>/annotations.sqlite`，仅保存来源、索引、候选和人工结论；新建工程后可继续编辑该文件，不覆盖旧标签。训练派生数据默认导出到检测副本 `output/data_preparation/rosbag_centers/<名称>/`，按下述方法显式链接为 `data/datasets/wheelchair_ros_centers`，不复制源 bag；操作见[检测训练](perception/检测训练.md#rosbag人工中心复核与增量训练)。

新机器仅对尚不存在的入口建立链接，例如：

```bash
mkdir -p data/datasets
ln -sT /path/to/CODa_full data/datasets/coda_raw
ln -sT /path/to/wheelchair-data data/datasets/wheelchair_raw
ln -sT /path/to/prepared/coda_downsample data/datasets/coda_downsample
ln -sT /path/to/prepared/wheelchair_weak data/datasets/wheelchair_weak
ln -sT ../../../../data/datasets perception/detection_tracking/training/simpledet3d/data
```

更换入口前检查链接及真实目标，只替换链接本身。软链接不是只读保护；原始/共享数据、人工标签与既有结果默认只读。新增预处理写到副本 `output/data_preparation/` 的新目录，确认资源适用后再调整链接。路径可重定位不等于旧划分、sweep 或标注语义已经验收。

VLM 公共默认路径按仓库根解析，显式 CLI 路径按调用者工作目录解析。便携包使用包内资产，不依赖仓库数据链接。数据用途、来源划分和标注边界见 [数据与评测](experiments/数据与评测.md)及 [弱监督设计](perception/弱监督设计.md)。

## 权重、输出与来源

默认检测权重入口由 `inference.json` 指定；模型及历史训练来源单独放在 `models/wheelchair_detector/`，不随 Git 提供。部署 `detector.yaml` 独立于后续训练 YAML。新设备须另行提供可信权重和适用的 CUDA 扩展，详见检测手册。

构建使用 `outputs/perception/` 的 ROS 工作区和私有依赖；检测训练使用副本 `output/<配置名>/<实验名>/`；其余工具将参数、必要日志和结果写入显式指定的新输出目录。不要反复复制原始数据、权重或整个环境。

远程标注的原bag和正式`annotations.sqlite`继续留在Linux。Windows默认在`%LOCALAPPDATA%/SocialNav/annotation/`按服务地址与工程区分客户端缓存；Linux客户端默认位于`~/.cache/SocialNav/annotation/`。缓存同时含待同步人工编辑与冲突存档，不当作可随意删除的临时文件；可用`--cache-dir`明确位置，只有资产执行容量淘汰。客户端包仅按代码清单生成，不包含原始数据、模型、本机连接配置或凭证。

`training/source_snapshot.json` 仅保留迁移时的源码历史摘要，不参与运行或日常校验，不改写历史记录来掩盖适配差异。检测训练直接使用副本脚本，不再经过外层审计或命令打印入口。

资产来源说明和第三方许可证留在所属目录。旧项目资料在 `outputs/archive/`，恢复时解压到新的临时目录并成套查看，不直接覆盖当前源码。已生成的便携 ZIP、冻结输入和用户结果不会因文档调整而改写。

## 按改动范围验证

默认复用仍适用的检查结果，只在变更、失败或具体疑点出现时追加。文档查受影响链接与示例；代码先运行相关模块测试，只有跨模块行为改变等实际需要时才集中执行完整离线回归。

有资源定位疑点时，从仓库根运行：

```bash
python -m scripts.system_status
python -m scripts.dataset_links --datasets coda_raw wheelchair_raw coda coda_downsample wheelchair
```

前者不启动模块；后者只检查所选链接和检测 data 桥接。返回可达不代表标签、模型、CUDA或训练可用。源码历史审计、全量数据审计、GPU推理和模型调用都不作为每次修改的固定步骤。

根级离线测试入口为 `PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s tests`；专题手册提供相关测试入口。临时验证和日志放临时目录，交付保留一份汇总与必要复现产物，不为每个补丁新增报告。
