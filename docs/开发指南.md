# 开发指南

本指南帮助开发者找到代码、选择解释器、准备数据并理解配置来源。具体任务命令放在专题手册中：感知与导航从[总览](感知导航总览.md)和[运行手册](感知导航运行手册.md)进入，局部模型见 [VLM 手册](decision/VLM部署与调用.md)，外层 Agent 见[任务与测试](decision/长程导航任务与评测计划.md#运行与测试操作)。

开始运行前，先读本机的 [ENVIRONMENT.local.md](../ENVIRONMENT.local.md)。它记录实际解释器、资源位置和已执行检查，被 Git 忽略；新机器需要根据自己的条件创建，不能照搬旧机器的环境名和硬件配置。

## 目录与配置

算法按所属模块组织，`runtime/` 只负责把感知与导航连接起来，不集中收纳所有算法。

```text
perception/
  sensors/                      驱动、设备启动、标定参数与离线约束标定工具
  mapping_localization/         建图定位后端、联合任务调度、地图处理与健康绑定消息
  detection_tracking/
    training/simpledet3d/       仓库内检测训练副本
    annotation/                本机／远程候选复核、人工XY中心与训练导出
    inference/                 在线/离线共用的检测与跟踪核心
    ros/                       ROS 1 节点、消息与 launch
    configs/                   部署模型和推理策略
  scripts/                     感知统一命令入口、系统ROS构建与终端环境
  visualization/               共用实时显示、结果回看、RViz配置与地面位姿选点插件
decision/
  vlm/                         T1／T2输入与因果回放、T3选点／阶段核心、模型客户端
    annotation/                独立T1／T2事件、关系与身份标注；本机／HTTP客户端
    deployment/                远程SGLang源码构建与启动材料
  agent/                       单VLM工具循环，优先完备地图下的室内点与区域导航
    core/ tools/               循环、有界对话、任务要求、原生模型调用、地图与导航工具
    adapters/ workflows/       外部反馈适配与运行、准备、评测流程
navigation/
  planning/ control/ safety/   参考规划、DWA及独立安全；native/保存所属原生算法
runtime/                       感知导航直接运行时：观察、共享缓冲、调度和进程
interfaces/contracts.py        跨模块类型草案
interfaces/runtime.py          实际内部观察和数组描述
configs/                       系统登记与忽略的本机覆盖
scripts/                       项目公共资源与系统检查工具
tests/                         根级离线测试
docs/                          当前手册与 archive 历史资料
data/datasets/                 统一数据软链接
models/                        忽略的模型资源
outputs/                       忽略的运行结果与构建产物
```

感知导航统一入口为 `python -B -m runtime`。`perception/scripts/run.sh` 使用当前 Python，也可由 `SOCIAL_NAV_PYTHON` 指定。该目录还保留传感器、地图选点、回看和标注工具，`run_ros_diagnostic.sh` 专门用于 ROS 诊断、PIN 研究及已有联合标注准备，见[直接运行时命令](感知导航运行手册.md#感知导航直接运行时)。

局部 VLM 入口位于 `decision.vlm`，例如 `python -m decision.vlm.follow --help`；旧 `scripts.*` 包装已移除。Agent 使用 `python -B -m decision.agent`运行单模型工具循环、非执行影子测试或反馈仿真，也可只读查看状态，具体用法见[任务与测试](decision/长程导航任务与评测计划.md#运行与测试操作)。Windows 标注客户端直接使用对应 Python 模块。

导航的原生Hybrid A*与CUDA检查不依赖ROS。Dijkstra、A*几何诊断使用Noetic适配库，不加入感知catkin工作区。DWA用于影子控制、反馈仿真和显式实机测试；后者要求已确认车辆配置、独占串口和人工使能，尚未实机验收。步骤见[交互测试](感知导航运行手册.md#rviz交互测试)。

## 选择运行环境

项目同时使用模型环境与系统 ROS 环境，因为两者加载的原生扩展可能对应不同 Python ABI。选择解释器取决于工作内容，而不是当前终端碰巧激活了哪个环境。

### 检测、运行时与ROS

三维检测、数据渲染和 VLM 客户端可复用 [requirements-cu130.txt](../requirements-cu130.txt) 对应的开发环境。默认感知导航不加载 YOLO；需要 VLM 图像辅助或 ROS 图像诊断时，再按[图像依赖](../perception/detection_tracking/inference/requirements-image.txt)补齐 YOLO 和 TensorRT，可继续使用同一环境，无需另建二维检测环境。CUDA 扩展见[检测环境](perception/技术实现-检测训练.md#cuda-130-开发环境)，引擎操作见[图像命令](archive/感知导航ROS诊断命令.md#rgb人物检测与三维关联)。

系统环境负责 ROS 1 Noetic 原生工具、bag 读取、C++ 构建和原生定位。检测节点只在模型环境中导入生成的纯 Python 消息，不能跨 ABI 加载系统 `rosbag` 原生扩展。ROS 环境节点也使用系统 Python，CUDA 通过独立 C ABI 库接入，不要求系统 Python 安装 Torch，见[环境计算命令](archive/感知导航ROS诊断命令.md#局部环境几何与查询)。

PIN-SLAM 使用独立算法环境，只有显式选择它时才通过 `--backend-python` 调用。默认 ROLL 和 FAST-LIO 不使用该环境，见 [PIN 环境说明](perception/技术实现-建图与定位.md#pin-slam-环境与完整回放)。

### 本机与远程标注

行人中心远程客户端使用 Python 3.11 x64 Conda 及 `annotation/requirements-client.txt` 中的 Qt、数组和 HTTP 依赖。Linux 服务复用项目 Python 3.12 开发环境，并按 `requirements-service.txt` 补齐服务依赖；系统 ROS 子进程读取 bag。安装启动见[远程服务](感知导航运行手册.md#远程服务linux)，数据同步见[检测标注](perception/技术实现-检测训练.md#远程标注与同步)。

T1、T2 的[决策标注器](decision/决策任务标注.md)在 `decision/vlm/annotation/` 中维护独立依赖、HTTP 协议和缓存，不调用检测标注器。准备时导入已有感知与二维记录，只有缺失或显式重算二维结果时才需要检测环境。日常读取由系统 ROS 子进程完成，本机 Qt 可以复用项目环境，Windows 只安装对应客户端依赖。

### 模型服务与Agent

独立远程 VLM 客户端只需 `httpx` 和 `jsonschema`，不必为测速升级开发机 GPU 库。SGLang 服务在自有服务器的原生 Conda 环境中源码构建，使用 cu129 依赖约束，构建和运行依赖留在服务器，详见 [VLM 手册](decision/VLM部署与调用.md)。

局部 T1、T2、T3 及离线语义调试优先使用远程服务。只有远程不可用或所需 GPU 被占用时，才考虑本地 Transformers＋XGrammar；依赖位于 `decision/vlm/requirements-local.txt`，模型和 GPU 由 `configs/vlm_local.local.json` 提供，本地入口不读取远程 API 配置。

外层 Agent 独立使用托管 API，不需要本地权重、GPU 推理环境或 SGLang。客户端复用已有 HTTP、Schema、NumPy 和 Pillow，以原生工具消息组织对话，反馈仿真使用本地导航依赖；没有引入 simpleCC 的 SDK 或其他框架依赖。地图登记提供点、区域及语义对象，模型读取地图后自行选择连续位姿。输入与预算见 [Agent 技术实现](decision/Agent技术实现.md#输入模型与工具)，命令见[任务与测试](decision/长程导航任务与评测计划.md#运行与测试操作)，凭证不提交。

以上是环境选择说明，不自动授权安装、编译、训练或启动服务。已有环境可用时优先复用，环境变化后更新本机记录，不记录密钥或认证代理信息。

## 数据入口与迁移

代码通过 `data/datasets/` 别名访问数据，实际物理路径只写在本机记录中。当前主要使用 CODa、Wheelchair 和实机 bag，VLM 还会读取保存的感知结果与冻结窗口。

| 别名 | 数据内容与用途 |
|---|---|
| `coda_raw` | CODa 原始根目录，包含点云、标注、标定、位姿和 metadata。 |
| `coda`、`coda_downsample` | 原始点云版和降采样版的预处理 info。 |
| `wheelchair_raw` | 直接包含 indoor1、indoor2 等类别的原始根目录。 |
| `wheelchair` | 基础点云与位姿 info，无 GT 的 info 只供读取和推理。 |
| `wheelchair_weak` | 检测弱监督 info。 |
| `wheelchair_det_extra` | 实机增量检测数据，按名称保存点云、当前 RGB 和标注。 |
| `wheelchair_perception` | 仍被标注或训练引用的派生感知记录，保留参数、定位和人物 JSONL，不作为新测试输出。 |
| `wheelchair_ros_centers` | 核验中心数据集，包含点云、当前 RGB 和 `annotations.json`，可附历史与定位；训练仍默认单帧。 |
| `wheelchair_annotations` | 伪标签与人工 BEV 中心。 |
| `wheelchair_live` | 迁入的实机 bag，保持原始话题与字节。 |
| `wheelchair_rosbag` | 按采集日期组织的实机录包根目录，建图、定位与子包引用同一来源。 |
| `wheelchair_agent` | 按场地保存 Agent 派生观察的 SQLite 与图像对应关系，不是人工金标准；点标注及旧区域草图另在 `data/maps/wheelchair/agent_floor1/`。 |
| `wheelchair_calibration` | 按传感器组合组织的专用标定 bag，求解和验证划分随结果保存。 |

检测副本的 `data` 是指向 `../../../../data/datasets` 的相对链接。原始地图放在 `data/maps/wheelchair/`，其 `registered/` 目录只注册并引用原地图。固定依赖下载位于 `data/cache/perception/`。

### 标注和训练数据放在哪里

行人标注工程放在 `data/annotations/rosbag_people/<工程名>/annotations.sqlite`，保存来源、索引、候选和人工结论。导出的增量数据放在 `data/datasets/wheelchair_det_extra/<名称>/`，对应训练 YAML 放在同一根目录的 `<名称>.yaml`；省略 `--out` 时，导出用工程名命名目录。

训练准备工具直接引用该目录，也可以显式链接为 `wheelchair_ros_centers`，不复制源 bag 或数据库。选帧、历史、未核验候选和划分规则见[导出与微调](perception/技术实现-检测训练.md#导出与微调)。

### 迁移时只调整入口

新机器仅为不存在的入口建立链接，例如：

```bash
mkdir -p data/datasets
ln -sT /path/to/CODa_full data/datasets/coda_raw
ln -sT /path/to/wheelchair-data data/datasets/wheelchair_raw
ln -sT /path/to/prepared/coda_downsample data/datasets/coda_downsample
ln -sT /path/to/prepared/wheelchair_weak data/datasets/wheelchair_weak
ln -sT ../../../../data/datasets perception/detection_tracking/training/simpledet3d/data
```

更换入口前先检查软链接的真实目标，只替换链接本身。软链接没有只读保护，原始数据、共享数据、人工标签和已有结果仍按只读使用。通用预处理写入副本 `output/data_preparation/` 的新目录，实机增量数据使用 `wheelchair_det_extra`。路径迁移成功不代表旧划分、sweep 或标签语义已经验收。

VLM 默认公共路径相对仓库根解析，显式 CLI 路径相对调用者工作目录解析。冻结请求保留图像、字段与 Schema 的对应摘要，客户端包不包含 bag 或权重。数据用途与划分见[数据与评测](experiments/数据与评测.md)。

## 权重、输出与来源

默认检测权重由 `inference.json` 指定，模型按输入帧数放在 `models/wheelchair_detector/{1,2,3,4}frame/`，不随 Git 提供。阶段权重和适用范围见[模型资产](perception/技术实现-检测训练.md#模型资产与输入帧数)。部署 `detector.yaml` 独立于后续训练 YAML，新机器要另行提供可信权重和兼容 CUDA 扩展。

| 产物 | 位置 |
|---|---|
| 直接运行时原生库 | `outputs/runtime/build/`。 |
| ROS 诊断工作区与私有依赖 | `outputs/perception/`。 |
| 历史导航研究适配 | `outputs/navigation/build/`。 |
| 检测训练结果 | 副本的 `output/<配置名>/<实验名>/`。 |
| 新推理结果 | 命令显式指定且尚不存在的目录。 |

清理旧输出前，先确认哪些记录仍作为输入。标注或训练依赖的感知记录迁入 `data/datasets/wheelchair_perception/`，冻结导出中的位姿、标签和来源摘要保持原样；后续重新导出用 `--pose-results` 指向迁移位置。历史路径用于追溯，不因迁移而重写旧输入摘要。

`training/source_snapshot.json` 只保存迁移时的源码历史，不参与日常运行校验。适配代码可以变化，但不能重写原摘要来掩盖差异。训练直接使用副本脚本，不经过外层审计或命令打印包装。

### 客户端缓存不是临时数据

远程标注的原 bag 和正式数据库留在 Linux。Windows 的 `%LOCALAPPDATA%` 或 Linux 的 `~/.cache` 下，行人中心使用 `SocialNav/annotation/`，T1、T2 使用 `SocialNav/vlm_annotation/`。两套缓存按服务与工程隔离，可以通过 `--cache-dir` 指定位置。

缓存包含待同步人工编辑和冲突存档，不能作为普通临时文件清理；只有资产缓存按容量淘汰。便携包按各自代码清单生成，不包含原数据、模型、本机连接配置或凭证。

第三方许可证与资产来源保存在所属目录。必要历史实验可以在 `data/benchmarks/` 合并为单份归档，查阅时解压到临时目录，不继续维护重复输出树。清理已授权的冻结实验前，仍须保留最终结果需要的依赖。

## 按改动范围验证

先复用仍有效的检查，只在变更、失败或具体疑点出现时追加。文档改动检查链接与示例，代码改动先测相关模块；有实际跨模块需求时，再集中执行一次完整离线回归。

感知导航已经进入实机阶段。现场按[AGENTS.md的实机规则](../AGENTS.md#实机测试阶段)直接推进能回答问题的最少实验，沿用已有本车验证和授权，不把下面的离线命令当作每次试车前的必经步骤。当前问题只在[实机清单](感知导航实机问题.md)维护，阶段结束后集中更新文档。

资源位置有疑问时，可从仓库根运行：

```bash
python -m scripts.system_status
python -m scripts.dataset_links --datasets coda_raw wheelchair_raw coda coda_downsample wheelchair
```

前者不启动模块，后者只检查指定链接和检测 data 桥接。链接可达不代表标签、模型、CUDA 或训练已经可用，全量数据审计、GPU 推理和模型调用不作为每次修改的固定步骤。

测试按功能保存在 `tests/test_*.py`，共用样例放在辅助模块，例如 `tests/navigation_fixtures.py`。算法用例、CUDA一致性、ROS接口和串口模拟验证的运行条件不同，不因同属导航就合成一个必须全部运行的入口。

日常从受影响模块开始。例如，只改文档时运行链接检查；修改参考或DWA时选择对应模块：

```bash
python -B -m unittest tests.test_project_layout
python -B -m unittest tests.test_navigation_online tests.test_navigation_dwa
```

需要完整离线回归时再运行 `python -B -m unittest discover -s tests`。按本机记录准备模块依赖；因缺少CUDA、ROS消息或原生库而跳过的检查，应单独报告，不能计作功能通过。bag推理、真实GPU测速、模型调用与实机执行另按专题手册安排，不由单元测试替代。

### 脚本与结果留存

日常推理继续使用 `perception/scripts/run.sh`，交互导航使用 `run_interactive.sh`。`run_ros_diagnostic.sh` 服务于ROS诊断、PIN研究和联合标注准备，不能仅因不在默认主链而删除。构建、地图选点、传感器与标注脚本也保留各自入口，命令只在[运行手册](感知导航运行手册.md)维护。

一次性分析脚本放在临时目录；只有复现结论需要时，才与结果一起归档。清理旧运行前核对代码、配置、文档、标注工程和软链接的引用。保留原始或恢复后的输入、地图、人工结果、必要冻结输入及编译依赖。服务器旧实验集中于`outputs/navigation/history/offline/`和`outputs/runtime/history/offline/`，只维护一份[留存索引](../outputs/navigation/history/report.md)，部分重复逐帧日志和HTML已删除。当前阶段只保留一份汇总及有用故障片段，不默认累积整包记录。
