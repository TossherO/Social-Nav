Identify observable social groups for a navigating robot at the LAST observation. Use all three images and the measured geometry. Return only the required JSON; no explanation or Markdown. The geometric input contains no social-group truth.

INPUT
IMAGE_0, IMAGE_1, IMAGE_2 are real observations, oldest to newest. Each has front RGB on the left and metric BEV on the right. BEV contains only valid front-camera people, NOT a panorama; all input colors are neutral, NOT group labels. A visual tag P7 denotes integer PID 7, not string "7" or "P7". Use only the current PIDs listed in v; historical-only PIDs are forbidden.
The final observation table uses: v=current valid PID list; dt=relative seconds ending at 0; ts=time-source metadata; e=[xmin,xmax,ymin,ymax] in metres, x forward/y left; o=rows [pid,xy,b,h], each with three chronological positions, RGB boxes and original box heights. xy is [x,y] in metres; b is [x1,y1,x2,y2] normalized to 0..1000; h is pixels. Null means missing, NOT zero. d=rows [pid_a,pid_b,distance_t0,distance_t1,distance_t2]; only pairs with a distance <=3.5m at some time are listed. This is a geometry filter, NOT a suggested group. BEV range may extend beyond 12m. Ego motion is unknown: raw position differences are NOT person velocities; same-frame pairwise distances are invariant to rigid ego motion. Box yaw is NOT gaze.

SOCIAL DECISION
Associate PID tags with bodies, then inspect formation, depth and body actions across time. Report supported coherent units of companions or people sharing an activity. Persistent compact formation and coordinated walking/body orientation can support companionship without visible speech or faces. Proximity or same direction alone is insufficient. Overlapping RGB boxes at different depths are not evidence. Separate distinct formations; do not merge via a chain of nearby strangers or split a coherent multi-person unit into arbitrary pairs. No universal distance threshold defines a social group.
Report every supported group of at least two. Put a PID in top-level u only when membership is genuinely unresolved; small faces alone are not sufficient reason to abstain. Omit confirmed ungrouped people from both g and u. If membership is supported but activity is unclear, keep the group with relation "u". Readable distant formations can be evaluated; never invent links for unreadable people. Empty g and u means ALL valid people are confirmed ungrouped, not a default answer.
Relations: w=walking as companions; t=conversation with mutual orientation/communication evidence; q=queue toward a shared service; p=actively photographing another member; o=other supported shared activity; u=supported membership, uncertain activity. Standing alone is not t; a line alone is not q; holding a phone alone is not p. For multiple supported activities in one coherent group, prioritize q>p>t>w>o.
Flag k=1 ONLY for q/p when order or roles are visible. For q, members are head-to-tail. For p, members start with photographer, main subject, then other members ascending. Otherwise k=0 and members are ascending. Preserve visible q/p order; never sort away roles. Sort groups by minimum PID and top-level u ascending. Each PID occurs at most once across all groups and u.

OUTPUT CONTRACT: top-level object has exactly keys "g" and "u". g is ALWAYS an array of group OBJECTS, even for a single group. Each group has exactly keys "m","r","k": m is an array of at least two integer PIDs, r is one STRING from "w","t","q","p","o","u", k is INTEGER 0 or 1. u is an array of integer PIDs. Never quote PIDs; never flatten members into g. Do not use tuple/positional groups, boolean flags or extra fields.
